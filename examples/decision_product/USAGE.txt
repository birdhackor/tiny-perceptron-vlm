C-v3 裝置決策成品

這是從隨機權重訓練的小型決策模型，負責有限且明確的裝置工作流程。
支援 record / play / save 任務，根據許可、就緒狀態及給定候選提出動作建議。
它也能判斷必要資訊是否齊全，或依固定規準給0、1、2分。
建議可被接受或拒答；本程式不會實際操作裝置。

使用方式

以下指令以交付ZIP解壓後的資料夾為工作目錄。
原始repo中的範例另放在 examples/decision_product/；實際權重在交付包的 bundle/。
在已安裝課程環境的 Python 中，切到解壓目錄執行：
python -m tiny_perceptron.decision_product --bundle bundle --request examples/record-ready.json

另外兩個範例：
examples/record-unknown.json：就緒狀態未知，動作與評分應拒答。
examples/answer-absent.json：候選沒有正確動作，應拒答。

獨立環境需要 Python3.11以上、PyTorch2.11以上、numpy、safetensors0.8.0。
requirements.txt 列出依賴；依 PyTorch 官方指示安裝適合電腦的 CPU 版即可。
CPU版PyTorch安裝完成後，可用 python -m pip install -r requirements.txt 補齊其他依賴。
本次實際驗證使用 CPU；沒有要求安裝 Qwen，也不需要 Modal 或 Colab。

如何使用自己的資料

複製範例JSON，修改 devices、target，並以 null 表示不知道的欄位。
每筆裝置都須有 id、task、permission、ready。
id 可以使用自己的中文或英文名稱。permission、ready 只能為 true、false、null。
本版同時接受3–6個裝置；task 僅支援 record、play、save。
kind 可選 choice、info、rubric 或 all；language 可選 zh、en。
未提供 candidates 時，會使用目標裝置的五項動作。
自行提供時，須有1–7項，每項明列 id、device、action，且不能重複語意。
候選id是回傳答案的代號，須唯一且不得使用 none；device須是devices中的裝置id。
候選action只接受 stop、wait、record、play、save。

判讀結果

choice 的 status 為 accepted 才代表模型建議採用 selected 所指的候選。
status 為 abstained 時 selected 為 null，reason 會說明未採用的原因。
model_choice 是模型原始判斷；none 表示沒有合適選項或必要資訊不足。
confidence 是校準後分數，不是對任何新情況都成立的正確機率保證。
info 的答案在 results.info.selected：yes表示必要資訊齊全，no表示必要資訊缺漏。
這兩種都是完整判斷，status都為 prediction；prediction是status的值，不是另一個答案欄位。
rubric 的答案在 results.rubric.selected，分數是字串0、1或2，status為 prediction。
rubric 拒答時則 status為 abstained，selected為 null。
info、rubric 的 prediction 供查看，不套用choice的動作採用門檻，也不會執行動作。

固定規則

選動作：許可和就緒都必須已知；許可否先 stop，否則就緒否 wait，否則執行任務。
資訊齊全：record 需要許可與就緒；play 只需要許可；save 只需要就緒。
「已知」包含 true 和 false，因此資訊齊全不代表已取得許可或已經就緒。
評分：兩欄須已知；record 計算 true 的欄位數；play 在許可為 true 時得2分，
否則看就緒得0或1分；save 在就緒為 true 時得2分，否則看許可得0或1分。
動作與評分所需欄位缺漏時必須拒答。
上述規則用於製作訓練標籤；實際三類答案由神經模型產生。
結構化介面會先依裝置ID取出對應記憶；這一步只處理名稱對應，不計算答案。
採用動作前也會核對候選是否屬於目標裝置；對象不同的建議會被拒絕。

驗收範圍

qualification-summary.json 保存本次實際測量、採用門檻與來源指紋。
正式新情境測試是4–6個裝置的未參與訓練、選模、校準或政策選擇的可見事實組合。
三裝置入口另做手寫真值表與實際服務檢查，不宣稱有另一份未見三裝置的正式測試。
測試資料屬明確規則生成的有限工作流程；結果不能推廣成任意自然語言或通用助理能力。
請透過JSON入口使用。自由改寫狀態敘述、規則或新增任務，需要另外蒐集資料與驗證。

檔案

bundle/：實際權重、tokenizer、校準政策與逐檔SHA-256。
tiny_perceptron/decision_product/：推論、訓練、資料生成與驗收原始碼。
evidence/：保留本次結果與三項獨立審閱；MANIFEST.json 核對交付檔案。
本成品與既有已審閱教材分開保存，沒有為了改善成品而改寫教材。
