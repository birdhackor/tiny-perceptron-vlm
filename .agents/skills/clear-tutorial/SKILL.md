# 易懂教材的寫作與審閱

## 使用範圍

本 skill 隨 repo 保存，可用 `$clear-tutorial` 明確指定。它提供寫作與驗收規則，不代表模型已被永久訓練成另一種寫法。

先遵守使用者本輪指定的工作階段。若使用者只要分析、討論或審閱，不修改教材、不啟動訓練。新增本 skill 也不等於授權重寫全書。

預設讀者是數學不錯的高中生，或有基本數學能力但不熟的大學生。只假定他已學過明確列入入門內容的 Python，並依序讀過本節以前的課文；不假定他熟悉機器學習術語或本專案的開發歷史。依使用者指定調整這個背景。

## 本專案的工作順序

使用者指定分階段完成，不混做不同性質的任務：

1. 確定大綱、新增內容、權威來源與成品的有限任務。
2. 完成新增教材內容。
3. 依新架構改寫既有教材與必要圖解。
4. 依序完成易讀性、正確性、前後銜接的審閱與修正。
5. 獨立處理模型工程、訓練與能力驗收。
6. 回填成品事實、更新操作與權重並發布。

同一階段可以分工；上一階段尚未完成時，不預先進行下一種工作。實驗成績不決定成熟知識的教學安排；只有發現實質錯誤或實作與說明不符，才回修受影響的內容。

教材以原論文、官方文件及可靠教學支撐機制、用途與適用條件。小實驗用來建立直覺、展示實作與驗收成品，不要求每次重新證明業界知識。只保留有教學用途的數字與失敗案例；排版、文字或圖解更新不因此重跑訓練，只有能力宣稱或實作受到影響時才做相應驗證。

主線整合成品使用本課自行訓練的文字、視覺、語音與接頭權重。成熟模型的應用是清楚標示的延伸，不能用上游能力代替主線驗收。

## 核心標準

讀者在正文使用一個概念進行推理之前，就應知道它目前需要的意義。允許先提出問題，再立即解釋；不以後文、程式或外部知識替前面的說明補洞。

每一小節有一個主要學習問題。讀者應能用自己的話說出：現在要解決什麼、材料是什麼、希望得到什麼，以及這一步為什麼有幫助。

## 寫作流程

1. 先用一句話寫下本節的學習目標，例如「理解分類答案為什麼要轉成數字」。若需要同時解釋三個不同實驗，先檢查是否應拆節或明確安排過渡。
2. 從讀者能看懂的任務與具體材料開始。先展示圖片、文字、聲音的適當表示或資料表，再引入編號、向量與公式。明確交代答案的含義及每個編號的對應。
3. 沿用例子與名稱；每一步增加一個主要變化。換資料、任務、模型或評分方式時，先說明為什麼換、保留什麼以及現在要回答的新問題。
4. 讓正文形成「問題 → 材料與答案 → 做法 → 可觀察結果 → 原因」的連續關係。用自然段落呈現，不把每節寫成僵硬的欄位表。
5. 在需要時解釋術語，先給足當下夠用的意義。用貼切的譬喻建立直覺，再對應到實際操作；說清楚譬喻的適用範圍，不用譬喻代替機制。
6. 把導覽、前置連結、安裝細節、完整參數與重做紀錄放在合適的註解框、可展開區塊或操作頁。正文仍保留理解任務所必需的背景與實驗設計；不能把必要說明一起藏起來。
7. 顯示結果並解讀它。連結 JSON、指令或得分表只能補充查證，不能代替輸入、輸出與設計的說明。避免「我們已完成正式實驗」等開發進度敘事。
8. 選擇能教會明確概念的失敗案例。與學習問題無關的試錯歷史移出正文；不能為了敘事漂亮刪去限制結論所必需的證據。

可直接貼用的短 prompt 見 [writing-prompt.md](references/writing-prompt.md)。

## 圖解與實驗

- 檢查讀者是否需要自行想像空間位置、素材差異、資料流、答案對應或前後變化才能理解。如果是，評估加入圖片、SVG、表格或動畫；不要只清點已有圖檔。
- 實驗需要讀圖時，展示實際素材或忠實代表的示意，並清楚標明哪一種。圖中箭頭、框線、顏色及編號都應有意義，正文指出這次要看哪裡。
- 桌面正文內應看得清必要細節，手機上也能合理閱讀。放大檢視是補充功能；不能靠點擊放大才能理解基本說明。動畫的關鍵資訊也應能從靜態畫面讀到。
- 展示機器學習實驗時，交代任務、輸入、答案規則、哪些參數更新、訓練與測試如何不同、結果如何判定，以及結論的適用範圍。
- 分清手工算例、資料整理示範、梯度流通、真正更新參數及訓練後評測。沒有更新參數的 `backward()` 示範，不能當成模型已學會的證據。
- 比較效果時，列出主要改變與重要混淆因素。分類若讓顏色與形狀完全綁定，不能據此斷言模型學到其中某一種。
- 得分交代分母、判準與失敗類型；區分辨識、選取範圍、格式、正常結束與內容正確。資料有多少、訓練是否完成與能力是否提升各自需要證據。

## 審閱與修正

依 [review-protocol.md](references/review-protocol.md) 執行。不要先把全文交給審查者，再要求他假裝逐段看不懂。

先檢查第一次閱讀能否理解，修正後再檢查技術正確性，最後檢查前後銜接。若使用者要求獨立 subagent，使用不同審查者，提供最少必要背景並保存每輪原始記錄；沒有獨立審查者時，明確標記為作者自查，不聲稱獨立驗收。

審閱必須留下讀者遇到問題的位置、原文、當時能得到的理解，以及是否需要猜測或回讀。存在必要說明或圖解缺漏時，不判通過。AI 審閱是輔助證據，不等同實際高中生或大學生的理解測試。

本 repo 的已知問題示範見 [review-example-10-5.md](references/review-example-10-5.md)。

## 完成條件

- 一節的主要問題與例子相互對應，關鍵名詞、編號及箭頭在使用前已交代。
- 必需素材與圖解實際可見；證據連結、圖說與正文的數據一致。
- 沒有把計算梯度、較低訓練代價或較多資料直接當成泛化能力。
- 審閱問題有具體處理；修正後重新檢查受影響的段落、圖與銜接。全文摘要不能代替這些檢查。
- 回覆使用者時只陳述實際完成的工作與查證範圍，清楚區分已測、推測與尚未測試。
