# 第 20 章新版編輯計畫

這是寫作與遷移提案，不是已完成的獨立讀者審查。作者已完整閱讀目前的第 20 章、19.12、11.14–11.16、12.13–12.14，並檢視學生操作與訓練指引、章節產生器與閱讀時間規則。新版資料、底座、ASR、微調結果及公開版本尚未定案；本文不預填成績、資源需求或模型能力。

## 一、學生正文要講的故事

一位讀者想拿照片向助理提問，也想把打字換成說話。我們先讓他看懂並試用成品，再帶他找出成品的零件、準備適合任務的練習、調整小份權重，最後按用途驗收與交付。整章回答的是「怎麼做出並判斷這套助理」，不是「作者這幾天跑了哪些工作」。

第 19 章仍負責從頭組裝與追蹤教學 MoE；第 20 章接手已有圖文能力的底座。兩者的起點不同，無須把它們假裝成同一份權重一路長大。Dense/MoE 的資源理由只在模型選擇處交代一次。若本輪選擇不同底座或 ASR，按真正實作改寫，不預先固定成舊版 Qwen＋Whisper。

第一個具體情境可以是一張有店門口、人物與中文字的公開授權照片：先問可見物件，再讀招牌，把其中一個問題改成錄音。使用同一張示範圖讓三條輸入路線容易連起來；示範圖必須註明它屬於教學／訓練示範，不借它證明留出泛化。不替圖片編造「今天營業」「店主心情」等無法只由畫面確認的事實。若合法素材沒有同時具備三種內容，可以使用一張自然照片與一張文字照片，仍保持同一套對話介面。

全章只使用已選定、實際發布的新版本及其驗收結果。歷史 v3 紀錄留在舊的證據目錄與 Git 歷史；正文不逐句追加「原本……後來……這次又……」。

把試用放在前面是合理的：使用者不用先會推導 LoRA 才能按「送出問題」。但 20.1 應先講清楚路線，20.2 才要求下載，避免開篇把安裝命令、參數與授權一起塞進來。沒有足夠硬體的讀者可以只看已完成的介面截圖與實際原回答，繼續學後面的原理；不能用硬編答案的假介面冒充成品推論。

### 20.1：先看共同入口

開頭從「同一張圖、同一個問題，只把打字換成說話」出發。用 `natural_shared_chat.svg` 或其按本輪零件重畫的版本，展示圖片旁路、文字路徑、ASR 逐字稿、共用歷史與文字回答。第一次出現的「底座」「小份調整」「ASR」各用一句普通話說明，不先列大型參數表。

短程式只檢查相同文字如何接入相同對話，明示它是手寫資料卡，尚未辨識或推論。這一點可用一個句子說清楚，不每段重複三層免責。結尾只指向 20.2 試用和 20.12 定位語音錯誤。刪除舊 CPU 底座入口試跑、臺／台、蘑菇及語音歪曲的歷史片段；正式成績不在此頁出現。

### 20.2：成品先跑起來

本頁提供唯一完整的主要安裝、下載、啟動示範，優先採實際驗證過、最多學生能重現的路線。正文只保留選定作業系統的一條主線；其他平台與 GPU 分支交給補充操作指引，未實測的平台不標成已通過。

第一個框交代作業系統、Python、磁碟下載量與已量測的硬體範圍；數字由新測試填入，不沿用 v3 的 12.36 GiB 或載入秒數。權重粗估不是最低 RAM 保證。指令只顯示安裝、固定版本下載／核對與啟動；版本細節從正式清單取得，避免讀者手抄多個 SHA。

四步操作為：文字→附圖→辨識錄音→讀過逐字稿後送出。保留「辨識語音」尚未請聊天模型回答、照片與歷史可接續、開始新對話與 Ctrl+C。用新成品的實際 UI 截圖標出按鈕和逐字稿，不在此重述完整測試分數。GitHub Pages 是教材，本機網址才在學生電腦運算，這一區別應說清楚一次。

補充 `STUDENT.md` 可以包含斷線、離線、CUDA、dtype 與常見錯誤；它不能成為只在 repo 看得到、網站主線缺少操作前置的第二份教材。兩者的最短命令必須一致。此頁重現的是使用，不假裝已經重新訓練。

### 20.3：分清「整套多大」與「本課改多少」

先接回 20.2 的下載：「小份調整很小，為什麼還要下載底座？」列圖文底座、調整權重、ASR 的職責；精確數量只用本輪實際載入與去重數出的結果。正文最多一個簡短權重乘法，將權重 bytes 與執行時記憶體分開。

Dense/MoE 只保留一小段決策理由：MoE 的部分專家計算並不讓所有權重消失；這裡按能用的成熟底座、資料與實測資源選擇，而不以名稱宣稱較好。更深入的 MoE 比較連回 19.2／15.1。上游已訓練能力與本課更新範圍要分清，但無須再重述 v3 每項失敗。

### 20.4：先讓練習題對上用途

用一組「我要它怎麼回答→需要什麼示範」配對介紹資料：

- 中文照片短問答，需要保留圖片且真的回答物件、動作或關係；單把英文 caption 改名 `answer` 不會使它等同中文問答。
- 自然圖片讀字，需要原圖與匹配的轉寫，涵蓋本任務的字形、背景、角度及字型；整齊合成字卡仍可隔離機制，不能取代全部自然素材。
- 聊天與多輪回應，需要完整請求與合理回答，以及回合間需要保留的條件；同一題複製多次不是多樣性。
- ASR 的錄音／逐字稿和聊天的請求／回答提供不同監督。若只換用成熟 ASR，本課沒有因此完成 ASR 微調；若本輪真的更新它，另列那個模型的資料和更新實驗。

展示各一筆真正納入本輪訓練的資料卡，含來源、題目、完整回答與用途。用小表給出每項選取的獨立素材數與題數，完整授權及篩選紀錄連到新 `DATA.md`。公開可下載與可用來訓練、改作、重新散佈不是同一句話；只引用已確認正式權利來源的素材。若某資料卡僅宣稱程式碼 MIT，不把它寫成所有圖片都可重發布。

正文不展開法律來源抓取過程、資料庫 API 失敗或所有雜湊；但一張表裡清楚給出資料集、來源、主要用途與授權。AI 翻譯／改寫的答案要註明，不能說成來源官方人工繁中標註。新增資料量或更多步數是否改善仍由之後的驗收回答，這裡不作因果保證。

### 20.5：把同一份素材留在同一邊

保留現有四筆家族資料卡的短程式及跨份交叉檢查，改成與本輪來源相符的圖、檔案、聊天家族。增加裁切、同圖多問、改寫／翻譯等衍生例子只需一句，不拉成新的分類課。

正文提供新切分摘要，註明什麼是獨立家族、什麼是衍生題。檔案指紋與來源 ID 配合查重，不能用替一題改名來消除重複。若來源提供同景照片、同對話串或同說話者身份，切分依據應使用可核驗的更高層家族；沒有說話者 ID，不自行宣稱說話者全獨立。

v3 已公開的最後錯題不能繼續當作 v4 未見過的盲測。它們可作固定回歸或外部觀察，但本輪應另準備在選版前不看輸出的留出驗收；清楚區分這兩種用途。公開底座是否在上游預訓練見過某公開資料也通常不能證明，正文用一個短限制交代。

### 20.6：LoRA 只改指定分支

保留現有 LoRA 小矩陣真更新與 `natural_base_adapter.svg`。說清楚固定 W 仍運算、修正 A/B 更新、合計可訓練數與 rank 的意義。小例子的數字屬於 CPU 演示，不冒充本輪大模型更新。

最後用一個簡短表填真正選定的模組、rank／alpha、可更新參數及未更新的模型。q/v 的矩陣尺寸推導可以保留為折疊／補充連結；不是本節主知識，不必先補 GQA 才能理解改了誰。梯度／實際更新證據用一句「指定權重得到梯度且更新，凍結檢查按記錄範圍通過」概括，抽樣只稱抽樣。完整張量指紋與更新器名單留審計檔。

### 20.7：只把要學的回答計入代價

接著前一頁自然問：「哪一段文字告訴這份修正應該怎麼改？」用一筆真實資料畫出角色、問題、圖片位置與完整助手回答，其中問題仍可供模型讀取，但只在指定回答位置計算 SFT 代價。如果新訓練使用多輪助手監督，按實際遮罩說明，不能沿用「只最後一段」的舊說法。

短 CPU 例子只展示目標位置及結束符號，不下載完整底座。必須核對新 tokenizer／模板產生的實際標籤；視覺位置不是普通中文字，不能用字數猜序列上限。保留長題截斷會使答案消失這一因果概念，但完整的超長樣本拒絕、過濾比例與保留條件放配方說明。不同回答長度如何加權可以連回 5.2，而不是此頁重新推導梯度累積。

### 20.8：先驗證、再固定、最後驗收

本頁不把作者的每次訓練寫成時間線。先講新訓練的單一推薦配方，用一張簡短表格列真正的資料版、底座、更新範圍、訓練預算、圖片／文字預算與生成設定；完整可執行指令在新 `TRAINING.md`。若所有主線讀者都需要親手訓練才讀得懂，說明頁仍然寫得太依賴環境。

用流程 SVG 說明：train 更新→validation 選設定→固定權重與配方→test 驗收。正文提供完成狀態、實際更新量與訓練檢查摘要，然後交代驗證用哪些任務避免某一能力倒退。若跑多個候選，最多一張與學習問題有關的候選表；沒有要教受控比較時，不放每次 LR、失敗 job 或秒數。

訓練代價下降、程式正常結束、回答符合用途分開看。GPU 訓練秒數、峰值與中途儲存屬於重做需要，可放實測資源框及技術指南，不能充滿每頁。新能力驗收在接下來各頁進行；不先用最後分數選最漂亮的候選。

### 20.9：按畫面支持的事實核對照片

保留人／車相同物件、不同動作的示意和短卡片程式，它直接教可見關係。然後用一張本輪留出照片以及一段完整實際回答，標出哪些內容能由圖確認。若例子中有學概念必要的錯誤，只留一個「名詞對，但關係／新增細節錯」對比；不再放機車、玻璃、兩次 TRAIN 換圖與多段重複生成四套展示。

本頁只列新底座與新選定版的照片分項表，明示圖片數、問題數、判分規則、生成是否完成。物件、動作、關係和整體描述的成功不能互相冒用；人工語意評閱與關鍵詞命中不是同一個指標，關鍵詞的詳細副表可省略。換圖對照若已實測且必要，用同一段問題、實際不同像素及留出條件的一組短對照；TRAIN 示範須保留其身份。

結果好壞都按完整集合報，必要限制用一小段交代。刪去 LR 選版、舊驗證結果及歷史重複解釋。公開圖例必須具有可再發布的權利與適當署名；不能為了漂亮的案例重散佈權利未明照片。

### 20.10：抄寫文字內容

本頁從「臺／台」或本輪真正有差異的短字串切入：意思相近不等於逐字一樣。連回 11.16 的編輯距離，用一個最短程式教整串正確與 CER；不在同頁再做完整 Counter／讀序課。

一次交代預先固定的 NFKC、空白、標點、異體字與簡繁政策。規則若本輪改變，屬於新評估版本，不能重算舊原始gold後稱舊模型進步。總 CER 要按全體編輯次數／全體參考字數計算；無字圖另報有字／無字，避免空分母。CER 超過 100% 如有必要只用一個插入例子解釋，無須展示77行或126行重複文字。

正式新表分開清楚字卡、自然文字圖片與有字／無字，並給各自獨立素材數。至少包含適合本輪用途的繁中文字形評估；若只有簡體素材，明說範圍，不把繁體prompt當作已訓練繁體OCR。字卡／街景差別是必要的概念，最多展示一組與新成品相關的對比；不復述舊 CC-OCR 藥局、刺袖/刺繡、密集ABCD三套案例。標註有遺漏或歧義的題目按事前規約另記，不靠看模型答案後改gold提高分數。

### 20.11：讀序與版面

使用現有兩行圖或按新實作擴成兩欄，保留 Counter 相同但次序錯的短程式。各字辨識、行間順序與版面讀法分開說；橫排先上後下不是所有中文頁面共用規則。

本輪若有真實讀序標註，報對應一項數量及結果；若只有攤平成文字的答案，不能宣稱已驗收完整版面。合成版面可以當控制例，但清楚標為合成，與自然多欄頁面分開。圖片細節預算只連回11.15/20.3與配方，不再重複權重或像素數字。若新訓練沒有版面任務，這頁只能教其所需知識與概念實驗，能力卡需標未測／未訓練，不能將概念演示寫成已具備能力。

### 20.12：語音兩站的責任

優先用真正的請求或問句，以及合理回應，檢查「文字／語音都能聊天」。朗讀百科陳述可作 ASR 題，不能繼續用一條「不得重述」的規定暗中改稱一般聊天成功率。若沒有合法自然問句語料，應清楚區分公開朗讀轉寫評估與另建的提問/回應評估；合成人聲示範亦不能冒充真人問句能力。

同一語意保留正確文字輸入、真ASR輸出、兩份聊天原回答、同歷史／照片。兩條路分別報告聊天品質，轉寫另報告 CER 和內容關鍵字問題。ASR 如果已升級，說明其真實模型；如果沒有本課更新，就不報告「訓練前後ASR進步」。

只留一組能清楚定位的對照：例如錯在ASR的關鍵字，或逐字稿正確但聊天無據判斷。二者都重要，但不用各展示兩段長篇百科錯句。12.14 已有手寫「我不吃辣」接力例，不在本頁再堆一個手寫十三加二及兩套真實案例。ASR顯示、使用者更正、原始評估不換真值分別一句說明，結尾提醒本成品是否有TTS、原生音訊、即時對話，以實際交付範圍為準。

### 20.13：把成品作為一套東西交付

把模型、調整、處理器、tokenizer／模板、ASR與配置畫成一張配套清單，解釋版本／檔案指紋只保證「拿對了」，不保證「答對了」。SHA人工小例可保留，正文不要求學生讀112個張量指紋或審批日誌。

本頁是唯一總能力矩陣：文字聊天/多輪、自然影像、自然中文OCR、讀序、有字/無字、ASR及語音聊天各自保留獨立分母與範圍。與20.9–20.12不同，本頁只給摘要，詳細子分數不再重複列出。結果按新真實檢驗填寫；沒有測到的能力明確寫未測，不因這一章節教過概念便打勾。

公開入口指向新正式清單與匿名下載，操作連結回20.2，不再次重複列出整套安裝指令。訓練資料取得與重訓各有一條連結；推論小包和精確續訓狀態不同，再用一個短句連回19.11。保留資料與模型授權、修改說明、來源與新能力卡；私人HF路徑、費用帳本、CI job編號、三輪審查人數與反覆補審的過程不進學生正文。
