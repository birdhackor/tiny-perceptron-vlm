# 小小感知機：從接話開始理解模型

輸入「今天天氣」，手機會提供幾種接法。程式怎麼猜下一個字？這套教材把問題縮到幾個字，讓你看見它如何整理例子、分配機率、衡量猜錯的代價，再修改自己的猜法。接著才逐步加入較長前文、對話、圖片、聲音與工具。

## R.1 先讀一節，不必先安裝

從[第一節：文字怎麼變成數字？](chapters/01.md#1.1)開始。材料是「貓看狗，狗看貓。」：先替字編號，再換回原句。你可以在紙上列字表，確認兩次「貓」使用相同編號，最後能還原原文。這件事弄清楚後，再看程式怎麼做。

網站的說明、程式與結果放在同一個位置，可以直接閱讀。想修改例子時，頁尾的「在 Colab 動手做」會開啟同一節 Notebook：一份把文字與可執行程式放在一起的文件。也可以下載 Notebook，在自己的電腦練習。[W.1](first-steps.md#W.1)提供兩種開啟方式。

不熟 Python 時，先看[W.2 的清單與字典](first-steps.md#W.2)。遇到數字表的形狀，再看[W.3](first-steps.md#W.3)。數學暖身可以隨用隨查；正文會在需要時解釋術語，你不用先背一份名詞清單。

第一節讀完，可以試著解釋：為什麼同一個字需要固定編號？編號和字的意義有什麼不同？說得出來，就已經完成這一小步。

各主題也可以分開學。有時一張小數字表就能說明機制；討論圖片時，可以換成簡單圖卡。局部範例各自成立，最終整合專題才追蹤同一個模型如何接續學習。

## R.4 理解零件，再驗收整合

一個只有幾個數字的小例子，能讓你追蹤每一步。例如查表得到向量，再把向量混合成下一字的分數。它的價值是把機制看清楚；真正訓練時，再用許多例子反覆更新，並留下不參與更新的題目檢查能力。

譬喻幫我們找到起點，實際數字讓譬喻落地。「查筆記」對應的是比對位置、算比例、混合內容，不代表模型像人一樣讀書。每節會指出眼前結果能支持哪件事，讓你逐步學會判讀。

第19章把前面學過的零件接成一位有限助理。文字核心讀問題並生成回答；圖片與聲音入口先把素材轉成特徵，接頭再把這些特徵轉成核心能接收的向量。這樣，問商品、讀字卡、聽客服錄音和使用計算器，都能交給同一位助理。連接方式見[19.6](chapters/19.md#19.6)。

模型中會隨訓練調整的數值稱為權重。這份成品先由程式建立初始權重，再從我們提供的資料學習；它沒有借用成熟模型已學好的神經權重。主線使用MoE設計，也保留較簡單的Dense對照設計，兩者的差別會在[19.2](chapters/19.md#19.2)說明。

這兩種v2模型已完成訓練、公開推論權重與固定最後測試，仍未通過全部原定能力判準。任務限於少量教過類型的文字請求、商品與位置圖、已知中文字卡、真人語音需求及計算工具。完整成績與限制見[19.12](chapters/19.md#19.12)，試用見[公開CPU操作](../docs/selftrained/v2-public-cpu-commands.md)，自己重做見[本機訓練指引](../docs/selftrained/TRAINING.md)。成熟Qwen／Whisper的路線另放第20章，讓你練習接手已有能力的模型。

MoE、PPO、DPO、MTP、量化、蒸餾各自回答不同問題，也有互為替代的安排。第一次完成小助理，不必把每個方法都套一次。先看任務需要什麼，再選架構、訓練訊號與交付方式；成品的能力與限制集中在[19.12](chapters/19.md#19.12)；下載與重做步驟見[19.11](chapters/19.md#19.11)，舊合成示範保留自己的[固定清單](../docs/course-experiments/capstone-public.json)，各局部實驗的操作見[操作頁](training.md)。

# 操作與數學暖身

想知道電腦怎樣從一段文字接著寫出下一個字，不必先背完數學名詞。這份暖身先教你打開可動手的工作頁，再用動物清單、考試成績與飲料配方認識後面會用到的工具。各節可以按需回來查：程式的資料怎麼取、數字表的軸怎麼讀、機率如何計代價、可調數字怎樣改善。每次只改一個具體輸入並核對輸出，讓閱讀和實驗接在一起。

## W.1 第一次開啟教材

讀程式和動手改程式的感覺不同。你可以先把教材當作書讀，等某個數字引起好奇，再打開那一節的工作頁執行。本課每節會先交代一個問題，再用小例子說明做法；程式不是需要全部背起來的答案，而是讓你核對「剛才的解釋是否真的會產生這個結果」。暖身各節也可按需閱讀：遇到清單就看 [W.2](#W.2)，遇到數字表的形狀就看 [W.3](#W.3)，不用先修完一套數學課才開始第 1 章。

線上閱讀入口是[教材網站](https://birdhackor.github.io/tiny-perceptron-vlm/)。選一節後，「在 Colab 動手做」會開啟雲端 Notebook，也就是把正文和可執行程式放在同一份文件。登入 Google 並連線到 CPU 執行環境後，可從「執行階段 → 全部執行」跑完整份；第一個程式框（「準備本節的工具」）會下載專案並安裝工具，要等它完成才能使用後面的程式。雲端介面和服務狀態可能改變，若下載失敗，可先讀正文或改用下述本機方式。

本機方式先準備 [uv](https://docs.astral.sh/uv/getting-started/installation/) 和 [Git](https://git-scm.com/install/)：uv 負責安裝與管理 Python 套件，Git 負責下載與管理專案檔案。安裝 Git 後在終端機執行 `git --version`，應顯示版本號。終端機是輸入指令的視窗；下列三行依序下載專案、進入專案資料夾、安裝 CPU 與 Notebook 所需工具。每行完成、回到可輸入狀態後再輸入下一行。

```bash
git clone https://github.com/birdhackor/tiny-perceptron-vlm.git
cd tiny-perceptron-vlm
uv sync --frozen --extra cpu --group notebook
```

`uv sync` 根據專案的套件清單建立 `.venv`，這是只供本專案使用的工具箱。`--frozen` 採用已記錄的套件版本；`--extra cpu` 選 CPU 用的 PyTorch；`--group notebook` 加入開工作頁的工具。GPU 選擇另見 [環境說明](../docs/environment.md)，現在用 CPU 足夠做短實驗。下載和安裝需要網路。完成後可在本機 CPU 環境執行本書的小型示範程式；若需要下載新的專案版本、套件或實驗檔案，請保持網路連線。

在 macOS 或 Linux 執行 `source .venv/bin/activate` 啟用工具箱；Windows PowerShell 執行 `.venv\Scripts\Activate.ps1`。啟用後，`python` 指向剛安裝的 Python 工具箱。仍在專案資料夾內，接著執行：

```bash
python scripts/check_env.py
python -m ipykernel install --sys-prefix --name tiny-perceptron --display-name "Tiny Perceptron"
jupyter lab notebooks
```

如果 Windows PowerShell 在啟用時顯示「此系統上已停用指令碼執行」或 `PSSecurityException`，被擋住的是 `Activate.ps1` 啟用腳本，不表示 Python 工具箱沒有裝好。仍在專案資料夾內，改用以下三行，直接指定工具箱裡的 Python，不必先啟用：

```powershell
.\.venv\Scripts\python.exe scripts/check_env.py
.\.venv\Scripts\python.exe -m ipykernel install --sys-prefix --name tiny-perceptron --display-name "Tiny Perceptron"
.\.venv\Scripts\python.exe -m jupyterlab notebooks
```

往後若教材寫 `python ...` 或 `.venv/bin/python ...`，也可把 Python 的路徑換成 `.\.venv\Scripts\python.exe`，其後的參數保持相同。

兩組指令做的是同樣三件事。第一行檢查 Python 與 PyTorch 能否使用；看到 `compute` 那列為 `OK`（括號中的裝置名稱依電腦而異），且套件沒有「未安裝」或最後的紅色錯誤，就表示計算環境可以使用。第二行登記工作頁要用的執行環境，第三行啟動 JupyterLab，終端機會提供瀏覽器網址。開啟 `01/1.1.ipynb`，選 **Tiny Perceptron**，點進一個程式框並按 **Shift+Enter**。一個框叫 cell；負責執行它的程序叫 kernel，可想成工作桌：上一格取過的名字還留在桌上，後面才能使用。

要試讀暖身中的短程式，可以在 Colab 用上方「＋程式碼」新增程式框；JupyterLab 則用工具列的「＋」。把暖身的整段程式貼入新框，先跑完「準備本節的工具」程式框，再選新框按 Shift+Enter。貼入時保留每行開頭的空格，它們可能是 Python 分辨重複動作範圍的縮排。

因此更改前面的輸入後，需要重跑依賴它的後續格子；只跑最後一格可能仍使用舊資料。第一次開啟、或想檢查整份能否從零重現時，在 JupyterLab 選「Kernel → Restart Kernel and Run All Cells」，清空工作桌再由上到下跑；Colab 則在「執行階段」選單找「重新啟動工作階段並全部執行」（介面也可能稱重新啟動執行階段）。練習打開 [1.1 正文](chapters/01.md#1.1) 對應的工作頁，先執行一次，再把輸入那行 `text = "貓看狗，狗看貓。"` 改成 `text = "鳥看狗，狗看鳥。"`，重啟並全部執行。程式最後的文字輸出應為 `鳥看狗，狗看鳥。`，而非舊句；這就是要核對的還原結果。若看到紅色錯誤，先讀最後一行再查 [W.7](#W.7)，不要急著重裝所有工具。

## W.2 看懂程式如何存取與重複資料

你要整理兩張動物照片，先記下「貓、狗」，再替第一張加上「貓在睡覺」的說明。Python 也能按順序保存這些資料，再依位置或欄位名稱取出。下面沿用這份動物清單，看程式怎麼存、怎麼取，以及如何逐項重複同一個動作。

`animals = ["貓", "狗"]` 把右邊的清單取名為 `animals`。方括號表示清單（list），逗號分開其中的項目，引號表示文字。`=` 的意思是「讓這個名字指向右邊的結果」，不是數學課的等號。電腦從 0 開始編位置，所以 `animals[0]` 取出「貓」，`animals[1]` 取出「狗」。方括號放在名字後面時，就變成「取出某個位置」。這個位置編號叫索引（index）。

字典（dictionary）則像貼好欄位名稱的表單。`record = {"animal": "貓", "caption": "貓在睡覺"}` 用大括號裝入兩個對應；冒號左邊的名字叫鍵（key），右邊是值（value）。`record["caption"]` 根據鍵取出說明，不是查清單的第幾項。鍵和值都可以是數字或文字，鍵在同一份字典裡不能重複。

下面的輸入是兩個動物名稱和一筆記錄。`len` 計算項目數量；`print` 把括號中的結果顯示出來。先逐行執行，再觀察最後的迴圈怎麼重複同一個動作。

```python
animals = ["貓", "狗"]
record = {"animal": "貓", "caption": "貓在睡覺"}
print(animals[0], len(animals))
print(record["caption"])
for animal in animals:
    print("看到", animal)
assert len(animals) == 2
```

前兩行輸出依序是 `貓 2` 和 `貓在睡覺`。`for animal in animals:` 每次從清單拿一項，暫時叫它 `animal`；下面縮排四格的 `print` 因而跑兩次，印出 `看到 貓`、`看到 狗`。冒號和縮排告訴 Python 哪些行屬於這個迴圈。`==` 是詢問兩邊是否相等，`assert` 是檢查這個問題的答案：成立就繼續，不成立就停下來顯示錯誤；通過時不會額外印出訊息。

## W.3 tensor 是有軸的數字盒子

班上有兩位同學，每人有三次小考成績。若只把六個數字寫成一排，就容易忘記哪些屬於同一人；把它們排成兩列、每列三格，就能沿著「同學」或「考試」兩個方向查資料。模型也經常同時記錄多筆資料，每筆又有很多數字。tensor 是 PyTorch 保存這類有規則分組數字的容器，中文常譯為張量；先理解分組，比先背名稱更有用。

一個單獨的數字叫純量（scalar），一排數字叫向量（vector），兩個方向的數字表叫矩陣（matrix）。它們都是 tensor 的不同形狀。每個可編索引的方向叫一個軸（axis）。下面以兩位同學的三次成績作輸入，第一個軸選同學，第二個軸選小考；需要的 Python 索引已在 [W.2](#W.2) 說明。

接著用這張表回答兩個不同問題：每位同學的平均是多少，以及每次小考的班級平均是多少。跨哪個方向計算，會決定留下哪個方向的資料。

下圖上方是本例中的六個成績，列標同學、欄標小考。下方兩種箭頭表示選取不同方向的數字一起平均：跨三次小考，得到兩個「每人平均」；跨兩位同學，得到三個「每次小考平均」。箭頭指的是一起計算的數字，不是把資料搬到另一格。平均跨過哪個軸，結果就不再保留那個軸。

![同一份兩列三欄的成績，跨小考平均得到70與90，跨同學平均得到70、80、90](figures/rewrite-W-3-axes.svg)

平均時要先說清楚要跨哪個方向。`mean(dim=1)` 跨小考軸，把每人的三個數平均，得到 `[70, 90]`，留下同學軸。`mean(dim=0)` 則跨同學軸，得到三次小考的班級平均 `[70, 80, 90]`，留下小考軸。`dim` 是指定軸的編號，從 0 算起；寫 `dim=-1` 表示最後一個軸，在這張兩軸表上和 `dim=1` 相同。軸的編號取決於資料放法，不是固定代表某種意義。

程式先建立這份表，再印出形狀、取出的成績與兩種平均。

```python
import torch

scores = torch.tensor([[60.0, 70.0, 80.0], [80.0, 90.0, 100.0]])
print(scores.shape)
print(scores[0])
print(scores[1, 2].item())
print(scores.mean(dim=1))
print(scores.mean(dim=0))
```

`torch.tensor` 把兩層清單變成數字表。`.shape` 告訴我們每個軸有幾格，輸出 `torch.Size([2, 3])`，也就是兩位同學、每人三個數。`scores[0]` 取第一位同學整列，得到 `[60, 70, 80]`；`scores[1, 2]` 取第二位同學的第三次成績，得到 100。`.item()` 把只有一個數的 tensor 取成普通 Python 數字，方便顯示；它不能用於整張表。

後面有時會用普通 Python 資料印出結果：`tuple(scores.shape)` 把軸長度收成以括號表示的一組數字，得到 `(2, 3)`；`scores.tolist()` 把這張 tensor 的數值轉成兩層 Python 清單。若只取一列再用 `.tolist()`，得到的就是那一列的一層清單。這兩種轉換用來方便顯示或讀取，不會修改原本的 `scores`、數值或軸順序。

後面的文字模型常看到 `[B, T, D]`：B 是同時處理幾筆句子，T 是每筆有幾個文字位置，D 是每個位置保存幾個特徵數字。這些字母只是我們替三個軸取的標記，不是 Python 特殊語法。例如 `[2, 4, 3]` 表示兩句話，每句四個位置，每個位置三個數；第一個軸取 0 後，仍是一張 `[4, 3]` 的表。看到新形狀時，先把每個軸的意思寫在旁邊。

`reshape` 可以把同樣的數字重新分組，例如 `scores.reshape(6)` 把兩列排成六個數的一排。它不改數值，也不知道哪些數屬於同學；要分回來，就得知道原本是 `reshape(2, 3)`。兩邊總格數必須相同，六個數不能重排成八格。

練習把第一位同學的最後一次成績從 80 改成 110。執行前先預測：每人平均中誰會變？哪次小考的班級平均會變？核對應得到 `[80, 90]` 與 `[70, 80, 105]`。若分不清兩種平均，不妨在紙上畫兩列三格，把正在平均的數字圈起來。

## W.4 機率、log 與猜錯的代價

袋子裡有三張「貓」卡和一張「狗」卡，每張抽到的機會相同。隨手抽一張，抽到貓的機率就是 3/4，抽到狗是 1/4。機率（probability）用 0 到 1 的數字表示事件出現的機會：0 表示不會，1 表示一定；互斥且涵蓋所有結果的機率要加總為 1。若候選只剩貓和狗，不能同時把兩者都說成 0.9。

文字模型也會分配候選字的機率，但我們需要一把尺衡量分配好不好。假設答案是貓，甲給貓 0.9，乙給貓 0.1；甲應該受到較小的處罰。光看「最後是否選貓」不夠，還要看把正確答案看得多可信。常用的代價是 `-log(p)`：p 是給正確答案的機率，`log` 是自然對數，也就是以數學常數 e（約 2.718）為底的對數。

對數是在已知次方結果時，反求指數 a。若 `p = e ** a`，那麼 `log(p) = a`。`**` 是 Python 的次方符號：`e ** 2` 是 e 乘 e，`e ** -1` 則是 1/e，約 0.368；因此小於 1 的正數能對上負的次方。a 也可以不是整數，程式會用 `math.log` 算出它。當 p 在 0 與 1 之間，a 是負數，因此加負號後得到非負代價。p 越接近 1，代價越接近 0；p 越接近 0，代價越大。下列程式逐一輸入三個正確答案機率，看看代價如何改變。

```python
import math

for p in [0.9, 0.5, 0.1]:
    cost = -math.log(p)
    print(p, round(cost, 3))
```

`round(..., 3)` 只把顯示的數字縮成小數三位。三種代價依序約為 `0.105`、`0.693`、`2.303`：給正確答案 0.9 時代價小，給它 0.1 時代價大。這把尺特別懲罰「很有把握地排除正確答案」。

為什麼對數常出現？若兩個答案的機率相乘，對數會把乘法變成加法：`-log(p1*p2) = -log(p1)-log(p2)`。例如假設兩題答對與否互不影響，這叫獨立；此時兩題正確機率都為 0.5，同時答對的聯合機率是 0.25，總代價是 `1.386`，等於兩個 `0.693` 相加。於是我們能把很多位置的代價加起來或取平均，而不必一直乘越來越小的數字。真的給答案機率 0 時，代價沒有有限值；程式也不能直接計算 `log(0)`。

後面會遇到 softmax，它把一組自由的分數換成總和為 1 的機率；cross entropy 則是一個計算正確答案平均代價的工具。先記住兩者做不同工作即可，具體分數與計算會在 [1.7](chapters/01.md#1.7) 和 [1.8](chapters/01.md#1.8) 展開。PyTorch 的 `cross_entropy` 接收原始分數，內部已處理換算，因此不要先把它的輸入換成機率。

練習在清單加入 `0.25`，先預測代價比 0.5 大還是小，再執行核對，應約為 `1.386`。正確答案得到的機率越小，這份猜法的代價就越高。

## W.5 忘了線性代數，可以先想配方

兩間店各有一份飲料配方，材料是紅茶、牛奶和糖。第一間的用量寫成 `[2, 1, 0]`，第二間是 `[1, 2, 1]`。如果三種材料每單位分別提供 10、20、30 分成本，第一杯成本就是 `2×10 + 1×20 + 0×30 = 40`。每種材料乘自己的權重，再把結果加起來，叫加權和。矩陣乘法只是把許多這種配方一次做完，沒有忽然增加一種神秘運算。

先回顧 [W.3](#W.3)：兩間店、每間三個材料量，形狀就是 `[2, 3]`。現在要同時計算兩種指標，成本權重是 `[10, 20, 30]`，另一種假想甜度的權重是 `[0, 1, 4]`。把兩套權重排成三列兩欄，每列對應一種材料，每欄對應一個指標，就能用 `@` 做矩陣乘法。左右相接的軸都是三種材料，這個方向會被乘完加總。

```python
import torch

recipes = torch.tensor([[2.0, 1.0, 0.0], [1.0, 2.0, 1.0]])
weights = torch.tensor([[10.0, 0.0], [20.0, 1.0], [30.0, 4.0]])
result = recipes @ weights
print(result)
print(result.shape)
```

輸入 `recipes` 每列是一杯飲料；`weights` 的第一欄計成本，第二欄計甜度。`result` 輸出兩列：`[40, 1]` 和 `[80, 6]`。以第二杯為例，成本是 `1×10+2×20+1×30=80`，甜度是 `1×0+2×1+1×4=6`。結果形狀 `[2, 2]`，保留兩間店，將每杯三個材料量換成兩個指標。只有對應材料的三個格子互相乘，不會把第一間的資料和第二間混在一起。

通常用 `[2,3] @ [3,2] → [2,2]` 記住這個規則：內側兩個 3 要相同，外側兩個 2 決定結果形狀。若右邊只有兩列，程式不知道第三種材料該乘什麼，就會報錯。模型也用這種計算，把一組輸入特徵按權重混合成另一組；特徵在這裡只是描述每筆資料的數字，不一定有飲料材料那樣清楚的名字。

PyTorch 的 `nn.Linear(3, 2)` 包裝了「三個輸入配成兩個輸出」。`nn` 是神經網路工具箱，Linear 稱線性層。它還加上一個偏移量（bias），例如每杯固定的杯子成本，所以實際做 `輸入 @ 權重轉置 + 偏移量`。Linear 儲存的權重形狀是 `[輸出數, 輸入數]`，與上例相反；轉置 `.T` 把列欄交換，才配得上輸入。

```python
from torch import nn

layer = nn.Linear(3, 2)
with torch.no_grad():
    layer.weight.copy_(weights.T)
    layer.bias.copy_(torch.tensor([5.0, 0.0]))
print(layer(recipes).tolist())
```

這段接續前段執行，沿用 `recipes` 的材料用量，將相同的成本、甜度權重 `weights.T` 手動寫入 Linear，再為成本加 5。`copy_` 把數字抄進層的權重；`torch.no_grad()` 表示這次設定不必記錄如何求導，求導會在 [W.6](#W.6) 解釋。`.tolist()`把數值表轉成一般Python清單，方便直接讀數字。兩列結果是 `[45, 1]`、`[85, 6]`，甜度不變。練習只把偏移量的 5 改成 8，先預測兩杯成本都增加 3，再執行核對；若甜度也變了，就檢查你改的是哪一欄。

## W.6 忘了微積分，可以先想旋鈕敏感度

想把水溫調到 3 個單位，眼前的旋鈕位置卻是 1。為了比較調整前後，用「離目標的差，自己乘自己」當代價：`(1-3)²=4`。把旋鈕調到 1.1，代價變成 `(1.1-3)²=3.61`，下降了 0.39。這個例子想回答的不是「目標在哪」，而是「從目前位置往哪邊調、調一點會影響多少」。模型有很多可調數字，不能每次靠人試完所有方向，因此需要一種計算敏感度的工具。

當調整量越來越小，「代價改變數 ÷ 旋鈕改變數」會靠近某個數，這個區域性敏感度叫導數（derivative）。上例在 1 附近約為 -4：旋鈕稍微增加，代價就減少；負號表示方向，絕對值表示每單位改變的強弱。有多個旋鈕時，每個旋鈕各算一個導數，排列起來叫梯度（gradient）。模型中的這些可調旋鈕叫參數（parameter）；訓練要改的就是它們的數值。

下面先讓 PyTorch 自動算出導數，再試著調一次旋鈕，最後重新計算代價。輸入 `w=1`，目標固定為 3；`requires_grad=True` 要求工具記錄與 `w` 有關的運算，稍後才能沿著它們計算敏感度。tensor 的概念見 [W.3](#W.3)。

算出導數只是知道方向，真正調整還需要一條規則：從目前的 w 減去「步長乘梯度」，沿梯度相反方向走一小步。這裡選步長 0.1，叫**學習率**（learning rate）。`w -= 0.1 * w.grad` 就是這條更新規則的簡寫；`w.grad` 是工具存放此次導數的位置。梯度為負時，減去負數會讓 w 增加。更新放在 `torch.no_grad()` 中，暫時不把這次改參數記成求導運算。步長是本例的選擇，是否改善仍要看新的代價。

```python
import torch

w = torch.tensor(1.0, requires_grad=True)
loss = (w - 3).square()
loss.backward()
print(loss.item(), w.grad.item())
with torch.no_grad():
    w -= 0.1 * w.grad
print(w.item(), (w - 3).square().item())
```

`loss` 是代價的英文名；`.square()` 就是平方。`backward()` 從代價往回計算每個參數的導數，把結果存到 `.grad`。第一行輸出 `4.0 -4.0`，確認代價 4、梯度 -4。但呼叫 `backward()` 之後，w 還是 1，它只算出方向，沒有真的調旋鈕。

下圖橫軸是旋鈕位置 w，縱軸是代價 `(w−3)²`。藍點是目前的 w＝1，橘點是更新後的 w＝1.4；沿箭頭往右，代價從 4 降到 2.56。最低點仍在 w＝3，表示這一步改善了猜法，但還沒到目標。

![代價曲線上，旋鈕從1更新到1.4，代價從4下降到2.56，目標位置仍為3](figures/rewrite-W-6-gradient-step.svg)

第二行輸出對應圖中的橘點：用梯度 -4 更新時，`1 - 0.1 × (-4) = 1.4`，新的代價是 `(1.4-3)² = 2.56`。這次有改參數，也有用新參數重新評分；浮點數輸出可能帶少許小數誤差。

這個例子也能寫成公式：代價 L=(w-3)²，在目前位置的導數是 2(w-3)。代入 w=1 得到 -4；代入 w=1.4 得到 -3.2。注意導數會隨位置改變，所以每次更新後要重算。梯度只描述目前附近的斜率，不保證一大步後仍沿著同樣方向下降。PyTorch 會把多次求導的結果累加到 `.grad`，如果重複算新的一步，要先清除舊梯度；[1.13](chapters/01.md#1.13) 會用具體數字拆開看。

練習只把學習率 0.1 改成 0.6，先算下一個 w：`1-0.6×(-4)=3.4`。它跨過目標 3，但代價仍降到 0.16。再試 1.1，應到 5.4、代價 5.76，比原先更差。核對這兩個結果，便能看到「方向正確」和「步子合適」是兩個問題。

```python
print(Path("tiny_perceptron").exists())
```

第一行輸出依你電腦而不同。在專案根目錄執行時，後兩行應都是 `True`；若都是 `False`，先看第一行，確認是否站在別的資料夾。這比把所有路徑改成電腦上的絕對位置容易重現。若用終端機執行這段，先輸入 `python` 並按 Enter，看到 `>>>` 就進入 Python 互動模式；逐行貼上包含 `from pathlib import Path` 在內的程式，輸出會緊接在後。輸入 `exit()` 並按 Enter 可回到終端機指令模式，才能再用 `cd` 切換資料夾。練習先退出 Python，在專案根目錄輸入 `cd notebooks`，再輸入 `python` 進互動模式重跑這段。先預測 `pyproject.toml` 是否還會被找到；核對後用 `exit()` 退出，再 `cd ..` 回到上一層專案根目錄。只換起點，檔案本身仍存在。

紅色錯誤通常會列出哪個檔案、哪行程式，最後一行說明原因。`ModuleNotFoundError: No module named 'torch'` 表示現在的 Python 找不到工具；先確認 Notebook 選 **Tiny Perceptron**，或終端機已啟用 `.venv`。`FileNotFoundError` 是找不到指定檔案，先查目前起點和檔名。`KeyError` 是字典中沒有那個鍵，可回看 [W.2](#W.2)。`IndexError` 是索引超出範圍。例如 `animals = ["貓", "狗"]` 從前面用 0、1 編號；取 `animals[2]` 是取第三項，就會超出範圍。`SyntaxError` 則先檢查括號、冒號與縮排。

模型訓練的指令碼有些預設只檢查資料與流程。報告中的 `dry-run-no-weight-update` 表示這次沒有更新模型；依[操作配方](training.md)加上 `--train` 才正式訓練。不要只因看到報告檔就以為模型學過了。閱讀錯誤時也採同樣原則：指出程式實際做到了哪一步，再處理阻擋下一步的那個原因。
