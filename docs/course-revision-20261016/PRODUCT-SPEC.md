# 新成品資料與驗收契約

本契約在新成品正式訓練與查看最後測試之前訂定。它把PLAN的有限任務具體化；不是實測報告。修改生成規則、題目範圍或門檻時另存版本與理由。

## B：有限文字解題器

核心狀態任務使用兩個有名字的暫存盒，初值各在0–7。事件是覆寫其中一盒，或交換兩盒內容；最後問其中一盒的值。例：「A=2，B=6；A設成5；交換A與B；問B」正解5。先後順序、被問對象與交換都會改答案。正文單盒的最後覆寫是這個任務的簡單特例，不代表完整考卷只問最後出現的數字。

範圍內核心測試包含1–4個事件，初值、事件組合與所問對象由規則生成。較長5–6事件另列壓力測試；名稱與措辭變化另列，不能把未知token自動宣稱為一般文字理解。正式語法、值域及長度限制隨tokenizer固定公布。

次要算術任務是0–6三個整數的加法，答案0–18；用排序後的三元組當家族，同組數字的排列和措辭不跨切分。它測同值域的新組合，沒有測超出數字範圍。答案頭至少覆蓋0–18。

核心門檻：範圍內未見事件家族最後測試，狀態追蹤正確率至少90%。次要算術目標85%，未達必須列明。記錄實際題數及分事件長度成績，不用整體平均掩蓋4事件的失敗。

## C：有限世界的機率判斷

支援的世界有卡片進度、地址規則、App密碼服務，以及B的狀態與算術請求；另含不支援／無法判類的材料。明確列出必要欄位：執行卡片進度查詢需要申請編號，地址規則說明不需要個人編號；App示範流程需要裝置資訊；狀態題需要兩盒初值、事件及所問對象，算術需要三個運算元。這些只是本世界規則。

共享候選評分器回答：Choice任務類型、yes/no資訊充分、三級資訊規準（必要資訊都缺／只齊部分／全部齊）。三級規準按該流程的必要欄位計，不按字數；對完全沒有必要個人欄位的規則說明，已知任務即可算充分。

每個候選意義單獨與state、question編碼，使用同一網路與評分頭。候選間不加入位置編號或注意力，以便在評估模式下檢查語義重排一致性。資料包含刪去最佳服務、仍提供「皆不適合」的例子，以及同state換question的配對。對含義重疊的候選先拒絕或定義評分，不任意標一個唯一答案。

核心門檻：最後Choice正確率至少90%，候選重排後語義選擇一致率至少99%。yes/no與三級分開報正確率、CE、Brier；校準前後的T與Brier採類別平方差總和、再平均樣本。缺候選、未見措辭／實體及高集中度錯誤例另外列出。不得把集中度叫作答對機率。

## 共同隔離與預算

所有世界先有family_id，再用穩定雜湊分配train／calibration／policy／test。狀態事件家族包含相同初值及事件序列衍生的所有問題與改寫；算術家族依排序三元組；客服家族包含同一服務與欄位事實的各問題／候選版本。跨模型、跨任務繼承split，不重新抽籤。

每個底層家族另有固定且不表示答案的case/entity識別碼，各衍生題保留它。資訊刪除可能使原本不同情境露出相同短句；要在生成後檢查觀測輸入與模型實際token序列的跨組重複，明列合併／排除方式，不能只檢查family_id字串不相交。若刻意保留具有相同資訊與標籤的簡單通用格式，報告須說明它測哪種規則，不能稱完全未見格式。實體隔離由底層家族共同分配，措辭／模板變化另列留出壓力測試，不與固定語法核心門檻混稱。

開發時只使用train、calibration及policy；最後test在模型、校準器、檔位與Auto規則固定後執行。若以test錯誤改善模型，該批改標診斷並另留一批最後測試，不能保留最後測試的名義。

第一版Auto目標：在policy上選一組明確規則，在平均B輪數不超過3的條件下提高正確率；完整時間仍包含C成本。使用者固定檔位優先於Auto；超過硬上限回報受限，不悄悄加算。報所有固定檔位，包含medium。資訊不足先澄清，只有受支援且資訊充分才交B。

先驗工程規模：單GPU小型網路與合成有限資料，正式工作分小批、先估上界再預約。沿用現有官方gross增量＋未對帳保留的額度守門，不增加額度、不清帳、不將歷史reserved當實際已花。每次派工依新快照核准可容納的上界；不用剩餘估計取代實際reserve結果。
