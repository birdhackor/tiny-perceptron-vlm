## 資料與實驗契約

- 以世界／事件家族識別碼共同分配 train、validation、test；相同事件改寫、提問、候選重排及路由標籤繼承同一 split，不跨產品重新抽籤。保留生成版本、seed、逐題 ID 與家族 ID。
- 另列實體／措辭變化與較長事件等分布外測試；不能只憑隨機列切分宣稱泛化。
- 策略及校準只用 validation；需要多次挑選時將 validation 再分 calibration／policy。最後 test 不參與選權重、輪數、溫度或門檻。
- 機制實驗分別跑固定3輪末端CE及抽1／3／5輪末端CE，評估1–6輪；中間狀態參與梯度不等於在那些終止深度直接監督。
- 產品 B 的正式訓練配方可監督多個輪數，與奇數終止的機制實驗分開命名。比較 loss／正確率／實際工作量；不保證加輪單調改善。
- 同工作量或同參數的架構因果比較需要新的匹配 Dense 控制；舊 MoE 只作成品用途比較。
- GPU 走既有官方 gross usage＋本輪 pending bounds 保護，不使用歷史全期 reserved 當實際花費，不重置帳本。每次正式派工前讀取新快照並保留上界；不得擅自提高現有額度。

## Auto 的第一版與進階版

第一版接受 `auto/low/medium/high`；手動選擇優先，硬上限優先於偏好。C 判斷任務與資訊是否充分，validation 選定規則再選 B 的輪數。缺資訊先澄清。目標是在事先指定的平均計算上限下提高正確率；規則與硬上限寫進設定。

報告所有固定 low／medium／high、基本 Auto 的正確率、控制器開銷、總時間、實際輪數、硬體及 batch；樣本足夠才解讀尾端延遲。Auto 輸給某個固定檔也照實呈現。舊 MoE 沒有受訓的 effort 控制，不替它新增虛構檔位。

進階 learned-auto 另列里程碑：先凍結解題器、提示、tokenizer、解碼、預算定義，再產生各預算成敗資料並獨立校準。單次0／1不是每題成功機率；若估隨機成功率需要重複。增加路由訓練後重驗原判斷能力，解題器更新則重建證據。回看答案的 oracle 只是離線上界，部署時拿不到真解。
