## 14.12 每輪到底把什麼交回去？

訂單文字沒有變，第二輪為何能做不同的事？因為區塊讀的不只是原文字，還有上一輪留下的**隱藏狀態**：每個輸入位置的一排向量。向量是可變的工作材料，權重則在一次推論期間固定。

令 `e` 是原文經入口後的向量序列，`s_r` 是第 r 輪後的狀態。最小示意寫成 `s_(r+1)=F(e,s_r;θ)`，θ 是共享區塊的參數。每輪把 e 再送入，讓更新仍可參照原問題；模型不用完全依賴上一輪把所有線索留住。輸出頭 `H(s_r)` 才把狀態轉成答案分數。不同架構可以另加入口／出口區塊或輪數表示，本課先把共享關係看清楚。

下面是**手工狀態更新**，沒有注意力、參數學習或訓練成果。把要接近的答案向量簡化成數字4，每輪補上目前差距的一半；目的是看出輸入不變，狀態仍能改變。

```python
e, state = 4.0, 0.0
for round_id in range(1, 5):
    state = state + .5 * (e - state)
    print(round_id, state)
```

狀態依序是2、3、3.5、3.75。這個人寫的更新規則會靠近4，因為每次誤差恰好減半。訓練出來的 Transformer 並沒有自動繼承這項性質；把「反覆處理」畫成箭頭，不能證明它也在朝正解收斂。

還要分清兩條軸：輸入 token 軸是「訂單、增加、取消」這些位置；loop 軸是對**同一批位置的狀態**反覆處理。跑四輪不代表新增四個輸出 token。自回歸語言模型仍可在產生每個下一字前做多輪；本課第19章則先用一份文字讀完後分類最後答案，省去逐字生成的干擾，讓輪數容易量測。

原問題應否每輪再注入，也是一項可檢查的設計。若只剩已被改寫的狀態，早期丟掉的細節可能難以恢復；保留 e 提供再讀入口，但沒有保證區塊真的使用它。正式模型還要用改問題、改關鍵事件的測試來確認。

練習把補差距係數由0.5改成2。狀態會在0與8之間來回，不再接近4。相同的循環形式可以收斂，也可以振盪；下一步要看訓練目標到底監督哪一輪。
