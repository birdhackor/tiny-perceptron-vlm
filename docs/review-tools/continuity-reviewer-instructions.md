# 本輪前後銜接審閱

這是第三輪的方法。全書正確性查證與必要的原讀者複查完成後，才派出本輪讀者。提前準備這份方法不代表銜接審閱已開始或通過。

## 讀者與範圍

使用新的 `fork_turns="none"` subagent，不能沿用作者、第一次閱讀者或正確性審閱者的身分。背景是數學不錯的高中生或有基本數學能力的大學生，知道入門 Python；不能用自己的模型知識補上文章沒有教的步驟。

協調者依實際閱讀導覽分配一章或一組相鄰小節，另指定前面的相關小節與後面接續的小節。範圍要涵蓋全部正文、導言、附錄與入門頁；可以重疊檢查章節邊界，不能因為一頁是選讀就漏掉。第20章的成熟模型路線要依其延伸入口讀，不假定它是第19章的同一份自行訓練模型。

只提供來源、閱讀順序與這份方法，不提供作者希望讀者得到的答案。不讀作者筆記、其他讀者或技術審閱報告。可以回讀正文明確引用的必要前文，記錄實際範圍；不能先讀後文，再假裝前面的首次理解已經完整。

## 實際閱讀方法

先讀指定前文，再沿順序讀指定範圍，最後讀接續部分。每讀完一個小節就追加紀錄，再往下讀，不在全文看完後倒填最初的理解。保存讀到的原始 UTF-8 版本與必要圖解的指紋。

每個交接點用自己的話說清楚：

1. 前文已經交代的任務、素材與概念是什麼？指出實際讀到的位置。
2. 下一節要解決哪個新問題？它依賴的背景是否真的已教過？
3. 例子、資料、字表、模型或評估方式改變了嗎？讀者在哪一句得知改變？
4. 上一節留下的問題是否在合理位置接上？「它」「這一步」「正式實驗」是否有可辨識的對象？
5. 此處是手算例子、程式示範、既有實測，還是待實作的成品計畫？兩節的敘述有沒有讓人誤認為同一項成果？

對沒教過的詞、無素材的實驗、缺圖或突然跳換任務，記錄當時原句、自己的理解、缺少的橋梁及影響。後文補說時另記它何時補上，不把原本的斷點刪掉。如果理解依賴圖，實際渲染並查看；alt文字或搜尋SVG標籤不能代替看圖。

必要圖解也要在實際網頁的桌機與手機版確認大小、字體與閱讀順序，記錄網址、viewport 和實際看過的畫面。原 SVG 放大後可讀，不代表正文中的圖就可讀；不能讓讀者每次都必須點放大，才能理解主要說明。

回讀連結可以補充背景，但主要任務的必要交代應在讀者需要它的位置。不能用大量「前置」列表取代一段合理的引入，也不能要求順序讀者一直離開正文查答案。

連續閱讀時也檢查重複負擔：相同的限制、工程流程與無助理解的失敗紀錄，是否反覆占去各節開頭或打斷正在解決的問題。數字和反例只在幫助理解當節機制時保留；不能因為它們有來源就一律塞進正文。

作者說明的繁體用字、術語與稱呼也應一致，避免讀起來像不同筆記拼接。引用原始資料時可以保留原文並說清來源；不要為統一字形而改掉實際輸出或訓練資料的字串。

## 報告與修正

報告列出審閱身分、實際閱讀順序與來源／導言／圖版本，每個交接點的上述紀錄，以及問題的嚴重程度、建議和 `pass`／`revise` 判定。通過理由必須對應實讀內容，不能只寫「順暢、沒問題」。未做的檢查明列為未驗證。

協調者衡量建議，保留合理的讀者問題並安排修正。修正後由原銜接讀者實際重讀受影響的前文、本節與接續段，保存原問題與新紀錄；若涉及知識、算例或圖，另交原技術審閱者核對，並依第一次閱讀的方法安排受影響原讀者複查。純文句調整不觸發GPU重訓。

全部已分配範圍與邊界都在目前版本通過，才宣告本輪完成。版本核對程式只能驗證檔案與紀錄一致；它不能證明讀者讀過文章，也不能替讀者判斷銜接是否自然。
