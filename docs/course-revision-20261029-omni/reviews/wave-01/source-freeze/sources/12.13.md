## 12.13 整段平均後，還分得出哪個聲音先來嗎？

先有 440 Hz、再有 880 Hz，與把兩段順序交換不同；「哪段先來」的正確答案會變。先用已提取的時間框看這個問題：把框序列倒過來，框的集合不變，先後卻不同。

![相同兩組時間框交換先後；哪段先來的正確答案改變，整段平均摘要近似相同](../figures/rewrite-12-time-order.svg)

```python
import math
import torch

sample_rate, n_fft, hop, bands = 16000, 400, 160, 16
time = torch.arange(1600) / sample_rate
wave = torch.cat([0.5 * torch.sin(2 * math.pi * f * time) for f in [440, 880]])
# 重列12.6–12.8的固定前處理，讓本格可直接執行。
mels = torch.linspace(0, 2595 * math.log10(1 + 8000 / 700), bands + 2)
hz = 700 * (10 ** (mels / 2595) - 1)
frequency = torch.linspace(0, 8000, n_fft // 2 + 1)
left = (frequency[None] - hz[:-2, None]) / (hz[1:-1] - hz[:-2])[:, None]
right = (hz[2:, None] - frequency[None]) / (hz[2:] - hz[1:-1])[:, None]
bank = torch.minimum(left, right).clamp(min=0)
spectrum = torch.stft(wave, n_fft, hop, window=torch.hann_window(n_fft),
                      center=True, pad_mode="reflect", return_complex=True)
sequence = (bank @ spectrum.abs().square()).clamp(min=1e-8).log().T
reordered = sequence.flip(0)  # 倒轉已取得的特徵框，不重算倒放波形。
print("時間框與頻帶", *sequence.shape)
print("先後序列相同", torch.equal(sequence, reordered))
print("平均摘要近似相同", torch.allclose(sequence.mean(0), reordered.mean(0)))
```

`time`有1600個取樣時間，先合成0.1秒440 Hz，再接0.1秒880 Hz。`bank`與`spectrum`直接重列前面已教的mel三角權重與STFT，沒有把關鍵步驟藏在外部報告函式。這裡對整段聲音採反射補邊；要做嚴格局部特徵時，[12.17](12.md#12.17)會改成每塊獨立處理與`center=False`。

功率經`bank @ ...`合成頻帶、取log，再以`.T`換成「時間框、mel頻帶」，得到21×16。`flip(0)`只搬動這21框的位置，所以第一個比較印False；沿時間平均後，每一頻帶仍加到同一批數，第二個比較印True。`allclose`容許加總順序造成的微小浮點誤差。這沒有把真實錄音倒放後重算頻譜，不能據此聲稱兩段波形的每框特徵相同。

平均不管框在哪個位置，倒轉前後便得到同一摘要；它保留每個 mel 頻帶的平均 log 特徵，卻失去「先低後高」的順序。若回答需要先後，入口與後續模型要保留時間位置；用監督式訓練教模型回答先後時，還要提供帶有先後答案的資料，訓練目標才會要求模型利用這些位置。

語音辨識一句話更依賴有序的聲音：同一批音節換了位置，轉寫文字就可能不同。回答需求則不一定要逐字照抄。兩者都可能需要時間線索，但目標不同，要分開判斷。倒轉單音框的反例只說明平均會丟掉順序，不能證明模型會語音辨識；反過來，轉寫錯了一個字，也不能直接判定需求的回答一定錯。

保留相對順序還不等於知道實際幾毫秒。既有第19章A已保留16個有序聲音區間；新版要再讓每個局部區間對應共同時間。[12.17](12.md#12.17)會直接列出這些支持範圍，先用看得見的時間資料解釋需要，再到第14章學不同的位置表示。

練習把問題改成「是否出現過較高的單音」，平均摘要是否可能足以幫忙？再改成「較高的先來嗎」，指出缺少的條件。接下來先介紹轉成文字的聊天路線，再設計保留聲音特徵的有限需求路線。
