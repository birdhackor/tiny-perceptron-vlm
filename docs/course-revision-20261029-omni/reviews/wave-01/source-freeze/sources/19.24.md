## 19.24 新版整合如何分清路由錯誤與解題錯誤？

使用者填入三個數字，希望解題器作答。C可能判錯任務；即使選對B，輸入也可能超過B的值域；即使輸入合法，B仍可能算錯。要改進這個助理，必須保留每一步，才知道下一輪應該改哪個零件。

[19.17](19.md#19.17)的Auto已經示範選檔。本版繼續用程式規則組合模型：C判斷任務和資訊是否足夠，程式依固定門檻決定接題或轉交；B保留原來的Looped權重與文法，A保留舊文字入口並增加[19.21](19.md#19.21)的影音分支。這是多個已界定零件的助理產品，這輪沒有再訓練一個會自己決定所有工作量的總控制器。

先把B的入口約定寫出來。下面的`numbers`是使用者提交的公開欄位；適配器只檢查三個0到6的整數，組成B原本接受的文字，不計算答案。`type(x) is int`也排除Python會當作整數子類別的布林值。

```python
def adapt_sum(numbers):
    if not isinstance(numbers, list) or len(numbers) != 3:
        raise ValueError("需要三個整數")
    if any(type(x) is not int or not 0 <= x <= 6 for x in numbers):
        raise ValueError("B的三數入口只接受0到6")
    x, y, z = numbers
    return f"三數加法;x={x};y={y};z={z}"


def select_route(request, judgment, tau, manual=None):
    # judgment是C的公開預測；這段示範沒有呼叫已訓練C。
    if manual is not None:
        route = manual
    elif judgment["p_max"] < tau or not judgment["info_yes"]:
        return {"route": "handoff", "reason": "固定接受規則未通過"}
    else:
        route = judgment["route"]
    if route == "b_sum":
        try:
            text = adapt_sum(request.get("numbers"))
        except ValueError:
            return {"route": "handoff", "reason": "B輸入契約未通過"}
        return {"route": "b_sum", "state": text, "loops": 3}
    if route == "a_av":
        if not (request.get("has_video") and request.get("has_audio")):
            return {"route": "handoff", "reason": "缺少影音線索"}
        return {"route": "a_av", "output": "canonical semantic result"}
    if route == "a_text":
        return {"route": "a_text", "text": request["text"]}
    return {"route": "handoff", "reason": "沒有支援的入口"}


request = {"text": "計算三個數", "numbers": [1, 2, 3]}
c_fixture = {"route": "b_sum", "p_max": 0.96, "info_yes": True}
print(select_route(request, c_fixture, tau=0.9))
request["numbers"] = [1, 2, 7]
print(select_route(request, c_fixture, tau=0.9, manual="b_sum"))
```

第一行得到`b_sum`、`三數加法;x=1;y=2;z=3`與三輪；第二行轉交，理由是B輸入契約未通過。手動指定優先於C選路，仍要通過所選模型的輸入檢查。這兩行只核對控制流程，`0.96`是人工填入的示意機率，不是新版C的成績；程式也還沒有讓B算出答案。完整入口另外檢查B的tokenizer與長度；兩盒題則依原有事件文法驗證。C能讀UTF-8新說法，不會自動擴大B可解的題目。

C選路時若只取得文字及「是否附有影片／聲音」欄位，就只能宣稱根據這些資訊選入口；影片裡的圓或方，仍由A的影音分支判斷。A的`circle/square/unknown`是真正交給[19.22](19.md#19.22)聲音模組的語義結果，舊文字模型若將它寫成一句自然的回答，不可改掉驗收與發聲使用的原預測。

接著分開測兩條路：**gold路由**使用資料事先規定的入口，檢查適配器與後端；**真C路由**使用C的預測，檢查整套系統。兩者用同一組100個預先留出的整合家族，這組另於C核心60家族之外保存，不能用重排或換句話把60湊成100。下面用四筆人工紀錄看計算方式；正式結果要由實跑紀錄回填。

```python
# 每列是同一家族的兩次測試；數值為手工示意。
rows = [
    {"gold_backend_ok": True,  "route_ok": True,  "actual_backend_ok": True},
    {"gold_backend_ok": True,  "route_ok": False, "actual_backend_ok": True},
    {"gold_backend_ok": False, "route_ok": True,  "actual_backend_ok": False},
    {"gold_backend_ok": True,  "route_ok": False, "actual_backend_ok": False},
]
gold_ok = sum(row["gold_backend_ok"] for row in rows)
route_ok = sum(row["route_ok"] for row in rows)
whole_ok = sum(row["route_ok"] and row["actual_backend_ok"] for row in rows)
print("指定正確入口：", gold_ok, "/", len(rows))
print("C選對入口：", route_ok, "/", len(rows))
print("真路由整條成功：", whole_ok, "/", len(rows))
```

輸出依序是`3/4`、`2/4`、`1/4`。第二筆雖然錯入口的後端正常結束，仍未完成原任務；第三筆選路正確，後端失敗；第四筆則錯路而且後端也失敗，先記下選路錯誤，才能避免把它全歸給解題器。真測試需保留原輸入、C分數／資訊判斷、固定門檻、選路、適配結果、A或B輸出及聲音分析。轉交、拒答與解析失敗都留在原分母。

升版時，還要把新wrapper與固定舊版本並排跑保留能力面板，逐任務列正確數、分母與退步。B的舊三數世界只有84個獨立家族，換措辭不會變成100個新家族；該面板只能照實報歷史回歸。新版分開保存推論權重、設定／tokenizer、完整optimizer/RNG狀態和資料生成版本，下載後核對指紋；各材料的角色接續[19.19](19.md#19.19)。只有通過能力與發布檢查的候選才成為預設，已見失敗與舊下載版本仍保留。

**練習：**把第一段的三個數改回合法值，將`info_yes`改為`False`。先預測自動模式與手動`b_sum`模式分別走哪裡，再印出核對。手動模式讓使用者選入口，並不證明C已判對資訊是否足夠；評估時兩種模式要分開。
