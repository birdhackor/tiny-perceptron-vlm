## 17.17 一個聲音碼不夠，怎樣逐次補上誤差？

假設同一個音框的中間特徵是1.4，第一個碼本只有 `[0,1,2]`。最近碼是1，還差0.4。若希望保留更細的差異，可以把第一個碼本做得更大；也可以讓第二個碼本專門描述「還差多少」。這種拆法先保留粗略結果，再用額外的碼補細節。[17.16](17.md#17.16)教一個碼本怎樣學，本節先固定三個人工碼本，觀察拆分後每個碼負責什麼。1.4是中間特徵，不是受限在−1到1的波形振幅。

第二個碼本設為 `[-0.5,0,0.5]`。它要逼近的是殘差0.4，所以選0.5，累計變成1.5；新的殘差為 `1.4−1.5=−0.1`。第三個碼本 `[-0.125,0,0.125]`再選−0.125，累計得到1.375，只剩0.025。每次都先減掉已表示的部分，再量化剩餘量，稱為 **RVQ（Residual Vector Quantization，殘差向量量化）**；真實 codec 的每個碼通常是一條向量，這裡縮成一個數，好讓相加與誤差可手算。

重建時不需要原來的1.4：只要保存三個碼的 ID `[1,2,0]`，各查自己的碼本，便能相加得到 `1+0.5−0.125=1.375`，再交給 decoder。[EnCodec §3.2](https://arxiv.org/pdf/2210.13438v1)就是逐碼本量化殘差、將對應向量加總的做法。這些 ID 都從0開始，而且分屬不同碼本；第2個碼本的 ID 2，不等於第1個碼本的 ID 2。

同一音框需要多個碼，便多出「碼本深度」這個方向。下圖 A 的橫向是音框時間，直向是碼本；`[1,2,0]`沿同一欄往下，始終在描述第0音框。圖 B 才是[7.20](07.md#7.20)的文字 **MTP（multi-token prediction，多 token 預測）**：讀到「雨」，分別預測較後位置的「停」「了」。它們沿文字時間向右，不能把 A 往下的箭頭也讀成未來文字。

![聲音在同一音框往下補碼本，文字MTP則沿文字時間向右預測不同未來位置](../figures/omni-17.17-rvq-axes.svg)

[Qwen3-Omni §2.4–2.5](https://arxiv.org/html/2509.17765v1#S2.SS4)的 Talker 先預測第0碼本，再用 MTP 模組逐步預測同一音框其餘殘差碼本；完整音框的碼備妥後，才送 Code2Wav，也就是把碼轉回波形的下游解碼模組。此處 MTP 的工作是補同框細節。它仍有碼本之間的先後步驟，不能由「multi」推論所有碼一次平行完成，也不能直接推論等同[16.14](16.md#16.14)的草擬與核對加速。

還要分清「codec 正在編碼參考音訊」和「Talker 正在生成新聲音」。前者有1.4，能算殘差並選最近碼，所得 ID 可作訓練 target（目標）；推論的 Talker 沒有真音訊可偷看，必須從條件、先前音框，以及本框已自行預測的碼來猜下一碼。下面先完整算出 target，再用一個未訓練的小條件模型展示這個界線。它把兩個條件數映成四維特徵 `h`，每個 head（評分頭）替當前碼本的3個 ID 打分；猜出的 ID 查 embedding 加回 `h`，才猜下一碼。`tanh`把各維壓到−1到1。這只示意同框順序，沒有重現 Qwen3 的 Transformer MTP，也沒有聲音品質成果。

```python
import torch
from torch import nn

torch.set_num_threads(1)
books = [torch.tensor([0.0, 1.0, 2.0]), torch.tensor([-0.5, 0.0, 0.5]), torch.tensor([-0.125, 0.0, 0.125])]
value = torch.tensor(1.4)
residual = value.clone()
total = torch.tensor(0.0)
target_ids = []
for q, book in enumerate(books):
    # 若恰好等距，argmin 取排列中第一個，也就是較小 ID。
    k = (residual - book).square().argmin()
    total = total + book[k]
    residual = residual - book[k]
    target_ids.append(k.item())
    print(
        q,
        "ID",
        k.item(),
        "加上",
        book[k].item(),
        "累計",
        round(total.item(), 6),
        "殘差",
        round(residual.item(), 6),
        "平方誤差",
        round(residual.square().item(), 6),
    )
print("重建用targets", target_ids)

# 未訓練的小條件模型，只展示同框逐碼生成時可讀到什麼。
torch.manual_seed(1)
context = nn.Linear(2, 4)
heads = nn.ModuleList([nn.Linear(4, 3) for _ in books])
embeddings = nn.ModuleList([nn.Embedding(3, 4) for _ in books])


@torch.no_grad()
def predict_frame(condition):
    h = torch.tanh(context(condition))
    predicted = []
    for q in range(len(books)):
        k = heads[q](h).argmax(-1)
        predicted.append(k.item())
        h = torch.tanh(h + embeddings[q](k))  # 只接回自己剛猜的碼。
    return predicted


predicted = predict_frame(torch.tensor([0.3, -0.4]))
generated = sum(book[k].item() for book, k in zip(books, predicted))
print("未訓練條件模型自猜", predicted, "解碼", generated)
```

前三行的「累計／殘差／平方誤差」依次是 `1／0.4／0.16`、`1.5／−0.1／0.01`、`1.375／0.025／0.000625`。第三碼是負修正，並不是聲音時間往回走。這組距離沒有平手；程式也明定若等距就選較小 ID。最後的條件模型只接收 `[0.3,−0.4]`，沒有傳入 `value` 或 `target_ids`；在這個固定起點自猜 `[2,1,0]`，解碼成1.875，與最近碼重建的1.375不同。碼本能表示好的重建，沒有替條件模型完成預測工作；真正訓練要另外用目標碼的交叉熵教它，生成時接回的仍是自己的預測。

增加碼本也有代價：每框要傳更多 ID，條件模型多做幾步。本例每個碼本3選1，若固定用2 bits（二進位位元）保存一個 ID，三層就從2增為6 bits／框，尚未計額外格式資訊。例中誤差縮小不能保證任何訓練後多碼本都更好聽或更快。本輪正式聲音產品的最低路線採單碼本；RVQ 與同框 MTP 先作 CPU 教學，能力與成本留待各自評估。

練習只把 `value` 改成1.6，先算各層選碼，再執行：應依序加上 `2、−0.5、0.125`，得到1.625，ID 是 `[2,0,2]`。未訓練條件模型的輸入與參數都沒變，所以仍自猜原來的三碼。這個對照可檢查：你修改的是 codec 的參考音框，還是生成端實際可用的條件？
