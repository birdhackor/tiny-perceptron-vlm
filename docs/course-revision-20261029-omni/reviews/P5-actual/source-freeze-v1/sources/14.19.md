## 14.19 文字位置以外，時間與空間怎樣進入旋轉？

在[12.17](12.md#12.17)，同一個發聲區塊的中心可以是 1300 ms，也可以是 2300 ms；它在輸入序列裡卻一直是索引 20（從 0 起算）。如果只用這個序號旋轉 Q、K，移時前後的旋轉完全一樣。我們希望聲音與畫面之間的比對能反映實際相隔多久，因此需要把物理時間也表示出來。

[14.1](14.md#14.1)已教過 RoPE（旋轉位置嵌入）：把 Q、K 的數字兩兩成對，讓每對按座標旋轉。現在把「座標」從一個序號擴成三種：時間 `t`、圖塊所在的高度 `h`、寬度 `w`。**軸分配**就是指定每一對讀哪種座標。例如六維向量分成三對，第 0、1 格用時間，第 2、3 格用高度，第 4、5 格用寬度；改時間便只轉動第一對。圖塊的高、寬是[10.2](10.md#10.2)中的列、欄位置，不是把灰階亮度當座標。

先約定每 250 ms 是一個時間單位：1250 ms 變成 `t=5`，1300 ms 變成 `5.2`，2300 ms 變成 `9.2`，保留小數，沒有四捨五入成影格編號。圖中把這些物理座標放在上方，下面另列序號；兩者的工作不同。

![六維向量三對分別使用時間、高度、寬度；聲音時間平移而序號20與因果可見範圍不變](../figures/omni-14.19-axis-time-index.svg)

以下固定同樣的內容 `[1,0,1,0,1,0]`，每軸一對，每單位轉 π/4 弧度。為了單獨看移時，每張圖先當一條觀測，高寬都設 0；音訊沒有圖內位置，也填 0。`axis_rope` 從 `coordinates` 的 `t,h,w` 中，按 `pair_axis` 替各對挑座標，再做 14.1 的旋轉。這個小設定讓軸分配可讀；實際模型可給各軸多對、每對不同轉速。

```python
import math
import torch

unit_ms = 250.0
pair_axis = torch.tensor([0, 1, 2])  # 第 0 對讀 t、第 1 對讀 h、第 2 對讀 w
speeds = torch.tensor([math.pi / 4] * 3, dtype=torch.float64)


def axis_rope(vector, coordinates):
    pairs = vector.reshape(-1, 2)
    if len(pairs) != len(pair_axis):
        raise ValueError("每一對都要有軸分配")
    angles = coordinates[pair_axis] * speeds
    a, b = pairs[:, 0], pairs[:, 1]
    c, s = angles.cos(), angles.sin()
    return torch.stack([a * c - b * s, a * s + b * c], dim=-1).flatten()


def coordinates(time_ms, h=0.0, w=0.0):
    return torch.tensor([time_ms / unit_ms, h, w], dtype=torch.float64)


content = torch.tensor([1.0, 0.0] * 3, dtype=torch.float64)
key = axis_rope(content, coordinates(1250.0))  # F5：影格索引 5，從 0 起算
q_a = axis_rope(content, coordinates(1300.0))  # A1：發聲的第 1 塊
q_b = axis_rope(content, coordinates(2300.0))
print("F5／A1 原時／A1 移時的 t", [1250 / unit_ms, 1300 / unit_ms, 2300 / unit_ms])
print("原時／移時對 F5 的點積", [round(float(q @ key), 4) for q in [q_a, q_b]])
print("移時只改時間對", torch.equal(q_a[2:], q_b[2:]))

# 固定 12.17 的區塊順序，沒有按物理時間重排。
tags = ["video_begin"] + ["frame"] * 16 + ["video_end", "audio_begin"]
tags += ["audio"] * 4 + ["audio_end"]
indices = torch.arange(len(tags))
causal_mask = indices[:, None] >= indices[None, :]
video_index, audio_index = 6, 20  # 標記後的 F5 與 A1

# 對照：三對都只用序列 index；兩個移時版本會得到相同旋轉。
index_key = axis_rope(content, torch.tensor([video_index] * 3, dtype=torch.float64))
index_scores = []
for index in [audio_index, audio_index]:  # 兩個版本的 A1 都在 index 20
    query = axis_rope(content, torch.tensor([index] * 3, dtype=torch.float64))
    index_scores.append(float(query @ index_key))
print("序號版兩個分數相同", index_scores[0] == index_scores[1])
print("A1 可讀 F5／F15", bool(causal_mask[audio_index, video_index]), bool(causal_mask[audio_index, 16]))
print("A1 可讀下一個聲音塊", bool(causal_mask[audio_index, audio_index + 1]))

moved_h = axis_rope(content, coordinates(1300.0, h=1.0))
print("只改高度後三對", moved_h.reshape(3, 2).round(decimals=4).tolist())
```

時間座標印 `[5.0,5.2,9.2]`，兩個點積為 `[2.9877,1.0123]`；「移時只改時間對」印 `True`。原時相差 0.2 個時間單位，時間對的角差為 `0.2×π/4`，點積約 0.9877；另外兩對的座標都為零，各貢獻 1，所以合計 2.9877。移時後相差 4.2 單位，時間對改成約 −0.9877，合計 1.0123。這讓實際時間差進入比對，不代表「越近必然越相關」：旋轉有週期，內容向量與後續訓練仍會影響答案。

序號版兩個分數相同，正因索引 6、20 的觀測沒有換位。**因果序號**決定序列中哪些位置能讀哪些位置；遮罩只比較 index，與物理時間分開。輸出 A1 可讀 F5／F15 都為 `True`，可讀下一聲音塊為 `False`。F15 在 3750 ms，卻排在音訊區塊之前，所以這裡是離線觀察完整短片，不能解讀成聲音每到一點就只能看物理過去。

最後一行只把高度改為 1，得到三對約 `[[-0.5878,-0.8090],[0.7071,0.7071],[1,0]]`，只有高度對相對 `q_a` 改變。這一操作說清三軸怎樣分工；前面的移時比較將高寬固定，只展示時間部位的作用，不能由它宣稱完整時空位置法的空間優勢或模型已學會影音對齊。

練習把最後一段改成 `coordinates(1300.0, w=1.0)`。先預測前兩對維持 `q_a`，第三對變成 `[0.7071,0.7071]`，再執行核對。若把 `unit_ms` 改成 500，先重新算三個時間座標；這會改時間旋轉速度對應的物理尺度，不能換了單位仍直接沿用舊分數解讀。
