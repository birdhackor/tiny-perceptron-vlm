## B.8 依能力與成本，何時值得借助工具？

對1加2，工具可能提供可核對的結果，也會多一道等待。對大數字乘法，省掉這道等待卻可能增加答錯的機會。前面先教固定策略，是為了看清選擇機制；現在才問：如果想允許簡單題直接回答，怎樣判斷這個取捨？前置是[B.7分開測選擇與成功](0B.md#B.7)及[9.10信心與正確率](09.md#9.10)。

先把「模型說很有把握」和「在新題上可靠」分開。預測下一個文字單位（token）時，某個候選的機率很高，並不等於整份算術答案有同樣高的正確率，見[9.9](09.md#9.9)。選卡器對TOOL很有把握，也只是偏好這張卡，不能拿它當成自己心算會答對的機率。因此，實際做這種決策時，應先量題型在獨立驗證資料上的成功率；下面只用人工假設示範比較，尚未量出這兩條路的成功率。要再訓練逐題信心估計與決策，需要另一個實驗，這次沒有完成。

比較的也應是整條路。工具加法函數算對，模型卻把結果抄錯，仍然失敗，正如[B.3的實際例子](0B.md#B.3)。所以下面tool_accuracy假定包含選對工具、參數正確、執行成功與最後回答正確，不是單獨的計算器正確率。direct_accuracy則是直接回答的成功率。

為了看清算式，先假設直接答對機率0.90，完整工具流程答對機率0.99。把一次錯答記為10點損失，工具額外等待和運算費用折成0.02點。這些數字全部是人工假設，點數也不是美元或毫秒；它們不來自前面的選卡實驗。平均損失可用「答錯機率乘錯答代價，再加額外成本」表示。

```python
direct_accuracy = 0.90
tool_accuracy = 0.99
wrong_cost = 10.0
tool_extra_cost = 0.02
direct_loss = (1 - direct_accuracy) * wrong_cost
tool_loss = (1 - tool_accuracy) * wrong_cost + tool_extra_cost
print("直接回答平均損失", round(direct_loss, 3))
print("工具流程平均損失", round(tool_loss, 3))
print("本例選擇", "TOOL" if tool_loss < direct_loss else "DIRECT")
```

應印出1.0、0.12與TOOL。第一條路有10%失敗機會，乘10得到1點；第二條路有1%失敗機會，乘10再加0.02得到0.12點。`round(..., 3)`只把顯示四捨五入到三位小數，不改模型能力。這個規則由外層Python比較點數，沒有讓TinyLM學會按信心選工具，也沒有量到真實等待時間。

若要把這個例子變成實際系統，先準備不拿來更新答案模型的驗證題，按題型量直接回答與完整工具流程的品質和等待，訂出代價與策略；最後再用未參與選策略的測試題檢查。不可以看到最後測試在哪題答錯，就替那題臨時設定門檻後報成泛化成功。驗證集上的平均成功率也不保證下一題一定答對，尤其換問法、數字範圍或工具狀態時，需要重查適用範圍。

練習只把direct_accuracy改成0.999，其餘值不動。先預測直接回答損失變0.01，小於工具流程的0.12，因而改選DIRECT，再執行確認。這不是宣稱我們的小模型在1加2上有99.9%成功率，而是說明：即使工具仍然能用，是否值得用，取決於實際可靠性與你選的代價。前面的固定策略是第一個可理解的起點，這裡的成本比較才是往下一步擴展的方法。
