# 遇到陌生名詞時，回到一個例子

這頁是查找入口，不是開課前的背誦清單。找到陌生詞時，先看它在一個小例子裡做什麼，再點進對應小節看完整過程。同一個中文譬喻有時涵蓋好幾個步驟，所以也要核對它究竟對應哪個英文名詞。

## G.1 文字與數字怎麼對上

拿「貓看狗」作例子。先把可用字排成一份清單，約定「狗」是 0、「看」是 1、「貓」是 2；原句便寫成 `[2, 1, 0]`。這些編號叫 ID，只負責指出位置，不表示貓比狗大。如果再拿 ID 2 去查一張數字表，取出 `[0.2, -0.1]`，這一排可調整的數字才是 embedding，中文常說嵌入向量。編號與向量是兩個步驟，不能混為一談。

| 名詞 | 在例子裡做什麼 | 完整講解 |
| --- | --- | --- |
| ID、編碼與解碼 | 字轉編號，再按同一約定換回字 | [1.1](chapters/01.md#1.1) |
| token、tokenizer | 把文字切成模型處理的小單位；小單位未必是一整個字 | [6.1](chapters/06.md#6.1)、[6.7](chapters/06.md#6.7) |
| embedding | 用 ID 查出一排可學習的數字 | [2.1](chapters/02.md#2.1) |
| tensor、shape | 數字的集合，以及每個方向有幾格；兩列三欄就是 shape `[2,3]` | [W.3](first-steps.md#W.3) |
| Linear、activation | 用加權配方混合數字，再加入不能只靠直線表達的變化 | [2.3](chapters/02.md#2.3)、[2.4](chapters/02.md#2.4) |

「一張字卡」只是 token 的第一個譬喻。當切法換成位元組，同一個中文字可能拆成幾張卡；當切法合併常見片段，一張卡也可能放好幾個字。閱讀時要問「這裡採哪種切法」，不能看到 token 就一律算中文字數。

試著回答：`2` 與 `[0.2, -0.1]` 哪個是 ID、哪個是向量？前者指出要查的位置，後者才是查回的數字。若仍分不清，建議先讀 1.1，看看文字如何換成編號；再讀 2.1，看看如何用編號查出一排向量。

## G.2 猜法、學習與保存

假設模型替三個候選字打分 `[2, 1, 0]`。這些分數叫 logits，還不是機率。softmax 把分數換成加總為 1 的比例，這個例子約為 `[0.665, 0.245, 0.090]`。若正確答案是第三個字，模型只分給它 0.090，猜錯代價就偏高。訓練用這個代價告訴模型：內部哪些數字應往哪個方向改。

| 名詞 | 可以怎麼理解 | 完整講解 |
| --- | --- | --- |
| logits、softmax | 候選分數，以及由分數換出的比例 | [1.6](chapters/01.md#1.6)、[1.7](chapters/01.md#1.7) |
| loss | 猜錯的代價；不是「這個模型的一切品質」 | [1.8](chapters/01.md#1.8) |
| gradient | 每個可調數字微動時，代價如何變化 | [W.6](first-steps.md#W.6)、[1.9](chapters/01.md#1.9) |
| batch | 一次拿來計算的一組例子 | [5.2](chapters/05.md#5.2) |
| checkpoint | 把模型數字保存成檔案；要接續訓練，還需保存更新工具與進度 | [5.7](chapters/05.md#5.7) |
| pre-training，預訓練 | 先從大量一般材料學習，例如用文章本身的後文練習預測 | [7.17](chapters/07.md#7.17) |
| post-training，後訓練 | 沿用已學到的權重，再用示範、偏好或作答回饋教目標任務 | [7.17](chapters/07.md#7.17)、[7.18](chapters/07.md#7.18) |
| SFT | 用理想回答作示範，教模型在對話中回答 | [7.11](chapters/07.md#7.11) |
| DPO | 直接用同題兩篇回答的偏好比較更新模型，保留起點作固定參考 | [13.1](chapters/13.md#13.1)、[13.5](chapters/13.md#13.5)、[13.17](chapters/13.md#13.17) |
| LoRA | 保留原本數字，只學一組較小的修正零件 | [8.8](chapters/08.md#8.8) |

比例高與回答可靠也是兩回事。模型可能很肯定地接出一個錯字；要知道它的信心是否與正確率一致，需要另外檢查，[9.9](chapters/09.md#9.9)會用具體例子說明。

看到某次 loss 下降，先找出那個 loss 算在哪些題目、哪些位置，再判斷能說什麼。可以用[5.8](chapters/05.md#5.8)的例子練習：寫一句「這個結果支持什麼」，以及還需要哪種新題檢查。這比把 loss 當成所有能力的總成績更準確。

## G.3 模型如何混合線索

看到「那隻狗追著球，它跑得很快」，先暫把每個字看成一格，「目前位置」就是正在處理的「它」那一格。實際模型每格放一個token，也就是切分後的文字小單位；一個字可能拆成多格。每格文字先換成編號，再查表取得一排數字，這排數字就是文字特徵，讓模型能用數字處理文字。

模型把每格的特徵交給三套可學習的加權配方，分別產生Q、K、V。「它」那格的Q與可讀各格的K比較，例如前面「狗」與「球」所在格的K，得到每格的讀取比例，再按比例混合各格的V。attention，也就是注意力，是這套比較、計算比例、再混合數字的方法。「查筆記」可以幫你記住流程；哪些格真能提供正確線索，仍要用模型的實際結果檢驗。

| 名詞 | 在流程裡的角色 | 完整講解 |
| --- | --- | --- |
| Q、K、V | 查詢用的數字、供比較的數字，以及要取回的內容數字 | [3.3](chapters/03.md#3.3)、[3.4](chapters/03.md#3.4) |
| causal mask | 擋住目前位置之後的答案，避免訓練時偷看 | [3.6](chapters/03.md#3.6) |
| padding、loss mask | 補齊長度的空位，以及哪些位置計入猜錯代價 | [7.6](chapters/07.md#7.6)、[7.3](chapters/07.md#7.3) |
| residual | 留住原數字，再加上這次處理的修正 | [4.2](chapters/04.md#4.2) |
| normalization | 調整數字尺度，使後續處理更穩定 | [4.3](chapters/04.md#4.3) |
| patch、projector | 圖片小方塊，以及把圖片特徵接到文字模型的轉接頭 | [10.2](chapters/10.md#10.2)、[10.6](chapters/10.md#10.6) |
| spectrogram、mel | 按時間看各頻率的強弱，以及把鄰近頻率分段彙整 | [12.5](chapters/12.md#12.5)、[12.6](chapters/12.md#12.6) |

頻率是聲音起伏每秒重複的次數，440Hz就是每秒440次；像單音這樣規律的聲音，頻率較高通常聽起來較高。spectrogram（頻譜圖）按時間顯示各頻率成分的強弱；mel則用一組有重疊的區段，將鄰近頻率加權彙整，得到每個時間段中各區段的強弱。前者讓你看各個頻率位置，後者把附近位置合成較少的區段。

幾種「遮罩」也要分開：不讓模型看未來，與不把某些位置列入考題，是不同工作。提示文字可能不算 loss，卻仍提供回答線索。試著用一句話說出「看得到」和「需要作答」的不同，再到[7.5](chapters/07.md#7.5)核對。

## G.4 後段主題先對應到問題

後段名詞很多，但每個都可以先對應到一個問題：想少算、想少存、想學較好回答，或想取得模型原本不知道的資料。這些目的可以組合，也可能互相影響；要先知道自己想改善什麼，再選方法。

| 名詞 | 想解決的問題 | 完整講解 |
| --- | --- | --- |
| Dense、MoE | 每次全用同一組計算零件，或只選少數專家零件處理 | [15.1](chapters/15.md#15.1)、[15.4](chapters/15.md#15.4) |
| KV cache | 生成下一字時，保存先前已算過的內容，減少重算 | [16.3](chapters/16.md#16.3) |
| Flash Attention | 分塊計算，減少大型中間表的儲存與搬移 | [16.9](chapters/16.md#16.9) |
| quantization，量化 | 用較少刻度記錄原來的數字，減少儲存需求 | [17.2](chapters/17.md#17.2) |
| distillation，蒸餾 | 讓較小的學生模型學習教師提供的答案或分佈 | [18.1](chapters/18.md#18.1) |
| RLHF | 回饋來自人類的判斷，用它指引強化學習；這個名稱交代回饋來源與流程 | [7.18](chapters/07.md#7.18)、[13.17](chapters/13.md#13.17) |
| PPO | 一種更新方法：作答得分後，對照收集時的舊機率，用裁切代價調整回答傾向 | [13.11](chapters/13.md#13.11)、[13.12](chapters/13.md#13.12)、[13.13](chapters/13.md#13.13) |
| reward model，獎勵模型 | 先學回答比較，再替一份回答估計分數 | [13.10](chapters/13.md#13.10) |
| policy，策略 | 決定怎樣選回答的機率規則；在有限選卡例子中，決定哪張卡較常被選 | [13.11](chapters/13.md#13.11) |
| value model／critic、baseline | 價值模型估計這題平常能拿多少分；這個預期分數可作比較此次表現的基準 | [13.11](chapters/13.md#13.11)、[13.14](chapters/13.md#13.14) |
| fixed reference，固定參考 | 保留後訓練起點的模型副本，用來比較回答傾向偏移多少 | [13.12](chapters/13.md#13.12)、[13.14](chapters/13.md#13.14) |
| safety alignment，安全對齊 | 教模型辨認可完成的請求、需要澄清的情境與應拒絕的邊界 | [9.1](chapters/09.md#9.1)、[9.4](chapters/09.md#9.4) |
| RAG | 先找外部資料，再把相關內容交給模型作答 | [A.2](chapters/0A.md#A.2)、[A.3](chapters/0A.md#A.3) |
| tool call | 讓模型提出工具要求，由程式檢查並實際執行 | [B.1](chapters/0B.md#B.1)、[B.2](chapters/0B.md#B.2) |

例如「模型檔案太大」可先看量化與蒸餾；「模型已放得下，但接話很慢」可先查時間花在哪裡，再看 cache。檔案變小不等於所有硬體上都變快；少啟動幾位專家也不等於所有權重都能不存。

查後訓練方法時，先分清材料來源與更新方法：人類回答比較可以提供RLHF的回饋，PPO則說明怎麼更新。第13章新增的PPO實驗只選整張預寫回答卡，標籤由程式規則提供；它示範更新流程，沒有使用真人評分，也沒有逐字生成答案。直接用偏好對更新的DPO，則可從G.2的連結查起。

挑一個你目前想解決的問題，在表裡選起點，讀那節的具體數值例子。最後用那個例子解釋為何選它；若只是因為名詞熱門，先回到要改善的量是儲存、時間還是回答品質。
