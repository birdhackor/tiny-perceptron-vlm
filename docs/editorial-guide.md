# 本次完整改寫與讀者審閱標準

本輪把教材寫成第一次順序閱讀能理解的說明。讀者要看見任務、材料、答案及每一步的關係；程式可執行不能代替這些說明。範圍依目前來源檔案列出的編號小節，不使用過期的固定節數。

依使用者指定，本輪先完成大綱與新增內容，再改寫既有教材，之後才做易讀性、正確性、銜接三輪獨立審閱，最後另處理成品訓練與發布。同一階段可以分工，不邊寫舊課文邊開始審閱或訓練。細節見[本輪工作順序](course-revision-20261005/README.md)與[clear-tutorial skill](../.agents/skills/clear-tutorial/SKILL.md)。

## 作者的工作

- 保留既有小節編號，讓連結與讀者書籤接續；含混標題可以改為清楚的學習問題，每節仍只聚焦一件事。
- 寫給第一次接觸本專案的人。必要回顧放在當前概念使用的位置；跳讀的回讀連結與操作資訊放補充區，開頭從具體問題開始。入門小節不能先要求讀者知道ID、tensor、模型、參數或梯度。
- 開頭先完整說明眼前要解決的問題，接一個可追蹤的例子；用連貫段落鋪陳「為什麼要這樣做、每一步發生什麼」，再引入正式名字。
- 常見篇幅是每節700至1200個中文字，複雜概念可更長，簡單概念可較短。這是深度提醒，不是通關字數；不能用重複套話湊長度。第一次看到術語時，明確解釋它在這個例子裡代表什麼。
- 不沿用「先想一想／把直覺寫成數學／最小實驗／如何讀結果／只改一件事」的機械段落模板。少量有意義的小標題可以使用，但正文必須像人在講解一件事。
- 圖放在讀者已經知道要看什麼的位置。先解釋圖中的字、數字、箭頭與符號，再說它支持哪個結論。可以移除不相干的圖；不要每節硬塞整章共用圖。
- 每段Python要說明輸入、使用的變數／工具、關鍵行在做什麼，以及輸出中哪些具體數字值得觀察。保留可獨立執行的小實驗，必要時改寫並附合理註解。程式保持離線、CPU可跑，不額外下載資料或執行長訓練。
- 提出一個可操作的短練習，說清楚改哪裡、先預測什麼、怎麼核對；必要時附答案思路。練習不能引入未教過的能力。
- 公式只在有助理解時放入，逐一解釋符號與一個數值例子。不要用未解釋的英文縮寫或集合式描述取代講解。
- 用繁體中文與自然的書面語。對話風格、instruction following、安全、Dense／MoE、量化／蒸餾等範圍保留，不能刪掉難題假裝改善可讀性。
- 只修改分配的來源檔案；不提交Git，不修改產生出的Notebook或共同建置程式。主代理統一重建、測試與發布。

## 每節必須有獨立讀者審閱

改寫階段全部完成後，由協調者逐節派一個新的reader subagent，`fork_turns="none"`，只給檔案、編號、讀者設定與報告格式。讀者不繼承作者推理或專案歷史。每節都有自己的新讀者，不合併成整章摘要；同一審閱階段可同時處理不同節。不能帶著未審閱的小節發布。

閱讀依[分段初讀流程](../.agents/skills/clear-tutorial/references/review-protocol.md)：逐個有意義單元前進，先保存當下理解與疑問，再看下一段；不能先掃完全文再假裝第一次閱讀。零張圖也要檢查是否缺必要圖，圖檔存在也需實際查看基本資訊是否可讀。

讀者可以打開本節明確連結的前置材料，不能用自行搜尋整個專案的知識替作者補缺。請讀者用自己的話說明本節的問題、例子、程式輸出與練習；指出所有在文本中找不到解釋的詞、跳步與缺少的前置。遇到不能理解的部分就退回，不以「看起來正確」當通過。

reader在`docs/reader-reviews/<小節編號>.json`寫下：`lesson_id`、`source`、`reviewer_task`（自己的完整task名稱）、`source_sha256`、`verdict`（`pass`或`revise`）、`reader_summary`、`issues`與`checks`。SHA-256計算從該節`## 編號 標題`起、到下一個`## `之前的UTF-8原文。`checks`列出背景與連結、術語、例子、程式解釋、練習能否理解。開始指南的暖身小節也使用此格式。

`checks`可以用名稱作鍵的字典，或每項包含`name`的清單；各項都記錄狀態與理由。純文字的名詞頁不必硬加程式，沒有程式區塊時，`program_explanation`可記`not_applicable`並說明原因；其餘理解檢查仍須通過。這不表示曾執行程式，也不能用來略過有程式的小節。

作者修正退回意見後，請同一位reader重新核對，不自行把報告改成pass。主代理最後核對所有節號都有真實reader報告，且報告的hash對應最後發布的文本；過期的pass不算通過。最終把subagent審閱與程式驗證分開報告，不能把AI審閱說成真人學生測試。

後續跨工作階段維護時，若原reader已無法呼叫，另派一位沒有專案背景的新reader，重新完整閱讀修改後的小節並產生新報告。不能只改舊報告的hash；舊版審閱紀錄仍可從Git歷史核對。

有SVG的節，reader也要核對圖中的數字、位置、箭頭與正文是否一致，並在報告加`figure_sha256`字典，key為圖檔相對repo路徑、value為該SVG檔案的SHA-256。圖改過也要重審，不能只靠正文hash通過。主代理另外以瀏覽器檢查實際排版。

必要前置的圖若也記入報告，發布檢查同樣核對它的雜湊；不能讓已修改的前置圖沿用舊審閱紀錄。
