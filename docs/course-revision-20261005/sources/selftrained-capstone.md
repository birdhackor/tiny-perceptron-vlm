# 從隨機權重訓練的有限多模態助手：成品規格與來源筆記

日期：2026-10-05。狀態：第一階段規劃；沒有執行訓練、下載資料集、蒐集錄音、改寫教材或實作程式。本筆記的數字是待試跑的範圍與候選驗收門檻，並非既有成果。公開頁面與 metadata 的查核只證明來源敘述與可用條件，不證明小模型能達標。

## 1. 主線成品的定義

主線應讓讀者親手訓練出一個有限範圍的文字聊天核心，再把自行訓練的影像、中文字辨識與語音元件接上它。核心以小型 MoE 為主、Dense 為對照；所有神經權重從隨機初始化開始。現有第 19 章的 328,128 參數成品可作為形狀與高低音的入門里程碑；它的測試範圍不足以證明商品影像、中文字或真人中文問句能力。第 20 章的 Qwen／Whisper／LoRA 等現成模型路線適合作為延伸，不算本主線的成功。

合理的產品文字是「會處理幾種教過的中文需求、指定格式、少量服飾商品圖／關係圖、有限字卡與中文意圖語音問答的助手」。不承諾任意中文聊天、任意物件、任意中文字、自由口音或任意語音。相同核心接收文字、影像特徵或語音特徵與對話歷史，並生成答覆；工具程式只負責確定性運算。

候選邊界如下，須在後續試跑前凍結，失敗時重新收斂、重新切分並保留原結果：

| 能力 | 可先試的教材範圍 | 本階段不能承諾的部分 |
| --- | --- | --- |
| 文字聊天 | 約 6–10 種教過的需求：問候、說明支援範圍、指定一句／兩點格式、在兩回合中記住有限選項、有限客服問答、計算請求 | 開放領域知識、長文、自由人物設定；範圍數量不代表訓練已足夠 |
| 服飾影像與關係問答 | Fashion-MNIST 先選 3 類：褲子、包、短靴；以原影像自製兩物件固定格位場景，問左／右或上／下的物件 | 任意自然照片、衣服材質、彩色屬性、自由物件偵測；28×28 灰階商品圖與拼貼應如實標示 |
| 中文字看圖 | 8–12 個繁體常用字；自製合法字型字卡、指定區域中的單字或 2–4 字；已知字元可組成未見短串 | 任意中文字、手寫、真實招牌、直排、多欄、未知位置的偵測；只認整塊固定字卡不能宣稱會組字 |
| 真人中文語音 | MInDS-14 zh-CN 先試 `address`、`app_error`、`card_issues` 三個意圖；模型輸出短答，且會受同一核心的歷史／格式要求影響 | 完整聽寫、任意問句、即時連續對話；語音可接受時長須由資料 metadata 與後續人工檢查決定，不能硬稱都是短語音 |
| 計算工具 | 正整數、加減乘與一種固定呼叫格式；先只需一次工具往返 | 模型心算正確率不等同工具能力；語音數字尚未教過時，不宣稱能以語音計算 |

以上字數、種類數是方便教學的候選邊界；參數量、訓練資料量、步數與硬體需求待之後的小試跑決定。不把 328,128 參數或任何固定新數字當作充足容量保證。

## 2. 「自力更生」的可稽核規則

- 必須從零訓練：文字 embedding、注意力、Dense FFN／MoE experts、router、影像 CNN／patch encoder、影像投影、OCR head、語音 encoder、語音投影，以及採用時的 CTC／語音 decoder。凍結「自己先從零訓練好的」元件可以，但須標明訓練階段與檢查點來源。
- 可用：PyTorch／NumPy、固定 resize、STFT／log-mel、確定性字元 tokenizer、一般最佳化器，以及受限的真正計算器程式。若學習 tokenizer，也只使用訓練側資料。從零訓練不要求手刻 FFT、autograd 或矩陣乘法。
- 不可把成熟模型移到別處：推論前後或資料管線中的 Whisper、Qwen、CLIP、預訓練 OCR、預訓練 speaker embedding、雲端 ASR、隱藏 API 都不算本路線。為清楚說明能力來源，主線訓練標籤優先使用來源原有標籤與專案作者人工核對的答覆，不以成熟模型生成的答案當必要教師。
- 測試時只給原始問題、必要歷史與實際模態內容。不能提供 gold transcript、物件名、意圖標籤或逐題標準答案；不能由 filename／路徑帶入標籤。MInDS-14 的路徑含有 `BALANCE` 等意圖名，必須從模型輸入排除。
- 允許提示說明支援範圍與一般輸出格式；不能把每一類的完整答覆對照表塞進 system prompt，也不能靠程式依意圖直接返回整段答案。有限類型可以教給模型，但至少要驗收改述、組合與歷史／格式差異。
- 公開每一個元件的權重來源、參數計數與輸入契約；總參數包含文字、影像、OCR、語音、router 和投影。MoE 另列總參數與每 token 啟用量，不用只列 experts 的數字。

## 3. 教學上可解釋的候選結構與階段

最小骨架是「字元序列 → 小型自回歸 MoE → 答覆／工具呼叫」。先學小範圍語言與格式，再教同一核心使用影像／語音訊息，最後驗收聯合對話。視覺可先採小 CNN，再投影成少量特徵 token；OCR 可用獨立從零 head，讓辨識出的字串進同一核心，或以直接影像條件生成為進階比較。一般物件特徵與 OCR 各自需要感知指標，不能只靠最後一句看似合理的答案驗收。

MoE 可先試少量 experts 與 top-1 routing，讓資料流容易畫出與逐步追蹤。Switch Transformer 是 routing 與負載平衡的成熟參考，不是本尺寸的效能保證。需要報告路由分布、expert 使用與是否崩塌；不把「第 1 位專家自動負責語音」寫成事實。對照 Dense 使用相同資料切分、tokenizer、任務配比、評分與可解釋的訓練預算；明示比較是配對總參數、啟用計算量還是訓練 token 數，這些不能全部假裝相等。MoE 若較差也應保留結果；不以「一定勝過 Dense」當結業條件。

規劃階段順序：

1. 凍結任務、詞表／字表、合法來源與切分群組，再選候選小模型尺寸。
2. 從零訓練有限文字核心；先驗收教過類型的新改述、已知字詞的新組合及兩回合歷史。
3. 分別從零訓練感知元件，再讓同一核心接收它們；先確認辨識能力，再評估聯合答覆。
4. 用自己生成的工具軌跡教會呼叫、等待結果與再答覆；不要要求網路同時學會所有算術。
5. 凍結 checkpoint、提示、模態處理和工具版本後，跑來源隔離的盲測；列出失敗案例與適用範圍。

資料增加、尺寸調整與階段訓練都屬於之後的實作工作。本筆記沒有把任何一個新組合稱作論文已驗證的方法。

## 4. 中文真人語音：直接問答與有限聽寫的分工

**直接語音問答**適合少量意圖：固定 log-mel → 自行訓練的語音 encoder／投影 → 同一 MoE 聊天核心 → 短答。可以增加意圖辨識輔助損失，但最後的答案仍由核心生成，且須使用對話歷史或格式要求。它能證明模型從真人聲音判斷教過的意思，不能證明逐字聽寫。需以不同措辭、不同聲音來源及相近意圖的對照測試，避免只把某一段聲音記成答案。直接語音輸入模型時不附來源轉寫。

**有限聽寫**適合需要保留字串、數字或物件名的需求：固定 log-mel → 自行訓練語音 encoder → 從零 CTC head／decoder → 字串 → 相同聊天核心。CTC 可用整句轉寫監督，不需手標每一幀對齊；blank、重複字與時間下採樣仍需教清楚。先限制字表、短句與錄音條件，分別報 CER、整句正確率、數字／關鍵詞正確率及最終答覆成功率。CER 低不代表「二十三」與「十三」都安全辨識，語音工具參數要另驗。

對本次教材，**直接問答是公開小型中文意圖資料最貼近的候選主線；有限聽寫是需要額外轉寫資料的獨立里程碑**。不能先用現成 ASR 取得測試問句，再宣稱語音模型從零成功。若直接音訊軟 token 路線難以收斂，可試自行訓練的離散意圖／槽位介面，但必須揭露中間輸出；固定程式只能把它序列化，不能查表返回完整答案。這種產品必須稱有限意圖語音助手，不稱開放語音聊天。

共享核心的驗收要能看見：打字先說「接下來請用兩點回答」，再以中文真人語音提出教過的意圖；接著打字「改成一句」時，原有主題與格式應延續。相同語音在不同歷史下不必回完全相同的字串，但語意與格式都須正確。核心須使用同一份 checkpoint 與歷史序列；兩條路各接一個不同的聊天模型，或讓語音程式回固定答覆，都不算共享核心。

### MInDS-14 zh-CN：目前較貼近的公開候選

查核的官方 HF repository revision 是 `40ce77cb32a384e4d50a568e1ec39ac804019d33`。資料卡 metadata 標為 **CC BY 4.0**，卡片正文寫 CC-BY；`zh-CN` 有 **502 條、8 kHz、14 個 e-banking 意圖，且只有一個名為 train 的 split**。這個名稱不表示已經替教材做好 train／validation／test。

schema 是 `path`、`audio`、`transcription`、`english_transcription`、`intent_class`、`lang_id`，**沒有 speaker ID、session ID 或現成客服答覆**。原論文說真人取得意圖、敘述與三個例句後自行提供新口語問句；中文屬網頁錄音收集，而不是中文真實銀行客戶通話。論文實驗使用 Google ASR 轉寫與預訓練 LaBSE／mUSE。因此其轉寫不能直接當人工聽寫 gold，其成績不能用來承諾從零音訊模型的成績。

候選先選 `address`、`app_error`、`card_issues` 三種，回覆由專案作者另外撰寫並人工核對。例如分別簡短說明「透過官方管道查詢地址更新方式」、「先檢查網路與重新啟動 App，仍失敗再詢問官方客服」、「確認卡片無法使用的情況並詢問官方客服」。這些是準備教給模型的作者原創答案範圍，不是可以塞入提示的查表答案，也不是實際銀行的操作流程。這是資料支援的特定客服問答；如果改成「辨識照片物件的中文語音提問」或「語音計算」，必須另有相應真人錄音，不能拿銀行問句或英語音訊改名充數。

**每意圖精確量尚未取得。** 公開論文列中文總數 502，沒有中文各類表；502／14 約 35.9 只是全類平均，不能保證每類都有 36 條，更不能保證每類有足量 2–6 秒短音訊。官方 dataset viewer 的 `zh-CN` statistics endpoint 回應 HTTP 500；`all` statistics 可查到全語言意圖數，但不能冒充中文各類數。原始 archive HEAD 回應 403；本階段沒有下載 archive 或 parquet，也沒有為取得計數而批量下載資料列。

後續選資料前須查各類數、時長、重複、說話者可辨識性與人工聽音品質。若只有 3–4 類、每類約數十條且無可靠說話者識別，這只是一個高風險試跑候選。**不能保證可驗收未見真人聲音**。需要在後續資料階段加入獲得錄製與重散佈同意、具有 speaker／session ID 的獨立中文改述與測試錄音；或找到另一個具有可靠來源群組的授權資料集。若這個必要條件未完成，成品須標為來源內的意圖示範，保留「真人新聲音問答尚未達標」，不能改用 Whisper 把主線寫成成功。

## 5. 圖片、中文字與聊天的合法資料方向

### 優先主線：Fashion-MNIST＋自製兩物件場景

Fashion-MNIST 的官方 README 不只提供 repository badge，也在 License 段落明文說 **Fashion-MNIST is licensed under the MIT license**。官方 LICENSE 是 Copyright © 2017 Zalando SE，允許複製、修改與散佈並保留 copyright／permission notice。此查核以官方 repository commit `b2617bb6d3ffa2e429640350f613e3291e10b141` 為依據，沒有下載影像資料。

原資料是 28×28 灰階服飾商品影像，10 類、60,000 train 與 10,000 test；論文列每類 7,000。先用 label 1（Trouser）、8（Bag）、9（Ankle boot）三類，各有官方 train 6,000／test 1,000 的規模。是否實際需要用滿，仍待試跑；不能拿全資料量寫成已經訓練的量。

主線先教單物件辨識，再將兩張合法來源商品圖置於明確格位，教「左邊是什麼／包在短靴哪一邊」等有限關係。生成器可以知道類別來產生訓練標籤，推論輸入只能帶像素、問題與位置契約，不能把類別順序或 gold 關係放進提示。位置與類別交叉平衡；提供同兩物件對調位置的成對測試，避免回答只跟物件共現頻率走。

先按原始影像 ID 分割再合成。train／validation 從官方 train 取不重疊 ID 群；test 只使用官方 test ID；同一原圖的所有單物件版本、配對、縮放與增強都不跨 split。如果重用官方 test 調參，該部分就不能繼續叫盲測。官方 image ID 分割也不保證不同商品實體／拍攝 session 隔離，應限制成績聲明為本資料來源與格位場景。

這個收斂方案比自然背景照片更可教：合法、小型、原始影像量清楚，且兩物件關係能驗收基本視覺條件問答。它仍需要從零的視覺 encoder 與同一聊天核心，不能讓程式依生成器標籤作答。它是 **服飾商品影像與自製關係圖問答**，不應寫成杯子、瓶子、任意照片或自然場景已通過。Dense／MoE 成績須在相同場景與來源切分下比較。

### 優先主線：有限字表、指定區域的自製字卡

可先選 12 字「大、小、上、下、左、右、開、關、入、出、人、口」，或縮成 8 字。可教單字與「入口、出口、開關、上下、左右、大小」等短詞，再測已知字元構成的新短串；字表與選用字型須凍結。詞表是教材作者原創、字型用經查核的 Noto CJK 或同等明確許可來源。

使用者指定框／固定區域，再問「讀出框內的字」；確定性的 crop 可以使用，但 crop 座標不能帶答案。這只要求範圍內字形辨識與生成，不暗藏成熟 OCR，也不宣稱會在任意圖片自動找文字。指定區域與字詞互換、同圖不同框、相同字元不同組合應有成對測試。合成文字的字級、間距與少量字型變化可當待試跑範圍；未驗收字體仍屬界外。

如果只用已知字體與合成字卡測試，成品能力就叫「有限字表字卡辨識」。真實招牌、未知字體與自然照片中文字是後續延伸；不能由字卡成績推出。若短串辨識失敗但固定詞可過，改稱有限短詞辨識並保留這個邊界，不用 OCR 一詞掩蓋整塊分類。

### 後續擴展選源：自然照片與實拍中文字

**照片**優先考慮 DOCCI 的小範圍物件子集，或逐張確認授權的 Wikimedia Commons 照片。DOCCI 官方卡為 CC BY 4.0，照片由作者及家人拍攝，描述為人工標註。它含相關、近似照片，因此同物件、同拍攝系列不能跨 split。既有 v4 的 k-means cluster 是相似度群組，不等同可證明的拍攝 session 或人物來源。若目標物件在來源中不夠，縮小物件清單；不能用合成形狀成果補成「自然圖片通過」。

**中文字**先用專案作者的有限詞表與合成字卡，再用有合法授權的實拍單行招牌／字卡測試。Noto CJK 的官方 Sans LICENSE 是 SIL OFL 1.1，允許使用與再散佈字型（保留相應 license／notice）；它明列文件不必因此受 OFL 約束。字型授權不會自動授權拿來排版的第三方文章，所以文字內容應由作者原創。合成資料的測試需隔離原文字串、版面與至少一部分字型／背景；若只測過同字體渲染，應稱合成字卡辨識。Commons 每個 File 頁面的作者、實際 license、修改與來源須逐張記錄；不能把平台一般說明當成每張圖都是 CC BY 4.0 的證明。

**聊天**從小範圍、作者可核對的原創對話開始；每種能力須有多種措辭、不同歷史與格式，並將同一對話樹及改述群放同 split。OpenAssistant/oasst2 官方卡是 Apache-2.0，可作適當範圍內的補充與格式參考，但不是品質保證或足夠的從零中文預訓練語料。既有 v4 的 122 training rows 是小型微調補充，不可移作「從隨機權重已有中文聊天能力」的證據。作者標籤要標作者、修改理由與人工核對狀態，不把來源使用者的問句誤標成來源提供了標準助手答覆。

每個實際選入來源需有版本／URL、作者、license 原文位置、實際挑選 IDs、修改說明、檔案 checksum 與 split group。CC BY 來源保留署名、授權連結與變更說明；Apache 來源保留 LICENSE 及適用 NOTICE；相容的來源也不必改寫成單一統一授權。此處是選源規格，尚未產生可散佈資料包。

## 6. 拆分與防止固定題記憶

先固定資料與測試規則，再訓練。不要對資料列隨機切分後就宣稱學到泛化。

| 資料 | 必須一起移動的群組 | 另外檢查的能力 |
| --- | --- | --- |
| 文字 | 完整對話樹、原問題與所有改述、同一作者原例的改編、近重複模板群 | 已知字詞的新組合；反事實歷史；未見措辭；少數例句之外能否守格式 |
| 真人音訊 | speaker、錄音 session、同原句所有裁剪／增強／重錄；來源能識別的群組 | 未見 speaker 與未見措辭分開報；噪音增強不是新說話者；沒有 ID 時不能宣稱 speaker-disjoint |
| 同一句文字＋音訊 | 相同語意題、來源 transcript／問句改寫群組 | 文字訓練側不能藏入語音測試側同題逐字標準答覆；另設熟悉意圖、陌生措辭的測試 |
| 照片 | 原圖、縮圖、裁剪、同物件與連拍／來源家族、相近圖片、所有附屬 QA | 新照片／新實體而非只換 crop；換圖答案是否跟著變；移除圖是否失去必要資訊 |
| OCR | 原照片與所有裁剪／字串，合成版面家族與其增強 | 已知字元的新字串；新字體與版面；實拍來源泛化；不能把完整 test 招牌字串先教過又稱自由 OCR |
| 工具 | 表達模板群與題目生成家族 | 新操作數組合、不同工具返回值、必要時真的呼叫、不需工具時不亂呼叫 |

測試至少分三層：熟悉類型的陌生來源；已知元素的陌生組合；超出範圍或資訊不足。增強圖／音訊、同一模板填不同數字和同一人多段錄音不能都算獨立樣本。逐項報樣本數、類別數、來源群數與失敗，必要時以群組而不是單列估計不確定性。極少量示範測試只證明示範，不能填上泛化通過。

資料不足時優先減少意圖、物件、字表、句長與場景；保留服飾商品影像／關係圖、有限中文字、真人中文提問與真正工具迴圈這四種任務本質。自然照片與實拍招牌是另外的能力延伸。若主線其中一項尚未通過，標示那項未達成，不以其他能力平均後宣稱完整成品通過。

## 7. 具體情境與可觀察行為

| 情境 | 輸入與期待 | 驗收要防的替代解法 |
| --- | --- | --- |
| 兩回合文字 | 「之後請用兩點回答。」→ 一個教過的簡短問題；同問題換成「只用一句」時格式改变 | 只記固定 prompt；忽略歷史；system 偷提供整段標準答案 |
| 真人中文意圖 | 真人問「我換地址了，要怎麼更新？」；相同核心回覆地址更新的短說明；新問法與相近類別應分得開 | 提供 gold transcript；filename 帶 `ADDRESS`；只重播訓練錄音；由程式直接查答案表 |
| 服飾／關係問答 | 兩格分別放未見過的包／短靴商品圖，問「左邊是什麼？」；交換圖位置後答案改變；單物件亦測 | 固定題返回固定物件；生成器洩漏物件順序；同原圖 crop 混入 test；程式直接查位置標籤 |
| 中文字圖 | 已知字元組成、訓練未出現的 2–4 字单行圖；使用者指定框，問「請讀出框內的字」；同圖换框應跟著改 | 整塊字卡分類成固定詞；框外文字主導答案；檔名含字串；成熟 OCR 隱藏辨識 |
| 真正計算 | 「幫我算 17×23。」→ 模型產生參數 → 計算器執行得到 391 → tool 訊息 → 同一核心答覆 | 在提示預先放 391；程式直接回完整答案；模型自己猜完卻附假 tool trace |

17×23 只是說明流程，實際測試應使用未見過的操作數組合；已教過的語法與結果字元可以共享，不把每個新數字都誤當開放數學泛化。

## 8. 候選驗收門檻與證據

下列是規格候選，後續可以用 validation 調整並在 test 前凍結；不能看 test 結果後偷偷改門檻。閾值只是要教清楚的最低行為，不是論文標準或成功預測。每項須列出分子／分母與來源群數，並保留未通過結果。

| 項目 | 可先評估的門檻候選 | 必需證據 |
| --- | --- | --- |
| 文字有限需求 | 每種意圖約 80% 語意通過；格式約 90%；依賴歷史的案例另列，不能靠無條件問候灌分 | 新改述與歷史對照；人工可讀逐題 rubric；最後答覆而非 training loss |
| 服飾物件與關係 | 每類／每關係約 80% 正確；必要資訊改變的配對案例須隨圖改变 | 未見原影像 ID；單物件、兩物件與位置交換各列；無圖／換圖對照 |
| 有限字表 OCR | 已知字元新字串先試 CER ≤10%、整串完全正確 ≥80%；單字、短詞與新組合分列 | 原始字串／版面隔離；指定區域对照；字表與未知字策略；實拍能力尚未列主線 |
| 真人中文直接問答 | 選定每意圖約 80% 語意通過；另列相近意圖混淆、未見措辭與聲音來源結果 | 無 test transcript 輸入；可核對的音訊來源；真正語音引出的核心答覆；speaker 不明則不成立未見 speaker 驗收 |
| 有限聽寫（若列為成品能力） | CER 與整句正確率同報；工具數字／參數試 ≥95% 正確，不能用平均 CER 替代 | 從零 ASR、人工核對轉寫、說話者隔離；感知錯誤與核心答錯分開 |
| 計算往返 | 題目語意決定參數且最後答案正確 ≥95%；有效結構／有界執行與每次真實回填須满足契約 | 每條 trace 含模型 tool call、實際執行結果、tool role、二次模型生成；工具服務自身的確定性結果另核對 |
| 界外／資訊不足 | 大多數明確界外案例能說明支援範圍或澄清；候選門檻約 80% | 無圖、無法辨識、未知類型、缺參數等逐項檢查；不能用全拒答取得高分 |

試跑先規劃每種任務與每類至少十多個獨立 heldout 案例，再估是否需要更多來源；若只有幾個例子，列為功能煙霧檢查而非泛化驗收。真正的 speaker／來源群數比測試列數更關鍵。達到分數也不推出任意中文能力。

工具另需一個小型依賴檢查：在測試專用 replay 中換成不同的 tool 返回值，確認生成答覆確實使用回填值；它只證明讀取工具訊息，正常精確率仍使用真計算器結果。禁止任意 shell／Python `eval`，用有界整數與白名單運算契約即可。工具受限的理由是教材能完整展示計算過程，不把執行其他程式當額外能力。

## 9. 主要風險與收斂方式

1. **從零中文生成資料不足。** 少量意圖有可能只學固定句。先縮小詞表與句長，強化已知元素的重組、指定格式與兩回合對照；若核心仍不會，記為未通過，不能將現成中文模型放進主線。
2. **MInDS-14 的說話者不可追溯。** 原始來源沒有公開 ID；普通逐列 split 只能證明列不重複。後續需要獨立、有來源 ID 的中文真人測試，否則不宣稱新聲音能力。
3. **語音意圖資料不能教任意聽寫。** 3–4 類分類與新數字／字串保留是不同問題。直接問答先驗收；有限 ASR 的資料與損失另規劃，不把轉寫能力省略成已完成。
4. **商品圖／字卡成績容易被誇大。** 主線只宣稱所選 Fashion-MNIST 類別、格位關係與已知字表，不延伸到任意自然照片／實拍招牌。跨字體、位置、商品實例與字串組合要分開報；沒有實拍 heldout 時不宣稱實拍能力。
5. **MoE 可能更難訓練。** Router 崩塌、負載不平衡與參數管理有額外成本；少量 experts、分段教學、Dense 對照帮助診斷。不能把大模型論文的加速數字移植成小模型承諾。
6. **多任務互相干擾。** 先固定各模態個別指標，再評估融合；主線能力數可收斂，但每個真正宣稱的任務都要有證據，不用平均分掩蓋語音／OCR 未通過。
7. **帳目與標籤會洩漏。** 名稱、來源 transcript、物件 caption、意圖與工具答案在測試輸入中都可能提供捷徑。凍結資料後審查 input manifest，與最終訓練紀錄分開保留。
