## G.4 後段主題先對應到問題

後段名詞很多，但每個都可以先對應到一個問題：想少算、想少存、想學較好回答，或想取得模型原本不知道的資料。這些目的可以組合，也可能互相影響；要先知道自己想改善什麼，再選方法。

| 名詞 | 想解決的問題 | 完整講解 |
| --- | --- | --- |
| Dense、MoE | 每次全用同一組計算零件，或只選少數專家零件處理 | [15.1](chapters/15.md#15.1)、[15.4](chapters/15.md#15.4) |
| KV cache | 生成下一字時，保存先前已算過的內容，減少重算 | [16.3](chapters/16.md#16.3) |
| Flash Attention | 分塊計算，減少大型中間表的儲存與搬移 | [16.9](chapters/16.md#16.9) |
| quantization，量化 | 用較少刻度記錄原來的數字，減少儲存需求 | [17.2](chapters/17.md#17.2) |
| distillation，蒸餾 | 讓較小的學生模型學習教師提供的答案或分佈 | [18.1](chapters/18.md#18.1) |
| RLHF | 回饋來自人類的判斷，用它指引強化學習；這個名稱交代回饋來源與流程 | [7.18](chapters/07.md#7.18)、[13.17](chapters/13.md#13.17) |
| PPO | 一種更新方法：作答得分後，對照收集時的舊機率，用裁切代價調整回答傾向 | [13.11](chapters/13.md#13.11)、[13.12](chapters/13.md#13.12)、[13.13](chapters/13.md#13.13) |
| reward model，獎勵模型 | 先學回答比較，再替一份回答估計分數 | [13.10](chapters/13.md#13.10) |
| policy，策略 | 決定怎樣選回答的機率規則；在有限選卡例子中，決定哪張卡較常被選 | [13.11](chapters/13.md#13.11) |
| value model／critic、baseline | 價值模型估計這題平常能拿多少分；這個預期分數可作比較此次表現的基準 | [13.11](chapters/13.md#13.11)、[13.14](chapters/13.md#13.14) |
| fixed reference，固定參考 | 保留後訓練起點的模型副本，用來比較回答傾向偏移多少 | [13.12](chapters/13.md#13.12)、[13.14](chapters/13.md#13.14) |
| safety alignment，安全對齊 | 教模型辨認可完成的請求、需要澄清的情境與應拒絕的邊界 | [9.1](chapters/09.md#9.1)、[9.4](chapters/09.md#9.4) |
| RAG | 先找外部資料，再把相關內容交給模型作答 | [A.2](chapters/0A.md#A.2)、[A.3](chapters/0A.md#A.3) |
| tool call | 讓模型提出工具要求，由程式檢查並實際執行 | [B.1](chapters/0B.md#B.1)、[B.2](chapters/0B.md#B.2) |

例如「模型檔案太大」可先看量化與蒸餾；「模型已放得下，但接話很慢」可先查時間花在哪裡，再看 cache。檔案變小不等於所有硬體上都變快；少啟動幾位專家也不等於所有權重都能不存。

查後訓練方法時，先分清材料來源與更新方法：人類回答比較可以提供RLHF的回饋，PPO則說明怎麼更新。第13章新增的PPO實驗只選整張預寫回答卡，標籤由程式規則提供；它示範更新流程，沒有使用真人評分，也沒有逐字生成答案。直接用偏好對更新的DPO，則可從G.2的連結查起。

挑一個你目前想解決的問題，在表裡選起點，讀那節的具體數值例子。最後用那個例子解釋為何選它；若只是因為名詞熱門，先回到要改善的量是儲存、時間還是回答品質。
