## W.4 機率、log 與猜錯的代價

袋子裡有三張「貓」卡和一張「狗」卡，每張抽到的機會相同。隨手抽一張，抽到貓的機率就是 3/4，抽到狗是 1/4。機率（probability）用 0 到 1 的數字表示事件出現的機會：0 表示不會，1 表示一定；互斥且涵蓋所有結果的機率要加總為 1。若候選只剩貓和狗，不能同時把兩者都說成 0.9。

文字模型也會分配候選字的機率，但我們需要一把尺衡量分配好不好。假設答案是貓，甲給貓 0.9，乙給貓 0.1；甲應該受到較小的處罰。光看「最後是否選貓」不夠，還要看把正確答案看得多可信。常用的代價是 `-log(p)`：p 是給正確答案的機率，`log` 是自然對數，也就是以數學常數 e（約 2.718）為底的對數。

對數是在已知次方結果時，反求指數 a。若 `p = e ** a`，那麼 `log(p) = a`。`**` 是 Python 的次方符號：`e ** 2` 是 e 乘 e，`e ** -1` 則是 1/e，約 0.368；因此小於 1 的正數能對上負的次方。a 也可以不是整數，不必在這裡手算，程式會用 `math.log` 算出它。當 p 在 0 與 1 之間，a 是負數，因此加負號後得到非負代價。p 越接近 1，代價越接近 0；p 越接近 0，代價越大。這會特別懲罰「很有把握地排除正確答案」。下列程式只用 Python 內建的數學工具箱，輸入三個正確答案機率，逐一印出它們的代價；執行方法見 [W.1](#W.1)，迴圈寫法見 [W.2](#W.2)。

```python
import math

for p in [0.9, 0.5, 0.1]:
    cost = -math.log(p)
    bits = cost / math.log(2)
    print(p, round(cost, 3), round(bits, 3))
```

`math.log` 計算自然對數；`round(..., 3)` 把本例印出的數字取成最接近的小數三位近似值。若恰好位於兩個候選值中間，Python 選最後一位是偶數的那個，例如 `round(1.0625, 3)` 得到 `1.062`。這只讓顯示的數字較短，沒有改變代價的定義。三行中的自然對數代價依序是 `0.105`、`0.693`、`2.303`。0.1 的代價大約是 0.9 的 22 倍，並非只大九倍。第三欄把代價除以 `log(2)`，改用二進位單位 bit，分別約是 `0.152`、`1.0`、`3.322`；只是在換單位，排序沒有改變。

為什麼對數常出現？若兩個答案的機率相乘，對數會把乘法變成加法：`-log(p1*p2) = -log(p1)-log(p2)`。例如假設兩題答對與否互不影響，這叫獨立；此時兩題正確機率都為 0.5，同時答對的聯合機率是 0.25，總代價是 `1.386`，等於兩個 `0.693` 相加。於是我們能把很多位置的代價加起來或取平均，而不必一直乘越來越小的數字。真的給答案機率 0 時，代價沒有有限值；程式也不能直接計算 `log(0)`。

後面會遇到 softmax，它把一組自由的分數換成總和為 1 的機率；cross entropy 則是一個計算正確答案平均代價的工具。先記住兩者做不同工作即可，具體分數與計算會在 [1.7](chapters/01.md#1.7) 和 [1.8](chapters/01.md#1.8) 展開。PyTorch 的 `cross_entropy` 接收原始分數，內部已處理換算，因此不要先把它的輸入換成機率。

練習在清單加入 `0.25`，先預測代價比 0.5 大還是小、bit 欄會是多少，再執行核對。自然對數代價應約 `1.386`，bit 是 `2.0`。你可以把它理解為：正確答案越難被猜中，猜錯的記帳數字就越高。
