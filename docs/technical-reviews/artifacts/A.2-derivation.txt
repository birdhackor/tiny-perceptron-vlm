A.2 透明算例與分母核對，2026-10-03。
公告字典恰有 id、date、address 三欄。context 先插入 date 與 address，prompt 再插入 id 與 context。
print(prompt) 的字串中有一個 LF，print 結尾再補 LF，故兩行；第二次 print 的兩個參數由一個預設空格分開，再補 LF，總共第三行。標準答案由 source['address'] 選出，不是 date；這只是固定公告真值，不是模型能力證據。
當 address='紅街9號'，原字典其他欄位與問題字串都不改；同一插入規則讓 context 與標準答案同時變成紅街9號。若只在原例執行後改字典而不重新求值 f 字串，舊 prompt 不會自動改；本練習依正文修改 source literal 後從頭重執行原 fence。

120 家族，split_records 以家族切分：floor(120×0.8)=96，floor(120×0.9)=108，故三側家族為96、108−96=12、120−108=12。
每個店名有8種變形，記錄數為96×8=768、12×8=96、12×8=96。
映射輸入值2至9共8家族，family split為6／1／1；每個值10個offset×2種順序+1個EMPTY=21筆。訓練側6×21=126筆；合併768+126=894筆。
有效回答目標以 ByteTokenizer/render_chat 後 labels != IGNORE 計算，包括 assistant 的答案 bytes 與 EOS，忽略 user、role 與 padding。每次從894筆有放回抽24筆，random.Random(42)連續抽1000次，A.2-formal-audit.json 重算總數157361；這1000次只是短計數迴圈，不執行 optimizer 更新。

凍結正式生成分母每種公告條件都是12個 held-out 店名，每個貪婪生成1答，seed=42，weights相同。答對判準為生成字串完全等於當次公告 address[source] 且沒有非法特殊 token。
正確公告5/12；改地址7/12；baseline與改地址同時對5/12。只改來源5/12；baseline與改來源同時對2/12。配對交集分母仍為12對，不是24答，也不是訓練的96筆test模板。
四份中間 checkpoint 來自1000步，每1000//4=250步保存：250、500、750、1000；最終model.pt另保存一次。
