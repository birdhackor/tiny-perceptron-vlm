# 18.1 的手算與支持範圍

候選順序為 `[4,3,5]`。

第一列 `p=[0.8,0.15,0.05]`：總和 `0.8+0.15+0.05=1`；最大項是第0欄0.8，答案4；第一名和第二名相差 `0.8-0.15=0.65`。

第二列 `q=[0.4,0.35,0.25]`：總和 `0.4+0.35+0.25=1`；最大項仍是第0欄0.4，答案4；第一名和第二名相差 `0.4-0.35=0.05`。

因此 argmax 文字相同不決定分布。這裡有兩個具體不同的前像，所以只存答案4無法唯一還原第1欄0.15或0.35。這是資訊遺失的透明算例，沒有宣稱實際教師算術可靠，也沒有從浮點列印推斷精確十進位值。CPU 原程式用預設 float32；總和／softmax／KL 比較容忍差1e-6，argmax答案文字要求精確相等。

額外核對實作方向：以兩列的自然對數作教師／學生 logits，溫度T=2後，`pT_i=sqrt(p_i)/sum_j sqrt(p_j)`、`qT_i=sqrt(q_i)/sum_j sqrt(q_j)`。forward KL是 `T² sum_i pT_i log(pT_i/qT_i)`，手算式獨立以Python math逐項代入得到約0.45224462380457714。實作只選一個有效位置；另設一個labels=-100位置並確認其學生logit梯度為零，教師detach後梯度為None。這只驗證固定前文逐位置方向、遮罩及T²，不是MiniLLM的整序列reverse KL或policy-gradient演算法。

純文字黑盒輸出可重新編碼：字串4在ByteTokenizer是byte52加8，即ID60，在CharTokenizer('345')是其第2欄。語义相同而ID不同，不需要逐欄比較教師分布。若要算逐詞表KL，求和下標i必須代表同一事件、同一前文與位置。前置18.6的順序交換例，`teacher=[貓,狗]`、`student=[狗,貓]`，重排索引為[1,0]；重排後同樣 `[0.8,0.2]`。不同切分粒度還需要另外的序列對齊設計。

本文白盒方式指讀每個有效回答位置完整詞表分布這種配置。每列V個浮點數對比只存一個選字或文字，可能增加資料與計算；這不排除top-k、線上快取或其他白盒訊號，也不是任何白盒方法都更昂貴或更好的一般定理。
