19.11 independent numeric and scope checks

The published joint/model.pt is exactly 1,327,950 bytes with SHA-256 d85cca83cdb4952f4653ef6b58d94562b41403db3a9db2ea31ff57e31246ca16. Joint-int4/model.pt is exactly 270,855 bytes. These are complete public package byte lengths, not tensor element sizes or experiment-source package byte lengths. Exact integer/SHA equality is the tolerance.

There are 11 unique model IDs. Each has 5 file references, so 11 × 5 = 55 references. Shared companion files yield 18 unique remote file paths (11 models + 7 distinct companion files). The original public measurement's 11 passing rows have exactly the same ID/public SHA/approved-source SHA/compared-field list as the independent existing-byte audit. All 11 raw weights/config/tokenizer and relevant quantized fields match their respective approved source numerically; serialized file hashes differ because public allowlisted packaging differs.

The same 84 unique validation case IDs, tasks, expected actions and expected final answers are used for joint and DPO. Recompute action_correct = action_trace.eos AND action_trace.raw == expected_action; end_to_end_correct = action_correct AND answer == expected_final. The original rows aggregate to joint 75/84 = 0.8928571428571429 and DPO 71/84 = 0.8452380952380952. This verifies the recorded validation-based choice of joint, not new model performance, causality or any new capstone acceptance.

One original student-kd-int4 command asks 1+2 (correct sum 3). Its saved trace requests 2+9, the actual original calculator_runtime computes 11, and its saved final trace says DIRECT:12. The sample denominator is 1. This is a concrete failure, not a student/joint aggregate capability estimate.

The trainer restores step = saved step and tests while step < requested total. For a hypothetical saved step 100 and --steps 600, the remaining update indices are 100 through 599, exactly 500 updates. It does not append 600. The five original training CLI lines dispatch totals 300, 1400, 600, 100 and resumed 600, all batch_size 24, seed 42 and default seconds 540; dispatch is tested with the training function replaced, not with a full training run. The time predicate is checked before each batch, so a final batch may cross the budget. Sync/save/export/validation/report work lies after the while loop.

PyTorch's official dtype table calls float32 a 32-bit float. The original int4 loader unpacks two nibbles per uint8 byte and restores integers.float() * float32 scale; int8 storage also restores float32 weights. The tiny CPU loader checks all restored parameter dtypes as torch.float32. This storage result is not a runtime-memory or speed benchmark.

The synthetic state proof uses a 5,520-parameter randomly initialized model and one optimizer transaction with fixed artificial gradients. It runs zero task training updates. It demonstrates exact model/optimizer serialization, continuation of CPU and Python RNG and of the independent sampler, and preservation of the original frozen DPO reference even when policy values differ. It does not establish complete production-stage trajectory replay or cross-device reproducibility.
