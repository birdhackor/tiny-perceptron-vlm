- **Nagel et al., A White Paper on Neural Network Quantization, arXiv:2106.08295v1**, PDF pp. 2, 4–6, introduction and §§2.2–2.3. Introduction distinguishes taking an already trained network for PTQ from retraining with simulated quantization for QAT. Eqs. (4)–(8) distinguish rounding/clamping integer codes from multiplication by scale for approximate reconstruction. §2.2.3 explicitly permits one quantizer per output channel. §2.3 distinguishes floating-point simulation from dedicated fixed-point inference hardware. The project uses a signed symmetric range with the most negative code unused; the paper's precise signed range is not a specification for this project's packing convention. The paper supports possible quantization error, not an assertion that any task or CPU must get faster. URL: https://arxiv.org/pdf/2106.08295v1.
- **Hinton, Vinyals and Dean, Distilling the Knowledge in a Neural Network, arXiv:1503.02531v1**, PDF pp. 1–3, §1 and §2, Eq. (1) and the two-objective paragraph. A separately chosen small model learns soft targets from a cumbersome trained model. Both distributions use the same temperature; hard-label CE uses temperature 1; the soft term receives T² to compensate its gradient scale. The original paper uses soft-target cross-entropy. Forward KL differs by the fixed teacher entropy: KL(p||q) = CE(p,q) − H(p). Therefore using fixed-teacher forward KL has the same student gradient, but the paper does not make the capstone's alpha=0.5 or T=2 universally optimal. Independently computed the actual helper's two valid positions with Python math: CE=0.9461954156465, raw KL=0.07145937117875664, mixed result=0.6160164501807632; observed FP32=0.6160165071487427. The helper already includes T² once; teacher gradient is None. URL: https://arxiv.org/pdf/1503.02531v1.
- **Jiang et al., Mixtral of Experts, arXiv:2401.04088v1**, PDF pp. 2–3, §§2 and 2.1. The router selects a sparse set of independently stored FFN experts per token; varying total experts and active experts are different structural quantities. The dense baseline applies a single FFN at each position. §2.1 discusses specialized kernels and distributed expert parallelism, so sparse activation alone is no evidence of the project's CPU speed. Read the formulas for G(x), the weighted expert sum and the discussion distinguishing total from active parameters. URL: https://arxiv.org/pdf/2401.04088v1.
- **Zhang and Sennrich, Root Mean Square Layer Normalization, arXiv:1910.07467v1**, PDF pp. 3–4, §4, Eq. (4), and the paragraph immediately after it. RMSNorm divides each feature by the root mean square and applies its learned gain. Short necessary quotation: “RMSNorm simplifies LayerNorm by totally removing the mean statistic”. This contradicts the section's unqualified statement that normalization adjusts feature center and scale when describing the actual capstone. Its config uses norm="rms"; `modern.py:14–16` has no mean subtraction. For [1,3], the project's default RMSNorm outputs approximately [0.44721317,1.34163952], whose mean is 0.89442635, while LayerNorm's initial-affine output mean is zero. Suggested correction: explain that the actual RMSNorm rescales by RMS without subtracting the feature mean, or explicitly distinguish it from LayerNorm. URL: https://arxiv.org/pdf/1910.07467v1.
