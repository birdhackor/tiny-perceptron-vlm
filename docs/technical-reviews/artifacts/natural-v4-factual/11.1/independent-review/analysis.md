## Independent derivations and CPU observations

For input row x, `nn.Linear(4,8)` computes `y_j = sum_i W[j,i] x_i + b_j`. Thus `y(0)=b`, `y(1)=W·1+b`, and the difference is `-W·1`. Width compatibility imposes no condition on the relationship of these outputs to a correct color label. A row with weights `[1,2,0,0]` and bias `0.5` gives `0+0.5=0.5` and `1+2+0.5=3.5`, exactly. Continuous random initialization normally gives nonzero row sums; neither floating point initialization nor the lesson asserts that every possible weight matrix must do so.

The exact current fenced block was executed by extracting it from the preserved raw source. Runtime: Python 3.13.5, torch 2.14.1+cpu, CPU FP32, seed 0; the bounded probe used one torch thread. It printed `(1, 8)` and `True`. The norm was `1.4805306196212769`. Independent Python double-precision sqrt(sum of the actual eight FP32 difference values squared) was `1.4805307492023276`. Their absolute difference is `1.2958105077842674e-7`, relative difference `8.752337690266935e-8`.

My first probe used an excessively tight absolute tolerance of `1e-7` and failed. That exact first script, stdout, stderr and execution receipt are retained. The discrepancy is below float32 epsilon relatively, and I changed only this comparison to `abs_tol=1e-6, rel_tol=1e-6`; exact shapes, boolean outputs, bias identity and zero remain exact checks. All subsequent assertions passed. This was a probe tolerance issue, not a discrepancy in the textbook's positive-norm or formula claims.

Inserting the stated no_grad/zero_ block before difference, then rerunning from the top with seed 0, printed `(1, 8)` and `False`, with exact norm 0 and unchanged bias. Both output rows equal their bias. zero_ returned the same weight object; the leaf Parameter still requires gradients. The expected negative control, calling zero_ on the trainable leaf without no_grad, raised the actual leaf-in-place RuntimeError and was captured as an expected failure. Clearing only after materializing the old difference left that old value at `1.4805306196212769`; recomputing the forward paths produced 0.

A separate constructed logits counterexample is `[0,0,10]` for a red image and `[1,0,10]` for a blue image, in the answer order red/blue/green. Their norm difference is 1, but both argmax predictions are green and both are wrong. This is a mathematical/software counterexample, not an empirical VLM benchmark.

If a deterministic encoder produces `E(red)=E(blue)=z`, then any deterministic projector P gives `P(E(red))=P(E(blue))=P(z)`. With the same question and no distinguishing side information, the downstream deterministic LM must also have the same conditional output. It cannot reliably choose two different correct color labels. Random decoding supplies randomness, not missing image information. This establishes the relevant information limitation without claiming a particular learned encoder actually has this defect. A downstream function that ignores visual embeddings similarly witnesses why projector-only training need not repair every language-side deficiency; the lesson appropriately says "may not be enough".

The three comparisons are useful controlled diagnostics: a correct answer from a textual red-circle description establishes that tested text path; a correct answer from a red-circle image establishes that tested image path; a correct blue answer after replacing only its color establishes an appropriate response to that intervention. Fix the question, model state and other inputs; control decoding randomness. Failure at a stage narrows investigation and does not uniquely identify a faulty component. Passing these few examples does not establish general vision or language understanding. The section and introduction avoid such an extrapolation.
