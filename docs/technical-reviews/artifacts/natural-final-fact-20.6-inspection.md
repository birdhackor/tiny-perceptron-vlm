## Original authority reading

Unicode UAX #15 revision 57 (Unicode 17.0.0, approved, dated 2025-07-30), §§1.1–1.3 and Table 1: compatibility normalization collapses width/style distinctions, and NFKC means compatibility decomposition followed by canonical composition. It does not implement a general regional/script conversion. Python 3.12.14 original `Doc/library/unicodedata.rst`, `normalize` and `unidata_version`: same definition, using UCD 15.0.0. The independently downloaded UCD 15 UnicodeData has FF21's `<wide> 0041` decomposition; 台 U+53F0 and 臺 U+81FA are within the 4E00–9FFF CJK range with no decomposition mapping. CPU results independently give Ａ→A, 臺→臺, 台→台. This directly supports the exact examples, without claiming that no CJK compatibility ideograph ever normalizes.

Python 3.12.14 original `collections.rst`, Counter: hashable elements and dictionary counts, bags/multisets; equality compares counts, not sequence positions. `stdtypes.rst`, splitlines: line boundaries and no retained line-ending characters by default; split/isspace: whitespace semantics used for the declared removal. Counter's dictionary iteration can remember insertion order, but Counter equality still does not certify original text order; the lesson correctly limits its claim to that equality check.

TorchMetrics v1.8.2 original `functional/text/cer.py` `_cer_update/_cer_compute` and helper `_edit_distance`: unit-cost Levenshtein over `list(str)` codepoints, summed edit counts divided by summed reference lengths. It does not cap this ratio at 1; a long insertion/extra-character suffix produces values above 100%. A zero reference length cannot supply a finite denominator for this definition; separate presence/error accounting is therefore necessary under this lesson's protocol.

CC-OCR author's pinned HF README `c64517e92179991d509776064174776700cdd5a2`: TSV release used for evaluation; links the official AlibabaResearch benchmark; the License Agreement says “The source code is licensed under the MIT License”. The frontmatter `license: mit` is not sufficient proof of uniform image redistribution rights. I downloaded the original README and LICENSE directly and independently read them. I read both full pinned TSV cache files, checked their entire byte SHA and sizes, indexed the selected original rows, decoded all ten base64 images, and compared the exact decoded bytes and unchanged answers to the current local originals. No complete ZIP download is claimed. These TSVs contain flattened answer strings; selected rows have no block-order annotation schema.

Both fixed Noto Sans/Serif original LICENSE files state SIL Open Font License 1.1 and exempt documents made using the font from the font-license retention requirement. Actual local font binary hashes match the fixed version manifest and generator pins. These facts establish font provenance/licensing and the generator's held-out font choice, not unseen-font pretraining or general OCR success.

Transformers v4.57.6 original Qwen2VL image processor `smart_resize`, `_preprocess`: pixel budgets cause resampling; patch-grid positions follow resized dimensions. Pillow 11.3.0 original `Image.resize`: output pixel dimensions and a resampling filter. This supports preserving actual size/preprocessing and the caution that magnifying a reduced image does not guarantee recovering discarded detail. A many-to-one reduction cannot have a universal inverse; a higher pixel budget is not established here as a measured quality improvement. Both actual evaluated run configurations use 524,288 pixels and 384 generated tokens, and this review launches no high-resolution inference.
