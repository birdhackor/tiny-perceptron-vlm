5: Tensor Attributes
6: =================
7: 
8: Each ``torch.Tensor`` has a :class:`torch.dtype`, :class:`torch.device`, and :class:`torch.layout`.
9: 
10: .. _dtype-doc:
11: 
12: torch.dtype
13: -----------
14: 
15: .. class:: dtype
16: 
17: A :class:`torch.dtype` is an object that represents the data type of a
18: :class:`torch.Tensor`. PyTorch has several different data types:
19: 
20: **Floating point dtypes**
21: 
22: =========================================  ===============================
23: dtype                                      description
24: =========================================  ===============================
25: ``torch.float32`` or ``torch.float``       32-bit floating point, as defined in https://en.wikipedia.org/wiki/IEEE_754
26: ``torch.float64`` or ``torch.double``      64-bit floating point, as defined in https://en.wikipedia.org/wiki/IEEE_754
27: ``torch.float16`` or ``torch.half``        16-bit floating point, as defined in https://en.wikipedia.org/wiki/IEEE_754, S-E-M 1-5-10
28: ``torch.bfloat16``                         16-bit floating point, sometimes referred to as Brain floating point, S-E-M 1-8-7
29: ``torch.complex32`` or ``torch.chalf``     32-bit complex with two `float16` components
30: ``torch.complex64`` or ``torch.cfloat``    64-bit complex with two `float32` components
31: ``torch.complex128`` or ``torch.cdouble``  128-bit complex with two `float64` components
32: ``torch.float8_e4m3fn`` [shell]_, [1]_     8-bit floating point, S-E-M 1-4-3, from https://arxiv.org/abs/2209.05433
33: ``torch.float8_e5m2`` [shell]_             8-bit floating point, S-E-M 1-5-2, from https://arxiv.org/abs/2209.05433
34: ``torch.float8_e4m3fnuz`` [shell]_, [1]_   8-bit floating point, S-E-M 1-4-3, from https://arxiv.org/pdf/2206.02915
35: ``torch.float8_e5m2fnuz`` [shell]_, [1]_   8-bit floating point, S-E-M 1-5-2, from https://arxiv.org/pdf/2206.02915
36: ``torch.float8_e8m0fnu`` [shell]_, [1]_    8-bit floating point, S-E-M 0-8-0, from https://www.opencompute.org/documents/ocp-microscaling-formats-mx-v1-0-spec-final-pdf
37: ``torch.float4_e2m1fn_x2`` [shell]_, [1]_  packed 4-bit floating point, S-E-M 1-2-1, from https://www.opencompute.org/documents/ocp-microscaling-formats-mx-v1-0-spec-final-pdf
38: =========================================  ===============================
39: 
40: **Integer dtypes**
41: 
42: =========================================  ===============================
43: dtype                                      description
44: =========================================  ===============================
45: ``torch.uint8``                            8-bit integer (unsigned)
46: ``torch.int8``                             8-bit integer (signed)
47: ``torch.uint16`` [shell]_, [2]_            16-bit integer (unsigned)
48: ``torch.int16`` or ``torch.short``         16-bit integer (signed)
49: ``torch.uint32`` [shell]_, [2]_            32-bit integer (unsigned)
50: ``torch.int32`` or ``torch.int``           32-bit integer (signed)
51: ``torch.uint64`` [shell]_, [2]_            64-bit integer (unsigned)
52: ``torch.int64`` or ``torch.long``          64-bit integer (signed)
53: ``torch.bool``                             Boolean
54: =========================================  ===============================
55: 
56: .. [shell] a shell dtype a specialized dtype with limited op and backend support.
57:   Specifically, ops that support tensor creation (``torch.empty``, ``torch.fill``, ``torch.zeros``)
58:   and operations which do not peek inside the data elements (``torch.cat``, ``torch.view``, ``torch.reshape``)
59:   are supported.  Ops that peek inside the data elements such as casting,
60:   matrix multiplication, nan/inf checks are supported only on a case by
61:   case basis, depending on maturity and presence of hardware accelerated kernels
62:   and established use cases.
63: 
64: .. [1] The "fn", "fnu" and "fnuz" dtype suffixes mean:
65:   "f" - finite value encodings only, no infinity;
66:   "n" - nan value encodings differ from the IEEE spec;
67:   "uz" - "unsigned zero" only, i.e. no negative zero encoding
68: 
69: .. [2]
70:   Unsigned types asides from ``uint8`` are currently planned to only have
71:   limited support in eager mode (they primarily exist to assist usage with
72:   torch.compile); if you need eager support and the extra range is not needed,
73:   we recommend using their signed variants instead.  See
74:   https://github.com/pytorch/pytorch/issues/58734 for more details.
75: 
76: **Note**: legacy constructors such as ``torch.*.FloatTensor``, ``torch.*.DoubleTensor``, ``torch.*.HalfTensor``,
77: ``torch.*.BFloat16Tensor``, ``torch.*.ByteTensor``, ``torch.*.CharTensor``, ``torch.*.ShortTensor``, ``torch.*.IntTensor``,
78: ``torch.*.LongTensor``, ``torch.*.BoolTensor`` only remain for backwards compatibility and should no longer be used.
79: 
80: To find out if a :class:`torch.dtype` is a floating point data type, the property :attr:`is_floating_point`
81: can be used, which returns ``True`` if the data type is a floating point data type.
82: 
83: To find out if a :class:`torch.dtype` is a complex data type, the property :attr:`is_complex`
84: can be used, which returns ``True`` if the data type is a complex data type.
85: 
86: .. _type-promotion-doc:
87: 
88: When the dtypes of inputs to an arithmetic operation (`add`, `sub`, `div`, `mul`) differ, we promote
89: by finding the minimum dtype that satisfies the following rules:
90: 
91: * If the type of a scalar operand is of a higher category than tensor operands
92:   (where complex > floating > integral > boolean), we promote to a type with sufficient size to hold
93:   all scalar operands of that category.
94: * If a zero-dimension tensor operand has a higher category than dimensioned operands,
95:   we promote to a type with sufficient size and category to hold all zero-dim tensor operands of
96:   that category.
97: * If there are no higher-category zero-dim operands, we promote to a type with sufficient size
98:   and category to hold all dimensioned operands.
99: 
100: A floating point scalar operand has dtype `torch.get_default_dtype()` and an integral
101: non-boolean scalar operand has dtype `torch.int64`. Unlike numpy, we do not inspect
102: values when determining the minimum `dtypes` of an operand.  Complex types
103: are not yet supported. Promotion for shell dtypes is not defined.
104: 
105: Promotion Examples::
106: 
107:     >>> float_tensor = torch.ones(1, dtype=torch.float)
108:     >>> double_tensor = torch.ones(1, dtype=torch.double)
