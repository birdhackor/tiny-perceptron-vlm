167: When evaluating different settings (“hyperparameters”) for estimators,
168: such as the
169: C
170: setting that must be manually set for an SVM,
171: there is still a risk of overfitting
172: on the test set
173: because the parameters can be tweaked until the estimator performs optimally.
174: This way, knowledge about the test set can “leak” into the model
175: and evaluation metrics no longer report on generalization performance.
176: To solve this problem, yet another part of the dataset can be held out
177: as a so-called “validation set”: training proceeds on the training set,
178: after which evaluation is done on the validation set,
179: and when the experiment seems to be successful,
180: final evaluation can be done on the test set.
181: However, by partitioning the available data into three sets,
182: we drastically reduce the number of samples
183: which can be used for learning the model,
184: and the results can depend on a particular random choice for the pair of
185: (train, validation) sets.
186: A solution to this problem is a procedure called
187: cross-validation
188: (CV for short).
189: A test set should still be held out for final evaluation,
190: but the validation set is no longer needed when doing CV.
