7.8 自有核對推導；審閱日期 2026-10-03。

索引採零起點。每筆時間長度T=4，詞表候選數V=5。
令valid[b,t]表示物理格t是否有效，p[t]=t，
m[b,t]=p[t]（valid=True）或-1（valid=False）。
對至少有一格True的每筆，max_t m[b,t]就是最後有效物理位置，
因有效索引皆>=0，而sentinel=-1小於全部有效索引。
這只選取輸出端點，不建立key mask、position IDs或多步生成規則。

原例：
[True,True,False,False] -> [0,1,-1,-1] -> last=1，count=2。
[False,True,True,True] -> [-1,1,2,3] -> last=3，count=3。
第二筆count-1=2，與物理端點3不同。
導入段的四個真token長題端點為3，兩個真token右PAD短題端點為1；
共取logits[:,-1]只對前者的物理端點成立。

連續arange(40)以[2,4,5]排布：L[b,t,v]=20*b+5*t+v。
selected[b,v]=L[b,last[b],v]。
b=0,last=1 -> 5+v -> [5,6,7,8,9]。
b=1,last=3 -> 35+v -> [35,36,37,38,39]。
兩個[2]索引broadcast後逐筆配對，留下V軸，故shape=[2,5]。
這裡的float32整數0至39都可精確表示，數值核對採精確相等。
這些數字是人為編號，並非模型品質、機率或正式實驗結果。

練習：第一筆[False,False,True,True] -> [-1,-1,2,3] -> last=3。
仍有2格有效，端點由1改3；b=0,last=3 -> [15,16,17,18,19]。
第二筆不變，仍取[35,36,37,38,39]。
因此count與max有效索引確為不同資訊。

全False：[-1,-1,-1,-1] -> last=-1。
CPU tensor進階索引將負索引加上該軸size：-1+4=3。
所以它會讀填充尾格，不能表示有效輸入存在；生成前應檢查每筆any(valid)。
不能把這個教材示範當作已有完整batch生成入口或空輸入驗證器。
