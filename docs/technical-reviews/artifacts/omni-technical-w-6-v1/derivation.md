# W.6 透明手算核對

此檔為 reviewer 的符號與十進位手算；不是執行紀錄。實際 PyTorch CPU 輸出另存 execution.json。

1. 定義本例 L(w)=(w−3)²。L(1)=(−2)²=4；L(1.1)=(−1.9)²=3.61；下降量 4−3.61=0.39。這個有限差商是 (3.61−4)/(1.1−1)=−3.9，並不是精確導數 −4。
2. h≠0 時，[L(w+h)−L(w)]/h=[(w−3+h)²−(w−3)²]/h=2(w−3)+h。h→0 得 L′(w)=2(w−3)。因此 L′(1)=−4；L′(1.4)=−3.2。由差商的極限可見導數量測目前位置的局部變化率。負值表示充分小的正向變動會降低本例代價。
3. 更新為 w_new=w−ηL′(w)。w=1、η=0.1 時，1−0.1×(−4)=1.4；L(1.4)=(−1.6)²=2.56。這裡只有一個可調純量；多變數時梯度的每個分量是固定其他座標所求的偏導數。
4. L(w)≥0，且只有 w=3 時等於 0，因此圖中最低點 (3,0) 正確。從 1 到 1.4 尚未抵達該點。
5. 練習 η=0.6：w_new=1−0.6×(−4)=3.4>3；L(3.4)=0.4²=0.16<4。練習 η=1.1：w_new=1−1.1×(−4)=5.4；L(5.4)=2.4²=5.76>4。兩者同用負梯度方向，但後者步幅太大。
6. 對此特定二次函數，令 e=w−3，更新後 e_new=(1−2η)e，因此 L_new=(1−2η)²L_old。非最小點且 η>0 時，只有 0<η<1 嚴格降低代價；η=1 代價不變，η>1 變差。這是本二次例子的精確條件，不能外推為一般模型的學習率範圍。
7. 本例重算的導數由 −4 變為 −3.2。若程式保留 −4，再把新 −3.2 累加，將得到 −7.2；清除舊梯度後再重算才會得到本步 −3.2。這裡的加法是手算，PyTorch 是否累加由官方 source 與獨立 CPU probe 另外核對。
8. 圖的線性座標映射為 x=75+123w、y=430−34L。三點 (w,L)=(1,4)、(1.4,2.56)、(3,0) 分別映到 (198,294)、(247.2,342.96)、(444,430)。y 向下為 SVG 正方向，所以代價下降的更新箭頭向右下。圖中箭頭連接前後結果，並非導數切線。

以上十進位／符號等式為精確手算，容忍差 0；execution.json 的 float32 結果採絕對誤差 ≤2e−6，SVG 曲線每個取樣點的座標因二位小數取整採 ≤0.014 px。
