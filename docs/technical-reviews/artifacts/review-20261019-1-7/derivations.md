# softmax 的可追蹤推導與核對範圍

## 指數、正值與順序

已讀 NIST DLMF 的 The Exponential Function 與 principal power 定義，版本為 1.2.8，發布日 2026-09-15，讀取日 2026-10-19。原始公式與 HTTPS 位置保存在 `original-source-excerpts.json`。

exp(x) 的冪級數是 Σ x^n/n!。當 x ≥ 0 時，各項非負且常數項是 1，所以 exp(x) ≥ 1；當 x > 0 時，還有正的線性項，因此 exp(x) > 1。對 x < 0，使用 exp(x) = 1/exp(-x)，可知 exp(x) > 0。

實數 a、b 的指數級數絕對收斂，因此可將乘積依總次方重排：

exp(a)exp(b) = Σ_n Σ_{k=0}^n a^k b^(n-k)/(k!(n-k)!)
             = Σ_n (a+b)^n/n!
             = exp(a+b)。

若 a > b，exp(a)/exp(b) = exp(a-b) > 1，因此 exp(a) > exp(b)。exp(x) = e^x 的實數意義與 DLMF 的 principal power 定義一致。

## 機率、共同平移與穩定計算

對非空、有限個有限實數分數 z_i，令 w_i = exp(z_i)、S = Σ_j w_j。由 w_i > 0、S > 0，可得 p_i = w_i/S > 0，且 Σ_i p_i = 1。所有候選共用同一個正分母，因此 p_i/p_j = exp(z_i-z_j)，分數與機率的大小順序相同。這支持離散候選的機率分配；它沒有證明分數本身符合真實答案。

共同加上實數 c 後：

p_i' = exp(z_i+c) / Σ_j exp(z_j+c)
     = exp(c)exp(z_i) / (exp(c)Σ_j exp(z_j))
     = p_i。

取 m = max_j z_j，再令 c = -m，則每個 z_i-m ≤ 0，故 exp(z_i-m) ≤ 1，且至少有一個權重是 1。這避免直接對大正數取指數所造成的上溢。在浮點運算中，極小權重可能下溢；輸入中的 NaN、無窮大、差值不可表示，以及平移過大導致分數差消失，都不在這個實數恆等式的數值保證範圍。教材算例的分數與加上的 100 均無這些問題。

已讀 PyTorch 對應 git 版本的 `_vec_softmax_lastdim`：先取最大值，再計算差的指數、加總、乘總和的倒數。這與上述方法相符；這次執行不主張涵蓋每個裝置或每個 kernel 分派路徑。

## 原始算例與浮點誤差

原分數 [1,2,-1] 的總和是 2，且含負數，不能直接作為三個互斥且完備候選的機率。獨立使用 Decimal 的 50 位有效數字計算得到：

- e = 2.718281828459045…。
- exp 分數為 [2.718281828459045…, 7.389056098930650…, 0.367879441171442…]。
- 分母為 10.475217368561138…。
- 機率為 [0.259496460342419…, 0.705384512698241…, 0.035119026959340…]。
- 減最高分後是 [-1,0,-3]，權重為 [0.367879441171442…, 1, 0.049787068367864…]。

課文權重與分母顯示到小數三位，採絕對誤差 0.0005；機率顯示到小數四位，採絕對誤差 0.00005。全部符合。

本次 CPU float32 手動換算的機率加總為 1.0000001192092896，與 1 的差是 1.1920928955078125e-7 = 2^-23；這也恰為 float32 在 1 附近的機器間距。原始程式與補充程式得到相同結果。float64 加總為 0.9999999999999999，也支持「實數總和等於 1」與「浮點輸出近似為 1」的區分。`.item()` 只將已算好的單元素 tensor 值取成 Python 數字，並非誤差的來源。

## 練習題與共用分母

第一個分數由 1 變成 3，另外兩個不動：分母由 exp(1)+exp(2)+exp(-1) 改成 exp(3)+exp(2)+exp(-1)，增加 exp(3)-exp(1) > 0。第二個機率的分子 exp(2) 不變、正分母增大，所以機率嚴格降低。

50 位計算的新分母為 27.842472463289760…，新機率為 [0.721399184273969…, 0.265387928772242…, 0.013212886953789…]，小數四位為 [0.7214,0.2654,0.0132]。補充 CPU 程式得到相同的四位近似值。

## API 與執行能支持的範圍

PyTorch 官方 `softmax` 的 `dim` 指定共同正規化的軸；[筆數,候選數] 必須各列沿最後一軸處理。本次對形狀 [2,3] 的例子比較 `dim=-1`、`dim=1` 及逐列獨立計算，三者一致；列和在 float32 誤差內為 1。

`torch.allclose` 的預設判準是逐元素 |input-other| ≤ 1e-8 + 1e-5×|other|，並非要求位元相等。以 1 附近相差 5e-6 和 2e-5 的數值分別核對，結果依序為 True、False。Python 的 assert 在條件為真時沒有輸出；此執行未開啟最佳化，已捕捉並核對 stdout、stderr 均為空字串。

softmax 的公式與 API 只收分數和計算設定，不收答案。將第三個候選分數設為最高，第三個機率也最高；若答案不是第三個候選，這個分配仍然會偏好錯誤候選。原始程式未呼叫 backward、optimizer 或任何就地更新；補充程式核對輸入值未改、requires_grad 為 False，沒有訓練或品質提升的證據主張。
