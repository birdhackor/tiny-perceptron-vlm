# quantization：教學模型

Completed FP32 and actual packed 4/8-bit conversion variants.

在同一個經120次屬性問答續訓的FP32 TinyLM上，按Linear輸出channel量化權重，比較FP32、實際打包4位元與8位元的儲存量、誤差及留出答案。推論時仍還原成FP32計算。

限制：

- weight-only per-channel Linear quantization; no activation calibration
- packed storage is real; forward dequantizes to FP32 and uses ordinary Linear
- reported timings and allocator probes do not establish low-bit kernel speed or RAM savings
- synthetic heldout attribute families; no broad language quality claim
- Teacher agreement, held-out gold accuracy and storage/timing are distinct outcomes. This small run cannot establish universal compression gains.
- Reported file-byte counts measure the experiment's source inference artifacts. The public exporter removes RNG/training metadata, so published file sizes can differ; tensor-byte counts describe the stored model tensors. Packed low-bit checkpoints are reference inference formats and do not support training resume.
- Only Linear weights are quantized per output channel; embedding/norm tables and floating scale/bias buffers remain. Reference forward dequantizes weights for ordinary FP32 Linear, with no activation quantization or specialized low-bit kernel speed claim.
- The same SFT-initialized model receives 120 CE continuation updates before both packed conversions. All three have 6/10 held-out test exact matches in this run; packed4 has only 1/5 validation exact matches versus FP32/packed8 2/5. Equal test accuracy on ten finite-task records does not establish general quality preservation.
- Stored model tensor bytes are FP32 566272, packed4 168736 and packed8 226336; the packed variants retain 25728 floating parameters. Both packed reference forwards have slower measured prefill/decode than FP32 in this CUDA run.
