# 遞迴與資訊條件的獨立推導

令原輸入 e=4，狀態 s₀=0，係數為 α，則

`s_(r+1) = s_r + α(e-s_r)`。

寫成差距 d_r=e-s_r，便有 `d_(r+1)=(1-α)d_r`，所以
`d_r=4(1-α)^r`、`s_r=4-4(1-α)^r`。

α=0.5 時，前四輪的差距是 2、1、0.5、0.25，狀態為 2、3、3.5、3.75。
在實數算術下，因為 |1-α|=0.5<1，差距趨近 0，狀態趨近 4。
這裡有限步的數字都是二進位可精確表示的值；一般浮點實作不能保證無限多步都維持同樣的精確等式。

α=2 時，`d_r=4(-1)^r`、`s_r=4-4(-1)^r`。
初始 0 之後依序得到 8、0、8、0；差距的絕對值一直是 4，不收斂到 4。
這兩個例子只有係數不同，已足以否定「有迴圈就必定收斂」的推論。

## 為何不能轉成 Transformer 的收斂保證

`s_(r+1)=F(e,s_r;θ)` 只指定資料依賴與參數共享，沒有給 F 對 s 的收縮條件，
也沒有指定狀態的極限必須對應正確答案。核對過的 `Block.forward` 是殘差結構。
將注意力的輸出設為 0、FFN 的最後權重設為 0、最後 bias 設為非零向量 b，便有
`Block(x)=x+b`；這些都是其可學參數允許的值。
有固定輸入注入時得到 `s_(r+1)=s_r+αe+b`，只要 `αe+b≠0` 就會漂移。
這是對架構允許參數的代數反例，不是訓練所得結果，也不是某個 checkpoint 的實測。
讀出層的權重若全為 0，答案分數更可以完全不依賴狀態；收斂與答對因而是不同條件。

## 為何保留輸入只提供存取途徑

假設兩份不同輸入 x、x′ 在某一步已被映到相同狀態 s，之後的確定性更新只讀 s，
則下一步狀態必相同；由歸納法，以後每一步與最後讀出也相同。
因此，若需要的細節已真的丟失、而且沒有別的輸入途徑，就無法從這份相同狀態恢復兩者的差別。
這不表示所有壓縮或所有未再次注入輸入的模型都一定丟失資訊。

保留 e 並計算 F(e,s) 則讓後續步驟仍有輸入途徑；但 F 可以忽略 e，例如
`F(e,s)=G(s)`。即使中間狀態依賴 e，最後讀出也可能是常數。
所以「有輸入途徑」不是「模型實際運用關鍵資訊」的充分條件。
在規則可核對的題目裡，改問題或改會改變正確答案的關鍵事件，再檢查輸出，能反駁不合理的不變性；
有限測試通過仍不能證明對所有題目都正確，也不能單憑輸出還原模型的內部推理。

## token 軸與 loop 軸

令狀態是 `s_r∈R^(n×h)`。在 n 個位置固定時，套用 F 四次只有 r 改變，n 不會因此增加。
自回歸的下一個 token 要經讀出及選取，再接回序列；這是另一個外層步驟。
分類解題器在整段輸入的狀態上循環後，直接讀出答案類別，因此沒有這個外層逐 token 生成迴圈。
