# 本輪單節正確性審閱

本文件是工作方法，不是教材的技術答案。正確性審閱在全書第一次閱讀與必要修正完成後才開始；不得用舊技術報告的判定取代新審閱。

## 身分與範圍

- 每節由一位新的 subagent 審閱，使用 `fork_turns="none"`；不得重用作者、第一次閱讀者或其他小節的技術審閱身分。
- 協調者只給小節編號、來源路徑、這份方法及需回查的疑點。疑點是待驗證的問題，不能當成結論。
- 審閱者直接讀目前原稿、引用圖、必要的前置段落、實作及原始權威資料。可讀全文，這一輪不是分段盲讀；記錄實際讀取範圍。
- 目前教材與必要前文中的概念解釋、既有實測及範圍說明，是待查證的主張，可以閱讀；它們不能自行證明正確。不要把讀到現稿的其他小節，就誤認為接觸了舊審閱結論。後述避開作者額外結果評語的規則，針對證據檔及工作筆記中預先附上的解釋或修正答案，不是禁止讀待審教材本身。
- 第一節同時讀章節導言，記錄原始 UTF-8 的指紋與自己的摘要。
- 不讀舊技術審閱的正文或結論。既有原論文、官方文件及原始實驗檔可以使用，但須親自核對內容、版本與支持範圍。
- 搜尋內容前先用 `rg --files` 定位原稿、實作、指定結果 JSON 或官方原始檔，再搜尋確切檔案。不要廣搜整個 `docs/`、`docs/course-experiments/` 或 repo；其中可能混有舊 `review-dispatch`、reader/technical reports、history、readability 及作者修正筆記。這些審閱摘要不能當原始實驗資料。
- 指定的原始結果 JSON 也可能附有作者筆記，不能因此全文列印或直接搜尋內容。先以程式列必要的上層 key 與型別，再按具名 JSON pointer 只讀原始測量、樣本、判準或 provenance；不要遞迴印出所有值，也不要讀取 `notes`、`review` 或 `*_scope_correction` 中的作者結果評語或修正摘要。判斷依內容性質，不能只因欄位名稱就排除必要的方法規約。保留原檔及其完整 SHA-256，記錄自己真正檢查的 pointers，不刪改原始附註來製造乾淨輸入。
- 原實作也可能把本 repo 作者預先寫好的結果解釋或修正結論放在字串常數中。先用 AST 定位必要函式與欄位，再精確讀計算、目標及判準分支，避開這些額外解釋值；保留完整原檔指紋與真正讀到的定位，不修改原碼。普通註解、docstring、API 形狀／參數說明及資料／計算規約仍是必要原方法；不能只因欄位叫 `note` 就認定污染，也不能把一般實作說明一律禁止。
- 一般方法限制也可閱讀，例如固定的是 token 預算而非參數量、只用一個 seed、只涵蓋已知字體，或未測長度外推。這些文字沒有提供實測勝敗或既有審閱答案；審閱者仍須自行核對方法與支持範圍，不能把作者的限制聲明當成權威證據。若先因疑慮停止、後確認只讀到這類方法規約，保留真實停止紀錄與分類理由，再由原審閱者續做；不製造污染事件或換身分。
- 原資料的目標答案、標註品質檢查與程式自動產生的選版紀錄，也是可查核的原始證據。先確認評價對象、產生方法與時間，不能只因欄位叫 `peer_review` 或 `decision` 就當作舊教材審閱結論。標註品質仍須自行核對，選版仍須追到原判準、計數與資料切分；原紀錄的判定不能代替本人的驗證。若誤分類而停止，保存原停止及分類更正的實際紀錄，再由原審閱者續做，不回改歷史或補造污染事件。
- 正式證據引用必須能在乾淨 checkout 中取得。若實際查核的原資料位於被忽略的本機快取，保存必要原始檔到永久 artifacts，親自核對原件與副本的 SHA-256，記錄原來源及實際保存範圍；正式引用使用該副本，不把快取或整包訓練資料強制加入普通 Git。改引用時保留自己的原報告，再自行核對與更新，不讓協調者代改判定。
- 若意外讀到舊判定或作者修正摘要，立即停止實質查證與判定，向協調者報告實際事件。保留原派遣與停止紀錄，由另一位未接觸摘要的 fresh reviewer 重新審閱；不得把原事件刪掉、複製報告換身分，或把污染片段轉給新讀者。

## 要核對什麼

逐項列出本節影響讀者理解的實質主張，再分開核對：

1. **概念**：查原論文、官方文件或原始官方程式，記錄公式、段落、API 或行號。來源庫與搜尋摘要只用來找原始資料，不能作為已查證的證據。
2. **算例**：自己代入數字或執行小型 CPU 檢查。核對軸、單位、分母、四捨五入及容忍差，不靠照抄教材輸出。
3. **程式**：實際執行原碼與必要的小變化，核對它在做示範、計算梯度、更新參數還是評測。涉及既有 helper 時，讀真正的函式契約。安裝版本與官方最新版不同時寫清楚。
4. **既有實測**：讀指定版本的原始結果，實際用程式核對樣本數、token、步數、判準或彙總。這是核對既有證據，不能寫成重新訓練。不得為文章修訂重跑 GPU 工作。
5. **圖解**：核對圖中的素材、標籤、箭頭、資料形狀與數字是否和文字及程式一致。需要判讀畫面時實際渲染並查看，不能只搜尋 SVG 字串。
6. **範圍**：小型示範只能支持它實際檢查的事情。成熟方法的特性由原始權威資料支持；不要拿玩具實驗替業界共識重新下定論。尚未實作的成品設計是計畫，不能宣稱已驗收；已有的成品則須追到實際完成紀錄與原始測試，分開判斷執行完成和能力達標。

沒有學習價值、來源不明的數字可以建議刪去；有教學價值的反例必須說清楚它展示的機制。不得替來源不明的指標猜名字，也不得為了讓報告通過自行產生一份漂亮的模型成績。

## 執行與證據

- 可用 `section_facts.py` 擷取原始小節與 fence，或自行保存等效的原始 bytes。不要正規化換行後才計算教材指紋。
- 正式 `source_sha256` 對應本節原始 bytes。另記最初讀取的完整 Markdown 指紋時，明確標成當次 frozen input 並連到實際保存版本，不用未註明意義的全檔欄位冒充目前整章版本。舊輸入快照應保留原指紋；只有本節或真正依賴的內容改動，才安排相應查證。
- `.venv` 是目前的 CPU 驗證環境。只跑與本節疑點相稱的短檢查；不要執行訓練資料下載、模型上傳、付費運算或完整訓練的 shell recipe。查閱、取得原論文與官方文件屬於這一輪的來源查證。
- helper 的離線／寫檔限制若阻擋編譯器等正常操作，記錄為工具限制；先檢查程式，再用獨立、有界的 CPU 檢查，不能直接判教材錯誤。
- 正式證據保存在 `docs/technical-reviews/artifacts/`，使用本輪與小節可辨識的檔名。保存實際原碼、命令、結果、版本、裝置及 SHA-256。`outputs/` 的暫存檔不能是唯一永久證據。
- 原始外部來源記錄 HTTPS URL、版本、存取日期、為何是權威來源，以及實際讀到的內容定位。必要時保存精簡原始快照，避免整頁無關內容。
- 報告使用 `scripts/check_technical_reviews.py` 的 schema。每個 claim 都要有自己的支持範圍；不要以一個籠統引用代替各項核對。檢查程式只驗證格式和證據版本，不能替你判斷內容正確。
- 正式報告路徑已有舊檔是預期狀況：協調者已保存其 opaque 歷史備份。本節的新審閱者可以用自己的完整新報告覆寫該路徑，不必讀舊檔，也不要因為舊檔存在而停工。先完成自己的報告，再執行 checker；不要對尚未替換的舊報告執行 checker，將舊版本錯誤混入本次查證結果。

## 判定與修正

有未確定或錯誤的實質主張，先交 `revise`，清楚說明原文、證據、影響及建議，不得先寫成 `pass`。由協調者安排修正；原技術審閱者親自核對新版本後才更新自己的報告。

教材或圖修改後，另交原第一次閱讀者重新讀受影響內容，使用新的完整閱讀 session；協調者不得只更新他人的指紋或判定。保留原問題、修正過程與真實複查紀錄。

協調者保存實際派遣與結果。正式通過需同時滿足目前原稿與圖的版本核對、不同審閱身分、可追查證據及已解決問題；不能由宣告、批次複製報告或 Git commit 代替。
