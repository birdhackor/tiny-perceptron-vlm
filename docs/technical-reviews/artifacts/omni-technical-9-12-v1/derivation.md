# 9.12：獨立推導與適用範圍

本紀錄由 /root/omni_technical_coordinator/technical_9_12 撰寫。理論推導與真正 CPU 執行分開；實際結果在 execution.json。

固定 state=s、question=q 及 n 個帶固定身分的候選 c_i，令 z_i=g(s,q,c_i)。g 共用參數且不讀候選位置或其他候選；置換 π 後 z'_i=z_{π(i)}。實數 softmax 滿足

p'_i=exp(z_{π(i)})/Σ_j exp(z_{π(j)})=p_{π(i)}。

這證明分數與機率的排列等變；不證明 g 理解任何語言或答案正確。例 g 恆給「更改地址」最高分，仍有等變性，卻會把查卡片任務判錯。若 g 不讀 q，它也可以滿足等變性；固定 s 並換成有不同正解的 q，是獨立的行為檢查。Deep Sets v3 §2.1 eq(1) 是等變性的定義，§3.1 明列可對額外 z 條件化；本推導沒有套用該論文的實測品質。

若唯一最大實數 z 對應 c*，單調 exp 與正的共用分母保留此最大項。若有真正並列，選 tied set 中固定 ID 最小者，則 tied set 與選定 ID 都不隨清單順序改。依位置挑第一個則不能保證。浮點 softmax 可把不同 z 捨入成同一 p，故「唯一最高 z」不足以保證教材 p.argmax() 的實作也穩定；execution.json 保存 float32 的 z=[0,1e-8]、p=[0.5,0.5] 反例。用 raw score 比大小並對 score 平手按固定 ID，可避開此特定問題。這不宣稱任何浮點運算跨平台逐位元一致。

單一 gold 的交叉熵 L=-log p_gold=-z_gold+logΣ_j exp(z_j)。置換後由 gold ID 重新找位置，L 不變；保持舊位置則 gold 意義變掉。刪去 gold 卻保留位置也可能把新位置的無關候選當正解，或造成越界；這不是原 gold 任務的評估。

對固定 z 的候選 c，原 p_c=exp(z_c)/D。新增有限分數 a 後，D'=D+exp(a)>D，所以原候選 p 降；刪去其他候選的正 exp 項則 p 升。這個方向須以原分數不變為前提；集合改變也可能改變 none 的分數。加入一個同分同義的新候選會讓各副本分母變大，單一副本機率降低；不能把兩個同義描述當作兩個互斥的語義真相。若允許多個有效答案，應先定多答案標籤／評分規則。softmax 僅對既有 n 項歸一化，沒有建立新 none 項的運算。明列 none 讓標籤可表達「本列表無合適答案」，仍須正確範例與測試才能談能力。

19.23 的必要精確前置：第一個 Python 區塊中 hidden 的每項 h_i 只由相同 memory、q、該描述及共享權重生成。score_k(H) @ score_q(q) 逐列計分。none 讀 [q, mean(H), max(H), len(H)]；這四項在實數置換下都不變，因此 none 的 logit 不變，其他 logits 只置換。平均、最大值、數量會隨候選加入／刪除而改，讓 none 能接收列表資訊。Deep Sets v3 §3.1 eq(4) 的 commutative maxpool 及等變函數可組合支持對稱彙整的機制；此頁只需要充分性，不主張 universal approximation。當版隨機 CPU 程式的運算關係已執行，沒有正式訓練、語義正確率、GPU或新 checkpoint。

若加位置特徵，例如 z_i=b_i，候選移位但分數留位置，排列關係立即失效。跨候選互動若本身對稱仍可保留等變（19.23 的 none 即例子）；一般互動沒有這個保證。因此正文要求重驗而不是斷言所有互動都失效，範圍正確。

透明數值的手工表達式：D=e²+e⁻¹+1；三項依序 e²/D、e⁻¹/D、1/D。三位小數應為 0.844、0.042、0.114，倒序為 0.114、0.042、0.844。這裡的式子是推導；實際 float32 數值、顯示捨入與容忍差見 execution.json，沒有把手算冒稱執行。
