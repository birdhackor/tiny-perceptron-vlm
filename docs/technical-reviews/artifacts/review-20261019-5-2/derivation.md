# 平均代價與梯度的核對

以下是審閱者的推導；執行結果在同目錄的 `section-run.json` 與 `verification.json`。公式依 PyTorch `CrossEntropyLoss` 的 class-index target 定義；實際讀取的官方版本與少量原文在 `source-excerpts.json`。

## 有效目標的權重

令位置 i 的目標為 y_i、候選分數為 z_i、有效集合為 I={i:y_i≠-100}。本例沒有 class weights，沒有 label smoothing。

p_ic=exp(z_ic)/Σ_j exp(z_ij)，l_i=-ln(p_i,y_i)。總代價 S=Σ_(i∈I) l_i，有效目標數 N=|I|，平均 L=S/N。所以每個有效目標的係數都是 1/N；忽略位置不進分子與分母。此處的 0.2 是五類的均勻機率，並不是從候選字表移除 -100 這個類別後得到的機率；-100 是 target 的哨兵值，五個候選仍全部存在。

本例有效目標數是 4+1=5，故每項係數 1/5。若各篇先平均、再對兩篇平均：第一篇各項係數 (1/4)/2=1/8，第二篇唯一一項係數 1/2。係數的差異成立，即使五項代價剛好一樣而使最後平均數碰巧相等。為檢查這個區別，補充程式另用 sin(arange(40)) 的非均勻分數；正確平均為 1.2532632399390036，各篇平均再平均為 1.178601941894513。

## 零分數的算例與練習

五個分數都是零，故 exp(0)=1，p=1/5=0.2。

- 每項代價 -ln(0.2)=ln(5)=1.6094379124341003。
- 五項總和 5ln(5)=8.047189562170502；平均 ln(5)。
- 六項總和 6ln(5)=9.656627474604601；平均仍為 ln(5)。

以上用自然對數。FP32 執行的總和分別是 8.047189712524414 與 9.656627655029297，與雙精度推導值的絕對差都小於 1e-6；平均 1.6094379425048828，絕對差小於 1e-7。正文的三位小數四捨五入應為 8.047、9.657 與 1.609。機率的 FP32 表示 0.20000000298023224 是浮點近似，未宣稱逐位等於實數 0.2。

改第二筆第二個 target 為 2，會把該位置加入 I。候選軸仍長 5，第一筆四個 True 不變，第二筆由一個 True 變兩個 True。重新建立計算圖後改回 -100，所有原始算例輸出恢復；程式未把已累積的舊 .grad 當成新結果。

## 梯度與拆批

對有效位置，∂L/∂z_ic=(p_ic-1[c=y_i])/N。N=5 時正確類別是 -0.16，其餘各類是 0.04；其絕對值總和為 0.32，大於零。忽略位置則每個候選的梯度均為零。因此本例的 received 表等於有效目標表。這只驗證本例的 logits 梯度，不保證任意模型的所有參數都得到非零梯度；中間 tensor 也不一定自動留存 .grad。本例的 logits 是直接建立且要求梯度的 leaf tensor。

把同一組位置拆成不重疊的集合 I_j，S_j=Σ_(i∈I_j)l_i，N_j=|I_j|，則 L=(Σ_j S_j)/(Σ_j N_j)。分母與參數無關，所以 ∇L=Σ_j∇S_j/(Σ_j N_j)。這解釋為何不能把不等長小份的均值直接等權平均。補充程式分成四個與一個有效目標，按總數五合併，與整批的代價和 logits 梯度一致，最大梯度差為 0。

此等價說的是固定的同一組逐目標代價及其梯度；分拆本身若改變前向運算，例如 batch 統計或隨機遮罩，須另外核對。沒有宣稱所有模型在拆批後都逐位相同，也沒有把等權算例當成模型品質或速度的證據。

## 一次更新與逐題更新

以 w=0、兩個目標 y=1 和 y=3、代價 (w-y)^2 為透明例子，平均代價的梯度是 [(2(w-1))+(2(w-3))]/2=-4。SGD 學習率 0.1，一次更新得到 w=0.4。

逐題各更新一次，先得 w=0-0.1(-2)=0.2；下一題在 w=0.2 計算，梯度為 2(0.2-3)=-5.6，再得 w=0.76。這證明兩個流程一般不同；不宣稱每一種資料都必然得到不同最終參數。執行值是 0.4000000059604645 與 0.7599999904632568。

## 字元與 token 的主張範圍

待審凍結稿的原句是：「token 是模型一次讀寫的一個文字單位，本章例子一個字就是一個 token」。它對本節沿用的五字手工字表成立，但不能概括本章所有例子。

同章凍結稿 `docs/course-review-20261019/freeze-01/sources/5.8.md` 明說：「這個模型把文字拆成 byte（位元組）」；`docs/course-review-20261019/freeze-01/sources/5.9.md` 也把預設字表說成「256 種 byte 值加上 8 個特殊 token」。這兩份凍結稿的全檔 SHA-256 已列在 `verification.json` 的 `source_hashes`。

實作中 `scripts/course_experiments/text.py` 的 `run_real_text` 同時處理 TinyStories 與 Chinese poetry，呼叫 `fit_lm`；`scripts/course_experiments/common.py` 的 `text_examples` 預設用 `ByteTokenizer`。`tiny_perceptron/data.py` 的 `ByteTokenizer.encode` 把每個 UTF-8 byte 轉為一個 ID，`CharTokenizer.encode` 則逐字元處理。補充執行證明「狗」在前者為 [239,147,159] 三個 ID，在後者為 [2] 一個 ID。`text_examples(["狗"])` 有三個 byte 目標加一個 EOS，得到四個有效目標，而非把中文字數當作有效目標數。

最小修正是將「本章例子」改為「本節沿用的五字示例」。其餘 token 的一般定義、有效目標計數、交叉熵公式與本節全部數值都不受這個修正影響。
