## 13.10 比較能不能教一位評分員？

老師比較了許多份作業，不能每天再替模型新寫的每篇回答評分。能不能先教一位評分員，估計老師比較時會偏好哪篇？對「只回數字：1+2=?」，我們仍沿用[13.1](#13.1)的規則：`3`比`1+2等於3。`合適。現在收到這個比較的，不是將來要回答的模型，而是另一個輸出分數的模型。

這位評分員叫**reward model，獎勵模型**。它讀取問題與回答，輸出一個數；分數越高表示它估計這份回答越合適。同題兩篇的分數差，可以轉成「較佳回答勝出」的機率：差0時是0.5，差正2時約0.881。[DPO原論文第3節的公式1–2](https://arxiv.org/pdf/2305.18290v3)先描述這種偏好模型，再介紹DPO如何省去獨立評分網路。前置是[13.2的偏好資料](#13.2)與[1.8的猜錯代價](01.md#1.8)。

```python
import torch
from tiny_perceptron.posttraining import preference_loss

for preferred_score in [0.0, 2.0]:
    chosen = torch.tensor([preferred_score])
    rejected = torch.tensor([0.0])
    gap = chosen - rejected
    win_probability = torch.sigmoid(gap)
    loss = preference_loss(chosen, rejected)
    print("差距", gap.item(), "勝出機率", round(win_probability.item(), 4), "代價", round(loss.item(), 4))
```

輸入是人工設定的兩篇分數，不是模型實測。`chosen`代表較佳回答的分數，`rejected`代表較差回答；`gap`保存較佳分數減較差分數的差距，`gap.item()`取出這個單一數字供打印；`sigmoid`把這個差映成0到1。`preference_loss`取這個勝出機率的負自然log，再平均樣本。兩行依序為機率0.5、代價0.6931，以及機率0.8808、代價0.1269。若標籤說chosen較佳，提高它相對rejected的分數，就能降低代價。

但分數3不代表「有三成正確」或「比1多懂三倍」。給同題所有回答的分數一起加10，上面的差與代價都不變。比較提供的是相對排序訊號，無法直接把每個原始分數當成校準過的正確率。評分員也可能把長回答、固定措辭或禮貌誤當成好答案，所以要用未教過的問題與反例檢查它。

為了把流程縮到可看清的小實驗，本章實際準備四張回答卡：正確的短答、包含算式與結果的一句話、錯誤數字，以及請求補資訊。題目有「只回數字」「用一句話解釋」「購買數量沒給」三種條件；最後一種情境下，直接報總價的前三張都缺少依據，應請補數量。程式已先算好候選文字；評分網路讀的是問題條件與候選編號的數字特徵，不讀中文，也沒有學會加法。偏好標籤來自我們寫定的程式規則，沒有招募真人標注，因此這份實驗不是人類回饋資料的RLHF實證。

實際訓練時先用訓練家族的偏好對更新評分網路，再凍結它，供[13.15](#13.15)的選擇模型使用。數字對調仍屬同一家族，不會把`1+2`與`2+1`分到訓練和最後測試兩邊。評分員是否把未見家族也排對，與它的訓練代價，會分別保存；預寫卡裡有正確答案，不等於模型會自己寫出答案。

練習把rejected分數改成1，先算兩個新差距為−1與1：勝出機率約0.2689與0.7311，代價約1.3133與0.3133，再執行核對。接著將兩個分數一起加10，應得到相同機率與代價。這能讓你分清比較學習與絕對正確率。


## 13.11 分數怎樣讓回答更常出現？

假設模型挑出一張回答卡，評分員給了1分。光收到這個數字，下一次的選擇不會自己改變。訓練還要決定：這次選擇比平常好多少？若這個題型平常只有0.4分，1分算不錯；如果平常都能拿1分，同樣1分就沒有超出預期。

模型依問題給各張回答卡機率，這個「怎樣選」的規則叫**policy，策略**。[1.7](01.md#1.7)已讓我們把候選分數轉成機率；這裡候選是整篇預寫回答，不是下一個文字token。估計這題平常能拿多少分的數字叫**baseline，基準值**。將實際分數減去更新前的基準，就得到**advantage，優勢估計**：正值表示比預期好，負值表示比預期差。

前置是[13.10的評分員](#13.10)與[1.11的參數更新](01.md#1.11)。我們先不用網路，拿兩次作答和相同基準做減法。

```python
import torch
from tiny_perceptron.posttraining import bandit_advantage

rewards = torch.tensor([1.0, 0.0])
old_values = torch.tensor([0.4, 0.4], requires_grad=True)
advantage = bandit_advantage(rewards, old_values)
print("優勢估計", [round(value, 2) for value in advantage.tolist()])
print("更新策略時還追蹤基準梯度嗎", advantage.requires_grad)
```

輸入rewards是兩次作答的分數，old_values是作答時保存的舊基準。函式計算`reward−old_value`，輸出`[0.6,−0.4]`。最後是False：這一輪把優勢當作固定評語，讓策略代價用它來更新回答選擇，不同時沿這份計算去改動基準。基準網路另外用自己的分數預測代價學習，會在[13.14](#13.14)拆開。

更新的直覺是：比預期好的那次選擇，應更常被選；比預期差的，應少一些。[C.7](0C.md#C.7)用REINFORCE展示過「分數×所選動作的log機率」如何形成梯度。這裡接著學PPO的更新方式：仍根據固定的優勢估計，但會比較更新前後的選擇機率，並處理一次改太多的問題。PPO全名是proximal policy optimization，近端策略最佳化；它是一種更新方法，不是新的語言模型架構。

本章的任務一次只選一張卡，隨後就拿分並結束，叫**contextual bandit，依情境做一次選擇的任務**。因此基準可以直接估計這次選擇的預期分數，優勢用上面的減法。真正逐token寫回答是一串相連的選擇：早期的字還會影響後面的前文與分數。它需要另外處理多步回饋與各位置的優勢估計，不能把本節兩個數字的減法原樣當成完整LLM訓練。

reward也不一定是答對1、答錯0。獎勵模型的數字可能為負，還可能加入偏離參考策略的代價；其定義與尺度要保存。這次1與0是人工例子，目的是讓「拿到0也會比預期差」看得清楚，不是本章實跑網路每次都剛好給這兩種分數。

練習只把兩個舊基準都改成0.9，先預測優勢變`[0.1,−0.9]`，再執行核對。兩次回答的評分沒有改，但超出預期的程度變了；最後說明為何不能用advantage的正負直接代替答案正誤。


## 13.12 更新前後回答機率差多少？

某張卡在收集資料時只有20%機率被選中，更新幾次之後變成40%。它在目前策略裡已經是原來兩倍常見。若反覆拿同一批作答當作每次都剛發生，就會忽略這個變化；我們需要保留作答當時的機率，讓更新知道這份樣本來自哪個策略。

前置是[13.11的策略與優勢](#13.11)。收集這批作答時的策略叫**old policy，舊策略**；正在被更新的是目前策略。對同一道題、同一張選中的卡，計算「新機率÷舊機率」，得到**ratio，機率比**。它等於1表示尚未改變，大於1表示這張卡更常見，小於1表示更少見。[PPO原論文第3節公式6–7](https://arxiv.org/pdf/1707.06347)用這個比值建構更新目標。

```python
import torch

old_probability = torch.tensor([0.2, 0.2])
new_probability = torch.tensor([0.4, 0.1])
old_log_probability = old_probability.log().detach()
new_log_probability = new_probability.log()
ratio = (new_log_probability - old_log_probability).exp()
print("更新前後的機率比", [round(value, 4) for value in ratio.tolist()])
```

兩格代表兩次作答各自選中的那張卡，不是一份只有兩張卡且機率需加成1的完整分布。輸入舊機率都是0.2，新機率分別0.4、0.1。自然log相減，再取exp，等於直接相除，因此輸出`[2.0,0.5]`；第一張兩倍常見，第二張一半常見。實作通常保存log機率，避免很小的機率相除；本例的數字則方便手算。

`.detach()`讓這份舊log機率停止被追蹤梯度，在更新時當作常數。它不會替我們保存歷史：收集作答後，仍要保留同一份數值，不能改用新策略重算來替換。本例手填的數字本來就沒有梯度；保留這個呼叫，是展示實際收集策略作答時的寫法。

將ratio乘上固定的優勢，可以形成一個待提高的分數。例如優勢0.6、ratio2，得到1.2；同一正向選擇在目前策略中更常見，這項分數就變大。這不是最終正確率，也不表示拿到兩倍品質，而是這批樣本對更新提供的目標。下一節會在這裡加入限制鼓勵程度的裁切。

舊機率不能每改一次參數就重新用新模型算。如果分母也同步更新，ratio會永遠接近1，失去「相對收集資料那一刻改多少」的用途。一輪作答可以用來做數個更新回合，其old log機率與優勢都要固定；開始下一輪時，才用更新後的策略重新取樣、保存新的old資料。[PPO原論文演算法1](https://arxiv.org/pdf/1707.06347)就是先收集，再做數次更新，最後再收集。

還有一份在[13.4](#13.4)出現的reference，固定參考模型。它跟old policy的用途不同：old對照這一輪開始時的機率；reference對照整個後訓練起點，避免偏離太遠。完成一輪後old會更新，reference仍可以是最初那份SFT副本。把兩個都叫「舊模型」，很容易在程式裡凍結錯對象。

練習只把第一個new_probability改成0.3，先預測比值1.5，第二格仍0.5，再執行核對。接著假設錯誤地用新機率作分母，口頭算會得到什麼：兩格都1，正好把我們要觀察的改變抹掉。
