6.7 UTF-8 邊界核對；2026-10-03，自有推導。
依据 RFC 3629 §3 的位元模板，本例碼點為貓 U+8C93、🙂 U+1F642。
貓：三 byte 模板 1110xxxx 10xxxxxx 10xxxxxx。
第一 byte = 0xE0 | (0x8C93 >> 12) = 0xE8 = 232。
第二 byte = 0x80 | ((0x8C93 >> 6) & 0x3F) = 0xB2 = 178。
第三 byte = 0x80 | (0x8C93 & 0x3F) = 0x93 = 147。
🙂：四 byte 模板 11110xxx 10xxxxxx 10xxxxxx 10xxxxxx。
第一 byte = 0xF0 | (0x1F642 >> 18) = 0xF0 = 240。
第二 byte = 0x80 | ((0x1F642 >> 12) & 0x3F) = 0x9F = 159。
第三 byte = 0x80 | ((0x1F642 >> 6) & 0x3F) = 0x99 = 153。
第四 byte = 0x80 | (0x1F642 & 0x3F) = 0x82 = 130。
因此總序列為 [232,178,147,240,159,153,130]，7 byte。
raw[:1] 只有 E8，需要另兩個後續 byte；strict 報錯，replace 得 U+FFFD。
raw[:3] = E8 B2 93，剛好完整貓。
raw[:4] = E8 B2 93 F0，貓已完整，但 F0 需要另三個後續 byte；replace 得貓後接 U+FFFD。
完整7 byte解碼為貓🙂。
U+FFFD UTF-8為 EF BF BD = [239,191,189]；若用它取代原 E8，後面接 B2 93 已不能組回原碼點。此過程非單射：其他無效前綴也可映成同一替代符號，單靠替代後內容沒有復原原 bytes 的資訊。
可正確解碼的充分條件是合法 UTF-8 序列，不能僅檢查 byte 總數。教材此例的資料來自原本合法字串 encode，前綴缺尾段造成顯示問題。
本節 token 數與字數不一一對應：6.3教學 tokenizer 本次把貓看狗的9 byte合為1 token，也把未見🙂的4 byte分成4 tokens；兩者都可把完整序列拼回。本次 ID/tie-breaking 不作一般固定值主張。
