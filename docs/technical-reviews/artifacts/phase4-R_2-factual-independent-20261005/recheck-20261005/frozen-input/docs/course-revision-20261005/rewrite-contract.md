## 寫正文

逐節閱讀後改寫，不能只用規則把所有「前置」搬到文末就宣稱完成。每節從一個能看懂的小問題與具體材料開始，解釋希望答案、做法與可觀察的關係。沿用例子，一次只增加一個主要變化，術語在使用時解釋；讀者不靠程式、後文或專案背景補出任務。

保留有教學價值的短程式、公式、材料與結果；不要靠刪掉理解所必需的設計來縮短。正文不放開發進度、完整長參數清單、無用失敗流水或一連串前置連結。前置與重做資訊用末尾可展開補充，必要回顧則放在概念真正被使用的位置。原始實報保留原路徑，必要時移長敘述到本輪的參考筆記並附有效連結。

圖解要補足素材、位置、對應或流程，包含答案與編號意義。新圖使用作者專屬 `rewrite-<章號>-<用途>.svg`，避免覆寫其他作者也使用的既有圖。關鍵字建議640寬／28px以上；需要更多空間時垂直排列或拆圖。資料示意不能冒充真實原圖，手算不能冒充訓練，`backward()`不能冒充已更新。
