A.7 的人工 token 預算與資訊條件核對
審閱者：/root/technical_round_coordinator/technical_a_7_fresh
日期：2026-10-03 UTC

1. 固定上下文視窗 C、完整序列化輸入 P、預留新增上限 G。
   保留完整輸入並允許最多 G 個新增位置時，安全規則是 P+G≤C。
   原例 P=20+15+40=75，G=25，總預算75+25=100=C。
   15 已包含當前問題、系統文字與分隔符；若另加格式，必須重新計數。
   本例四個數字是人工 token 數，不是從字串長度估計。

2. dict.values() 取出20、15、40、25，sum 給100。
   history += 30 得 history=50；總預算50+15+40+25=130。
   超出=max(0,130−100)=30；程式只修改 dict 並印預算，無截字或模型呼叫。

3. 唯一練習只把 retrieval 的初值40改10，保留原 history += 30。
   改動後初始輸入20+15+10=45，初始總數70；不是一開始就100。
   增加歷史後50+15+10+25=100，超出=max(0,100−100)=0。
   實跑兩個完整版本的 stdout 分別保存，沒有只測替代算式。

4. 回答上限 G 不是必須產生 G 次。EOS 或其他停止條件可以更早停止。
   若模型原本需要輸出 C2[D1]，允許的前綴只有3個文字 byte 時可只留下 C2[。
   這是可能的引用未完成例子，不是聲稱任何模型會產生該答案，也不是品質測試。

5. 容量與證據足夠是獨立條件。令同長度兩份公告給同店不同地址，
   刪掉區分地址的片段後，可見資料相同、正確答案不同。
   只看剩餘 token 數不能知道哪個答案；摘要若把兩情形映成同一摘要也會失去條件。
   因而裁切／摘要可能失去必要資訊，需要檢查留下的地址、日期、來源與使用者條件。
   日期並非每個任務都必要；此建議適用公告中的任務相關證據，不能推出所有無關日期都必留。

6. 40格人工 retrieval 預算沒有提供實際40個 ID／公告正文，也未標示任務相關位置。
   所以可以算40−10=30格，但無法指定實際哪30格能安全移除。
   練習要求「或說明目前無法判斷」在這個輸入下正確：資訊不足是可成立的答案。

7. KV 是逐層 K/V 張量，不是另寫入的完整文字或受保證的外部事實表。
   重用只對相同前文、權重、位置與注意力條件的計算成立；改前文須重建相應狀態。
   若文字不在可用上下文、K/V 也被丟掉，單有 cache 這種機制不提供取回內容的契約。
   若仍保留對應 K/V，這些計算仍然是模型可見上下文，不能稱已被真正移除。

8. 正式84筆只有12家族×7模式，全部一個 user message，沒有長歷史或摘要。
   input範圍58–94，16新增預留，最大94+16=110≤160（至少餘50位置）。
   84/84 EOS與0/84非法控制ID支持此固定短題的停止與協議行為；
   它們不是跨遠距線索取用的評分，也不能替代長上下文實驗。
