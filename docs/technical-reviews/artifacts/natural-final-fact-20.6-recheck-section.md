## 20.6 圖片裡的中文，怎樣逐字、逐行核對？

購物單第一行寫「牛奶」，第二行寫「麵包」。助理把它讀成「麵包、牛奶」，每個字都在原圖裡，卻改了原本順序。若我們要求按原行讀出，這仍是錯誤。中文OCR要先確認有沒有字，再讀內容，最後核對題目要求的順序；這些檢查不能只靠回答包含正確詞彙。

前置是[11.12字形與文字標籤](11.md#11.12)、[11.13整串正確與CER](11.md#11.13)，以及[11.9縮圖與裁切](11.md#11.9)。OCR是從圖片辨識文字；CER是字符錯誤率，把預測改成參考文字所需的最少插入、刪除與替換次數，除以參考字符總數。整串正確要求完整轉寫符合事先約定；它和「認對多少單字」不是同一項成績。

圖中上方紙張的箭頭表示本例按第一行到第二行的閱讀要求，下方保留正確與錯序兩份字串。箭頭是我們給的順序約定，不能把它當成所有中文文件的通用規則：多欄、直排或招牌可能有別的讀法，應另有標註與測試。

![牛奶在上、麵包在下；把兩行顛倒仍有相同字元，完整轉寫卻不相同](../figures/natural_reading_order.svg)

先觀察只數字元的盲點：

```python
from collections import Counter

reference = "牛奶\n麵包"
predicted = "麵包\n牛奶"
print("同樣字元與數量", Counter(reference) == Counter(predicted))
print("完整字串相同", reference == predicted)
print("參考行序", reference.splitlines())
print("預測行序", predicted.splitlines())
```

`\n`是換行字符，`splitlines()`按換行分成兩筆。Counter數每種字符的次數，兩份文本都含牛、奶、麵、包與一次換行，所以第一行True；它不記位置。第二行False，後兩行分別是牛奶→麵包、麵包→牛奶。這段沒有計算編輯距離，也沒有讀取圖片；它只是證明相同字元袋無法驗證閱讀順序。正式CER需使用能處理漏字、多字與錯位的最少編輯算法。

「沒有中文字」與「看起來有字，但讀不清」也要分開。空白圖片若被轉寫成「你好」，就是多添不存在的內容；參考文字空字串時，CER分母為0，應用另一項有字／無字檢查，而不是除以0或悄悄把那題忽略。看不清的圖片則需要相應標註與回應要求，不能只因模型生成流暢中文便算成功。

原樣抄寫也不能暗中換成慣用字形。圖片寫「臺」，模型寫「台」，日常可能表達同一地方，逐字抄寫卻有一字不同。可以事先約定接受哪些異體字或簡繁轉換，並分別報原樣轉寫與轉換後的比較；不能先看結果，再把所有錯字轉成同一字形提高分數。空格、換行與標點保留哪些，也要在報告中交代。同一張圖問「有沒有字」和「寫了什麼」，可以共用素材，卻有不同的答案要求。

實際圖片大小與視覺位置數同樣要記錄。原圖的小筆畫縮掉後，後續模型只能使用收到的版本；把模糊圖放大，不能保證找回原字。較細的圖片表示可以保留更多證據，是否真能讀對仍要看不同字、位置、字體與留出素材的實測。

這次用自製中文字卡，分別檢查認字、有字／無字，以及按指定順序抄寫。整句、整頁和衍生圖片按來源組別一起留出；訓練與驗證使用Noto Sans TC，正式測試改用Noto Serif TC。原先9題轉寫、3題有字／無字的驗證，原始與微調模型都全對，顯示底座已有讀取這些短字卡的能力，該驗證沒有看出微調增益。

版本在正式測試前已確定。測試共有12題單行短句、6題讀序，以及6題有字／無字。讀序含3題橫排由上到下、3題直排由右欄到左欄，每欄由上到下。逐題比較原始輸出，結果如下：

| 合成字卡的正式測試 | 原始模型 | 已選微調模型 |
| --- | ---: | ---: |
| 單行短句原樣整串相同 | 11／12 | 12／12 |
| 讀序題原樣整串相同 | 6／6 | 6／6 |
| 全部轉寫原樣整串相同 | 17／18 | 18／18 |
| 原樣CER：編輯次數／參考字符數 | 1／190≈0.53% | 0／190＝0% |
| 有字／無字判斷 | 6／6 | 6／6 |

190個參考字符包括短句117字符、讀序73字符，其中有6次換行。有字／無字另計3張有字、3張無字，不放進CER分母。比較前先約定一種字形整理規則，叫NFKC：它把某些相容字形整理成同一寫法，例如全形「Ａ」變成「A」，但不會把「臺」改成「台」。這次短句忽略空白，讀序保留換行；這次按該規約比較，整串與CER結果相同。若連讀序換行也全部移除，分母會變184，便無法用這個比較核對換行結構。兩個版本各24份回答都以EOS結束，沒有截斷。

唯一的原始模型錯字很適合說明「看懂意思」和「原樣抄寫」的差別：

```text
參考答案：臺灣學生在操場散步。
原始模型：台灣學生在操場散步。
微調模型：臺灣學生在操場散步。
```

原始模型只需替換第一字，就能變成參考答案，所以這題CER是1／10＝10%。「臺」與「台」在日常用語可能指同一地方，原樣抄寫仍有一字不同；NFKC也沒有把兩字合併。我們保留這個差異，沒有暗中做簡繁或異體字轉換。這份小測試能支持已選模型完成這些短字卡要求，不能從18題全對推成長文件、小字招牌或所有繁體中文都能讀對。

真實街景還會遇到反光、斜拍、遮擋和遠處小字，因此另固定10個CC-OCR外部觀察案例：6張街道、商店或工廠照片，4張含實物照片的商品或分享頁面。它們全部排除於訓練、驗證及版本選擇，主要使用簡體中文，不能代表完整的繁體中文街景能力。

| 10張自然影像的外部觀察 | 原始模型 | 已選微調模型 |
| --- | ---: | ---: |
| 原樣／規約整串相同 | 1／10；1／10 | 1／10；1／10 |
| 原樣CER | 1187／484≈245.25% | 729／484≈150.62% |
| 規約CER：NFKC後移除空白 | 953／431≈221.11% | 567／431≈131.55% |
| EOS結束 | 7／10 | 9／10 |
| 達384 token上限而截斷 | 3／10 | 1／10 |

這裡原始參考答案共484字符，按外部規約做NFKC並移除全部空格、換行等空白字符後為431字符；所有多餘輸出、重複內容和截斷前的文字都計入分數。CER是編輯次數除以參考字符數，多添的字可以比參考全文還長，所以CER可以超過100%。兩版本唯一整串相同的題目都是「汇一机动车检测中心」，也都以EOS結束；其他題目即使有EOS，也不能因此計為整串正確。已選模型的總CER較低，但兩個版本都只達到1／10整串相同，字卡成功沒有延伸成這組自然中文影像上的可靠OCR能力。

藥局圖提供第二個容易核對的例子。上游答案是3字「万民药」，已選模型的完整回答是4字「万民药房」，相較上游多了「房」，CER為1／3。原始模型則反覆輸出同一行77次；以下只展示開頭3行，完整答案仍原樣保存並用於計分：

```text
万民药房
万民药房
万民药房
```

原始模型最後達384 token上限，沒有EOS；去空白後是308字符，相較3字參考答案需305次編輯。讀到了「万民药」並不足以完成轉寫，反覆生成與停止失敗仍是這次的實際問題。已選模型在這題停止了，但它在另一張密集商品頁仍反覆生成「ABCD」126行，同樣到達上限；較少截斷不等於每一題都能正確讀完。

上游答案也要一起核對：這張藥局圖的上游答案只列大招牌「万民药」，沒有列完下方海報的小字，因此與上游相同不能當作已完整抄完照片，額外文字是否可見也要查看原圖。商品頁的事前來源註記指出末字可讀為「刺绣」，原答案卻寫「刺袖」；兩版本這次都輸出「刺绣」，這一處會被字串比較扣分，但完整回答還有其他差異，不能把整題錯誤都歸給上游錯字。我們保留原答案與事前註記，分別報字串差異與需圖像核對的地方。部分商品頁只有攤平後的文字串，沒有各區塊的讀序標註，字串成績也不能單獨驗證全部版面讀序。

逐題完整原文、token與停止旗標見[正式測試回答](../../docs/natural-assistant/evidence/final/generations.json)及[外部觀察回答](../../docs/natural-assistant/evidence/external-ocr/generations.json)；[正式測試設定](../../docs/natural-assistant/evidence/final/execution.json)與[外部實測設定](../../docs/natural-assistant/evidence/external-ocr/execution.json)記錄影像像素上限524,288及回答上限384 token，這輪沒有另做高解析度對照。[資料說明](../../docs/natural-assistant/DATA.md)、[評分規約](../../docs/natural-assistant/rubric.json)及[外部來源核對記錄](../../docs/natural-assistant/evidence/external-ocr/external-evidence.json)保留留出方式、原圖身分與事前上游答案註記。

練習只把`predicted`改成「牛奶\n麵包」，先預測四項都與參考一致，再執行。接著把它改成「牛奶麵包」，說明字符內容和換行結構改了哪一項；是否接受這份輸出，要由題目的轉寫規格決定，不能靠Counter替讀者選答案。
