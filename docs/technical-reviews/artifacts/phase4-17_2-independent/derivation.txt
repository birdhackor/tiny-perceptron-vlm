17.2 independent exact arithmetic inspection

Assume scale s > 0 and zero point 0. The code implements
q = clamp(round(x/s), -127, 127); restored = s*q.
The dimensionless integer code q indexes a grid; s has units of original
value per code step. Each input element is transformed independently.

s=0.5:
x                 -0.7      0.2      0.7      1.2
x/s               -1.4      0.4      1.4      2.4
nearest q           -1        0        1        2
s*q               -0.5        0      0.5      1.0
x-s*q             -0.2      0.2      0.2      0.2

s=0.25:
x/s               -2.8      0.8      2.8      4.8
nearest q           -3        1        3        5
s*q              -0.75     0.25     0.75     1.25
x-s*q              0.05    -0.05    -0.05    -0.05
The exercise's 'error about 0.05' describes the absolute magnitude.

For nearest integer n to a real y, |y-n| <= 1/2. When clamping has
not changed n, |x-s*n| = s*|x/s-n| <= s/2. A tie can choose either
nearest integer without changing this bound; PyTorch chooses the even one.
For s=0.5 the maximum is 0.25; for s=0.25 it is 0.125.
When x=100 and s=0.5, unclipped q=200 but clipped q=127;
restored=63.5 and absolute error=36.5 > 0.25.

Signed int8 has codes -128..127, 256 distinct values. This example chooses
-127..127, 255 codes: 127 negative steps, zero, and 127 positive steps.
Maximum positive representable values: 127*0.5=63.5 and 127*0.25=31.75.
Smaller spacing reduces the maximum nearest-grid rounding error but also
reduces the covered range when the set of codes is held fixed.

0.51, 0.70 and 0.74 all map to q=1 at s=0.5 and restore to 0.5.
Thus the map is many-to-one; q and s do not retain the original residual.

0.2=1/5 has no finite binary expansion. Rounding a float32 value to four
decimal places still returns float32, not a formatted decimal string;
tolist converts that stored number to a Python scalar. The observed
0.20000000298023224 differs from exact 0.2 by about 2.98e-9, distinct
from the approximately 0.2 error caused by this coarse quantization.

Arithmetic tables, integer codes, and dyadic restored values are exact.
CPU comparisons of decimal float32 errors use absolute tolerance 1e-7,
zero relative tolerance. The dense in-range check uses 1e-6 only for
floating representation; the bound is established by the derivation,
not by treating a finite sample sweep as a proof.
