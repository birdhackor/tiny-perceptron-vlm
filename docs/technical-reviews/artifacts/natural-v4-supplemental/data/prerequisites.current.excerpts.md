## 20.4 怎樣的練習，才能教到我們想要的能力？

如果想讓學生回答「誰站在門口」，只發一份英文看圖作文，學生不一定練過這種中文短問答。資料量增加之前，要先確認每道練習真的在教目標能力。模型學到的是圖片、請求與示範回答之間的關聯，不會因為資料夾叫「聊天」，就自動知道應該怎麼聊天。

先連回[11.14的整圖關係](11.md#11.14)和[12.13的聽寫與回答](12.md#12.13)。自然照片需要物件、可見動作與關係的示範；讀字需要圖片與對應文字；聊天需要完整請求與合理回應。錄音與逐字稿則教或檢查「他說了什麼」，不是「我們應怎樣回答他」。

例如下面這張DOCCI訓練照片，兩隻貓在書桌上看螢幕。先親眼確認可見的物件與姿勢，再寫出示範回答。

![DOCCI訓練照片：兩隻貓在書桌上看黃色電腦螢幕，左貓抬起前腳](../figures/natural-v4-training-cat.svg)

照片由Jason Baldridge and family創作，DOCCI透過Google LLC以[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)提供；[固定版本原圖](https://storage.googleapis.com/docci/thumbnails/train_01827.jpg?generation=1713028329088595)未裁切或改動。它可以提供兩種互補練習：

| 練習請求 | 示範回答 | 這題教什麼 |
| --- | --- | --- |
| 請用一至兩句繁體中文描述主要內容。 | 兩隻貓在書桌上看著黃色的電腦螢幕；左邊的貓抬起一隻前腳。 | 把物件與可見姿勢連成短描述。 |
| 桌上有幾隻貓？ | 兩隻貓。 | 直接回答畫面中的數量。 |

這兩份回答是本課AI助理實際看圖、讀原始人工英文描述後寫的繁中標註，並非DOCCI官方人工中文答案。原圖、原始描述與修改來源一起保存。照片是訓練示範，用它解釋題型，不能把它另報成未見過照片的能力。

本章的資料由用途來安排：

| 來源 | 使用方式 | 授權與標註要點 |
| --- | --- | --- |
| DOCCI自然照片 | 短場景描述與可見事實問答。 | 圖片與原描述採CC BY 4.0；繁中題目與回答是本課改寫。 |
| NVIDIA合成OCR（圖片文字辨識）文件 | 從文件取文字區域，配對原轉寫。 | 資料集採CC BY 4.0；它是合成文件，不稱真人街拍。 |

| OpenAssistant中文對話 | 練直接回應與保留對話條件。 | 資料集採Apache-2.0；從同一段開場對話延伸的不同回覆分支，合稱一棵對話樹，視為同一家族。 |
| FLEURS真人朗讀句子 | 只檢查語音辨識轉寫。 | 語料採CC BY 4.0；沒有來源助手答案，不拿它計聊天成功率。 |

合成資料便於控制字體、位置與答案，真實照片提供反光、斜拍和複雜背景。兩者分工不同。對話也一樣：把同一句問答複製三次，可以增加它在訓練中出現的比重，卻沒有新增三種情境。真正的多樣性來自不同請求、答案與需要保留的條件。

每份資料還保存來源、授權、修改與用途。公開可下載，不等於可以任意重散佈；這也是讀者取得與重做資料時需要知道的事。完整清單與取得方式見[本章資料說明](../../docs/natural-assistant/v4/DATA.md)。練習為「讀出店名」挑一種最直接的示範，再指出為什麼只提供「這是一間商店」的圖片分類答案不夠。題型對上用途後，下一步是把真正的新題留出來。

## 20.5 換個問法，為什麼仍可能是同一道舊題？

剛才那張貓照片，問數量和問姿勢是兩道問題，卻仍是同一張照片。如果一題拿來訓練，另一題算成測試，模型可能已經認熟那張桌子與兩隻貓。我們需要先分素材，再生題目。

[5.12](05.md#5.12)把這種關聯叫資料家族：同一份來源的裁切、換問法、翻譯或其他變體，不應各自抽籤到不同考卷。本章使用的DOCCI照片資料集提供公開的視覺相似群組：群內圖片看起來相近，但不等於已核實同一拍攝場次，也不保證不同群來自不同攝影者。聊天樹則有共享前文的多個分支。切分單位要跟真正會共享線索的來源相符。

![同一來源家族的原圖、裁切與不同題目一起留在同一側，另一家族另作留出](../figures/natural-v4-family-crops.svg)

用四張手寫卡片看一個最小例子：

```python
records = [
    {"family": "貓照片A", "split": "train", "question": "有幾隻貓？"},
    {"family": "貓照片A", "split": "train", "question": "哪隻貓抬起前腳？"},
    {"family": "招牌照片B", "split": "test", "question": "招牌寫什麼？"},
    {"family": "招牌照片B", "split": "test", "question": "有沒有中文字？"},
]
families = {name: {row["family"] for row in records if row["split"] == name} for name in ["train", "test"]}
print("訓練家族", sorted(families["train"]))
print("測試家族", sorted(families["test"]))
print("跨份重疊", sorted(families["train"] & families["test"]))
```

每筆卡片有家族、用途與問題。建立`families`時，外層先後取`train`與`test`作為字典的鍵；內層用`if`挑出對應用途的卡片，再收集它們的`family`欄位。集合把重複家族合成一項，`&`取兩邊共同的家族，所以最後是空清單。這只核對手寫卡片；正式資料另外保存來源ID與檔案指紋，防止同一圖片只換名字便跨到另一側。

訓練題用來更新權重，驗證題用來選設定，最後測試則留到版本固定以後才打開。已公開、看過答案的舊題可以作回歸檢查，觀察以前能力是否保留；它們不再是新一輪未看過的最後考卷。這裡的公開底座，是模型製作者已訓練好、提供大家使用的模型；製作者就是我們說的上游。本課在底座上繼續訓練稱為微調，再用驗證結果選定交付版本。家族切分隔開的是本課的訓練、驗證與最後測試；製作者先前可能用過這些公開素材，因此不能宣稱模型從未見過。

練習把第二張卡的`split`改成`test`。最後就會列出貓照片A，即使兩題文字不同。修正是把整個家族一起分配，不是替第二張卡改一個新家族名字。保留好這條邊界，接著才能談模型究竟改了誰。

## 20.8 訓練跑完後，怎麼決定可以交付哪個版本？

練習做完，可以檢查你寫過多少題；是否學會，仍需要一份沒用來背答案的考卷。模型訓練也有兩種證據：指定權重真的收到梯度並改變，以及新題回答符合用途。兩者缺一，都不能只說「跑完了，所以變強」。

前置是[5.10的驗證與最後成績](05.md#5.10)與上一節的答案位置。先按固定資料、底座和配方更新，再用驗證題決定是否保留設定。選定後，把權重、資料與生成設定固定，才做最後測試。像練習考用來調整讀書方法，正式考則用來瞭解選定方法的表現。

本章重訓從固定圖文底座建立[20.6介紹的LoRA小修正](20.md#20.6)，使用照片問答、中文讀字與聊天示範共同更新。這不是把只供推論的公開小包當作完整續訓狀態。訓練配方寫清楚更新器、步數、資料順序、圖片與文字預算；每步核對代價與梯度是否為有限值，並保存完成進度。可執行的整套指令放在[LoRA訓練指引](../../docs/natural-assistant/v4/TRAINING.md)，讀本節不需先租GPU。

完整訓練在第1,039與2,077次更新後各保存一份候選，再與原底座使用同一份驗證卷比較。保存中途與完成版，是讓驗證決定交付哪個版本，不能預設練得最久的一定最好。

驗證要照顧不同用途。只看讀字成功，也許漏掉照片回答變得愛添細節；只看文字聊天，也許沒發現圖片問題不再使用畫面。先約定各項如何判分、可接受多少退步，再比較同一底座與候選修正。題目、圖片處理與生成長度要相同，才知道比較了什麼。

本章先約定三個接受修正的條件：回答都按規則完整結束、各用途符合能力保留門檻，以及約定的綜合分數嚴格高於底座。只進步其中一項，還不能用它替整位助理加分。ASR在三個圖文候選間保持相同版本與同一份實際逐字稿，避免把聽寫元件的改變記到LoRA頭上。

這次驗證提供一個有用的取捨。以1,039步修正為例：

| 同一份驗證題的用途 | 原底座 | 1,039步修正 |
| --- | ---: | ---: |
| 照片短描述 | 16／28 | 23／28 |
| 照片可見事實問答 | 31／56 | 53／56 |
| 真人問句：直接給正確逐字稿後聊天 | 4／4 | 2／4 |
| 同組問句：用真正ASR逐字稿後聊天 | 3／4 | 2／4 |

照片的兩項成績改善，聊天的兩條路卻退步。連正確逐字稿直接交給模型都變差，這個問題便不能全歸到聽寫同學身上。語音聊天的保留門檻要求兩條路各自不低於底座，這份修正沒有通過。這些分母很小，也有同圖多問，不能把改善或退步幅度當成所有自然情境的估計。

2,077步修正同樣沒有通過語音聊天的保留門檻。兩份修正還各有三份回答用滿384個新token，沒有產生正常結束符號。token是模型逐步生成的文字單位，不一定等於一個中文字；達到這個生成上限仍未結束，便未通過完整性要求。約定的綜合分數也都沒有勝過底座。本版依這份驗證[選定原底座](../../docs/natural-assistant/v4/selection.json)，保留相同的Whisper-turbo語音入口，不加LoRA。完整判準與其他分項可查[驗證得分紀錄](../../docs/natural-assistant/evidence/v4-runtime/validation-37219466611/blind-review/scored/scores.json)。

保留底座仍有局限：它在驗證中也有答錯與未完整結束的回答。這個選擇是按規則保留原版，沒有證明助理已全面可靠。接著要固定這份配置，再用尚未參與選版的最後題目檢查；正式能力與適用範圍統一放在[20.13](20.md#20.13)。

訓練代價是示範答案的預測成本，不是直接替模型讀過整段回答的裁判。模型可能更偏好某些短示範，卻在開放描述時重複或添出沒有的東西。因此驗證會保留完整生成與停止原因；正常結束是完成條件，內容正確還要另外核對。

最後測試出現的錯誤可以幫助下一版設計，但這時已不能再用它選本版。如果要依錯題重訓，就另存一個實驗版本，重新安排新的最後考卷。練習只看上表兩條聊天路線：為什麼保留正確逐字稿那一列，有助於分清聽寫與回答的責任？再說明單靠照片高分，為何不足以接受這份修正。下面幾節將提供各用途的判尺。

## 20.9 回答出現正確名詞，就算看懂照片了嗎？

一張圖有「人、腳踏車」，可能是有人騎車，也可能是人站在車旁。答出這兩個名詞，還沒有回答他在做什麼。描述照片需要把看得見的物件、動作與關係接起來，再確認沒有多添畫面外的故事。

先讀[11.14](11.md#11.14)的整圖關係。物件回答「有什麼」，動作回答「正在做什麼」，關係回答「在哪裡、與誰相連」。同一張圖可以問不同項目；評分應跟著問題的主要要求，不用一個名詞命中替所有題加分。

![兩幅人工場景都有一人一車，人物姿勢與人車關係不同](../figures/natural_photo_evidence.svg)

先用兩張手寫回答卡，隔離物件與活動的差別：

```python
truth = {"objects": {"人", "腳踏車"}, "activity": "騎車"}
cards = [
    {"objects": {"人", "腳踏車"}, "activity": "騎車"},
    {"objects": {"人", "腳踏車"}, "activity": "站在車旁"},
]
for index, card in enumerate(cards):
    print("卡", index, "物件吻合", card["objects"] == truth["objects"])
    print("活動符合本題", card["activity"] == truth["activity"])
```

兩張卡的物件集合都相同，活動只有第一張符合。集合不看名詞順序；本例的活動標註則由我們先寫好，沒有讓程式讀圖。正式自然語言可以用不同措辭表達同一意思，需要按可見事實判斷，不能要求每句都與單一參考描述逐字相同。

回到[20.4訓練示範](20.md#20.4)中的兩隻貓：問「有幾隻」時，「兩隻」已直接完成。問「左邊那隻在做什麼」時，要核對抬前腳等姿勢；若又說牠正在等主人回家，那是照片沒有支持的意圖。回答更長，不會自動更完整。先看所問事實，再查新增細節，是讀整段回答的順序。

還可以保持問題與先前對話（歷史）相同，只換另一張圖，核對答案是否隨畫面改變。換的是實際像素，不把物件名稱偷偷塞進文字。不過少量換圖只能支持那組對照；廣泛能力仍看留出照片的分項檢查；這些照片未參與本課訓練，預留來檢查回答，摘要見[20.13](20.md#20.13)。

練習替「有人拿著杯子」寫一題物件問題與一題關係問題，再各寫一個畫面不支持的猜測。你已能檢查照片描述，下一節把要求收緊到圖片上的每一個字。

## 20.10 讀懂意思，和逐字抄寫，是同一項能力嗎？

告示寫「今天去臺北」，助理回「今天去台北」。日常對話可能理解了同一地點；如果要求原樣抄寫，「臺」與「台」仍然不同。OCR是從圖片辨識文字，評分要先決定我們要的是意思，還是圖片裡真正的字形。

前置是[11.16的逐字核對](11.md#11.16)。整串相同是一把很嚴格的尺，只要有一字多、少或不同就不相同。字元錯誤率CER則多告訴我們改了多少：把預測改成參考文字，最少需要幾次插入、刪除或替換，再除以參考字元數。

```python
from tiny_perceptron.natural_concepts import text_error_report

report = text_error_report("今天去臺北", "今天去台北")
print("完整相同", report["exact"])
print("最少編輯次數", report["edits"])
print("參考字數", report["reference_characters"])
print("CER", report["cer"])
```

輸出是False、1、5與0.2。第一個字串是參考，第二個是預測；只需一次替換，所以是1／5。這裡按Unicode字元計，不按UTF-8儲存bytes計。預測少了最後的「北」，分母仍是參考的5字，不能因漏字改小分母。

文字比較前，有時會整理全形字或空白，這叫正規化。例如NFKC能把全形「Ａ」整理成「A」，卻不把「臺」改成「台」。是否接受異體字、換簡繁、忽略標點，要在看結果前指定；原樣結果也應保留。逐字任務中，即使要求用繁中解釋，圖片寫簡體的部分仍應原樣轉寫，不自行改字。

「沒有字」也需要題目。空白圖若被補成一句熟悉的中文，是多添了不存在的內容。參考空字串時CER沒有可除的字數，因此有字／無字另測；看見模糊字影但讀不清，則是第三種情況，不等於圖片完全沒字。

合成文件讓我們控制字體與答案，真實招牌另外有斜拍、反光與背景。要分開列結果，才能知道模型會讀哪種材料；一張裁切上的短行也不等於完整大頁。新成品的範圍留在[能力卡](20.md#20.13)。練習把預測改成「今天去臺」，再指出刪掉哪一字、CER分母是什麼。字元內容核對完，下一節還有順序。

## 20.11 字都認對，為什麼整頁仍可能讀錯？

購物單第一行是「牛奶」，第二行是「麵包」。如果助理先讀麵包，字沒有少，順序卻變了。完整轉寫除了認字，還需要保留題目指定的行與版面次序。

[11.16](11.md#11.16)已分清字元與字序。這裡先用橫排兩行，約定由上往下、每行由左到右。直排、多欄或幾塊分散招牌可能有別的讀法；這些規則應在資料標註中說清楚，不交給評分者看完答案後臨時決定。

![上行牛奶、下行麵包；交換兩行保留相同字元，卻不是相同完整轉寫](../figures/natural_reading_order.svg)

```python
from collections import Counter

reference = "牛奶\n麵包"
predicted = "麵包\n牛奶"
print("字元種類與數量相同", Counter(reference) == Counter(predicted))
print("完整字串相同", reference == predicted)
print("參考行序", reference.splitlines())
print("預測行序", predicted.splitlines())
```

`Counter`只數每種字元出現幾次，也包括換行，所以第一行True；它像把兩份購物單都倒進同一個字袋，丟掉了排列。完整字串比較是False。`\n`表示換行，`splitlines()`把文字按行分開，後兩項清楚列出上下交換。

移除全部空白可以方便某些文字內容比較，卻也移除了換行結構。這時就不能只靠「整理後一樣」宣稱讀序完整。對長頁面，最好保存文字區域、各區域內容與閱讀順序；只有一串攤平後的答案，未必足以評完整佈局。

圖片裁切像拿放大鏡：容易看清小字，但如果忘了原位置，就不知道這行原本在頁首還是頁尾。訓練文字區域與訓練整頁版面是不同用途。完整成品會在[20.13的能力卡](20.md#20.13)記錄各項能力與限制，把這兩項分開；有圖片文字辨識（OCR）分數，也不能自動打勾所有多欄文件。

練習把`predicted`改成「牛奶麵包」。哪些字仍正確，哪個結構消失？再想一張左右兩欄的單據，應先沿欄讀，還是每一行跨兩欄讀？答案需要版面規約。下一節再把「先後相接」的觀念帶到語音與聊天。

## 20.12 助理答錯時，怎麼分清聽錯與回錯？

你說「請推薦不辣的晚餐」，辨識器漏掉「不」，助理就收到相反條件。聊天模型可能很認真推薦辣菜，卻沒有回答你的原需求。要修好這個系統，先找出紙條在哪一棒被改了。

前置是[12.13的聽寫與回答](12.md#12.13)及[20.1的共同入口](20.md#20.1)。ASR的任務是寫出聽到的話，聊天的任務是依收到的話回應。把正確逐字稿直接送進聊天，可以檢查第二站；把真ASR結果送進相同聊天，才是完整語音路線。

![同一問題分為正確文字對照與真錄音路線；ASR逐字稿和兩份回答分開核對](../figures/natural-v4-asr-two-routes.svg)

先用手寫漏字例子看影響。字元錯誤率CER的算法是：把辨識文字改回原話，最少需要幾次插字、刪字或換字，再除以原話的字元數。例如補回漏掉的「不」，只需要一次插字。這裡每個中文字與句號各算一個字元，不移除標點。

```python
from tiny_perceptron.natural_concepts import text_error_report

reference = "請推薦不辣的晚餐。"
recognized = "請推薦辣的晚餐。"
report = text_error_report(reference, recognized)
print("最少編輯次數", report["edits"])
print("參考字數", report["reference_characters"])
print("CER百分比", round(report["cer"] * 100, 1))
print("兩份問題相同", reference == recognized)
```

`report`保存核對結果：`edits`是最少編輯次數，`reference_characters`是參考字元數，`cer`是前者除以後者。這題只漏一個字，原話含句號共9個字元，1÷9×100約為11.1%，所以輸出1、9、11.1與False。這個CER描述轉寫的字元差距，不能代替需求是否仍相同：一個否定詞就能反轉限制。程式沒有播放錄音，也沒有請聊天模型生成；它隔離的是中間文字改動。

正式檢查留下三項：ASR逐字稿與來源原話的差距，正確文字輸入時的聊天回應，以及真ASR輸入時的聊天回應。兩路使用相同歷史、問題要求與照片。若正確文字已答不好，問題不全在ASR；若文字能答、辨識後不能答，再查看關鍵字是否被聽錯。

本課用真人朗讀的問句檢查這條路，例如詢問如何加強溝通。來源給錄音與逐字稿；本課在生成回答前，先訂好什麼樣的回應才算符合問句要求。這些是人讀出來的問句，不是自然錄下的即興聊天，仍需另外測口音、噪聲、多人重疊與長對話。ASR採現成權重時，這份檢查也不是本課重新訓練辨識器的證據。

使用者可以在介面改正逐字稿，再送出。這是明確的人工操作；評估原始語音路線時，仍保存更正前辨識，不偷偷換成來源真值。練習把「不」補回，確認CER變0，再想：即使聽寫完全正確，聊天還要滿足哪些條件？[20.13的能力卡](20.md#20.13)記錄各項能力與限制，會把兩站的結果分開回答。
