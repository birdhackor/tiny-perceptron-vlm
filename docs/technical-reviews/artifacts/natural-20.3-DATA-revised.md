# 自然圖片、中文文字與語音：這一版用了哪些資料？

這一版要讓同一個聊天核心接收文字、照片，以及經過語音辨識的文字。為了讓學生能實際跑完流程，我們準備的是小型、固定版本的示範包：144 張自然照片、139 張自製中文文字圖片、42 段真人華語錄音，以及少量自己編寫的聊天範例。

這些資料是模型練習與考試的題目，模型權重則是練習之後改變的參數，兩者要分開保存。完整版使用已有能力的預訓練元件，再做小量調整；這些樣本不足以從零教會模型認識世界、閱讀中文或辨識華語。模型表現得好，也不能全部歸功於我們新增的這一小包資料。

## 先分清楚：練習題、模擬考與正式考試

`train` 是訓練時可以看答案的練習題；`validation` 是用來選擇設定與檢查過度背誦的模擬考；`test` 是設定確定後才使用的正式考試。正式考試的答案不能拿回去訓練，也不能看完考試結果後挑一個分數較高的版本，再把同一份考卷稱為公平的測試。

同一張照片可能有三個問題。如果把其中一題放進訓練、另一題放進測試，模型早已看過那張照片，就像先讀過文章再考同一篇閱讀測驗。因此，我們按照片、完整文字頁面或錄音句子的來源身分分組；同一組的問題與衍生版本留在同一個切分中。

目前的[整合清單](manifest.json)逐筆記錄題目、答案、切分、圖片或音訊位置，以及來源。以下數字是「問題或紀錄的筆數」，不是不同檔案的數量。

| 題目種類 | 訓練 | 驗證 | 測試 | 實際在練習什麼 |
| --- | ---: | ---: | ---: | --- |
| 一輪文字聊天 | 30 | 3 | 4 | 回答簡單提問與承接情緒 |
| 多輪文字聊天 | 2 | 1 | 2 | 記住前面說過的名字、飲食限制等資訊 |
| 自然照片問答 | 120 | 36 | 36 | 描述場景，指出動作與物件關係 |
| 中文文字辨識 | 96 | 9 | 18 | 抄寫文字與依序讀出多行文字 |
| 是否有文字 | 24 | 3 | 6 | 分辨有字與沒有字的圖片 |
| **上述有助手答案的合計** | **272** | **52** | **66** | 用於聊天與圖文流程 |
| 另列的真人語音紀錄 | 24 | 6 | 12 | 檢查語音辨識，再把辨識結果送進聊天核心 |

30 筆一輪聊天訓練資料，其實是 **10 個自己編寫的範例各重複三次**。這是為了調整它們在混合訓練中的比例，不是增加了 30 種不同的情境。多輪聊天另外保留真正的對話歷史，訓練目標是最後一輪助手應該如何回答。[產生整合資料的程式](../../scripts/build_natural_assets.py)公開了這些範例。

語音紀錄另放在 `audio_rows`，因為它們有真人說話的逐字稿，**沒有助手接下來應該說什麼的標準答案**。這一版不拿它們重新訓練語音辨識器，也不把它們算進上述 272 筆聊天與圖文訓練答案。

## 自然照片：從「有什麼」走到「正在做什麼」

照片取自 Google 公開的 [DOCCI](https://google.github.io/docci/)（[論文](https://arxiv.org/abs/2404.19753)）。原始資料附有人工寫成的英文詳細描述，涵蓋物件、位置、動作與關係。例如，「有一隻狗」只指出物件；「狗躺在窗邊」還需要看懂狗的姿勢，以及狗和窗戶的相對位置。

我們使用 120 張官方 `train` 照片作為訓練。每張照片配一個英文描述問題，答案取自原始人工描述的開頭片段。截取程式在句末標點後緊接空白時切開，多數片段是一句；句末標點後若還有引號，就可能帶入下一句。實際的 `train_03125` 描述含有 `STOP."`，切句後也保留了下一句關於邊框顏色的描述。因此，本課不把每筆都稱為只有一個完整句子。這些訓練答案沒有用另一個模型臨時生成，也沒有把原描述擅自翻譯成中文。

驗證使用 12 張官方 `qual_dev` 照片，測試使用 12 張官方 `test` 照片。每張留出的照片有三題：一題用中文詢問整體場景，兩題詢問可核對的短事實，因此各有 36 筆問答。新增問題與參考答案由 AI 助手實際查看照片、對照原始人工描述後編寫；它們不是 DOCCI 官方另行提供的人工中文標註。問題在這一輪模型推論前已固定。

整體場景題保留原始模型輸出，交由閱讀者或獨立評閱者核對。短事實題使用事先列好的可接受詞組，例如答案需要同時提到物件和它正在做的動作。詞組檢查只是有限的評分尺：它可能漏掉意思正確的另一種說法，也可能被一個碰巧含有關鍵字的錯誤句子騙過。不能把它的通過率直接叫作「完整圖片理解成功率」。

這一包下載的是 DOCCI 發布者提供的 144 張網站縮圖，並保留所選照片的原始完整描述與署名資料；沒有下載約 7.59 GB 的完整原圖 ZIP。縮圖對觀察大場景較方便，但很小的文字、遠處物件與細微動作可能需要更高解析度，不能把縮圖沒有顯示的細節當作模型應該看見的資訊。

我們核對了切分之間的完全相同檔案與解碼後相同像素，沒有發現這類跨切分重複。然而，相近的照片、同一隻動物或相似拍攝場景仍可能分散在官方切分中；預訓練模型是否曾看過相關照片也無法證明。因此，這份小考卷適合展示與檢查流程，不能證明模型能處理所有未見過的自然照片。

## 中文文字圖片：先控制難度，再面對真實照片

中文練習圖片由本教材自行產生，共 139 張，包含短句、多行文字、閱讀順序，以及沒有文字的背景。部分圖片同時回答「有沒有字？」和「字是什麼？」，所以共有 156 筆問題：訓練 120、驗證 12、測試 24。

其中，抄寫與閱讀順序題合計 96／9／18 筆，是否有字題為 24／3／6 筆。訓練和驗證使用 Noto Sans TC 字型，測試使用 Noto Serif TC，並把整句、整頁與衍生圖片一起切分。這樣能檢查模型是否只是記住某一句或某一種字形。部分測試中文字也沒有出現在這個小訓練包裡；若模型讀得出來，它原先的預訓練能力可能扮演重要角色。

人工產生的圖片適合教學，因為我們知道畫上去的字是什麼，也能一次改變一個因素，例如字型、背景或閱讀順序。真實街景還會遇到反光、斜拍、遮擋、招牌與小字混雜。合成圖片上的成績，不能直接當作真實中文街景的能力證明。

因此，我們另外固定了 [10 個 CC-OCR 外部觀察案例](external-ocr.json)：6 張街道、商店或工廠照片，以及 4 張包含真人照片的商品或分享頁面。它們主要使用簡體中文，不能代表完整的繁體中文 OCR 測試。這 10 張全部只用於額外檢查，不進入訓練、驗證或版本選擇。

這組案例也提醒我們：參考答案不一定完美。有一張藥局照片的原始答案只列出大招牌「万民药」，沒有列完下方海報的小字；另一張商品頁最後的字，圖片可讀為「刺绣」，原始答案卻寫成「刺袖」。我們保留原始答案，另行註記問題，避免看到模型輸出後改答案來提高分數。字元錯誤率（CER）會比較模型輸出和參考答案之間需要改動多少字。逐字評分時，正確讀到額外小字或讀出「刺绣」也可能被扣分，因此要一起查看圖片與原始輸出。[兩個案例的獨立查看紀錄](evidence/data/ocr/independent-annotation-spot-check.json)保存了來源圖片的雜湊與觀察範圍。

CC-OCR 的資料卡雖然標示 MIT，正文的授權敘述明確說的是**原始碼**，不足以證明所有混合來源圖片都可用 MIT 再發布。因此，本 repo 只保存固定版本的來源、下載位置、原始答案與檢查資料；這 10 張原圖不放進 Git 或 Git LFS。需要重現檢查時才由程式向原來源取得。

## 真人華語：把聲音接到同一個聊天核心

錄音來自 [FLEURS](https://huggingface.co/datasets/google/fleurs) 的 `cmn_hans_cn` 華語部分（[論文](https://arxiv.org/abs/2205.12446)）。42 段都是**真人朗讀**，不是文字轉語音產生的檔案。選取官方訓練切分 24 段、官方開發切分 6 段，以及官方測試切分 12 段，總長 440.48 秒，約 7 分 20 秒。所選 WAV 保留原始位元組，聲音為 16 kHz、單聲道，逐字稿保留來源的簡體字形。

語音聊天的流程是：「真的聽錄音 → 語音辨識得到文字 → 把文字和對話歷史交給聊天核心 → 產生文字回答」。另外把正確逐字稿直接輸入同一個聊天核心，才能比較問題出在聽錯，還是文字聊天本身答不好。正確逐字稿只用於這個對照與評分，不能偷偷塞進語音路徑，代替模型真正聽聲音。

這些朗讀句子沒有對話回覆標註，也不是自由交談的錄音。我們目前的語音辨識器保持凍結，所以這裡的 `train` 是**來源語料庫的切分名稱**，不表示已用這 24 段重新訓練辨識器。這一小包能檢查語音輸入是否接通，不能證明模型已處理口語停頓、打斷、吵雜背景或台灣各種口音。回答目前仍是文字；資料包也沒有教模型產生語音。

官方資料卡說，訓練錄音者與開發／測試錄音者不同。這不等於開發與測試兩邊的錄音者也互不重複；我們也沒有可逐人核驗的公開身分清單。這裡實際檢查的是句子來源身分與錄音檔案是否跨切分重複，不把它誇大成完整的說話者獨立測試。

本教材自己寫的聊天文字、中文短句、版面標註與程序產生背景使用 MIT。繪字所用的 Noto 字型本身使用 **SIL Open Font License 1.1**；OFL 明確區分字型軟體與使用字型產生的文件，並不要求每張繪字圖片也採 OFL。字型檔沒有放進圖片小包，產生程式會下載並核對固定版本，授權文件則隨包保存。

版本名稱像書籍的版次，SHA-256 雜湊則像檔案的封條：下載後再計算一次，能檢查拿到的位元組是否與公開清單相同。固定 DOCCI 的 Hugging Face loader，並不會自動固定它去其他網站下載的圖片；因此，我們還保存 Google Cloud Storage 的物件 `generation` 與每個檔案的 SHA-256。完整原始描述的 generation 為 `1714384012999810`，所選圖片各自也有固定 generation，記錄在照片包的清單中。

FLEURS 則從固定版本的壓縮串流選出這 42 個錄音，並核對取得的每個檔案。沒有完整下載上游全部錄音壓縮包，所以來源清單中的「上游整包 SHA」是來源提供的中繼資料，不能說成我們親自驗證了整包。CC-OCR 的兩個來源 TSV 有實際完整下載與雜湊檢查，所選 10 張圖片也有逐檔核對；約 3.13 GB 的官方完整 ZIP 則沒有下載。

## 小包、原始清單與實際核對紀錄

三個教學小包合計 **70,648,031 bytes，約 70.65 MB**，不含模型權重。每包內都有自己的原始來源清單、選取方式、署名與授權；整合清單供執行程式使用，不能取代這些逐來源資訊。

| 小包 | 壓縮後大小 | 包內根目錄 | 重建程式 |
| --- | ---: | --- | --- |
| [自然照片](../../assets/training/natural-vision-v3.tar.gz) | 25,775,400 bytes | `vision/` | [prepare_natural_vision.py](../../scripts/prepare_natural_vision.py) |
| [自製中文圖片](../../assets/training/natural-ocr-v3.tar.gz) | 22,303,642 bytes | `ocr/` | [prepare_natural_ocr.py](../../scripts/prepare_natural_ocr.py) |

這些 `.tar.gz` 使用 Git LFS 管理；一般文字來源與證據可直接在 repo 查看。完整取得 LFS 檔案後，應按[整合清單](manifest.json)核對每個小包的大小與 SHA，而不是把 Git LFS 的小型指標檔誤當成實際資料。

學生在 repo 根目錄執行下列命令，即可匿名取得這三包資料，不需要另外安裝 Git LFS 或提供帳號。這個入口只抓第20章資料；原有八包的小實驗仍用原先的下載程式。

```bash
python scripts/fetch_natural_data.py --list
python scripts/fetch_natural_data.py
python scripts/fetch_natural_data.py --verify
```

程式使用固定公開 Git 版本 `21a24124353487e08881302bbd71614766a489ac`，先核對遠端清單，再核對三個壓縮包和全部解包檔案，最後放到 `data/natural`。第一次下載約70.65 MB；已有完全相同資料會跳過，遇到不同內容則保留原資料並停止。[學生下載入口的實際匿名測試](evidence/data/student-fetch/run.json)記錄了這三包與345個檔案的核對。

這次核對以整合清單 SHA `7604526c67da31a41940f16f9c87027c73cf2782c63522dbde8c7efbf015db91` 為準，實際讀取解開後的全部 **345 個檔案**，並另外讀取三個壓縮包的全部一般檔案成員：照片包 154 個、中文圖片包 143 個、語音包 48 個。大小與 SHA 全部相符，也檢查了路徑與跨切分來源組別。[完整核對結果](evidence/data/merged-assets-and-archive-audit.json)與[本次使用的核對程式](evidence/data/verify_snapshot.py.txt)公開保存；這證明取得的是指定檔案，並不證明每個標註都無誤。

另外保留了原先實際執行的[照片獨立重建紀錄](evidence/data/vision/original-reconstruction-proof.json)、[中文圖片重建紀錄](evidence/data/ocr/original-generator-verification.json)、[語音獨立重建紀錄](evidence/data/speech/original-reproducibility-check.json)，以及[外部 OCR 下載核對紀錄](evidence/data/ocr/original-external-preparation-verification.json)。[證據複製索引](evidence/data/copy-index.json)列出這些小型公開證據的原路徑與 SHA；檔案是原樣複製，沒有把舊紀錄改寫成一次新的執行。

證據目錄不另外塞入原始照片、WAV、字型二進位檔，或大型完整 TSV。可再發布的教學資料在上述小包裡；外部圖片的權利與資料範圍限制則如實保留。
