# 候選集合與位置標籤的核對推導

核對對象是固定 state、question、評分器參數的有限候選集合。每個候選有固定意義與唯一 ID，分數為有限實數；推論評分是確定性的，沒有候選位置特徵，也沒有跨候選的排列依賴。以下是數學關係與反例，不是模型訓練成果。

令候選為 m_i，s_i = f(state, question, m_i)，Z = Σ_j exp(s_j)，p_i = exp(s_i)/Z。
任意排列 π 下，s'_k = s_{π(k)}，Z' = Σ_k exp(s_{π(k)}) = Z，所以 p'_k = p_{π(k)}。
因此唯一最高分的候選意義不變。有限精度實作的加總順序可能造成末位差異；實跑比較採 float64 絕對差小於 10^-15，原文的三位小數另外按預設 float32 核對。

若最高分並列，列表 argmax 會選第一個最高值；候選重排便可能改選另一個意義。
改為在最高分候選中選固定 ID 最小者，且 ID 唯一，即與列表位置無關。
若評分改成 f(state, question, m_i) + 10·1{i=0}，排列會改變位置加分的歸屬，以上等式不再保證成立。
跨候選互動也不一定破壞等變性，但必須另外證明或測試；原文只說不能沿用獨立評分器的結論，沒有宣稱所有互動一定失敗。

單一正確答案 t 的無權重交叉熵是 L = -log p_t = -s_t + log Z。
重排後正確位置必須改為 t' = π^-1(t)，才有 L' = L。
只記 label=0 並在倒序時保留它，會把「以上皆不適合」當成正解；正確的「查卡片進度」新位置應是 2。
只刪除正確候選、卻仍用原 label，可能發生索引越界，也可能讓舊索引指向錯誤意義；兩者都不是原先的正確答案判斷任務。固定 ID 提供重排與跨集合追蹤的對應。

對 logits [2,-1,0]，exp 值依序約為 [7.389056098930650, 0.367879441171442, 1]，
Z 約為 8.756935540102093。機率約為 [0.843794734481340, 0.042010066134066, 0.114195199384595]。
三位小數為 [0.844,0.042,0.114]，倒序為 [0.114,0.042,0.844]，兩者唯一最高分都是「查卡片進度」。

對任意固定候選 i，新增有限分數 r 的候選時，p'_i = exp(s_i)/(Z+exp(r)) < p_i；
刪除其他候選時，只要候選 i 仍存在且分數不變，分母變小，p'_i > p_i。
若增加一個與 i 同分的同義候選，原候選的機率變成 exp(s_i)/(Z+exp(s_i))，新候選也取得相同機率。
這說明各選項的機率會分散；並不表示兩個同義選項合計的機率必須等於原機率。
softmax 的輸出維度等於輸入候選數，總和為 1；它沒有能從公式中創造額外「皆不適合」類別的步驟。
在本文的單答案分類介面內，若要回傳「皆不適合」，必須把它納入候選與相應目標資料。這不排除另設拒答閾值等不同系統設計。

機率會隨候選集合改變，故 softmax 正規化本身不能保證不依集合的客觀可信度或校準。
共享評分與排列一致也不能證明語意正確：把錯候選的固定分數設為最高，同樣滿足上述排列關係。
要查 question 是否真的有影響，可固定 state，設計正解不同且候選定義有效的問題對；不要求任意改寫問題都必須改變答案，也不把本頁的人工字典當作這種測試的完成證據。

官方依據為 PyTorch softmax 定義、CrossEntropyLoss 的單類別公式與 class-index 契約，以及 argmax 的首個最高值規則；取得收據見同目錄的 official-source-receipts.json。具體執行與各排列輸出見 verification.json。
