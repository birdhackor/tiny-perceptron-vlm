# 16.12 本輪獨立推導

位置是序列順序 p，不是字彙 ID。令 n 為位置數，w>=1 為包含自己的窗口寬度。

單層來源集合 V_w(p)={max(0,p-w+1),...,p}。集合元素是來源位置；注意力配對的單位是有序 (query位置,key位置)，包含對角線的自己。

完整因果配對數 sum(p+1,p=0..n-1)=n(n+1)/2。令 q=min(n,w)，滑窗配對數為 n*q-q*(q-1)/2；n>=w 時即 n*w-w*(w-1)/2。

n=8,w=3：完整 8*9/2=36；滑窗 1+2+6*3=21。位置7來源為{5,6,7}。下一層來源的聯集為{3,4,5}∪{4,5,6}∪{5,6,7}={3,4,5,6,7}。邊界裁切在0；兩層沒有來源2或更早。

n=8,w=2：位置7來源{6,7}；兩層來源{5,6,7}；滑窗配對數1+7*2=15。本节練習沒有宣稱這個新增計數，驗證它只為交叉檢查規則。

L層可達集合 A_L(p)={max(0,p-L*(w-1)),...,p}。每層最多向前追溯w-1個位置，因為自己也佔一格。w=1只有自己；w>=n退化為完整因果關係。這是結構可達性，不能保證特定原文或答案仍保留在中間特徵。

固定w且n很大時，滑窗有序配對為O(n*w)，完整因果配對為O(n^2)。這比較整段序列的一層配對數；單次逐字生成在位置p的直接比對則是O(min(p+1,w))對O(p+1)。固定頭數／通道數時才可用配對數討論注意力部分的算術成本，不包括FFN、編譯、傳輸或核心啟動等成本。先形成QK^T完整n×n矩陣再套mask的演算法，已經做了密集的配對運算；mask本身不證明稀疏執行。原論文的式(1)、圖2和表1可交叉核對此區別。

若每層K/V確實只儲存最多w個位置，固定批次B、K/V頭數H、頭維D、每元素s bytes，這部分的儲存上限為2*B*w*H*D*s bytes。這是理論上限，沒有量測記憶體，也不包括其他張量／配置器。滾動覆寫已淘汰的原位置K/V，後來位置就無法直接對該K/V做attention；透過未淘汰特徵的間接資訊仍可能存在。若另加全域層，它的快取不受這個局部層條件自動涵蓋。

本輪沒有模型、token準確率、任務分數、訓練步數、實際速度或GPU記憶體的實測分母。所有整數以精確相等驗證，不需要浮點容忍差。Mistral v1 §2的W文字／圖說不可直接搬成本節w的精確數值約定；本節自定義w包含目前位置，且沒有聲稱重現Mistral設定或成績。
