2330: zip(*iterables, strict=False)¶
2331: Iterate over several iterables in parallel, producing tuples with an item
2332: from each one.
2333: Example:
2334: >>> for item in zip([1, 2, 3], ['sugar', 'spice', 'everything nice']):
2335: ...     print(item)
2336: ...
2337: (1, 'sugar')
2338: (2, 'spice')
2339: (3, 'everything nice')
2340: 
2341: 
2342: More formally: zip() returns an iterator of tuples, where the i-th
2343: tuple contains the i-th element from each of the argument iterables.
2344: Another way to think of zip() is that it turns rows into columns, and
2345: columns into rows.  This is similar to transposing a matrix.
2346: zip() is lazy: The elements won’t be processed until the iterable is
2347: iterated on, e.g. by a for loop or by wrapping in a
2348: list.
2349: One thing to consider is that the iterables passed to zip() could have
2350: different lengths; sometimes by design, and sometimes because of a bug in
2351: the code that prepared these iterables.  Python offers three different
2352: approaches to dealing with this issue:
2353: 
2354: By default, zip() stops when the shortest iterable is exhausted.
2355: It will ignore the remaining items in the longer iterables, cutting off
2356: the result to the length of the shortest iterable:
2357: >>> list(zip(range(3), ['fee', 'fi', 'fo', 'fum']))
2358: [(0, 'fee'), (1, 'fi'), (2, 'fo')]
2359: 
2360: 
2361: 
2362: zip() is often used in cases where the iterables are assumed to be
2363: of equal length.  In such cases, it’s recommended to use the strict=True
2364: option. Its output is the same as regular zip():
2365: >>> list(zip(('a', 'b', 'c'), (1, 2, 3), strict=True))
2366: [('a', 1), ('b', 2), ('c', 3)]
2367: 
2368: 
2369: Unlike the default behavior, it raises a ValueError if one iterable
2370: is exhausted before the others:
2371: >>> for item in zip(range(3), ['fee', 'fi', 'fo', 'fum'], strict=True):
2372: ...     print(item)
2373: ...
2374: (0, 'fee')
2375: (1, 'fi')
2376: (2, 'fo')
2377: Traceback (most recent call last):
2378:   ...
2379: ValueError: zip() argument 2 is longer than argument 1
2380: 
2381: 
2382: Without the strict=True argument, any bug that results in iterables of
2383: different lengths will be silenced, possibly manifesting as a hard-to-find
2384: bug in another part of the program.

132: 2.3   Inference
133: 
134: During inference the model can generate the full sequence y1T given X by generating one token at a
135: time, and advancing time by one step. When an <EOS> token is generated, it signifies the end of
136: the sequence. For this process, at time t, the model needs as input the output token yt−1 from the
137: last time step in order to produce yt . Since we do not have access to the true previous token, we can
138: instead either select the most likely one given our model, or sample according to it.
139: Searching for the sequence Y with the highest probability given X is too expensive because of the
140: combinatorial growth in the number of sequences. Instead we use a beam searching procedure to
141: generate k “best” sequences. We do this by maintaining a heap of m best candidate sequences. At
142: each time step new candidates are generated by extending each candidate by one token and adding
143: them to the heap. At the end of the step, the heap is re-pruned to only keep m candidates. The beam
144: searching is truncated when no new sequences are added, and k best sequences are returned.
145: While beam search is often used for discrete state based models like Hidden Markov Models where
146: dynamic programming can be used, it is harder to use efficiently for continuous state based models
147: like recurrent neural networks, since there is no way to factor the followed state paths in a continuous
148: space, and hence the actual number of candidates that can be kept during beam search decoding is
149: very small.
150: In all these cases, if a wrong decision is taken at time t − 1, the model can be in a part of the
151: state space that is very different from those visited from the training distribution and for which it
152: doesn’t know what to do. Worse, it can easily lead to cumulative bad decisions - a classic problem in
153: sequential Gibbs sampling type approaches to sampling, where future samples can have no influence
154: on the past.
