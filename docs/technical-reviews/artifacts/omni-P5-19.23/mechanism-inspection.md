## Computation and representation

UTF-8 encodes the entire scalar-string input before checking its byte length. The teaching and formal encoders allocate IDs 0..255 plus separate PAD/CLS/SEP, and reject empty required strings, invalid surrogates and over-limit strings. `len(('漢'*171).encode('utf-8')) = 513`; a count of Unicode characters is not a byte count. This supports input coverage and validation, not semantic understanding. The formal implementation additionally caps stable IDs at 64 bytes; no contrary unlimited-ID promise occurs in the lesson.

The short example computes M = E(state) without question/candidate inputs. Each h_i is a function only of M, kind, question and description_i. Hence adding a candidate cannot change an existing branch's score in exact arithmetic. The example has no dropout or padding; the formal encoder uses `src_key_padding_mask=tokens.eq(PAD)`, and the two read layers pass the matching key-padding mask. Official PyTorch 2.14.1 source at commit `5c4886908584029761b579af026dcfb627c84070` documents True as an ignored key in `MultiheadAttention.forward` and defaults `is_causal=False`. The installed activation/transformer/functional source bytes equal the fetched original commit bytes. The full formal block AST equals `tiny_perceptron/omni_products/choice.py` after removing only the latter's module docstring.

For a permutation P of valid candidates, row-wise shared encoders, attention and scoring give H' = PH and s' = Ps. Mean, coordinatewise max and count are invariant, so the none logit is invariant in exact arithmetic. Softmax commutes with a permutation. Floating reductions and different batch shapes need a tolerance; a mathematical invariance does not promise bitwise identity. The saved 8-dev-family maxima are all <= 4.76837158203125e-7. These saved maxima were inspected, not regenerated with trained weights. Artificial mixed batches give <= 2.9802322387695312e-8 finite-logit differences and preserve invalid output positions as -inf.

Adding a candidate changes sum_j exp(s_j/T), and may also change the none logit through the symmetric summary. Consequently the probability of an existing candidate can change even when its branch score and M do not change. The third-candidate artificial test gives exactly zero difference in the first two short-model scores while their probabilities change. This tests a mechanism, not a correct service answer.

For positive finite T, order of raw real-valued scores is preserved by division by T. Cross entropy uses the gold index in the current ID order; the None label is appended only for Choice. The temperature fixture has equal scores, so NLL is log(K) independent of T, and the specified secondary rule chooses T=1 from the grid. It is not a fitted model result.

The formal state cache hashes state bytes, state-encoder state_dict, configuration, preprocessing and the position/padding/dtype/device metadata. M does not depend on branch/reader/scorer weights. Returned cloned values protect the internal cache from a caller's mutation. A caller could still corrupt its own explicitly supplied StateMemory values; the implementation does not authenticate those values, and the lesson promises protection of the internal cache only. FP32 evaluation, no dropout and unchanged dependencies delimit the equivalence claims.

## Findings retained for author decision

Necessary T19.23-01: the short `selected()` ranks float32 `p`, but its comment promises a stable-ID rule for a true tie. For scores [0, 1e-8], softmax rounds both to .5, and IDs [a,b] make it return a although the distinct raw score maximum is b. Use the available raw `scores` for argmax and only then stable ID. The full formal ChoiceModel already does this correctly; no archived final result is invalidated by this short-example finding.

Optional T19.23-02: the full standalone `ChoiceModel.predict()` rejects T<=0 but accepts NaN/+inf. NaN produces nonfinite probabilities; +inf produces uniform probabilities. Add finite-number validation for API consistency if this method is intended for direct use. The service wrapper `CJudge.__init__` and `reliability.calibrated` already validate finite T, and the archived T is valid, so this is optional hardening rather than a failure of the measured service contract.
