選擇程式：初始 selected 是 lr=0.001、validation=0.7。後續候選 0.8>0.7，故 selected 改為 lr=0.01、validation=0.8。第三份若是 0.6，0.6>0.8 為假；若是 0.9，0.9>0.8 為真，故選 lr=0.1。程式只讀 validation 鍵，test 只出現在字串，沒有計分資料、模型或 test 分數變數。

選最高的有限樣本偏差：以各候選真正成功率同為 μ 的簡化模型，驗證估計為 μ+ε_i，ε_i 為獨立的 +a 或 -a，兩者各半。挑最高後，有任一正波動的機率為 1-(1/2)^m；選出的平均波動為 a(1-2^(1-m))。m=1 為 0，m=2 為 a/2。這說明沒有權重梯度仍可能挑中驗證特有運氣。一般候選會相關、真實能力也不同；教材的「越容易」是機會與傾向，不是對任意候選集合都有嚴格增加量的定理。論文提供有限樣本模型選擇偏差的一般依據；此式只給透明特例。

測試再調參：方法 θ 原先由 train/validation 決定；若依 test 分數選出 θ'，最後的 θ' 就是 test 的函數。改資料標籤不會移除這項依賴，單靠只報 θ' 最高值也不會移除。新的獨立檢查需要未參與這項選擇的資料；重用原 test 可作開發證據並說明用途，不能再叫全新證據。

Loss 與整串成功不同：令四個二類位置的正確類機率 A=(0.9,0.9,0.9,0.49)，B=(0.6,0.6,0.6,0.6)，每格另一類機率為 1-p。最高機率選字時 A 第四字錯，整串失敗；B 全對。A 的平均 NLL=-(3 ln 0.9+ln 0.49)/4=0.2573578587127359；B=-ln 0.6=0.5108256237659907。較低 loss 的 A 卻不是較高整串成功的 B。假設前文不改變這些機率；這是尺度的反例，不是訓練或自由生成效果的測量。

切分與窗口：完整文字 d 編成 [BOS]+bytes(d)+[EOS]，下一項目標共 bytes(d)+1。common.text_examples 以 start=0,128,... 取最多 129 個 ID，再 shifted 成最多 128 個輸入與目標；相鄰窗口只共享前一輸入 ID，每個目標只出現一次。先把完整文字家族分側、再逐篇分窗，故不會因分窗把同篇拆到 train 與 holdout。這不消除不同篇的近重複。CPU 重建得到 TinyStories 409/51/52 篇、validation/test 42,453/40,685 個目標；詩集 292/36/37 篇、6,707/8,314 個目標；三側 JSONL 指紋全部與正式凍結報告一致。
