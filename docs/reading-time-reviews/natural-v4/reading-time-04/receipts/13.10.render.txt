13.10 比較能不能教一位評分員？¶

老師比較了許多份作業，不能每天再替模型新寫的每篇回答評分。能不能先教一位評分員，估計老師比較時會偏好哪篇？對「只回數字：1+2=?」，我們仍沿用13.1的規則：3比1+2等於3。合適。現在收到這個比較的，不是將來要回答的模型，而是另一個輸出分數的模型。

這位評分員叫reward model，獎勵模型。它讀取問題與回答，輸出一個數；分數越高表示它估計這份回答越合適。同題兩篇的分數差，可以轉成「較佳回答勝出」的機率：差0時是0.5，差正2時約0.881。DPO原論文第3節的公式1–2先描述這種偏好模型，再介紹DPO如何省去獨立評分網路。前置是13.2的偏好資料與1.8的猜錯代價。

怎麼從分數差算到機率？這裡採用一個固定換算規則：把「較佳回答的分數減去另一篇的分數」記成d，機率就取1 / (1 + exp(-d))，程式把這個換算叫做sigmoid。exp(x)表示e的x次方，e約為2.718。差距是0時，exp(0)=1，所以機率是1 / (1 + 1)=0.5；差距是2時，exp(-2)約為0.1353，所以是1 / (1 + 0.1353)，約0.8808。差距若是負數，機率就低於0.5。這個規則把沒有固定範圍的分數差換到0和1之間；它描述評分員估計老師會選哪篇，並不表示回答真的答對的機率。

import torch
from tiny_perceptron.posttraining import preference_loss

for preferred_score in [0.0, 2.0]:
    chosen = torch.tensor([preferred_score])
    rejected = torch.tensor([0.0])
    gap = chosen - rejected
    win_probability = torch.sigmoid(gap)
    loss = preference_loss(chosen, rejected)
    print("差距", gap.item(), "勝出機率", round(win_probability.item(), 4), "代價", round(loss.item(), 4))


實際執行結果 · CPU

差距 0.0 勝出機率 0.5 代價 0.6931
差距 2.0 勝出機率 0.8808 代價 0.1269


輸入是人工設定的兩篇分數，不是模型實測。chosen代表較佳回答的分數，rejected代表較差回答；gap保存較佳分數減較差分數的差距，gap.item()取出這個單一數字供打印；sigmoid把這個差映成0到1。preference_loss取這個勝出機率的負自然log，再平均樣本。兩行依序為機率0.5、代價0.6931，以及機率0.8808、代價0.1269。若標籤說chosen較佳，提高它相對rejected的分數，就能降低代價。

但分數3不代表「有三成正確」或「比1多懂三倍」。給同題所有回答的分數一起加10，上面的差與代價都不變。比較提供的是相對排序訊號，無法直接把每個原始分數當成校準過的正確率。評分員也可能把長回答、固定措辭或禮貌誤當成好答案，所以要用未教過的問題與反例檢查它。

為了把流程縮到可看清的小實驗，本章實際準備四張回答卡：正確的短答、包含算式與結果的一句話、錯誤數字，以及請求補資訊。題目有「只回數字」「用一句話解釋」「購買數量沒給」三種條件；最後一種情境下，直接報總價的前三張都缺少依據，應請補數量。程式已先算好候選文字；評分網路讀的是問題條件與候選編號的數字特徵，不讀中文，也沒有學會加法。偏好標籤來自我們寫定的程式規則，沒有招募真人標注，因此這份實驗不是人類回饋資料的RLHF實證。

實際訓練時先用訓練家族的偏好對更新評分網路，再凍結它，供13.15的選擇模型使用。數字對調仍屬同一家族，不會把1+2與2+1分到訓練和最後測試兩邊。評分員是否把未見家族也排對，與它的訓練代價，會分別保存；預寫卡裡有正確答案，不等於模型會自己寫出答案。

練習把rejected分數改成1，先算兩個新差距為−1與1：勝出機率約0.2689與0.7311，代價約1.3133與0.3133，再執行核對。接著將兩個分數一起加10，應得到相同機率與代價。這能讓你分清比較學習與絕對正確率。
