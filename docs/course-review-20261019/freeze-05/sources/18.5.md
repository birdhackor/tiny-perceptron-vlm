## 18.5 如何顯示較低機率的候選？

沿用同一題和候選 `[4,3,100]`，這次改用更尖的人工分數 `[4,1,0]`，讓第一名占約94%。其他候選只剩少許份量，它們在軟目標代價裡的份量也很小。可以讓分布平一些，保留排名但縮小差距嗎？[1.15](01.md#1.15)選字時用過同一招：先把分數除以正數τ（讀作tau），再softmax。在蒸餾裡，這個τ叫蒸餾溫度（temperature），τ越大，分布通常越平。

取候選 `[4,3,100]` 的分數 `[4,1,0]`。`exp(x)`就是`e ** x`，e約為2.718，把分數轉為正數份量。softmax把各份量除以同一個總和；兩個機率相除時，共同的總和消掉，所以候選4比候選3是`exp(4/τ) / exp(1/τ) = exp(3/τ)`。τ=1時，第一和第二的分數差3，機率比為 `exp(3)`，約20.1；τ=2時，差縮為1.5，比例約4.48，所以第二名的相對份量增加。τ=4時差0.75，比例約2.12。沒有改教師的排名，改的是它展示給學生的選項差距；溫度不是答案正確率，也不是讓教師重新推理一次。

```python
import torch

logits = torch.tensor([4.0, 1.0, 0.0])
for temperature in (1.0, 2.0, 4.0):
    probability = (logits / temperature).softmax(0)
    print(
        "τ",
        temperature,
        "機率",
        probability.round(decimals=4).tolist(),
        "第一比第二",
        round((probability[0] / probability[1]).item(), 4),
    )
```

輸入三個固定分數，不用已訓練的教師。`softmax(0)`沿候選軸轉成機率；溫度在softmax之前除，不是把最後的機率隨便除以τ，那會讓總和不再為一。三行的第一比第二依序約20.0855、4.4817、2.117，和上面的手算一致。最後一個候選從τ=1的1.71%增到τ=4的19.99%，它在學生代價裡占的份量也跟著變大。

下圖每條的完整長度都是100%機率，由左到右的顏色固定對應候選4、3、100。溫度提高時，橘色與綠色的份量變大，藍色的候選4仍是第一名；這表示次要選項更清楚，不表示答案排名改了。百分比四捨五入到小數點後兩位，條寬按原始機率繪製。

![提高蒸餾溫度讓次要候選份量增加，候選4、3、100的排名保持相同](../figures/p7-18-temperature.svg)

分布更平不一定更有用。τ非常大時各候選接近平均，原本有意義的差異也被抹掉；教師給錯候選的份量同樣會變得更明顯。τ要用驗證資料來選：拿沒有用來訓練學生的驗證題，比較不同τ訓練出的學生在這批題目上的回答品質，再決定τ，而不是只希望所有候選都平均。最後報成績用的測試題另外保留，不拿來反覆選τ；資料的分工可回看[1.2](01.md#1.2)。學生也要用相同的τ形成比較用的分布，否則比較的是兩套不同的尺度。

除以τ還有一個副作用：τ夠大時，學生收到的梯度會變小。[18.4](18.md#18.4)的分數梯度是 `q−p`；分數先除以τ之後，梯度變成 `(q−p)/τ`，這裡的p、q都是除過τ的分布。前面多了一個1/τ；τ又遠大於教師、學生各自分數彼此之間的差距時，p、q都接近平均，兩者的差距也大約縮成1/τ，所以整體大約縮成原本的1/τ²。τ沒有大到這個程度時，兩個分布的差距不一定隨τ縮小，梯度甚至可能變大。若同時還有正確答案的CE（它不除以τ），提高τ就會讓教師那一項的份量悄悄變輕。常見做法是把教師那一項乘上τ²（文獻常寫成T²），把梯度補回原本的量級；這是[Hinton等人原文第2節](https://arxiv.org/abs/1503.02531v1)給的理由。下面讓學生分數全為0，核對這件事。

```python
import torch

teacher = torch.tensor([4.0, 1.0, 0.0])
for temperature in (1.0, 2.0, 4.0):
    student = torch.zeros(3, requires_grad=True)
    p = (teacher / temperature).softmax(0)
    loss = -(p * (student / temperature).log_softmax(0)).sum()
    loss.backward()
    size = student.grad.norm().item()
    print("τ", temperature, "梯度大小", round(size, 4), "乘τ²後", round(size * temperature**2, 4))
```

`loss`是18.4的軟目標交叉熵，只是教師與學生的分數都先除以τ。`student.grad.norm()`把三個梯度平方加總再開根號，得到一個總大小，`temperature**2`是τ²。τ從1升到4，梯度大小從0.7387縮到0.0651，只剩約十一分之一；乘上τ²後是1.0416，回到和τ=1相近的量級。乘τ²不會讓三種τ完全相同；本例只是回到相近的量級。它補償的是高溫時常見的尺度變化，不保證兩項代價的相對力道固定，換τ之後仍要用驗證資料檢查兩項的比例。本章[18.8](18.md#18.8)的`distillation_kl`已在函式內乘上τ²，外層不用再乘；使用其他計算蒸餾代價的函式時，要先確認它是否已內建這個乘數，避免重複相乘。τ²只是尺度的約定，不是教師突然多教了τ²倍的知識。

蒸餾溫度和[1.15](01.md#1.15)生成時抽樣（sampling）用的溫度應分開記錄。這裡改的是訓練時的教師／學生分布，不是要求最終回答以相同的τ抽樣；同一個蒸餾學生可以搭配不同的選字規則。

練習只把第一段程式的 `logits` 改成 `torch.tensor([8.0, 2.0, 0.0])`，溫度清單不變。先預測新的τ=2與原本τ=1的結果相同、新的τ=4與原本τ=2相同，再執行核對。兩者都是同樣的「分數除以溫度」，這能幫你分辨絕對數值與相對尺度的作用。
