## 7.4 回答第一個 token 在哪個位置被預測？

問題 Q，回答 A。完整序列是 BOS、user、Q、EOS、assistant、A、EOS。要教模型寫出第一個 A，代價應落在 assistant 所在的位置，因為讀到 assistant 的那個位置正在猜下一項。

兩個字都是 ASCII，各一個 byte；Q 的 ID 是 81＋8＝89，A 是 65＋8＝73。X 去掉原序列的最後一項，Y 則去掉原序列的第一項，讓每個位置對上它的下一項：原序列索引 5 的 A 落在 Y 的索引 4，成為 X 索引 4（assistant）要猜的答案；原序列索引 6 的 EOS 落在 Y 的索引 5。圖把位置索引、輸入 ID 和目標 ID 分欄，先看索引 4 的 assistant→A，再看索引 5 的 A→EOS。

![首答案由assistant所在的位置預測，索引和token ID各有用途](../figures/rewrite-07-04-answer-alignment.svg)

```python
from tiny_perceptron.data import ByteTokenizer, render_chat

tok = ByteTokenizer()
x, y = render_chat(
    [
        {"role": "user", "content": "Q"},
        {"role": "assistant", "content": "A"},
    ]
)
first = (y != -100).nonzero()[0].item()
print("X", x.tolist(), "Y", y.tolist())
print("首答案預測位置", first, "輸入", x[first].item(), "答案", y[first].item())
assert x[first].item() == tok.assistant_id
assert y[first].item() == tok.encode("A")[0]
```

輸出的 X 是 `[1,3,89,2,4,73]`，Y 是四個 −100 後接 73、2。`(y != -100).nonzero()` 列出條件為 True 的位置，`[0]` 取第一個，`.item()` 轉成整數，得到 first＝4：這個位置的 X 是 4（assistant），Y 是 73（A）。下一個位置的 X 是 73，負責預測 EOS（2）。原序列的索引、當前的輸入 ID 和目標 ID 是三種用途不同的數字，讀的時候要分開。

有效目標的數量對了，不代表位置對了。`render_chat` 已經移過一位；若訓練程式又自己移一次（[4.7](04.md#4.7) 提醒過的錯誤），X 會變成 `[1,3,89,2,4]`、Y 變成 `[-100,-100,-100,73,2]`。有效目標仍是 2 個，但 A 改由 user 段 EOS 的位置預測，assistant 的位置反而去猜 EOS。所以要同時檢查兩件事：第一個有效目標所在的位置，X 是 assistant，Y 是回答的第一個 byte。程式最後兩個 assert 做的就是這兩項檢查。`TinyLM` 保留輸入的位置順序，`masked_loss` 再按同一個位置比較 logits 和 labels；兩者都不會再替你移位。

練習把問題 Q 改成 `"QQ"`，先預測回答的第一個目標從位置 4 移到 5，但 X[first] 仍是 4、Y[first] 仍是 73，再執行核對。接著只把答案 A 改成 B，先預測：first 仍是 5，答案 ID 變成 74，最後一個 assert 會失敗，因為它比對的仍是 A 的 ID 73；把那一行的 `"A"` 也改成 `"B"` 就會通過。兩次分別改變前文長度與回答內容，可以看清第一個目標的位置取決於哪些材料。
