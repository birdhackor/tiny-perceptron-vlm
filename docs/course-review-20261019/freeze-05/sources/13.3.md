## 13.3 逐字機率如何合成整篇答案的分數？

假設回答有兩個有效目標，第一步目標機率0.8，第二步在已看見第一個目標後也為0.8。整段機率是`0.8×0.8=0.64`。因為第二步已把第一步當成條件，兩步直接相乘就是整段機率。

很多小數連乘會很小；取自然log後，乘法變加法：`log(0.8×0.8)=log0.8+log0.8`。下面只把答案位置的log機率相加；前文和補齊用的PAD位置，標籤都設成不計分的`-100`。這是替已寫好的答案算機率，沒有先讓模型隨機生成。

```python
import torch
from tiny_perceptron.alignment import sequence_log_probability
from tiny_perceptron.data import IGNORE

logits = torch.tensor([[[0.0, 2.0, 0.0], [2.0, 0.0, 0.0], [0.0, 0.0, 2.0]]])
labels = torch.tensor([[IGNORE, 0, 2]])
score = sequence_log_probability(logits, labels)
print("IGNORE的值", IGNORE)
print("整段log分數", round(score.item(), 4))
print("還原機率", round(score.exp().item(), 4))
```

`logits`是候選尚未轉成機率的分數，形狀`(1,3,3)`代表一筆、三個位置、每處三個候選。`IGNORE`就是[7.1](07.md#7.1)那個表示「不計代價」的`-100`。標籤`[IGNORE,0,2]`忽略第一個位置，第二個位置的目標是候選0，第三個是候選2。輸出的整段分數約−0.4791，`exp()`還原的機率約0.6193。

`sequence_log_probability`的寫法如下：

```python
# 節錄自 tiny_perceptron/alignment.py：sequence_log_probability
def sequence_log_probability(logits, labels):
    valid = labels != IGNORE
    safe_labels = labels.masked_fill(~valid, 0)
    selected = logits.log_softmax(-1).gather(-1, safe_labels.unsqueeze(-1)).squeeze(-1)
    if not valid.any(-1).all():
        raise ValueError("偏好回答不能没有有效 token")
    return (selected * valid).sum(-1)
```

輸入`logits`的形狀是`(筆數,位置數,候選數)`，`labels`是`(筆數,位置數)`。逐行看：

- `valid = labels != IGNORE`逐格比較，得到真假表，標出哪些位置是有效目標；本例是`[False,True,True]`。
- `labels.masked_fill(~valid, 0)`：`~`把真假對調，`masked_fill`把`~valid`為真的位置換成0，得到`safe_labels`。`-100`不是合法的候選編號，下一行取值會出錯，所以先換成0；這些位置取出的值稍後會被丟掉。
- `logits.log_softmax(-1)`沿最後一軸（候選）先做softmax再取log，得到每個位置每個候選的log機率。例如`[0,2,0]`這組分數的softmax約`[0.1065,0.7870,0.1065]`，取log約`[−2.2395,−0.2395,−2.2395]`。
- `.gather(-1, safe_labels.unsqueeze(-1))`在每個位置按標籤取出一個候選的log機率。`unsqueeze(-1)`先在最後多加一個長度1的軸，讓標籤從`(1,3)`變成`(1,3,1)`，和`logits`的軸數相同；`gather`沿最後一軸，按這個編號取值：例如第二個位置的三個log機率約`[−0.2395,−2.2395,−2.2395]`，標籤是0，就取出候選0的−0.2395；結果也是`(1,3,1)`；`squeeze(-1)`再拿掉長度1的軸，得到形狀`(1,3)`的`selected`。
- `if not valid.any(-1).all():`檢查每一筆是否至少有一個有效目標：`any(-1)`問每筆裡有沒有任何一個真，`all()`問是不是每筆都有。沒有有效目標的回答無從計分，就用`raise ValueError(...)`停下來並說明原因。
- `(selected * valid).sum(-1)`：真當1、假當0相乘，忽略位置的值歸零，再沿位置加總，得到每一筆的整段分數。

把中間結果印出來核對：

```python
valid = labels != IGNORE
safe_labels = labels.masked_fill(~valid, 0)
selected = logits.log_softmax(-1).gather(-1, safe_labels.unsqueeze(-1)).squeeze(-1)
print("valid", valid.tolist(), "safe_labels", safe_labels.tolist())
print("每個位置取出的log機率", [round(value, 4) for value in selected[0].tolist()])
```

`[round(value, 4) for value in ...]`是把清單裡每個數取到小數四位、再收成新清單的簡寫。第一個位置取到候選0的−2.2395，但`valid`是False，乘上0後不計入；兩個有效目標的機率都約0.7870，log各約−0.2395，加總約−0.4791。若多加一個同樣機率的有效目標，總log約−0.7186，逐步平均仍約−0.2395。

所以**整段加總**與**逐步平均**是不同的量。機率不超過1，每個log項都不大於0；長回答多加了幾項，總log常更負，不能單靠它說人類更不喜歡。後面會先對每篇答案減去固定參考的同篇分數，再比較較佳與較差回答。本章的整段約定也包括EOS結束目標。

練習把第一段程式的`labels = torch.tensor([[IGNORE, 0, 2]])`改成`[[1, 0, 2]]`，先預測整段分數多加一個約−0.2395的項，變成約−0.7186，再執行核對。這是求和手算檢查；實際的第一個位置若屬提問，就仍須忽略，不能為了改分數把它算入回答。
