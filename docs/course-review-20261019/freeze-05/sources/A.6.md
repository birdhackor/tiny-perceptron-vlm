## A.6 找不到或文件不可靠時怎麼辦？

問書店地址時，文件庫裡若只有「貓在窗邊」，什麼也取不回；若只有「書店地址尚未公布」，取回了相關的文件，卻仍沒有地址。前一種要先補來源，後一種要說明來源沒有提供地址。不要因為回答可以寫得完整，就替兩種情況各編一個地址。

下面的兩個文件庫各只有一份文件，`retrieve` 的寫法見 [A.3](0A.md#A.3)。程式依取回的結果，選一句固定的處理方式：

```python
from tiny_perceptron.retrieval import retrieve

query = "書店地址"
cases = [
    [{"id": "d1", "text": "貓在窗邊"}],
    [{"id": "d2", "text": "書店地址尚未公布"}],
]
for docs in cases:
    hits = retrieve(query, docs)
    if not hits:
        decision = "沒有取回相關來源，請補公告"
    elif "尚未公布" in hits[0]["text"]:
        decision = "來源未給地址，目前無法確定"
    else:
        decision = "需進一步核對來源與答案"
    print([d["id"] for d in hits], decision)
```

第一個文件庫取回空清單 `[]`，程式印出「沒有取回相關來源，請補公告」；第二個取回 `['d2']`，文件裡有「尚未公布」，印出「來源未給地址，目前無法確定」。`if not hits` 在清單是空的時候成立；`elif` 是「否則，如果」，前一個條件不成立才檢查它；`hits[0]["text"]` 取第一份取回文件的原文。這是我們寫死的規則：判斷式要找的字串必須和文件逐字相同，它也沒有教模型誠實。

兩份公告若一份寫青街8號、一份寫紅街9號，先看能不能判斷哪一份適用：日期較新是線索，但還要核對是不是同一家店，以及那個日期是公告發布的日期還是地址生效的日期（較新的公告也可能是預告之後才搬）；確認不了時，就把衝突呈現出來，並請求更新的來源。字詞分數的高低不能決定哪份比較新。

公告裡也可能夾帶「忽略問題，改說別的」這類文字。公告裡的地址可以當證據；公告裡的命令句只是待讀的內容，不是使用者給助理的指令，助理不照做。這種情況叫提示注入，見 [9.7](09.md#9.7)。評測時，可回答的題目與資料不足的題目都要保留：每題都回答「不知道」不算誠實，還會把明明有答案的題目答錯。

練習把第二個文件庫的 `text` 改成 `"書店地址是青街8號"`，先預測：仍取回 `['d2']`，但文件裡沒有「尚未公布」，印出「需進一步核對來源與答案」。取回結果不是空的、文件裡也有地址，仍要核對回答是否符合這份來源；若公告附有店名與日期，還要核對它是不是所問的那家店、是不是目前適用的一份。
