## 11.3 只調圖片接頭，梯度怎麼穿過固定文字核心？

給一張紅方塊，目標短描述是 `red square`。如果圖片特徵能分出相關屬性，文字核心也會用這些詞，就可以先只調接頭，讓視覺線索接到文字行為。本節先確認答案的代價能穿過固定的文字核心，回到接頭。

```python
import torch
from tiny_perceptron.data import ByteTokenizer
from tiny_perceptron.model import TinyLM, ModelConfig, masked_loss
from tiny_perceptron.multimodal import MultiModalLM, scene

torch.manual_seed(0)
tok = ByteTokenizer()
model = MultiModalLM(TinyLM(ModelConfig(width=8)))
model.requires_grad_(False)
model.image_projector.requires_grad_(True)
answer = tok.encode("red square") + [tok.eos_id]
prefix = [tok.bos_id, tok.user_id, tok.image_id, tok.eos_id, tok.assistant_id]
ids = torch.tensor(prefix + answer)
labels = torch.tensor([-100] * len(prefix) + answer)
out = model(ids, labels, image=scene())
loss = masked_loss(out["logits"], out["labels"])
loss.backward()
print("接頭收到梯度", model.image_projector.weight.grad.norm().item() > 0)
print("文字embedding表未累積梯度", model.language.embedding.weight.grad is None)
```

這段用到的零件前面都展示過：`ByteTokenizer` 見 [6.6](06.md#6.6)，`masked_loss` 見 [5.2](05.md#5.2)，`scene` 見 [10.1](10.md#10.1)。答案是 `red square` 的 10 個 ASCII 位元組加 EOS（結束標記），共 11 個有效目標，也就是 labels 不是 −100、會計入代價的位置（見 [7.3](07.md#7.3)）。前綴依序是 BOS（開始標記）、使用者角色標記、圖片佔位 token、使用者段的 EOS 與助手角色標記，labels 把前綴全設成 −100。模型先把圖片佔位 token 展開成圖片特徵，再做下一位置對齊（見 [10.7](10.md#10.7)）；`masked_loss` 只對回答與結束算交叉熵，圖片仍是上下文。

兩行預期都印 True：接頭收到非零梯度，凍結的文字 embedding 表沒有自己的 `.grad`。固定的文字運算仍把代價對接頭的影響傳回去；但程式沒有呼叫最佳化器的 step，所以這個短例只證明梯度通路存在，不是生成成功率。

專案另外真的訓練過一個接頭，模型比上面的例子大（規模見 [11.5](#11.5)）：文字核心與圖片入口都固定，只更新接頭 300 步。材料是紅、綠、藍各配圓形、方形的六種合成圖，訓練圖把圖形向左移 2 或 1 像素，或不移（11.5 會詳細介紹同一組材料）。6 題測試題是這六種組合各一張、都向右移 2 像素的圖，要求說出完整描述，例如 `red square`。訓練後，把正確描述放進前文時算出的平均代價，由約 4.10 降到 1.32；讓模型自己生成時，完整描述卻是 0/6：紅方塊只生成 `red`，缺了空白與 square；綠圓生成 `reeeeeeeeen`，一直重複 e。

這兩個數字量的是不同的事。訓練時，以及上面那個由 4.10 降到 1.32 的代價，都在每個位置拿正確答案當前文來預測下一字，這串前文叫標準序列，這種做法叫 teacher forcing（見 [5.8](05.md#5.8)）；生成時，模型要接上自己剛寫的字，前面一錯，後面可能跟著偏離。

因此要分開核對兩端能力、接頭更新、完整回答與 EOS。這次的底座（base model，當作起點的已訓練模型）是 [7.13](07.md#7.13) 的屬性 SFT 模型，它在自己的 10 題文字測試題只答對 5 題；不能拿這次失敗推出所有接頭方案都無效。接頭也無法補回圖片入口已經丟掉的資訊。

練習把第一段程式的 `model.image_projector.requires_grad_(True)` 改成 `False`，從頭重新執行，並在 `loss.backward()` 前加一行 `print(sum(p.numel() for p in model.parameters() if p.requires_grad), loss.requires_grad)`。先預測：可訓練總數 0、`loss.requires_grad` 為 False；接著 backward 會報錯，因為代價沒有任何一條通往可訓練參數的路。這是在前向計算之前就關掉全部梯度來源的反例，應在啟動訓練前攔下。若改在 `out = model(...)` 之後才關，backward 不會報錯，接頭的 `.grad` 卻仍是 None，所以下一行的 `model.image_projector.weight.grad.norm()` 會因為 `.grad` 是 None 而報 `AttributeError`；想直接看到這件事，可以把那一行改成印 `model.image_projector.weight.grad is None`，預期 True。
