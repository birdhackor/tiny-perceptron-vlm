## 7.7 填充的位置會被當線索嗎？

原序列是 `[1,2,3]`，在左邊補兩個 PAD 後變成 `[0,0,1,2,3]`。我們希望真實的三個 token 得到和補齊前相同的預測。要做到這點有兩個條件：它們不能讀到 PAD；它們查位置表時，仍要用位置 0、1、2。

這裡有兩種編號。**物理欄位**是補齊後陣列裡的欄位索引，0 到 4，只用來在陣列裡找資料。**模型位置**是送進位置表的編號；位置表就是 [4.1](04.md#4.1) 那張依位置查向量的表，`TinyLM` 的 forward 用 `x = x + self.position(positions)` 把查到的位置向量加到 token 的 embedding 向量上。不傳 positions 時，TinyLM 直接用物理欄位 0、1、2…… 當模型位置，於是左補兩個 PAD 後，真實 token 會查到位置 2、3、4 的向量，和補齊前不同。所以要另外傳入 `positions`，讓最後三個真實 token 的模型位置仍是 0、1、2。

讀取許可則交給 `valid`：它標出哪些位置是真實 token。[3.6](03.md#3.6) 的因果遮罩只禁止讀未來，`valid` 另外禁止讀 PAD；兩個條件同時成立，一個位置才可以讀另一個位置。圖的上半是未補齊的三個真實 token 和它們的模型位置；下半是左補兩個 PAD 之後的序列，依序標出物理欄位、valid 與模型位置。

![左PAD改變物理欄位，模型位置仍從0編起](../figures/rewrite-07-07-padding-positions.svg)

```python
import torch
from tiny_perceptron.model import TinyLM, ModelConfig

torch.manual_seed(42)
model = TinyLM(ModelConfig(vocab_size=10, width=8))
base = model(torch.tensor([[1, 2, 3]]))["logits"]
ids = torch.tensor([[0, 0, 1, 2, 3]])
valid = ids != 0
positions = torch.tensor([[0, 0, 0, 1, 2]])
actual = model(ids, valid=valid, positions=positions)["logits"][:, 2:]
print("非填充位置最大差", (base - actual).abs().max().item())
assert torch.allclose(base, actual, atol=1e-6, rtol=0.0)
```

base 是未補齊、三個真實 token 的 logits。補齊版的 ids 用 0 當 PAD，`valid` 是 `[False,False,True,True,True]`；positions 的最後三個是 0、1、2，前兩個 PAD 填什麼都不會被真實位置用到，這裡填 0。模型把 valid 與因果遮罩合成讀取許可，輸出再用 `[:, 2:]` 只取最後三個非填充位置來比較。最大差應是 0 或極小的浮點誤差；assert 容許百萬分之一的絕對差。

本例假定 ID 0 專供 PAD、真實內容不會用到 0，所以能用 `ids != 0` 算出 valid。換成別的字表要確認同樣的約定，不能無條件把所有 0 當成空位。一般的 batch 工具會直接回傳 valid（[7.10](#7.10) 的 `pad_batch` 就是），不必從 token 值去猜；後面的程式都應保留它。

訓練時，PAD 位置的目標另設為 −100，不計入 [5.2](05.md#5.2) 的平均代價；本例只比較 logits，沒有算代價。取消 valid，真實位置可能讀到 PAD；取消自訂的 positions，真實位置會查到不同的位置向量。兩種改動各自都會破壞相同的結果。

練習先只刪掉呼叫裡的 `valid=valid`、保留 positions。先預測差值不再接近 0、assert 失敗，再執行核對。恢復 valid 後，改成只刪 positions 再試一次，分別找出兩種差異的來源。比較時固定種子與模型，避免重新初始化把 PAD 的影響和其他變化混在一起。

<details>
<summary>補充：前面兩個 PAD 位置讀什麼？</summary>

前兩個 PAD 位置在因果遮罩下只能讀自己與更早的位置，而那些全是 PAD，又被 valid 禁止，於是它們沒有任何可讀的位置。注意力會把不可讀的分數設成負無窮；若一整列都是負無窮，softmax 會算出 NaN（not a number，不是有效數字），還可能擴散到後面的計算。本課的注意力程式把這種「沒有可讀位置」的輸出直接設成 0，原始碼見 [3.6](03.md#3.6) 的 `manual_attention`。這些 PAD 位置的輸出本來就不用：比較時用 `[:, 2:]` 排除，訓練時目標設為 −100。

</details>
