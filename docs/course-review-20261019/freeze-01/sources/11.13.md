## 11.13 四個字對三個，整串編號就正確嗎？

材料寫 `1010`，預測寫 `1000`。第三位的 1 被讀成 0，四位對了三位，整串卻不相同。查驗編號要用完整字串，所以要把逐位正確與整串成功分開。

```python
truth = "1010"
predicted = "1000"
assert len(truth) == len(predicted)  # 本實驗只比較等長且對齊的字串
matched = sum(a == b for a, b in zip(truth, predicted))
print("等長逐位正確率", matched / len(truth))
print("整串正確", truth == predicted)
print("本例一次替換的CER", 1 / len(truth))
print("獨立錯誤假設下五位全對", round(0.9**5, 4))
```

本例等長且逐位對齊，`matched` 是 3，印出逐位正確率 0.75、整串 False。字元錯誤率（Character Error Rate，CER）的一般算法是：把預測改成正確答案，最少需要幾次插入、刪除或替換——這個次數叫編輯距離（edit distance）——再除以正確答案的字數（文獻也把正確答案叫參考，reference）。本例只有一次替換，所以 CER 是 1/4＝0.25。程式只算這個已知一次替換的例子，沒有用 `zip` 假裝算出通用的編輯距離；編輯距離怎麼用程式算，[11.16](#11.16) 再看。

若預測 `10100`，刪掉多的一個 0 就對了，仍是 1/4；若預測 `010`，在開頭補一個 1，也只要一次編輯，不能把錯位之後的逐位差異全部算成錯字。分母仍是正確答案的長度 4，不是預測的長度。

`round(0.9**5, 4)` 假設每位的正確率都是 0.9，而且互相獨立，五位全對約 0.5905。這只是乘法直覺；真實的裁切或字序錯誤可能一起發生，仍要直接量完整字串，不能由逐字平均推算。

完整的有序答案最後加 EOS，通知生成停止；它不是圖片上的字。[11.12](#11.12) 的 OCR 實驗中，30 題測試題全都以 EOS 結束，完整內容卻只對 2/30；30 題的編輯距離合計 40 次，正確答案共 57 個字，CER＝40/57，約 70.2%。會停止和讀對，仍是兩個能力。

練習把第一段程式的 `predicted` 改成 `"1010"`，預期逐位 1.0、整串 True；CER 那行仍按「一次替換」寫死，要自己改成零次編輯（`0 / len(truth)`）。再把 `predicted` 改成 `"101"`：少了末尾的 0，編輯距離是 1，CER 仍是 1/4；但程式的等長 `assert` 會先停下來，拒絕直接拿它做逐位比較。
