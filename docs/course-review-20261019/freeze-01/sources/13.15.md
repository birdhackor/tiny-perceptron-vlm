## 13.15 一輪選卡與更新，如何接起來？

現在用同一組四張回答卡做一次完整循環。題目「只回數字：1+2=?」的理想卡是0號「3」。輸入小網路的不是中文原文，而是13.10的情境`[0.1,0.2,0,0]`：兩個數各除以10、是否要求一句話、是否缺購買數量。

這一輪沿用13.14的五種角色：策略模型（policy）選卡，獎勵模型（reward model）評分，價值模型（critic）估平均，舊策略（old policy）是收集時的機率紀錄，參考模型（reference）是PPO開始時的固定副本；下面的程式依序叫`policy`、`reward_model`、`critic`、`old_log_probability`、`reference`。

情境的四個數直接交給模型；回答內容也由Python預先寫好。它只學哪張卡合適，沒有學中文閱讀、加法計算或逐token生成。這樣縮小任務，是為了能追清PPO中每份數值的去向。

```python
import copy
import torch
from torch import nn  # 本節節錄的FiniteResponsePolicy與FiniteValueModel會用到nn
from tiny_perceptron.posttraining import FiniteRewardModel, bandit_advantage, exact_kl, ppo_clipped_objective

context = torch.tensor([[0.1, 0.2, 0.0, 0.0]])
print("情境形狀", list(context.shape))
```

`context`是一題的情境，形狀`[1,4]`：1題、4個數。獎勵模型與三個函式在13.10–13.14已經看過，這裡從函式庫載入；策略模型與價值模型的程式在下一段。

```python
# 節錄自 tiny_perceptron/posttraining.py：FiniteResponsePolicy、FiniteValueModel
class FiniteResponsePolicy(nn.Module):
    """輸入四個人工結構特徵；輸出四個事先寫好的回答的 logits。"""

    def __init__(self, features=4, width=16, actions=4):
        super().__init__()
        self.network = nn.Sequential(nn.Linear(features, width), nn.Tanh(), nn.Linear(width, actions))

    def forward(self, features):
        return self.network(features)


class FiniteValueModel(nn.Module):
    """從 context 預測目前策略會拿到的 RM 回饋；不是另一個偏好評審。"""

    def __init__(self, features=4, width=16):
        super().__init__()
        self.network = nn.Sequential(nn.Linear(features, width), nn.Tanh(), nn.Linear(width, 1))

    def forward(self, features):
        return self.network(features).squeeze(-1)
```

兩個類別和13.10的獎勵模型一樣，是「Linear→Tanh→Linear」的小網路，差別在輸入與輸出：

- `FiniteResponsePolicy`讀4個情境數，經16個中間數，輸出4個分數，每張回答卡一個。分數經softmax才是各卡的機率，下面的`Categorical`會替我們做這一步。
- `FiniteValueModel`同樣讀4個情境數，但最後只輸出1個數；`squeeze(-1)`把形狀`(題數,1)`變成`(題數,)`，每題一個預測的平均獎勵。它看不到卡號，所以只能估平均。

一輪有四步：

1. 目前的策略模型按情境抽一張卡，保存該卡的舊log機率。
2. 固定的獎勵模型評這張卡，更新前的價值模型給基準值，兩者相減保存優勢。
3. 用目前的策略模型重算同一張卡的機率，求ratio與裁切代價，另加相對參考模型的KL；價值模型另算平方代價。
4. 清掉舊梯度、`backward()`算新梯度，最後由最佳化器（optimizer）的`step()`改策略模型與價值模型。獎勵模型與參考模型不在最佳化器裡。

下面的程式用隨機的小網路核對「誰真的變了」。這裡的獎勵模型也是隨機的、沒有教過，所以參數更新只能證明流程接通，不能證明任務變好。

```python
torch.manual_seed(42)
policy, critic = FiniteResponsePolicy(), FiniteValueModel()
reward_model = FiniteRewardModel().requires_grad_(False)
reference = copy.deepcopy(policy).requires_grad_(False)
optimizer = torch.optim.SGD(list(policy.parameters()) + list(critic.parameters()), lr=0.1)

with torch.no_grad():
    old_distribution = torch.distributions.Categorical(logits=policy(context))
    action = old_distribution.sample()
    old_log_probability = old_distribution.log_prob(action)
    reward = reward_model(context).gather(1, action[:, None]).squeeze(1)
    advantage = bandit_advantage(reward, critic(context))

new_logits = policy(context)
new_log_probability = torch.distributions.Categorical(logits=new_logits).log_prob(action)
terms = ppo_clipped_objective(new_log_probability, old_log_probability, advantage)
value_loss = (critic(context) - reward).square().mean()
loss = terms["policy_loss"] + 0.1 * exact_kl(new_logits, reference(context)).mean() + 0.5 * value_loss
before = next(policy.parameters()).detach().clone()
optimizer.zero_grad()
loss.backward()
optimizer.step()
print("選中的卡", action.item(), "優勢", round(advantage.item(), 4), "更新前ratio", terms["ratio"].item())
print("策略參數改變", not torch.equal(before, next(policy.parameters())))
print("獎勵模型有梯度", any(p.grad is not None for p in reward_model.parameters()))
print("固定參考有梯度", any(p.grad is not None for p in reference.parameters()))
print("輸出形狀", list(new_logits.shape), list(critic(context).shape), list(reward_model(context).shape))
```

逐段看：

- 開頭建立四個網路：`policy, critic = ...`用逗號一次建立兩個；獎勵模型與參考模型都用`requires_grad_(False)`凍結。建立最佳化器時，`list(policy.parameters()) + list(critic.parameters())`把兩份參數清單接成一份，所以`torch.optim.SGD`只管策略模型與價值模型；SGD就是[1.12](01.md#1.12)的「新參數＝舊參數−學習率×梯度」。
- 收集區塊包在`with torch.no_grad():`裡，算出的都是固定紀錄，不留梯度。`torch.distributions.Categorical(logits=...)`把四個分數換成四張卡的抽樣分布；`sample()`依機率抽出一個卡號；`log_prob(action)`查這張卡的log機率，當作舊策略的紀錄。
- `reward_model(context)`替四張卡各給一個分數，形狀`(1,4)`；`gather(1, action[:, None])`沿編號1的軸，也就是第二個軸（卡的方向），取出已選那張卡的分數。`action[:, None]`和13.3的`unsqueeze(-1)`一樣，先多加一軸讓形狀對上；`squeeze(1)`再拿掉它，每題得到一個獎勵，才能和價值模型的每題基準值相減。
- 更新區塊重新算`policy(context)`，這次會留梯度；新舊log機率送進13.13的`ppo_clipped_objective`。
- 總代價把三項加起來。`terms["policy_loss"]`是13.13的負替代目標平均；`0.1 * exact_kl(...)`是13.14的KL，0.1就是那個係數，和完整實驗設定裡的`reference_kl_coefficient`相同；`0.5 * value_loss`是價值模型的平方代價。策略模型與價值模型沒有共用參數，所以0.5只是把價值模型收到的梯度減半，在這個SGD例子裡等於讓價值模型用一半的學習率；完整實驗讓兩者各用自己的最佳化器，不需要這個係數。
- `optimizer.zero_grad()`清掉舊梯度，`loss.backward()`算新梯度，`optimizer.step()`才真正改策略模型與價值模型的參數。
- 最後的檢查：`next(policy.parameters())`取出策略模型的第一組參數，更新前先複製一份，好比較有沒有變；`any(p.grad is not None for p in reward_model.parameters())`逐一看獎勵模型的參數有沒有收到梯度，只要有一組收到就是True。

固定seed 42時，選中0號卡、優勢約−0.2658（隨機的獎勵模型給這張卡的分數低於價值模型的預測），更新前ratio為1；策略參數改變為True，獎勵模型與參考模型有梯度都是False。最後一行的三個形狀依序是`[1,4]`（策略模型替每張卡一個分數）、`[1]`（價值模型每題一個數）、`[1,4]`（獎勵模型替每張卡一個分數）。ratio為1是因為這一輪還沒更新過，新舊策略相同，不表示裁切把它鎖住。

存進實驗紀錄的選卡實驗，先用只回數字的示範對策略模型做SFT，再用比較資料教獎勵模型，凍結獎勵模型後進入PPO。題目按家族整組分配（同一組加數的三種要求同屬一個家族），18道測試題不參與更新。每題取機率最高的卡，選中符合題目完整要求那張卡的題數，由SFT底座的6／18變成PPO後的12／18；下一節逐項看哪些要求學會了。

練習把第一段程式的`context`第三格改成1，也就是`[[0.1, 0.2, 1.0, 0.0]]`，表示要求一句話。先預測：輸入與輸出形狀仍是一題四張卡，理想卡改成1號。隨機程式不保證選到它；「流程可更新」與「學會按要求選卡」要分別驗收。

完整CPU實驗則真的先教選卡與評分，再接PPO。兩個加數都在1到10、小的在前，共55個家族，先分44個訓練、5個驗證、6個測試；每個家族各有三種要求，所以分別是132、15、18題。用44筆「只回數字」的示範，從隨機參數開始教148個參數的策略模型60次，每批32題。這一步就是SFT（[7.1](07.md#7.1)的監督式微調）：給出情境與示範答案，教模型模仿示範的選擇。LLM流程中的SFT通常接在已預訓練的底座之後，見[7.17](07.md#7.17)；這裡沒有預訓練，直接從隨機參數開始。

這一步SFT使用0.2的label smoothing，意思是把原本全給正確卡的目標份額稍微攤開。四張卡若以0號為正確答案，原目標是`[1,0,0,0]`；保留其中80%，再把20%平均分給四張卡，得到`[0.85,0.05,0.05,0.05]`。正確卡仍拿最多份額，其他卡也保留少量，避免探索時它們的機率過早接近0。這是訓練時使用的目標分布，不表示模型訓練後必定輸出這四個機率；也不是所有SFT都必須採用的配方。

241個參數的獎勵模型用660對訓練偏好更新300次、每批64對，共抽用19,200對；97個參數的價值模型在PPO階段學分數估計。PPO收集120批，每批64次真實選卡，共7,680次；每批重用三回合，所以策略模型與價值模型各更新360次。重用不算新作答，紀錄另記23,040次被更新流程讀取的動作。這個選卡實驗沒有逐token訓練，所以紀錄裡的有效目標數`effective_tokens`記為0；學習的單位是選卡，這不表示沒有學習資料。
