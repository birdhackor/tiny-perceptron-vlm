## 13.14 獎勵模型、價值模型與兩種基準各做什麼？

假設選卡前估計這題平均能拿0.4分；選卡後，獎勵模型給這次選的回答卡1分。前者叫**價值模型（critic）**，英文也叫value model：在這個單步任務裡，它只看題目情境，預測選卡之前平均能拿到的獎勵，也就是13.11的基準值（標題的「兩種基準」不是它，而是後面的舊策略與參考模型）。後者是13.10的獎勵模型，看情境與已選的卡，評這一次。兩者要回答的問題不同：價值模型不看選了哪張卡，所以不能替某一張卡打分；獎勵模型只評眼前這一張，不管平均。

教價值模型時，把這次觀察到的1分當目標，用平方代價`(預測−目標)²`。

```python
import torch

value = torch.tensor([0.4], requires_grad=True)
target = torch.tensor([1.0])
value_loss = (value - target).square().mean()
value_loss.backward()
print("價值模型的代價與梯度", round(value_loss.item(), 4), round(value.grad.item(), 4))
```

代價`(0.4−1)²=0.36`，梯度`2×(0.4−1)=−1.2`；下降更新會增加估計值，朝這次的分數靠近。這裡只計梯度，沒有更新網路。一次拿1分不代表每次都能拿1；要有許多次不同選擇的樣本，才教得出平均估計。PPO算優勢時用的是更新前保存的價值模型估計值（13.11），之後價值模型再另外學自己的估計。

![機制示意：五種角色各自的輸入、輸出與固定時間](../figures/rewrite-13-model-roles.svg)

圖中每個方框寫一種角色的輸入→輸出，以及它什麼時候固定：策略模型給選卡機率，獎勵模型評已選的卡，價值模型估平均；舊策略保存本輪收集時的機率，參考模型保留PPO開始時、已完成SFT的策略模型，在這段PPO期間固定。獎勵模型先教好再固定，價值模型與策略模型在PPO期間更新。兩種基準的用途不同：舊策略是13.12機率比的分母，參考模型則是下面KL的比較對象。這是四個小網路加每輪的舊紀錄，不代表一定載入五個完整大語言模型。

參考模型怎麼發揮作用？本章的PPO對策略模型另加一筆「偏離參考模型」的代價，用**KL散度**（Kullback–Leibler divergence）量偏離多少。若策略模型目前給兩卡的分布`p=[0.8,0.2]`，參考模型給`q=[0.5,0.5]`：

`KL(p||q)=Σ p_i log(p_i/q_i)=0.8×log(0.8/0.5)+0.2×log(0.2/0.5)≈0.1927`。

i是卡號，Σ表示把所有卡的項加起來。分布相同時每一項都是`log 1=0`，KL為0。卡數有限，才能把每張卡的項逐一加總；不是只用抽到的一張卡去估計。

```python
from tiny_perceptron.posttraining import exact_kl

policy_logits = torch.tensor([[0.8, 0.2]]).log()
reference_logits = torch.tensor([[0.5, 0.5]]).log()
print("相對固定參考的KL", round(exact_kl(policy_logits, reference_logits).item(), 4))
```

`exact_kl`接收的是候選分數（logits），自己先換成機率；把機率取log後當分數傳進去，換回來仍是原來的機率。輸出約0.1927。它的寫法如下：

```python
# 節錄自 tiny_perceptron/posttraining.py：exact_kl
def exact_kl(logits, reference_logits):
    """可枚舉候選的 KL(policy || reference)，參考分布不接受梯度。"""
    if logits.shape != reference_logits.shape or logits.ndim != 2:
        raise ValueError("兩份 logits 必須同為 (context, candidate)")
    log_policy = logits.log_softmax(-1)
    log_reference = reference_logits.detach().log_softmax(-1)
    return (log_policy.exp() * (log_policy - log_reference)).sum(-1)
```

- `if`檢查兩份分數形狀相同，而且是二維的`(情境數,候選數)`。
- `logits.log_softmax(-1)`把每個情境的候選分數換成log機率（13.3），`log_policy.exp()`再取回機率p。
- 參考那一份先`.detach()`：參考分布不接受梯度，KL只會推動策略模型。
- `(log_policy.exp() * (log_policy - log_reference)).sum(-1)`就是`Σ p_i(log p_i−log q_i)`，沿候選軸加總，每個情境得到一個KL。

這筆KL乘上一個係數後加進策略模型的代價（[13.15](#13.15)用0.1）。它表達的取捨是：獎勵高的卡值得多選，但策略模型離參考模型越遠，就要多付這筆代價；係數越大，越不願離開參考模型。

練習把第一段程式的`value`改成`torch.tensor([1.4], requires_grad=True)`，先預測平方代價0.16、梯度+0.8，下降方向改為降低估計。再把第二段`policy_logits`那行的`[[0.8, 0.2]]`改成`[[0.5, 0.5]]`，預測KL變0。這兩種檢查各自核對估計與偏離，不是回答已進步的證明。
