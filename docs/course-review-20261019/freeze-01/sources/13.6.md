## 13.6 beta加大，單次推動一定更大嗎？

固定策略較佳−2、較差−4，參考兩篇都是−3，相對差距為`(−2−(−4))−0=2`。此時已經偏向人標的較佳答案。只改beta，我們要看同一位置附近的代價與梯度，而不是比較重新訓練後的模型。

```python
import torch
from tiny_perceptron.alignment import dpo_loss

for beta in [0.1, 1.0, 5.0]:
    chosen = torch.tensor([-2.0], requires_grad=True)
    loss = dpo_loss(chosen, torch.tensor([-4.0]), torch.tensor([-3.0]), torch.tensor([-3.0]), beta=beta)
    loss.backward()
    room = 1 - torch.sigmoid(torch.tensor(beta * 2.0))
    print(beta, "代價", round(loss.item(), 6), "1-sigmoid", round(room.item(), 6), "梯度", round(chosen.grad.item(), 6))
```

`dpo_loss`的四個分數依序是策略較佳、策略較差、參考較佳、參考較差（定義見[13.5](#13.5)）。每輪新建chosen，避免累積前輪梯度；`room`是13.5梯度公式裡的`1−sigmoid(beta×margin)`，這裡margin是2。輸出的`4.5e-05`是4.5×10⁻⁵，也就是0.000045。三種beta的結果為：

| beta | 代價 | 1−sigmoid(beta×2) | 較佳分數梯度 |
| ---: | ---: | ---: | ---: |
| 0.1 | 0.598139 | 0.450166 | −0.045017 |
| 1 | 0.126928 | 0.119203 | −0.119203 |
| 5 | 0.000045 | 0.000045 | −0.000227 |

梯度是兩個數相乘：`−beta×(1−sigmoid(beta×2))`。beta從0.1到1，前一個數變成10倍，後一個數只從0.45降到0.12，梯度絕對值變大；beta到5時，`sigmoid(10)`已非常接近1，後一個數只剩0.000045，乘上5也只有0.000227，梯度反而變小。差距已經夠大、代價幾乎不再下降的情形叫**飽和**。學習率固定時，這個局部更新幅度也按梯度絕對值變。

beta與學習率作用不同：beta先進入代價公式，會改變飽和程度；學習率最後才乘梯度。DPO論文推導時根據的目標是「獎勵減去偏離參考的代價」，beta就是那筆偏離代價的係數：獎勵不變時，beta越大，策略模型離參考模型越遠就越不划算（[13.14](#13.14)會用KL量這個偏離）。這是推導裡的意義，不等於本表能預測完整訓練的最終行為。選設定仍要看驗證題與原能力，beta必須大於0。

練習把程式裡的`chosen = torch.tensor([-2.0], requires_grad=True)`改成`[-6.0]`，並把`room`那行的`beta * 2.0`改成`beta * -2.0`，讓margin變−2：模型現在偏向較差答案。先用公式預測beta 5的梯度：`−5×(1−sigmoid(−10))`約−5，不再接近0；beta 0.1與1則約−0.055與−0.881。再執行核對：模型仍偏向較差答案時，還談不上「已經做得夠好」的飽和，大beta的梯度反而最大。
