## 18.14 蒸餾後再量化能省多少？

教師、普通小學生、蒸餾小學生、量化蒸餾學生，四個版本要怎麼比較？[較小的架構](18.md#18.2)減少數字的個數，[量化](17.md#17.9)縮短部分數字的儲存；教師訊號則改變學生的學習目標，希望改善小學生的品質。只比較教師與最終的量化學生，會看不出哪一步帶來品質變化。

實驗應保留四組：教師、同架構的普通SFT學生、蒸餾學生、量化蒸餾學生。普通SFT學生與蒸餾學生架構相同，權重bytes通常相同，品質差異才主要反映學習訊號；蒸餾學生與量化蒸餾學生則可以隔離量化的影響。每組都在同一批獨立資料上量正確率、格式與行為，再一起列成本，不能只有教師與最終版兩個端點。

下面只檢查結構的儲存量，不執行任何蒸餾。教師架構特徵寬度16、兩層，學生特徵寬度8、一層；量化副本換掉學生的Linear，其他的embedding表與正規化保留浮點。程式算參數與buffer的數字大小，讓我們先知道這條組合路線在此模型能省多少。

```python
import copy
from tiny_perceptron.model import TinyLM, ModelConfig
from tiny_perceptron.quantization import replace_linear_layers

teacher = TinyLM(ModelConfig(width=16, layers=2))
student = TinyLM(ModelConfig(width=8, layers=1))
quantized = replace_linear_layers(copy.deepcopy(student), bits=4)


def payload_bytes(model):
    tensors = list(model.parameters()) + list(model.buffers())
    return sum(t.numel() * t.element_size() for t in tensors)


for name, model in (("教師結構", teacher), ("學生結構", student), ("量化學生結構", quantized)):
    print(name, "bytes", payload_bytes(model))
print("量化學生/教師比例", round(payload_bytes(quantized) / payload_bytes(teacher), 4))
```

`payload_bytes`同時算parameters和buffers，避免轉換後的量化權重登記成buffer，就從加總裡漏掉。對每個tensor，`numel()`數它有多少元素，`element_size()`給每個元素佔幾個bytes，兩者相乘才是這張表的儲存量；最後把各表相加。輸出應是67840、24416、15680 bytes，最後的比例約0.2311。

學生架構先減少參數，四位元轉換再縮到15680。4位元的數只占FP32的4/32＝1/8，但這只對被量化的權重成立。被量化的是注意力、FFN與輸出層的權重矩陣，共 `4×64+2×256+2112=2880` 個數：FP32要11520 bytes，4位元只要1440 bytes，正好八分之一。embedding表、位置表、正規化與偏移（bias）共 `24416−11520=12896` bytes沒有量化；每個量化層還要為每一列存一個FP32的刻度（scale），共336個、1344 bytes。合計 `12896+1440+1344=15680`，整個學生只縮到約64%，遠不到八分之一。這些是數字本身的大小，不是磁碟檔案或執行時的峰值。

三個模型都隨機初始化，名稱中的「結構」提醒你：此例只確認成本的組合，沒有宣稱學生已學會教師。實際流程應先執行蒸餾、保存與驗證該學生，再對同一份權重做PTQ，最後重跑[品質與行為的保留檢查](17.md#17.15)。訓練過程的教師算力與生成資料的成本也要另算，不能因為部署時只放學生就忽略它們。

在屬性任務的實際對照裡，特徵寬度64的屬性教師，數字共566,272 bytes；特徵寬度32的普通學生與蒸餾學生都是134,528 bytes。把同一個蒸餾學生轉成packed4，也就是[17.8](17.md#17.8)每兩個4位元的碼裝進一個byte的格式後，數字儲存降到64,160 bytes，但一題原本答對的`blue`變成`ble`。學生架構與低位元確實各減少了儲存，最後一步卻帶來看得見的品質退步。這些是權重與buffer的數字bytes，不是完整檔案或執行RAM；完整四版的結果與範圍見選讀。

蒸餾代價、量化權重的平均絕對誤差（MAE：逐格比較還原值與原值，取絕對差後平均）與最終答案的品質是不同的指標。若四位元讓行為明顯改變，可以先比較八位元，或另設保留敏感層浮點的實驗。本例只量化權重，沒有量化中間特徵，也沒有執行[17.12的範圍校準](17.md#17.12)；若後來要量化中間特徵，才需要另外設計那條範圍校準流程，不能只改本例的bits就說完成。這些取捨要由評估題的結果支持，不能只因最終的bytes比最大的教師小就宣布成功。

練習只把程式的 `bits=4` 改成 `bits=8`。先預測學生原版仍是24416、量化後比15680大；用上面的算式，8位元的2880個權重要2880 bytes，`12896+2880+1344=17120`，教師的67840不變，再執行核對。這只改了量化這一步，不會自動改變學生架構，也不會補上尚未執行的蒸餾訓練。

這次packed推論仍完整反量化到FP32，沒有量專用低位元kernel的速度，也沒有單獨量執行RAM。較小的儲存、分布代價與自由生成的品質仍是不同的結果，不能讓最終的壓縮比遮住未解決的任務問題。
