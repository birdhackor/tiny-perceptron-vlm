## 20.5 換個問法，為什麼仍可能是同一道舊題？

同一張貓照片，可以問數量，也可以問姿勢，兩題共用同一個畫面。若一題拿去訓練，另一題卻當成「沒見過的照片」來測試，模型可能早已熟悉這張圖。所以原圖、裁切與各種問法要先歸成同一個家族（[5.12](05.md#5.12)：從同一個來源衍生的題目算一家），再讓整個家族一起分到訓練、驗證或測試的其中一邊。

![原圖、裁切與同來源問題一起留在同一份資料。](../figures/natural-v4-family-crops.svg)

下面用四筆手寫記錄，檢查已分到訓練資料（`train`）與測試資料（`test`）的題目，有沒有同一個家族同時出現在兩邊。程式只做檢查，不會自動重新切分。

```python
records = [
    {"family": "貓照片A", "split": "train", "question": "有幾隻貓？"},
    {"family": "貓照片A", "split": "train", "question": "哪隻貓抬起前腳？"},
    {"family": "招牌照片B", "split": "test", "question": "招牌寫什麼？"},
    {"family": "招牌照片B", "split": "test", "question": "有沒有中文字？"},
]
train_families = {row["family"] for row in records if row["split"] == "train"}
test_families = {row["family"] for row in records if row["split"] == "test"}
print("訓練家族", sorted(train_families))
print("測試家族", sorted(test_families))
print("兩邊都有的家族", sorted(train_families & test_families))
```

`{row["family"] for row in records if ...}` 和 W.2 的生成式寫法相同，只是外面換成大括號：收集的結果是一個 set，重複的家族名只留一個。`if row["split"] == "train"` 只收分到訓練資料的記錄。兩個 set 之間的 `&` 取交集，也就是兩邊都有的項目；`sorted` 把結果排成清單再印出。這裡訓練只有貓照片A、測試只有招牌照片B，所以「兩邊都有的家族」是空的 `[]`。

練習把第二筆記錄的 `"split": "train"` 改成 `"split": "test"`，先預測「兩邊都有的家族」會印出 `['貓照片A']`：兩題文字不同，卻共用同一張照片。修正的方法是讓整個家族一起移動，不是替其中一題改個名字。

真正的資料還要核對來源 ID 與實際檔案，避免同一份像素換了檔名就被當成新照片。家族能分到多細也有限度：DOCCI 公開的相似群組只表示畫面相近，不等於已確認是同一次拍攝；OpenAssistant 的共享前文分支則確定屬於同一棵對話樹。資料有哪一種分組，能力聲明就只能說到哪一種。

三種資料的用途也要分清楚。驗證資料用來挑選本課的微調版本；測試資料要等版本定下來之後，才拿出來檢查一次。已經用過、公開過的舊題，之後仍可以拿來檢查修改後是否還能完成原本的工作，這叫回歸檢查（regression check）；但它已經不是訓練與選版都沒看過的新題。本課的家族隔離也只管得到本課的資料，不能排除上游訓練 Qwen 時曾看過這些公開素材。
