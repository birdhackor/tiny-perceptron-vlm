## 11.2 怎麼確認真正被更新的是哪一批參數？

只想教圖片接頭，就先把它的名字與數量列出，再確認最佳化器（optimizer）收錄的是同一批參數。接頭得到梯度、被列入更新名單、數值真的改變，是三個不同的檢查；本節先做第二個。

```python
import torch
from tiny_perceptron.model import TinyLM, ModelConfig
from tiny_perceptron.multimodal import MultiModalLM

model = MultiModalLM(TinyLM(ModelConfig(width=8)))
model.requires_grad_(False)
model.image_projector.requires_grad_(True)
trainable = []
parameters_to_update = []
for name, p in model.named_parameters():
    if p.requires_grad:
        trainable.append((name, p.numel()))
        parameters_to_update.append(p)
optimizer = torch.optim.AdamW(parameters_to_update, lr=0.001)
print("可訓練", trainable)
print("更新參數總數", sum(p.numel() for group in optimizer.param_groups for p in group["params"]))
```

`MultiModalLM` 把圖片入口（image encoder）、接頭與文字核心包成一個模型，實作見 [10.8](10.md#10.8)。程式先用 `model.requires_grad_(False)` 把整個模型的參數都設成不追蹤梯度，也就是凍結；再用 `model.image_projector.requires_grad_(True)` 只打開接頭。`requires_grad` 決定這個參數會不會收到新的梯度；`named_parameters()` 逐一給出每個參數的名字與參數本身，`numel()` 數它有幾個數字。文字核心的特徵寬度是 8（`ModelConfig(width=8)`），圖片入口輸出的特徵寬度是 16（`MultiModalLM` 的預設），所以接頭的權重有 8×16＝128 個、偏移 8 個，共 136。

迴圈把打開的參數同時放進兩份清單：`trainable` 記名字和數量，方便印出來核對；`parameters_to_update` 交給 AdamW。最後的 `print("更新參數總數", ...)` 從最佳化器那一側再數一次：`optimizer.param_groups` 是最佳化器保存的參數分組清單，每組是一個字典，用 `group["params"]` 取出這組的參數。`sum(...)` 裡有兩個 `for`：外層走過每一組，內層走過組裡的每個參數，把數字個數加總。本例只有一組，印出 136，和名單一致。這裡沒有算代價（loss），也沒有執行 step，只確認名單，不宣稱已經更新。

凍結文字核心的參數，不等於禁止它參與計算。只要計算仍被記錄，答案的代價可以穿過固定的文字運算，傳回接頭；若把整段文字計算放在 `no_grad()` 中，就可能切斷這條路。`eval()` 改變的是訓練模式的行為，也不等於凍結（見 [5.17](05.md#5.17)）。

分階段訓練時，名單也要跟著換。假設先只訓練接頭，下一階段改成只訓練最後一個文字區塊：只把接頭的開關改成 False，原本的最佳化器仍握著接頭，也還保存它的最佳化器狀態（Adam 的 m、v）；新打開的文字區塊則不會自動加入原本的最佳化器。最穩妥的做法是每個階段先決定範圍，再為這個範圍建立新的最佳化器。若沿用舊的，至少要把凍結參數的 `.grad` 設成 None，不能只設成 0：[5.5](05.md#5.5) 示範過，AdamW 會跳過 `.grad` 是 None 的參數，但一份全是 0 的梯度仍算參與這一輪，權重衰減照樣把它縮小，保存的 m 也可能讓它繼續移動（見 [5.3](05.md#5.3)）。

練習在第一段程式的 `model.image_projector.requires_grad_(True)` 之後、`trainable = []` 之前，加入一行 `model.language.blocks[-1].requires_grad_(True)`，再重新執行。`[-1]` 選最後一個文字區塊；這個預設模型只有一個區塊，所以預期名單多出名字以 `language.blocks.0` 開頭的參數，總數由 136 變成 976，多出的 840 個就是這個區塊的參數。這次只核對名單與數量；[11.3](#11.3) 接著檢查梯度通路，[5.1](05.md#5.1) 示範 step 前後的數值更新。真正訓練時，三件事都要核對。
