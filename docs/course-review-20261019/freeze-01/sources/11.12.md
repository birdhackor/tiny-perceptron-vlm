## 11.12 像素寫的0與標籤字串0，怎麼對應？

下面兩張五列、三欄的字形，左邊寫數字 0，右邊寫數字 1。希望讀字的結果是字串 `"0"`、`"1"`。先把這些真正看得見的筆畫與標籤配好，再談辨識器。

![五列三欄字形0與1，白格為筆畫，黑格為背景](../figures/rewrite-11-glyph-labels.svg)

```python
import torch

glyphs = {"0": ["111", "101", "101", "101", "111"], "1": ["010", "110", "010", "010", "111"]}
for label, rows in glyphs.items():
    image = torch.tensor([[int(c) for c in row] for row in rows], dtype=torch.float32)
    print("文字標籤", label, "像素形狀", tuple(image.shape))
    print(image)
```

字典的鍵是正確的文字標籤，值是五列字形。`[[int(c) for c in row] for row in rows]` 對每一列的每個字元做 `int(c)`，把 `"101"` 變成 `[1, 0, 1]`：`"1"` 成為像素亮度 1，`"0"` 成為背景 0，五列疊成形狀 `(5,3)` 的 tensor。因此「像素 0」表示暗，「標籤 0」表示應讀的字，角色不同。

從圖片讀出字元，稱為**光學字元辨識**（Optical Character Recognition，OCR）。可以用分類頭選 0 或 1，也可以讓文字核心逐 token 生成答案。分類只要選對類別就算對；生成若要求完整字串，`"00"` 比標籤多一字仍算錯。這段只建立資料，沒有更新辨識器。

字形與標籤要人工核對，梯度不會發現畫圖器把 1 畫成 0。只改位移或粗細、沒有改字元時，答案標籤仍相同。本例每個字只畫了一種字形，以下叫原形，指沒有位移、加粗等變化的原始畫法。若把數字 0 的原形與它的所有變體整組放進測試資料，訓練資料裡就沒有 0 這個類別。要檢查模型認不認得熟悉類別的新原圖，需要為每類準備多張獨立的原圖，再把同一張原圖及其變體當成一個家族（family），整組放在訓練或測試的同一邊。若要送進 [10.5](10.md#10.5) 那種 RGB 圖片入口，要先把 `(5,3)` 的單通道小圖放到固定大小的黑色底圖上，再把這一層明確複製成紅、綠、藍三個通道；不能把 `(5,3)` 直接當成 `(3,16,16)`。

專案實際訓練過一個讀數字的小模型（以下叫 OCR 實驗）：把 0 到 99 這 100 個字串用固定的點陣字形（每個數字寬 5、高 7 個像素）畫在 16×16 的黑底圖上，每個字串再畫成左移 1、不移、右移 1 三個版本。100 個字串打亂後，80 個當訓練、10 個當驗證、10 個當測試，同一字串的三個版本一定放在同一邊，所以測試題是 10 個字串×3＝30 題。訓練資料已用到 0–9 全部字元，測試考的是熟悉字元組成的新字串，例如 `13`、`86`。同一批訓練題的代價由約 9.28 降到 0.81，30 題測試題卻只完整讀對 2 題，留下「熟悉的練習改善，不等於新組合讀對」這個例子。這個實驗沒有測新的字元類別、另一套字體或手寫。下一節再看整串與逐字的評分。

練習把第一段程式中 `"1"` 的第一列 `"010"` 改成 `"110"`，先預測印出的第一列變成 `[1., 1., 0.]`，標籤仍是 1。改變字體外觀和改變需要辨識的字，是不同的資料操作。
