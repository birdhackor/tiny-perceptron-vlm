## 17.8 兩個4-bit值，如何裝進一個byte？

七個4-bit碼若各放進一個int8，仍佔7byte。把兩個碼放進同一個byte，才只需4byte。七個碼兩兩一組，最後一組只有一個，另一半要補一個值；拆回時要記得原本只有七項。

函式庫的打包器`pack_int4`接受有號整數−8至7，先各加8，換成0至15，剛好是4個bit能表示的16種值。一個byte有8個bit：第一碼放在低四位，第二碼放在高四位。放進高四位等於乘16，所以這個byte的值是`第二碼×16＋第一碼`，兩個碼都取加8後的值。例如−8、−1先變成0、7，byte是`0111 0000`，即`7×16＋0＝112`。

![編碼示意：第一碼在低四位，第二碼在高四位，拆回順序相同](../figures/rewrite-17-int4-byte.svg)

圖由上往下：兩個原值各加8；第二碼7寫成二進位`0111`放在高四位，第一碼0寫成`0000`放在低四位，合起來是112；拆回時先取低四位、再取高四位，各減8。

```python
import torch
from tiny_perceptron.quantization import pack_int4, unpack_int4

q = torch.tensor([-8, -1, 0, 1, 7, 2, 3], dtype=torch.int8)
packed = pack_int4(q)
restored = unpack_int4(packed, q.shape)
print("原數字", q.tolist())
print("packed", packed.tolist(), "bytes", packed.numel() * packed.element_size())
print("拆回", restored.tolist())
assert torch.equal(q, restored)
```

packed是`[112,152,175,139]`，佔4byte。第二組0、1加8後是8、9，`9×16＋8＝152`；第三組7、2加8後是15、10，`10×16＋15＝175`；末項3加8是11，另一半補上8（減8後代表0），所以最後一個byte是`8×16＋11＝139`。`assert torch.equal`確認拆回的整數與原本完全相同。兩個函式的原樣如下：

```python
# 節錄自 tiny_perceptron/quantization.py：pack_int4、unpack_int4
def pack_int4(integers):
    flat = integers.flatten().to(torch.int16)
    if ((flat < -8) | (flat > 7)).any():
        raise ValueError("int4 可儲存 -8 到 7")
    values = (flat + 8).to(torch.uint8)
    if values.numel() % 2:
        values = F.pad(values, (0, 1), value=8)
    return values[0::2] | (values[1::2] << 4)


def unpack_int4(packed, shape):
    values = torch.stack((packed & 15, packed >> 4), -1).flatten().to(torch.int16) - 8
    count = 1
    for dimension in shape:
        count *= dimension
    return values[:count].reshape(shape).to(torch.int8)
```

`pack_int4`先`flatten()`攤平成一排，並轉成範圍較寬的整數型別`torch.int16`，再檢查每個數是否落在−8到7。`(flat < -8) | (flat > 7)`逐項標出超出範圍的位置，這裡的`|`是「或」；`.any()`只要有一項為真就成立，於是`raise`報錯。`(flat + 8).to(torch.uint8)`把−8至7換成0至15。`values.numel() % 2`的`%`是取餘數，項數是奇數時餘1，`F.pad(values, (0, 1), value=8)`就在尾端補一個8。

最後一行兩兩合併：`values[0::2]`從第0項起每隔一項取一個，是每組的第一碼；`values[1::2]`從第1項起取，是每組的第二碼。`<< 4`把位元往左移四位，等於乘16；接著的`|`把兩份不重疊的位元合在一起，這裡等於相加。

`unpack_int4`反過來做：`packed & 15`只留下低四位，等於除以16的餘數；`packed >> 4`把位元往右移四位，等於除以16的商。`torch.stack(…, -1).flatten()`把每個byte拆出的「低碼、高碼」依序排回一排，順序與打包前相同，再減8回到−8至7。`for dimension in shape`把形狀各軸的長度相乘，`count *= dimension`是「乘上後存回」，得到原本的項數7；`values[:count]`只取前7項，丟掉補上的那一個，最後`reshape(shape)`恢復原形狀。

```python
from torch.nn import functional as F

print("& 15", (packed & 15).tolist(), "除以16的餘數", (packed % 16).tolist())
print(">> 4", (packed >> 4).tolist(), "除以16的商", (packed // 16).tolist())
same = torch.equal(pack_int4(q), packed)
print("與函式庫版本相同：", same)
assert same
```

第三段用十進位核對拆法：`& 15`與除以16的餘數都是`[0,8,15,11]`，`>> 4`與商都是`[7,9,10,8]`。最後三行用第二段節錄的`pack_int4`重算一次，和第一段用函式庫版本算好的`packed`比較，先印出是否相同（True），再用`assert`確認；節錄的`pack_int4`要用`F.pad`，所以先匯入`F`。這要在Notebook裡依序執行過第二段才成立：跳過它，`pack_int4`仍是第一段匯入的函式庫版本，印出的True就沒有核對到節錄。

這個打包步驟是無損的，但在它之前，浮點數換成碼時已可能有誤差。`quantize_symmetric`只用−7至7，所以打包器雖然裝得下−8，量化時並不會出現。完整的層還要保存刻度、形狀、位元設定與偏移，[17.7](17.md#17.7)的`QuantizedLinear`就是這樣使用這兩個函式。一般乘法也不能把112當成原權重，要先按格式拆開，或交給懂得這種格式的運算。

練習在第一段程式的`q = torch.tensor([-8, -1, 0, 1, 7, 2, 3], dtype=torch.int8)`方括號裡最後加上`, 4`，變成八個數。先預測：八個數仍佔4byte，最後一個byte的高四位從補上的8變成4＋8＝12，byte改成`12×16＋11＝203`，拆回時也不用再丟掉補位。
