## 17.15 平均誤差很小，答案為什麼仍會改變？

候選只有兩個，依序是EOS（結束標記）與「貓」。原分數`[1,1.005]`表示EOS得1分、貓得1.005分，所以選貓；量化後變成`[1.01,1.005]`，改選EOS，也就是停止回答。平均絕對差只有`(0.01+0)/2＝0.005`，卻跨過了第一名的邊界。

```python
import torch

tokens = ["<EOS>", "貓"]
original = torch.tensor([1.0, 1.005])
quantized = torch.tensor([1.01, 1.005])
mae = (original - quantized).abs().mean().item()
print("分數MAE", round(mae, 4))
print("原版選擇", tokens[original.argmax().item()])
print("量化版選擇", tokens[quantized.argmax().item()])
```

`argmax`取最大分數的索引，再查出候選名稱。輸出是0.005、貓、EOS。這是手設分數的單步反例，沒有證明真模型必定提早停止；它說明平均數不能保證離散的選擇不變。若兩版選到不同的詞而仍繼續生成，下一步讀入的已生成內容也不同，後續差異還可能累積。

真正比較時，讓原版與量化版讀同樣的提示，用同樣的輸入處理與生成設定。既看正確答案的預測代價，也實際生成，分開核對內容、範圍、格式與是否正常以EOS結束。若用隨機抽樣，兩版配對使用相同種子，另換幾個種子觀察；每步都選最高分的生成方式叫greedy，報告時要寫明用了哪一種。

品質檢查要和模型檔案大小、記憶體與速度一起報告。[17.14](17.md#17.14)的QAT比較另有共同起點與更新預算；不能拿更新步數不同的PTQ，當成只改變QAT的對照。

練習把程式中`original`與`quantized`的第二個分數`1.005`都改成`2.0`。先預測：MAE仍是0.005，兩版都選貓。同樣的誤差，在排名餘裕不同時，後果也不同。
