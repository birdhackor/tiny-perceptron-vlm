## 19.14 同一個世界，怎樣避免三份資料互相洩題？

假設一筆事件是「A=2、B=6，A 設成 5，再設成 1，查詢 A」。Looped 解題器用它學最後狀態；機率判斷器可能用它學「這是兩盒追蹤任務」；Auto 又用它記不同輪數能否答對。如果各自隨機切資料，同一事件便可能在 Looped 解題器的訓練資料、機率判斷器的測試資料中同時出現，最後的整合分數不再代表新情境。

因此先給每個底層事件一個固定的**家族** ID，再共同決定切分。家族包含同一底層事件的措辭改寫、不同問題及候選重排；從家族衍生的兩個成品與 Auto 的紀錄，全部繼承相同的切分。題目 ID 標一筆具體輸入，家族 ID 標它和哪些題有共同來源，兩者角色不同。

下面直接用成品資料產生器的兩個函式，示範同一家族怎樣固定分到同一份；不訓練模型。它們會用到產生器開頭的 `SPLITS`（四份資料的名稱）與 `digest`，先取來：

```python
import hashlib

from tiny_perceptron.lesson_products.data import SPLITS, digest
```

```python
# 節錄自 tiny_perceptron/lesson_products/data.py：family、split_of
def family(task, facts):
    return task + ":" + digest(facts)


def split_of(family_id, salt):
    bucket = int(hashlib.sha256((salt + ":" + family_id).encode()).hexdigest()[:12], 16) % 1000
    return SPLITS[0 if bucket < 760 else 1 if bucket < 840 else 2 if bucket < 920 else 3]
```

- `family(task, facts)` 由任務名與底層事實組出家族 ID。兩盒追蹤的事實是「A 的初值、B 的初值、事件序列」。`digest(facts)` 把事實寫成固定格式的 JSON，再算 SHA-256 指紋（[5.11](05.md#5.11)用過的那種固定長度十六進位字串）；同樣的事實永遠得到同一串，所以家族 ID 也固定。查詢 A 還是 B、換措辭、刪掉欄位或重排候選，都不在 `facts` 裡，這些衍生題都帶著同一個家族 ID。
- `split_of(family_id, salt)` 只收家族 ID 與一段固定字串 `salt`，題目文字根本不是它的輸入，所以同一家族不論衍生幾筆、怎麼改寫，都分到同一份。`salt + ":" + family_id` 先把兩段字串接起來；`.encode()` 換成 bytes，`hashlib.sha256(…).hexdigest()` 得到 64 個十六進位字元；`[:12]` 取前 12 個，`int(…, 16)` 把它當十六進位數換成整數，`% 1000` 取除以 1000 的餘數，得到 0–999 的「桶號」。hash 的結果看起來像隨機，卻每次相同，所以能把家族穩定又平均地撒進各桶。
- `return SPLITS[…]` 依桶號挑資料份：`0 if bucket < 760 else 1 if …` 是接連的條件運算式，從左往右找第一個成立的條件。桶號 0–759 取 `SPLITS[0]`（`train`，訓練資料），760–839 是 `calibration`（校準資料），840–919 是 `policy`（決策資料），920–999 是 `test`（測試資料），也就是約 76%、8%、8%、8% 的家族。校準資料與決策資料的用途見下文。

```python
salt = "finite-worlds-v1-coverage-1"
for a, b in [(2, 6), (2, 3)]:
    world = family("boxes", (a, b, (("swap", 0),)))
    print("A=", a, "B=", b, "交換 → 家族", world[:16], "→", split_of(world, salt))
print("四份資料：", SPLITS)
```

`(("swap", 0),)` 表示事件序列裡只有一個「交換」。輸出顯示 A=2、B=6、交換的世界分到 train；只把 B 的初值改成 3，就是另一個世界，分到 test。不同家族各自分，同一家族的所有衍生題跟著走。`salt` 抄自資料 manifest 記下的 `split_salt`；換一個 salt 就會換一種分法。作者在訓練前依事先訂的條件選定它，例如 19 種加法答案（0 到 18）都要出現在訓練資料，沒有看任何成績。5–6 個事件的世界不進這四份，另做壓力測試（19.15）。

這能防同家族跨份，卻不自動證明測到新推理能力：如果所有問題仍套同一句型，模型可能只熟悉語法。實驗紀錄還會分開列未見事件組合、實體／措辭變化及更長事件序列；每種測試說明哪些關係見過、哪些沒有。有限語法任務可先驗收有限能力，不能改名成一般中文理解。

四份資料各有用途。train 用來更新參數。驗證資料再分成兩份：**校準資料**（calibration split）選[9.14](09.md#9.14)的校準溫度 τ；**決策資料**（policy split）選檢查點與 Auto 規則。test 是測試資料，封存到設定凍結後才評分。若已看過某批測試題的錯題並修訓練，那批只能作開發診斷，新的最後評估另留資料。不能反覆查看同一份測試資料，仍稱一次最後檢查。

這版資料的規模如下。不同問題、缺欄情況與候選集合會從同一個世界衍生多列，不能把列數當成同樣多個獨立世界。

| 規模 | Looped 解題器 | 機率判斷器 |
| --- | ---: | ---: |
| 全部資料列（四份加上各種變化測試） | 47,673 | 420,110 |
| 主要測試題 | 2,998（追蹤 2,956、加法 42） | 33,577（服務選擇 11,797、資訊充分 10,890、規準 10,890） |
| 主要測試題來自幾個家族 | 1,488 | 554 |
| 跨切分重複的輸入句 | 0 | 5,453 種，出現在 215,427 列 |

實際查重還發現一個重要差別：Looped 解題器沒有跨切分相同的輸入；機率判斷器則有 5,453 種**跨切分重複的輸入句**，也就是同一段輸入（連同問題與候選）出現在不同資料份的列裡。例如 `卡片進度;申請編號=?` 在四份資料裡都出現：許多不同的卡片世界刪掉申請編號後，都只剩這一句，而且答案都一樣（服務是查卡片、資訊不齊、等級 0）。這些重複沒有互相衝突的答案，卻表示「家族沒有跨份」不等於「模型從未看過這段文字」。因此機率判斷器的高分只支持固定任務與句型，不能宣稱對全新語義或一般中文的泛化。

每個版本保存生成器、seed、世界規則、家族與題目ID、欄位說明、檔案指紋及切分統計，見[資料manifest](https://github.com/birdhackor/tiny-perceptron-vlm/blob/main/docs/lesson-products/data-v2-manifest.json)（看 `config` 的 `split_salt` 與 `audit`）及[token與重複輸入稽核](https://github.com/birdhackor/tiny-perceptron-vlm/blob/main/docs/lesson-products/data-v2-token-audit.json)（看 `c.cross_split_shared_token_observations`）。上面那句卡片輸入的四份答案見[重複輸入例](https://github.com/birdhackor/tiny-perceptron-vlm/blob/main/docs/lesson-products/results/duplicate-observation-example-v1.json)。合成資料不等於免查洩漏；同義重排、對稱算式或相同事件的等價編碼，也要先定義如何合併家族。

練習：`2+3`與`3+2`要不要同組？若本次希望測未見加數組合，就應用排序後的加數建立共同家族。這是測試目標決定的契約，不能等看到成績才改。可以在第三段程式最後加一行 `print(family("sum", (1, 2, 3)) == family("sum", (3, 2, 1)))`，先預測會印 False：`family` 只看你給它的事實，順序不同就是不同事實。本課的產生器在呼叫 `family` 之前，先把三個加數排好順序，`1+2+3` 與 `3+2+1` 才同屬一個家族。
