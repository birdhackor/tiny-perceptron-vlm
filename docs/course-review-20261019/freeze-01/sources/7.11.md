## 7.11 預訓練模型怎麼學會對話？

讀文章時，模型練習「原文接下來是什麼」；當助手時，還要練「這位使用者要什麼回答」。先在大量文章上練續寫的階段叫**預訓練**（pretraining）。已經訓練好、拿來當下一階段起點的模型叫**底座**（base model），例如預訓練後保存、再拿去做 SFT 的模型。監督式微調把正確的問答與角色邊界放進輸入，只用回答位置的目標，繼續調整底座的參數。它仍是預測下一個 token、仍用 [1.8](01.md#1.8) 的交叉熵，不需要另換一種模型才能回答。

先用 0+0→0、0+1→1 兩筆對話，把輸入、答案與有效目標接到模型。下面新建一個隨機的小模型，只求梯度，讓這條從資料到代價的路看得見；真正的微調會載入底座和它配套的字表，再用 [5.1](05.md#5.1) 的最佳化器更新參數。`pad_batch` 回傳的 `valid` 標出非填充位置（[7.10](#7.10)）；Y 中不是回答的目標都是 −100，`masked_loss` 略過它們，只計回答的 bytes 與 EOS（[7.1](#7.1)）。問題仍在輸入裡供模型讀取。

```python
import torch
from tiny_perceptron.data import toy_conversations, render_chat, pad_batch
from tiny_perceptron.model import TinyLM, ModelConfig, masked_loss

torch.manual_seed(42)
examples = [render_chat(messages) for messages in toy_conversations()[:2]]
x, y, valid = pad_batch(examples)
model = TinyLM(ModelConfig(width=8))
loss = masked_loss(model(x, valid=valid)["logits"], y)
loss.backward()
print("batch形狀", x.shape, "有效目標數", (y != -100).sum().item())
print("代價", loss.item())
```

`toy_conversations` 產生專案合成的加法對話，前兩筆的問題是 0+0 與 0+1，回答 0 與 1；每個答案是一個 byte 加 EOS，所以有效目標共 4 個。`pad_batch` 回傳 X、Y 與 valid；這兩筆一樣長，每筆 10 個位置，形狀是 `[2,10]`。模型在每個位置輸出 264 個候選分數（256 種 byte 加 8 個特殊 token）。最後的代價為正，`backward()` 算出梯度，表示資料、模型和代價接通了；這段沒有呼叫 `optimizer.step()`，還沒有真正訓練。

`toy_conversations` 本身只有幾行：

```python
# 節錄自 tiny_perceptron/data.py：toy_conversations
def toy_conversations():
    return [
        [{"role": "user", "content": f"{a}+{b}=?"}, {"role": "assistant", "content": str(a + b)}]
        for a in range(4)
        for b in range(4)
    ]
```

這是 [1.1](01.md#1.1) 教過的清單寫法 `[... for ...]`，只是寫了兩個 `for`：外層的 a、內層的 b 各從 0 跑到 3，所以依序產生 0+0、0+1、0+2、0+3、1+0……共 16 筆。每筆是一份消息清單：`f"{a}+{b}=?"` 是 [7.10](#7.10) 的 f 字串，把 a、b 的值填進問題；`str(a + b)` 把和轉成文字當回答。`toy_conversations()[:2]` 取到的就是 0+0 與 0+1。

要知道微調有沒有用，得固定題目與選字規則（[1.15](01.md#1.15)），比較微調前後的內容、格式和原本的能力。為了比較而分開訓練的版本叫**支線**，比較時要寫明它們差在哪些條件，例如起點、資料或更新次數。專案用另一份合成資料比較過兩條支線，訓練題是 45 筆屬性問答：題目用欄位列出顏色、形狀等屬性再發問，例如 `color=green;shape=square;pitch=low;shape?`，答案是 `square`。兩條都從同一份隨機參數出發。第一條直接用 SFT 的資料格式（加上角色標記，只用回答位置的目標）訓練，沒有先學過續寫。第二條先把同一批問題與答案接成純文字練續寫，再用同樣的格式微調。這個文字階段只讀這 45 筆，不是在大量文章上預訓練；它也讓第二條比第一條多更新 250 次，所以成績差異不能全算在「先練續寫」這個安排上（細節見補充）。業界為什麼常分成兩個階段、資料成本差在哪裡，[7.17](#7.17) 再展開；眼前只需記住：材料從文章換成了回答示範。

練習取第一筆對話，沿用 7.1 的消息結構：每項是含 role 與 content 的字典，第二項是 assistant 的答案。下面逐項複製字典成新的消息清單，再把答案 0 改成 3。

```python
messages = [message.copy() for message in toy_conversations()[0]]
messages[1]["content"] = "3"
exercise_x, exercise_y = render_chat(messages)
print("練習的有效目標", exercise_y[exercise_y != -100].tolist())
```

`message.copy()` 建立一份新字典；這裡 role 與 content 都是字串，逐項複製就足以讓修改只發生在練習的副本，`toy_conversations()` 給的原資料仍保留正確答案。`exercise_y[exercise_y != -100]` 只選出要計代價的答案 ID。執行前先預測：原本「0」的 byte 48 加 8 是 56，改成「3」後是 51 加 8＝59，輸出應為 `[59, 2]`；EOS 仍是 2，角色與問題都不變。
