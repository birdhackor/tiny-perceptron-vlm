## 10.8 沒附圖時，包裝會改變原文字計算嗎？

前三節的零件——圖片入口、接頭、展開——要和文字核心組成一個能讀圖的模型。本課把它們包成 `MultiModalLM`：裡面放著原本的文字模型，外加圖片用的零件。包好之後先核對一件事：沒附圖時，包裝是否原封不動地使用文字核心？同一份文字模型、同一串三個 token ID，直接交給文字核心，和經過包裝交給它，候選分數應該逐項相同。這核對的是包裝有沒有改動計算，不是模型會不會寫文章。

函式庫的 `MultiModalLM` 同時處理圖片和聲音；本章只走圖片路線，下面是只保留圖片的精簡版。省略的是聲音入口（`audio`）、聲音接頭（`audio_projector`）和對聲音佔位 token 的檢查，第 12 章把聲音接進同一個 `MultiModalLM` 時才用到（[12.9](12.md#12.9)）。參數名稱和函式庫一致，兩者才能載入同一組參數值。

```python
# 精簡自 tiny_perceptron/multimodal.py：MultiModalLM（省略聲音入口、聲音接頭與聲音佔位 token 的檢查）
import torch
from torch import nn
from tiny_perceptron.data import IGNORE, ByteTokenizer
from tiny_perceptron.multimodal import VisionEncoder, expand_modalities


class MultiModalLM(nn.Module):
    def __init__(self, language_model, vision_width=16):
        super().__init__()
        self.language = language_model
        self.vision = VisionEncoder(vision_width)
        self.image_projector = nn.Linear(vision_width, language_model.config.width)

    def forward(self, ids, labels=None, *, image=None):
        tok = ByteTokenizer()
        if image is None:
            if (ids == tok.image_id).any():
                raise ValueError("placeholder 缺少配對圖片")
            return self.language(ids.unsqueeze(0))
        features = {tok.image_id: self.image_projector(self.vision(image.unsqueeze(0)))[0]}
        if labels is None:
            labels = torch.full_like(ids, IGNORE)
        x, y = expand_modalities(ids, labels, self.language.embedding, features, {tok.image_id})
        result = self.language(embeddings=x)
        result["labels"] = y
        return result
```

`__init__` 收下已建好的文字模型，存成 `self.language`；再建 [10.5](10.md#10.5) 的圖片入口 `self.vision` 和 [10.6](10.md#10.6) 的接頭 `self.image_projector`。接頭的輸出寬度直接讀文字核心的設定 `language_model.config.width`，兩邊因此接得上。

`forward` 參數列裡的 `*` 表示後面的參數只能寫名字傳，例如 `image=scene()`，避免把圖片誤當成 `labels`。`tok = ByteTokenizer()` 只是為了取得特殊 token 的 ID，例如 `tok.image_id` 就是 5。沒附圖時（`image is None`），`(ids == tok.image_id).any()` 先查 `ids` 裡有沒有圖片佔位 token：`==` 得到一串真／假，`.any()` 問其中是否有任何 True。有的話報錯，因為佔位 token 沒有配對的圖片，不能默默拿它去查 embedding 表、當成一般文字算下去；沒有的話，`return self.language(ids.unsqueeze(0))`——和直接呼叫文字核心完全一樣，只多加了筆數軸。這一行就是本節問題的答案。

附圖時，圖片先加上筆數軸，經過圖片入口與接頭，`[0]` 再取出這張圖的 16 條特徵，用字典交給 [10.7](10.md#10.7) 的 `expand_modalities`。沒給 `labels` 時，`torch.full_like(ids, IGNORE)` 做出和 `ids` 一樣長、全是 −100 的目標。`self.language.embedding` 是文字核心自己的 embedding 表，圖片佔位 token 以外的 token 都用它查。最後的 `self.language(embeddings=x)` 用到函式庫 `TinyLM` 的另一種輸入：不給 token ID，直接給已經算好的向量，跳過查 embedding 表那一步，位置向量與後面的計算照舊；[4.6](04.md#4.6) 的精簡版省略了這個參數。錯開好的目標放進回傳字典的 `"labels"`，訓練時拿它算代價。

下面核對精簡版與函式庫版本，也回答本節的問題：

```python
from tiny_perceptron.model import ModelConfig, TinyLM
from tiny_perceptron.multimodal import MultiModalLM as LibraryMultiModalLM, scene

torch.manual_seed(0)
lm = TinyLM(ModelConfig(width=8))
ours = MultiModalLM(lm)
library = LibraryMultiModalLM(lm)
loaded = ours.load_state_dict(library.state_dict(), strict=False)
print("精簡版缺少的參數", loaded.missing_keys)
print("函式庫多出的參數", loaded.unexpected_keys)
ids = torch.tensor([1, 20, 30])
same_text = torch.equal(lm(ids[None])["logits"], ours(ids)["logits"])
print("沒附圖：與直接呼叫文字核心相同", same_text)
sequence = torch.tensor([1, 5, 4, 73, 2])
same_image = torch.equal(ours(sequence, image=scene())["logits"], library(sequence, image=scene())["logits"])
print("附圖：與函式庫版本相同", same_image)
assert same_text and same_image and loaded.missing_keys == []
```

兩個包裝包住同一個 `lm`，文字核心本來就共用；圖片入口與接頭則各自從亂數開始。`state_dict()` 把模型每個參數的名字和數值收成一本字典，`load_state_dict` 依名字把數值抄進另一個模型；`strict=False` 允許兩邊的名字不完全相同，並回報差在哪裡。第一行印出空清單 `[]`：精簡版的每個參數，在函式庫版本都找得到同名的一份。第二行列出的名字全以 `audio.` 或 `audio_projector.` 開頭：函式庫版本多出來的只有聲音的零件。

`ids` 裡沒有圖片佔位 token：1 是 BOS，20、30 是一般的 byte ID。`lm(ids[None])` 直接交給文字核心，`ours(ids)` 經過包裝；`torch.equal` 比的是整份 `logits`，一筆、三個位置、每個位置 264 個候選分數，要逐項相同才印 True。結果是 True：包裝沒有改變文字計算。即使權重是隨機的、兩邊都答不好，一致性仍然成立；它和答案正確是兩個問題。附圖的 `sequence` 是 10.7 那串序列，圖片換成 `scene()` 的紅方塊，展開成 16 條特徵；精簡版與函式庫版本算出的候選分數也完全相同。最後的斷言把這三項比較一起核對。

訓練之後若開放文字權重更新，文字計算可能合理地改變；是否保住舊技能，要用固定的文字題核對答案。若一換包裝分數就不同，先查輸入、位置與運算路徑；若只在訓練後退步，再查更新範圍與資料。
