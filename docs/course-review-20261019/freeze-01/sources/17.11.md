## 17.11 中間特徵也量化，多了哪一種誤差？

前幾節只量化權重。若連送進層的輸入也換成碼，誤差就多一個來源。用兩筆輸入x與權重w，刻意都取同一組數字`[0.7,0.2]`、`[−0.7,1.2]`，方便對照。第一種比較只量化w；第二種把x與w都量化到刻度0.5。想看清的是：第二種比較多出來的，是輸入特徵的量化誤差。

這裡的**中間特徵（activation）**，指送進一層的輸入，以及模型計算途中產生、再交給下一層的數字。英文activation也用來稱呼[2.4](02.md#2.4)那種讓數字轉彎的**啟用函式（activation function）**，例如ReLU、GELU；本章說的是數值，不是函式。[16.10](16.md#16.10)的中間特徵重算（activation checkpointing）也是指這些數值。權重固定不變，中間特徵卻會隨輸入內容改變。

```python
import torch

x = torch.tensor([[0.7, 0.2], [-0.7, 1.2]])
w = torch.tensor([[0.7, 0.2], [-0.7, 1.2]])
scale = 0.5


def simulate_quantization(t):
    return (t / scale).round() * scale


qx, qw = simulate_quantization(x), simulate_quantization(w)
reference = x @ w.T
weight_only = x @ qw.T
both = qx @ qw.T
print("原輸出", reference.round(decimals=4).tolist())
for name, output in (("只量化權重", weight_only), ("權重與特徵都量化", both)):
    print(name, output.round(decimals=4).tolist(), "MAE", round((reference - output).abs().mean().item(), 4))
```

`simulate_quantization`量化後立即還原，仍回傳浮點tensor，沒有打包，也沒有低位元kernel。刻度固定為0.5是為了只看誤差；實際的權重與中間特徵通常各用自己的刻度。最後的`for name, output in (…)`每次取出一組名稱與輸出，依序印出兩種比較。

原輸出約`[[0.53,−0.25],[−0.25,1.93]]`。只量化權重的MAE是0.19，兩邊都量化是0.24。看非對角的兩格：只量化權重時是−0.15與−0.35，有誤差；兩邊都量化卻剛好回到−0.25。最後一格1.93變成1.25，比只量化權重的1.55更差。多一個誤差來源，不代表每一項一定更糟，有時方向會偶然抵消。

完整任務仍要另外檢查，而且中間特徵的範圍可能隨句子長度、圖片或音量改變。本章既有的整模型PTQ與QAT實驗只量化Linear權重，沒有量化中間特徵，那些分數不能當成本節做法的成績。

練習把程式的`x = torch.tensor([[0.7, 0.2], [-0.7, 1.2]])`第一列改成`[1.0, 0.0]`。1與0都剛好是刻度0.5的還原值，量化後不變，所以兩種比較的第一列相同，都是`[0.5,−0.5]`。
