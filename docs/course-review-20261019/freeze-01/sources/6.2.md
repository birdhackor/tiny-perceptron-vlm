## 6.2 常見片段怎麼合併？

兩份文件 `abab` 與 `abac`。數相鄰的兩個字母：a-b 共 3 次（第一份 2 次、第二份 1 次），b-a 2 次，a-c 1 次。把最常見的 a-b 接成一個新單位 ab 之後，第一份從四項縮成兩項 `[ab, ab]`，第二份縮成三項 `[ab, a, c]`；兩份原文仍是同樣的四個字母，變的只是切法。

反覆「數相鄰對、合併最常見的一對」，這種方法叫**位元組對編碼**（Byte Pair Encoding，BPE）。名字裡的「位元組」（byte）來自它最早是一種壓縮 byte 資料的方法；合併的步驟本身不管單位是字母還是 byte。這裡先用字母 a、b、c 看清規則，[6.3](#6.3) 再改成從 256 種 byte 開始。

下圖上半是合併前的兩份文件與三種相鄰對的次數，下半是把 a-b 接成 ab 之後的結果。每份文件各自合併，不跨文件：第一份結尾的 b 和第二份開頭的 a 不算相鄰。

![共有三對a-b，合併後保留各文件邊界](../figures/rewrite-06-02-bpe-merge.svg)

下面的程式先數相鄰對、挑出最常見的一對，再逐份文件合併。數次數用 [1.4](01.md#1.4) 的 `Counter`，這次每個鍵是一對相鄰符號；配出相鄰對用 [1.3](01.md#1.3) 的 `zip` 與切片。

```python
from collections import Counter

corpus = [list("abab"), list("abac")]
pairs = Counter()
for row in corpus:
    for left, right in zip(row, row[1:]):
        pairs[(left, right)] += 1
pair = pairs.most_common(1)[0][0]


def merge(row, pair):
    out = []
    i = 0
    while i < len(row):
        if i + 1 < len(row) and tuple(row[i : i + 2]) == pair:
            out.append("".join(pair))
            i += 2
        else:
            out.append(row[i])
            i += 1
    return out


print(pairs)
print("選擇", pair, "結果", [merge(row, pair) for row in corpus])
```

`list("abab")` 把字串拆成四個字母的清單。`row[1:]` 從第二項開始，`zip(row, row[1:])` 便配出每一對相鄰字母。`pairs[(left, right)] += 1` 把這一對的次數加 1 再存回；`Counter` 把還沒見過的鍵當作 0 次，所以不必先列出每一對。`most_common(1)` 取最常見的一項，得到 `[(("a", "b"), 3)]` 這樣的清單：第一個 `[0]` 取出「符號對、次數」這一項，第二個 `[0]` 再取出符號對 `("a", "b")`。第一行輸出 `Counter({('a', 'b'): 3, ('b', 'a'): 2, ('a', 'c'): 1})`，和手數的一樣。

這裡 a-b 唯一最多。若有兩對一樣多，要事先規定固定的選法，否則同一份資料可能學出不同的規則；`Counter` 遇到平手時，按第一次數到的先後排列。

`merge` 從左到右掃過一份文件，`i` 記錄目前看到第幾項。`while 條件:` 的意思是「條件成立就再做一次縮排裡的程式」；它和 [W.2](../first-steps.md#W.2) 的 `for` 不同，不會自動逐項走過清單，每次前進幾項由我們自己決定。`if` 的條件用 `and` 連起兩件事，兩件都成立才算：`i + 1 < len(row)` 確認後面還有一項，`tuple(row[i : i + 2]) == pair` 確認這兩項正是要合併的那一對（切片得到的是清單，`tuple` 把它換成和 `pair` 一樣的形式才能比較）。成立時用 `"".join(pair)` 接成 `"ab"`，前進兩項；否則照抄目前這一項，只前進一項。

用第一份 `["a", "b", "a", "b"]` 走一次：`i` 是 0 時前兩項是 a、b，輸出 `ab`，`i` 變 2；`i` 是 2 時又是 a、b，再輸出 `ab`，`i` 變 4；`4 < 4` 不成立，迴圈結束，得到 `['ab', 'ab']`。第二份在 `i` 是 2 時遇到 a、c，不是要合併的一對，只抄下 a、前進到 3；這時已是最後一項，抄下 c 後結束，得到 `['ab', 'a', 'c']`。這正是第二行的輸出。

ab 現在是一個 token，但不一定是有語言意義的詞，只是在這份資料裡常一起出現。完整的 BPE 會反覆做三件事：數相鄰對、合併最常見的一對、把新項加進字表並記下合併的先後順序；直到字表達到預先設定的大小（6.3 的 `vocab_size`），或再也沒有可以合併的相鄰對才停。合併只把相鄰項接起來，沒有改動任何字母，所以一定接得回原文。

這一步只是在決定切詞規則，還沒有訓練語言模型。規則只用訓練資料學，理由和 [1.2](01.md#1.2) 一樣：驗證與測試文字如果參與決定規則，就不再是沒見過的材料；它們只用來檢查新文字切出來有多長、能不能完整還原。

練習在 `corpus` 清單加入第三份 `list("acacacac")`，先預測再執行：a-c 在新文件出現 4 次，加上原來的 1 次共 5 次，超過 a-b 的 3 次，所以這次選 a-c。三份的結果應是 `['a', 'b', 'a', 'b']`、`['a', 'b', 'ac']`、`['ac', 'ac', 'ac', 'ac']`。前兩份原文一個字母都沒改，切法卻跟著新規則變了：tokenizer 的規則一變，舊文件的編碼也會跟著不同。
