## 10.2 圖片切成小塊後，如何排成序列？

沿用上一節的 16×16 黑底紅方塊圖，要排成一串可依序處理的材料。先切成邊長 4 的小方塊，英文叫 **patch**：每列 4 塊，共 16 塊；依列從左到右、再到下一列排列。每塊仍保存 RGB 的 3×4×4＝48 個數值。

![十六塊按列編號並展開，每塊仍有四十八個 RGB 數值](../figures/rewrite-10-patch-order.svg)

圖中的 0–15 是小塊在序列裡的位置，不是圖片類別。文字序列的每個位置放一個 token；圖片序列的每個位置放一整塊圖的 48 個數值，而不是每個像素各佔一個位置。

```python
import torch
from tiny_perceptron.multimodal import scene, patchify, unpatchify

image = scene("red", "square")[None]
patches = patchify(image, 4)
restored = unpatchify(patches, 3, 16, 16, 4)
print("小塊序列", tuple(patches.shape))
print("拼回相同", torch.equal(image, restored))
```

`scene("red", "square")[None]` 生成同一張圖，`[None]` 和上一節的 `unsqueeze(0)` 一樣，在最前面加筆數軸。`patchify` 切塊並攤平每塊，得到 `(1,16,48)`：一張圖、16 個位置、每位置 48 個數。`unpatchify` 按通道 3、高寬 16、塊邊長 4 放回原位；`torch.equal` 印出 True，表示往返後每個數值都相同。

兩個函式各只有幾行：

```python
# 節錄自 tiny_perceptron/multimodal.py：patchify、unpatchify
def patchify(images, patch_size=4):
    b, c, h, w = images.shape
    if h % patch_size or w % patch_size:
        raise ValueError("圖片高寬必須能整除 patch_size")
    p = patch_size
    return images.reshape(b, c, h // p, p, w // p, p).permute(0, 2, 4, 1, 3, 5).reshape(b, -1, c * p * p)


def unpatchify(patches, channels, height, width, patch_size=4):
    b, _, _ = patches.shape
    p = patch_size
    return (
        patches.reshape(b, height // p, width // p, channels, p, p)
        .permute(0, 3, 1, 4, 2, 5)
        .reshape(b, channels, height, width)
    )
```

`patchify` 先用 `b, c, h, w = images.shape` 一次取出四個軸的長度（本例 1、3、16、16）。`if h % patch_size or w % patch_size:` 問的是「高或寬除以塊邊長有沒有餘數」：`%` 是取餘數，16 除以 4 餘 0；只要有一邊的餘數不是 0，就用 `raise` 報錯，因為邊緣會剩下不完整的塊。真正的工作在最後一行，分三步：

1. `reshape(b, c, h // p, p, w // p, p)` 把高 16 拆成「第幾列塊、塊內第幾列」兩個軸，寬也同樣拆開，形狀變成 `(1,3,4,4,4,4)`。數字沒有搬動，只是換一種分組看法（[W.3](../first-steps.md#W.3) 的 `reshape`）。
2. `permute(0, 2, 4, 1, 3, 5)` 重排軸的順序：新的六個軸依序取舊的第 0、2、4、1、3、5 軸，也就是筆數、列塊、欄塊、通道、塊內列、塊內欄，形狀變成 `(1,4,4,3,4,4)`。和 `reshape` 不同，`permute` 會改變數字被讀出的先後順序。以 2×2 的 `[[1,2],[3,4]]` 為例：`reshape(4)` 攤平是 1、2、3、4；先 `permute(1, 0)` 交換兩個軸（二維時就是 [3.7](03.md#3.7) 的 `.T`），得到 `[[1,3],[2,4]]`，再 `reshape(4)` 就是 1、3、2、4。這一步不能省：若直接把 `(1,3,16,16)` reshape 成 `(1,16,48)`，第一個位置的 48 個數會是紅色通道最上面三列的像素，一條橫帶，而不是一個 4×4 方塊。
3. `reshape(b, -1, c * p * p)` 把「列塊×欄塊」併成 16 個位置，把每塊的 3×4×4 攤成 48 個數；`-1` 讓 PyTorch 自己算出 16。列塊排在欄塊前面，所以合併時先走完同一列的 4 塊，才換到下一列，這就是「依列排序」。

`unpatchify` 照相反順序做一次：先拆回 `(1,4,4,3,4,4)`，用 `permute(0, 3, 1, 4, 2, 5)` 把軸排回「通道、列塊、塊內列、欄塊、塊內欄」，最後併回 `(1,3,16,16)`。`b, _, _ = patches.shape` 裡的 `_` 表示那兩個值用不到。

往返成功只核對了兩個函式彼此相容，還不能證明排序符合「依列」的約定：若切和拼都改成依欄排序，照樣能還原原圖。所以還要直接看某個位置裝的是哪一塊。下面用一張 4×4、只有一個通道的小圖，格子依列寫上 0 到 15，切成邊長 2 的四塊；左上、右上、左下、右下應依序在位置 0、1、2、3。

```python
grid = torch.arange(16.0).reshape(1, 1, 4, 4)
print(grid[0, 0])
print(patchify(grid, 2)[0])
```

第一個輸出是小圖本身：第一列 0、1、2、3，第二列 4、5、6、7，依此類推。第二個輸出有 4 列，每列是一塊的 4 個數：位置 1 是 `[2,3,6,7]`，正是右上那塊（第 0、1 列的第 2、3 欄）。若排序錯成依欄，位置 1 會是左下的 `[8,9,12,13]`。真圖也能這樣核對：在圖上找一塊已知顏色的區域，看它的數值出現在序列的第幾個位置。

練習把第一段程式的兩個塊邊長都改成 8，也就是 `patchify(image, 8)` 和 `unpatchify(patches, 3, 16, 16, 8)`。先預測：每列 2 塊，共 4 塊，每塊 3×8×8＝192 個值，所以形狀是 `(1,4,192)`，而且仍能拼回。切塊沒有丟掉任何像素；下一節把每塊壓成短特徵時，才會碰到哪些差異被保留的問題。
