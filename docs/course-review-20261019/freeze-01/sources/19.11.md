## 19.11 下載一份權重，就能從中斷處繼續訓練嗎？

直接回答與接續訓練，需要不同的包裹。**推論包**只要能回答：完整神經權重、模型結構、字表和預處理規則。**續訓包**還要能回到中斷的那一步：最佳化器狀態（Adam 的 m、v，[5.7](05.md#5.7)存過同樣的東西）、亂數狀態、抽題進度（下一批輪到哪些題）與訓練步數。只拿到推論包，不能還原這些狀態。

本章有 4 組公開推論權重包，固定在[Hugging Face 這一版](https://huggingface.co/birdhackor/tiny-perceptron-course-models/tree/979cdfacc588ad0536f1c64fff96f264571cf054/selftrained/v2)：模型庫為 `birdhackor/tiny-perceptron-course-models`，revision 為 `979cdfacc588ad0536f1c64fff96f264571cf054`。revision固定一份不可變的發布版本，讓後來的下載仍指向同一批檔案。

| 版本名稱 | 模型庫內的目錄 | 用途 |
| --- | --- | --- |
| `moe-pretrain` | `selftrained/v2/moe-pretrain` | 觀察文字預訓練（pretrain 段）的推論權重。 |
| `moe-sft` | `selftrained/v2/moe-sft` | 觀察加入對話示範（SFT 段）後的推論權重。 |
| `moe-joint` | `selftrained/v2/moe-joint` | 本章選定的 MoE 助理；權重取自 native 段第 1,000 步（名稱由來見[19.4](19.md#19.4)）。 |
| `dense-joint` | `selftrained/v2/dense-joint` | 從自己的隨機起點訓練、比較用的 Dense 成品；權重取自 Dense 自己的 weighted 段第 1,000 步。 |

每組都包含4個檔案：`model.safetensors`保存完整神經權重，`model-config.json`描述結構，`tokenizer.json`保存字元與ID對應，`inference-manifest.json`記錄來源、預處理版本與檔案內容指紋。**safetensors** 是專門存張量的檔案格式：檔頭用文字記下每個張量的名稱、形狀與數值型別（另可附幾項文字說明），後面接數值本身；讀取時只解析這些資料，不會執行檔案裡的程式。其餘三個是 JSON 文字檔，讀取時同樣不執行程式；本章把這種讀取時不執行程式的檔案稱為**安全格式**。下載程式核對指紋，載入器再核對結構與所有權重；公開檔案不含最佳化器狀態。前兩組是階段比較用的權重，不具有最後成品的完整訓練歷程與能力。

![公開安全格式包用於回答與評測；自己訓練保存的best或latest工作檔分別用於新階段與同階段恢復。](../figures/p6-19-delivery-package-roles.svg)

圖中上路取得的是只能拿來回答與評測的權重。下路才有自己的完整訓練狀態：`best.pt`是驗證選出的起點，`latest.pt`是最近一次保存的進度。兩者即使都含權重，也不是同一用途。

<summary>操作：在CPU下載公開MoE並回答一個文字問題</summary>

以下命令在自己電腦的終端機執行，不是 Notebook 程式格。本頁的 Colab 入口只用 pip 安裝課程的基本套件，沒有建立這些命令使用的 uv 專案環境，也沒有安裝 `selftrained` 額外套件；我們也沒有在 Colab 驗證過，所以請用本機終端機。

沿用你在 [19.1](19.md#19.1) 執行 `chat.py` 的那個專案，下面的指令都在它的根目錄執行。從 `selftrained-v2` 或 main 分支取得的專案都可以：兩者的 `chat.py`、推論程式、示範訊息檔與 `uv.lock` 內容相同。若尚未裝好CPU依賴，先執行：

```bash
uv sync --frozen --extra cpu --extra selftrained
```

接著執行已核對的文字示例。`chat.py`會匿名下載上述4個檔案，存入 `outputs/selftrained-v2/public/moe-joint`，核對後直接在CPU生成；不需要私人 `.pt` 或登入。

```bash
uv run --extra cpu --extra selftrained python scripts/selftrained/chat.py \
  --model-dir outputs/selftrained-v2/public/moe-joint \
  --asset-dir outputs/selftrained-v2/data \
  --repo birdhackor/tiny-perceptron-course-models \
  --revision 979cdfacc588ad0536f1c64fff96f264571cf054 \
  --prefix selftrained/v2/moe-joint \
  --manifest-sha256 f27856892b0c46ca81ba43bfadf7051ed6bd31d848e4868a05147e5799df1e5e \
  --messages docs/selftrained/examples/v2/text.messages.json \
  --task text --device cpu --max-new-tokens 128 --threads 2
```

訊息檔先要求兩點格式，再問「App錯誤訊息一直重複出現。」本次CPU示例的 `answer` 是：

> 1. 先檢查網路並重新啟動App。  
> 2. 仍失敗再詢問官方客服。

JSON中的 `generations` 保留實際生成，`model`標示選定權重。相同下載可重用；若目的地已有不同內容，程式會拒絕覆寫，請改用新的 `--model-dir`。文字示例不讀圖音資產；想試圖片、OCR、錄音與真正後續對話，按[完整CPU操作頁](../../docs/selftrained/v2-public-cpu-commands.md)先取得固定素材，再執行對應命令。該頁的7組情境用來檢查安裝與介面，都是已知的驗證示例，不是未知問題的成功率。

</details>

練習判斷兩個需求各要哪個檔案：「前一階段完成後，開啟下一階段」，以及「native 段訓練中斷後接回原進度」。答案：前者用自己的 `best.pt` 與 `--init-checkpoint`，開新階段與新的最佳化器；後者用自己的 `latest.pt` 與 `--resume`，恢復最佳化器、亂數與抽題狀態，繼續到原本的總步數。公開 safetensors 不能代入任何一項：它只供推論與評測，目前的訓練程式沒有把它當成訓練起點的載入器。

這兩個命令都透過[本機訓練指引](../../docs/selftrained/TRAINING.md)的 wrapper（[19.3](19.md#19.3)補充介紹的啟動腳本）執行，完整命令見[19.4](19.md#19.4)的操作摺疊，要在那裡說明的 main 分支 clone 執行。wrapper 只接自己建立、可信任的檢查點，核對保存的資料、設定與執行紀錄，而且每次 attempt（一次執行嘗試）都用新目錄保存輸出。這條路已支援本機執行，不依賴作者的私人訓練儲存空間。
