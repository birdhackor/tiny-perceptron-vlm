## 8.8 保留原權重，能只學一條小修正嗎？

要教模型一種新寫法，不一定要更新每個原有數字。先看一個線性層`nn.Linear(16, 12)`：它讀16個輸入，算出12個輸出。照[W.5](../first-steps.md#W.5)的記法，Linear把權重矩陣W存成`[輸出數, 輸入數]`，所以W是`[12, 16]`，共`12×16=192`個數字。我們希望保留這條原路，同時加上一條可訓練的小修正。

**LoRA**（Low-Rank Adaptation）讓同一份輸入另走一條修正路：先經矩陣A，把16個數壓成2個；再經矩陣B，把2個數展開成12個；最後與原路的12個輸出相加。修正路中間只剩2個數，這個2叫**rank**（秩）。用同一種記法，A是`[2, 16]`、B是`[12, 2]`，兩者共`2×16+12×2=56`個數字。原W凍結，表示訓練不更新它；A、B可以學習。

先A後B的兩步，可以像[2.4](02.md#2.4)的`b.weight @ a.weight`那樣合成一個矩陣：`B @ A`是`[12, 2] @ [2, 16]`，得到`[12, 16]`，和W形狀相同，所以能逐格直接加到W上。加上去的改變量寫成`ΔW=(alpha/rank)BA`，其中BA就是`B @ A`，alpha是另外選的縮放設定；本例alpha與rank都是2，倍率為1。

既然兩層合起來仍是一個矩陣，為什麼要拆成A、B？因為這樣能表示的改變受限，要學的數字也少。`B @ A`的12列，每一列都只是A那2列按B的數字混合而成；所以這個`[12, 16]`的改變最多只有2個獨立方向，不能是任意的`[12, 16]`矩陣。這就是此處「低秩」的意思：能表達的改變變窄，換來只學56個數字，而不是192個。

圖中兩條路使用同一份輸入，在相加處才合流。框裡的「16 → 12」這類標示，是資料由幾個數變成幾個數的方向，不是矩陣的存放形狀。

![機制示意：凍結W的原路與可訓練A、B的修正相加](../figures/rewrite-08-lora-paths.svg)

下面用本課的`LoRALinear`建一層，看形狀、可學數字、初始輸出與第一次梯度；這段沒有用風格示範訓練新寫法。

```python
import torch
from torch import nn
from tiny_perceptron.alignment import LoRALinear

torch.manual_seed(0)
layer = LoRALinear(nn.Linear(16, 12), rank=2, alpha=2)
print("W", tuple(layer.base.weight.shape), "A", tuple(layer.a.shape), "B", tuple(layer.b.shape))
print("B@A", tuple((layer.b @ layer.a).shape))
print("可訓練參數", sum(p.numel() for p in layer.parameters() if p.requires_grad))
x = torch.randn(3, 16)
print("初始相同", torch.equal(layer(x), layer.base(x)))
layer(x).sum().backward()
print("A梯度為零", layer.a.grad.abs().max().item() == 0)
print("B梯度非零", layer.b.grad.abs().max().item() > 0)
```

程式裡的`layer.base`是原本的`nn.Linear`，`layer.base.weight`就是凍結的W；`layer.a`、`layer.b`是A、B。前兩行印出W是`(12, 16)`、A是`(2, 16)`、B是`(12, 2)`，`B@A`是`(12, 16)`：修正與W同形狀。第三行的`sum(p.numel() for p in layer.parameters() if p.requires_grad)`逐一走過這層的參數，只留下`requires_grad`為True、也就是可學的那幾個，再把各自的元素數`numel()`加總，得到56。後面三行依序是True：初始輸出與原層相同、A的第一次梯度全為0、B的梯度已經不是0。

這些結果從哪裡來？下面是函式庫裡的完整定義。

```python
# 節錄自 tiny_perceptron/alignment.py：LoRALinear
class LoRALinear(nn.Module):
    def __init__(self, base, rank=2, alpha=2):
        super().__init__()
        if rank < 1:
            raise ValueError("rank 必須為正")
        self.base = base
        self.base.requires_grad_(False)
        self.rank, self.alpha = rank, alpha
        self.a = nn.Parameter(torch.randn(rank, base.in_features) * 0.01)
        self.b = nn.Parameter(torch.zeros(base.out_features, rank))

    def forward(self, x):
        return self.base(x) + (x @ self.a.T @ self.b.T) * (self.alpha / self.rank)

    def merged_weight(self):
        return self.base.weight + self.b @ self.a * (self.alpha / self.rank)
```

讀法同[3.7](03.md#3.7)：`__init__`建立零件，`forward`定義呼叫`layer(x)`時的計算。

- `self.base.requires_grad_(False)`凍結整個原層：W和它的12個偏移都不再記錄梯度，最佳化器也就不會更新它們，所以上面數到的可學數字不含這192＋12個。
- `self.a`是A：`torch.randn(rank, base.in_features) * 0.01`做出形狀`[rank, 輸入數]`的很小隨機數；`nn.Parameter`把它標成可學參數，[1.13](01.md#1.13)用過。`self.b`是B：`torch.zeros(base.out_features, rank)`做出`[輸出數, rank]`的全0矩陣。
- `forward`的`self.base(x)`走原路；`x @ self.a.T @ self.b.T`走修正路，三筆輸入`[3, 16]`先變`[3, 2]`再變`[3, 12]`，和W.5的Linear用「輸入 @ 權重轉置」是同一種算法；乘上`self.alpha / self.rank`後與原路相加。
- `merged_weight`直接算出`W+ΔW`，回傳一個`[12, 16]`矩陣，[8.9](#8.9)合併修正與[8.13](#8.13)比較縮放時會用到。開頭的`raise ValueError(...)`則在rank小於1時停下來報錯，不建立這一層。

因為B一開始全是0，`B @ A`也是0，新層的輸出與原層相同。A的改變要經過B才影響輸出；B還是0時，A稍微改動也不會改變輸出，所以A的第一次梯度是0。B的輸入則是A算出的那2個數；A是隨機數，這2個數不是0，B的梯度也就不是0。等B被更新成非零，A才會有非零的梯度。若A也從全0開始，B的輸入全是0，兩者的梯度都是0，更新再多次也還是0；所以只讓B從0開始，A不能也是0。`sum().backward()`只計算梯度，沒有呼叫最佳化器的`step()`，也沒有風格示範，因此還不是學會新寫法的證據。

真正教風格時，把這種層換進完整模型，再用回答目標更新A、B，並與更新全部參數的完整微調比較。已保存的實驗從[8.3](#8.3)的加法底座出發做過這個比較：學積木比喻版的LoRA在七道加法測試題裡有6題寫出指定句，完整微調有7題；兩者都沒有答對新加法。要更新的數字比較少，這在建層時就由A、B的形狀決定；能學到多少寫法、答案對不對，要看測試資料上的結果。56也只是要學的數字：原W仍在層裡，每次輸出照樣經過原路。

練習把第一段程式的`rank=2, alpha=2`改成`rank=4, alpha=4`，維持倍率1。先預測A變`(4, 16)`、B變`(12, 4)`，`B@A`仍是`(12, 16)`；可訓練數字為`4×(16+12)=112`。窄通道變寬，修正最多能有4個獨立方向，要學的參數也跟著增加。

把這條修正路放進完整模型後，我們也真的訓練了兩套adapter，也就是各自為某種寫法訓練的一組A、B修正參數；[8.9](#8.9)會正式介紹這個名稱，並把兩套分別叫短答套與比喻套。起點是[8.3](#8.3)的加法底座：特徵寬度64、兩層，FFN中間寬度256，字表大小264，共141,568個參數；它在七道測試題上原本就零題答對。兩套各讀相同的49道訓練題，一套學短答版、一套學積木比喻版，各更新450次；模型每層的Query、Value、注意力輸出、FFN的兩個線性層，以及最後的輸出層，共11處加上rank 4、alpha 4的修正。

這些插入位置都是像前面W一樣的線性層。Query把當前內容轉成「想找什麼」的特徵，Value把各位置內容轉成「取回什麼」的特徵，分別可回看[3.3的查詢](03.md#3.3)與[3.4的取回內容](03.md#3.4)；注意力輸出再混合取回的結果。[4.4的FFN](04.md#4.4)對每個位置先擴展、再收回特徵，而[輸出層](04.md#4.6)把特徵轉成下一個token的候選分數。每處修正有`rank×(輸入數＋輸出數)`個可學數字：每層的Query、Value、注意力輸出都是64進64出，各`4×(64+64)=512`；FFN的兩層是64進256出與256進64出，各`4×(64+256)=1,280`；一層合計`3×512+2×1,280=4,096`，兩層8,192；輸出層64進264出，`4×(64+264)=1,312`。總共9,504個，約為底座參數量的`9,504÷141,568≈6.7%`；底座原本的141,568個參數全部凍結。第一步也出現上述A梯度全零、B已有非零梯度的現象，訓練前後的底座數字則完全相同。
