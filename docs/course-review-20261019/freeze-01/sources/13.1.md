## 13.1 偏好為什麼必須連同問題一起記？

對「只回數字：2+2=?」，A回答「4」，B回答「4，就像兩雙筷子共有四根」。兩份都算對，只有A符合只回數字。若要求改成生活比喻，B又可能較合適。**偏好**是在同一個任務條件下，標記哪份回答更合適，不是把一種寫法永久封為好答案。

先寫本次判準：「先正確，再遵循只回數字」，再保留提問、兩份原文、選擇和原因。

```python
pair = {"prompt": "只回數字：2+2=?", "A": "4", "B": "4，就像兩雙筷子共有四根。"}
rule = "先正確，再遵循只回數字"
chosen = "A"
print("條件", pair["prompt"])
print("比較", pair["A"], "／", pair["B"])
print("理由", rule, "選擇", chosen)
```

`chosen`直接寫A，是我們的人工判斷；程式只印出紀錄，不會自己讀兩份回答來排序。保存原因讓後來的人知道，A勝出是因為「只回數字」這個限制，不是所有比喻都不好。

兩份都不合適時，較佳的一份也不等於理想示範；沒有清楚差別時，則可以記平手或不確定。否則不同標註者各猜一套標準，訓練訊號就混在一起。

後面的數學先用最清楚的例子：加法的對錯。例如`2+2=?`，正確的`4`是較佳回答，錯的`5`是較差回答。格式偏好則另用兩份都算對的回答比較（[13.7](#13.7)）。

練習把程式第一行提問裡的「只回數字：」刪掉，變成`"2+2=?"`。先寫出新的判準放進`rule`，再決定`chosen`。原程式的A不會自動改：沒有格式限制後，兩份都正確，只剩「要不要比喻」的差別；請求沒說要哪一種時，可以記平手。問題變了，就要重新判斷。

我們真正訓練時先收窄問題，只比較加法的對錯。例如同一題`2+2=?`，較佳候選是`4`，較差候選是`5`，不是讓模型自訂什麼叫好。兩個加數都從0到7挑選，因此有8×8＝64道題，每題配一組較佳／較差回答。切分時，把交換加數後相同的題目算成同一個家族（[7.12](07.md#7.12)）：例如`2+3=?`與`3+2=?`必須留在同一組，不能一題拿來教、另一題拿來考，否則測試可能只是在考已見過的數字組合。整個家族一起分配後，共有49對訓練資料、8對驗證資料、7對測試資料。訓練資料用來更新參數；驗證資料用來觀察訓練途中是否學得更好；測試資料留到最後檢查未教過的組合，不能拿它的分數來選訓練設定。本次程式預先寫定兩種訓練設定與更新次數，也在訓練前記錄底座在測試題上的分數，並在每一支訓練後再測一次；測試題不參與參數更新，程式也不依這些分數改設定。這與只在全部訓練結束後才看測試題的流程不同，因此閱讀結果時，要分清「拿測試題量前後變化」與「看了測試分數再調設定」。這三組與[8.3的加法底座](08.md#8.3)使用相同的題目切分，讓前後比較對得起來。另做一條格式支線，把兩篇都算對的回答拿來比較，見[13.7](#13.7)。先分清這兩種理由，後面才知道模型是改了內容排序，還是只偏好沒有附加句的寫法。
