## 10.7 圖片展開後，答案目標如何跟著移動？

一串訊息裡，圖片原本只佔一個位置，用一個特殊 token 代表：ID 5，也就是 [6.6](06.md#6.6) 列出的 `<image>`，本章叫它圖片佔位 token。真正送進模型時，這一個位置要換成圖片入口算出的多條特徵；[10.5](10.md#10.5) 的圖片入口會給 16 條，本節為了好數，假設只有 3 條。替換後，後面的助手角色與回答都往後移兩個位置。除了移輸入，也要移對應的目標，讓助手位置仍然預測答案的第一個 token。

[7.4](07.md#7.4) 用問題 Q、回答 A 的例子，完整序列是 BOS（開始標記）、user、Q、EOS（結束標記）、assistant、A、EOS。圖片放在使用者那一段，也就是把 Q 換成圖片佔位 token。為了讓位置好數，本節再拿掉 user 角色（3）和圖片後的 EOS（2），剩下五個 token：BOS（1）、圖片佔位 token（5）、assistant（4）、答案 A（73）、EOS（2）。A 的 ASCII byte 是 65，照 6.6 的規則加 8 得 73。拿掉的兩個 token 在完整序列裡也不是答案，目標都是 −100；換成完整序列，下面的展開與錯開步驟相同，只多了兩個不計代價的位置。

交給函式的 `labels` 還沒錯開，和 `ids` 一個位置對一個位置：A 的位置標 73、EOS 的位置標 2，表示這兩個 token 要計分，還不是「這個位置要猜什麼」；其餘標 `IGNORE`，是函式庫裡表示不計代價的常數 −100。這和 [7.1](07.md#7.1) 的 `render_chat` 不同，它回傳的 Y 已經錯開。這裡的下一位置對齊（[7.4](07.md#7.4)）由 `expand_modalities` 在展開之後自己做一次，因為答案的前一個位置要看最後真正送進模型的序列。

```python
import torch
from torch import nn
from tiny_perceptron.data import IGNORE
from tiny_perceptron.multimodal import expand_modalities

embedding = nn.Embedding(264, 8)
ids = torch.tensor([1, 5, 4, 73, 2])
labels = torch.tensor([IGNORE, IGNORE, IGNORE, 73, 2])
features = {5: torch.randn(3, 8)}
x, y = expand_modalities(ids, labels, embedding, features, {5})
print("輸入特徵", tuple(x.shape))
print("下一位置目標", y.tolist())
```

`embedding` 是寬度 8 的文字 embedding 表，負責圖片佔位 token 以外的 token（本例是 BOS、assistant、A、EOS）；264 列對應 ByteTokenizer 字表的 264 個 ID。`features` 是一本字典：鍵 5 對到 `torch.randn(3, 8)` 造出的 3 條隨機特徵，代替圖片入口與接頭的輸出。`{5}` 告訴函式哪些 ID 是要展開的佔位 token；大括號裡只放值、沒有冒號，是 Python 的集合。輸出是六個輸入位置 `(1,6,8)`，目標是 `[[-100,-100,-100,-100,73,2]]`：只有 73 與 2 兩個有效目標。

函式怎麼做到？

```python
# 節錄自 tiny_perceptron/multimodal.py：expand_modalities
def expand_modalities(ids, labels, embedding, features, marker_ids):
    """一筆無 padding 資料：marker 展開成多向量，新增位置不直接算 loss。

    ids 與 labels 在此都尚未 shift。展開後才 shift，第一個答案的對齊才正確。
    """
    pieces, targets = [], []
    for token, label in zip(ids.tolist(), labels.tolist(), strict=True):
        if token in marker_ids:
            modal = features[token]
            pieces.append(modal)
            targets += [IGNORE] * len(modal)
        else:
            pieces.append(embedding(torch.tensor([token], device=embedding.weight.device)))
            targets.append(label)
    expanded = torch.cat(pieces)
    target = torch.tensor(targets, device=expanded.device, dtype=torch.long)
    return expanded[:-1].unsqueeze(0), target[1:].unsqueeze(0)
```

三引號說明裡的 marker 是佔位 token，shift 是錯開，padding 是 [7.6](07.md#7.6) 說的補 PAD。`for token, label in zip(ids.tolist(), labels.tolist(), strict=True):` 一次走一個位置：`zip` 把兩份清單逐項配對，`strict=True` 要求兩份一樣長，長度不同就報錯，避免 `labels` 沒對好卻默默算下去。遇到佔位 token（`token in marker_ids`）時，`features[token]` 取出那 3 條圖片特徵，整份放進 `pieces`；`[IGNORE] * len(modal)` 是把 −100 重複 3 次的清單，`+=` 把它接到 `targets` 後面。圖片特徵不是要生成的字，所以不計代價，但後面的位置仍能讀它們。遇到圖片佔位 token 以外的 token 時（包括 BOS、assistant 這些特殊 token），查 embedding 表得到一條向量（`device=` 只是讓 ID 和表放在同一個計算裝置上），目標用 `append` 照抄傳進來的 `label`。

迴圈結束時，`torch.cat(pieces)` 把各段接成 7 條向量，`targets` 也有 7 個：

| 展開後的位置 | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 放的內容 | BOS | 圖1 | 圖2 | 圖3 | assistant | A | EOS |
| 同位置的目標 | −100 | −100 | −100 | −100 | −100 | 73 | 2 |

最後一行才做下一位置對齊：`expanded[:-1]` 去掉最後一條輸入（切片 `[:-1]` 取到倒數第一個之前），`target[1:]` 去掉第一個目標（從索引 1 取到最後），兩者都剩 6 個，再用 `unsqueeze(0)` 加上筆數軸。於是位置 4 的輸入是 assistant、目標是 73；位置 5 的輸入是 A、目標是 EOS 的 2。若傳進來的 `labels` 已經錯開過，這一行會再錯開一次，每個位置都去猜再下一個 token，就是 [4.7](04.md#4.7) 提醒過的重複錯開。

![圖片佔位 token 展開成三個位置後再錯開一次：assistant 位置預測 73，A 的位置預測 EOS，其餘目標 −100 不計代價](../figures/rewrite-10-image-targets.svg)

圖把前四個位置合成一行顯示，仍是 BOS 加三條圖片特徵；這四個位置的目標都是 −100，猜什麼都不計代價。

文字核心接著算的位置編號和因果遮罩（[3.6](03.md#3.6)），也都按這六個輸入位置建立：位置編號是 0–5，遮罩是 6×6 的許可表，每列一個查詢位置、每欄一個候選位置。不能沿用原來的五個位置，也不能把錯開前的七個當成實際輸入長度。

練習把第一段程式的 `torch.randn(3, 8)` 改成 `torch.randn(5, 8)`，也就是圖片佔 5 條特徵。先預測：展開後 1＋5＋3＝9 個位置，錯開後輸入長度 8；目標前六個是 −100，最後兩個仍是 73 與 2。回答內容沒變，改變的是它在序列中的位置。
