## 4.6 每位置的八個特徵，怎樣變成候選字分數？

經過 block 後，每位置還是八個內部特徵；我們想要的卻是「下一字各候選得幾分」。因此最後再接一個八格到候選數的 Linear：每個候選各有一套權重，把八格加權成一個分數。

這個最後配方叫**輸出層**（output layer，也叫 LM head；LM 指語言模型，language model）；這裡的 head 和 [3.7](03.md#3.7) 的注意力頭不是同一個零件。尚未變成最終預測的一排特徵叫**隱藏表示**，只是內部計算的名字。

把前幾節的零件依序接起來，就是一個完整的語言模型：字的 embedding 表查出每個 ID 的特徵（[2.1](02.md#2.1)），加上位置表（[4.1](#4.1)），經過一疊 block（[4.5](#4.5)），最後 LN 再整理一次尺度（[4.3](#4.3)：主路上的數字大小沒有固定範圍），輸出層打分。本課叫它 `TinyLM`。

```python
# 精簡自 tiny_perceptron/model.py：TinyLM（省略 RoPE、RMSNorm、權重共享、cache、valid／positions／segments、多模態輸入與設定檢查）
import torch
from torch import nn

from tiny_perceptron.model import Block, ModelConfig


class TinyLM(nn.Module):
    def __init__(self, config):
        super().__init__()
        self.embedding = nn.Embedding(config.vocab_size, config.width)
        self.position = nn.Embedding(config.max_length, config.width)
        self.blocks = nn.ModuleList([Block(config) for _ in range(config.layers)])
        self.final_norm = nn.LayerNorm(config.width)
        self.output = nn.Linear(config.width, config.vocab_size, bias=False)

    def forward(self, ids):
        positions = torch.arange(ids.shape[1])
        x = self.embedding(ids) + self.position(positions)
        for block in self.blocks:
            x, _, _ = block(x)
        return {"logits": self.output(self.final_norm(x))}
```

零件類別的寫法同 3.7。`__init__` 建立五個零件：

- `embedding`：字的 embedding 表，列數是字表大小，每列 `width` 格。
- `position`：位置表，`max_length` 列。
- `blocks`：`layers` 個 block。`[Block(config) for _ in range(config.layers)]` 是把迴圈寫在方括號裡的清單寫法（[1.1](01.md#1.1) 用過）：重複 `layers` 次，每次造一個新的 block，收成一個清單，所以各 block 彼此獨立；`nn.ModuleList` 是裝零件的清單，和一般清單不同的是，裡面每個 block 的參數都會算進模型。這裡的 `Block` 從函式庫 import，就是 4.5 的那一層。
- `final_norm`：最後 LN。
- `output`：輸出層，`width` 格進、字表大小那麼多個分數出；`bias=False`，沒有偏移。

`forward` 收一批 ID：`torch.arange(ids.shape[1])` 依位置數產生 `[0,1,2,…]`，`self.embedding(ids) + self.position(positions)` 就是 4.1 的逐格相加。`for block in self.blocks:` 依序經過每個 block；函式庫的 `Block` 回傳三樣（4.5），`x, _, _ =` 只留新的表示。最後 `self.output(self.final_norm(x))` 給每位置每候選一個分數，放在字典的 `"logits"` 鍵下回傳。

先用二十個候選 ID 0 到 19，不賦予真實字義。輸入一筆 `[1,2,3]`，每位置都應產生二十個分數。假設完整序列是 `[1,2,3,4]`（[4.7](#4.7) 會用同一個例子），三個位置的答案就是 2、3、4。

```python
from tiny_perceptron.model import TinyLM as LibraryTinyLM

torch.manual_seed(42)
config = ModelConfig(vocab_size=20, width=8)
model = TinyLM(config)
ids = torch.tensor([[1, 2, 3]])
logits = model(ids)["logits"]
library = LibraryTinyLM(config)
library.load_state_dict(model.state_dict())
result = library(ids)
same = torch.allclose(logits, result["logits"])
print(logits.shape)
print("各位置最高分ID", logits.argmax(dim=-1))
print("與函式庫版本相同：", same, "函式庫回傳的鍵", list(result))
assert same and logits.shape == (1, 3, 20)
```

輸出形狀 `[1,3,20]`：一筆、三個預測位置、每位置二十候選。`"logits"` 是原始分數，還不是機率。函式庫版回傳的字典有三個鍵（`list(result)` 列出字典的鍵）：`"logits"` 同上；`"cache"` 是每個 block 的 KV 快取（[16.3](16.md#16.3)）；`"auxiliary"` 是各 block 輔助代價的總和，Dense 為 0（4.5）。第 5 章以後的程式寫 `model(ids)["logits"]`，取的就是這份分數。兩版算出相同結果，印出 True。

| 預測位置 | 這個位置可讀的前文 ID | 若正確續接，答案 ID |
| --- | --- | ---: |
| 0 | `[1]` | 2 |
| 1 | `[1,2]` | 3 |
| 2 | `[1,2,3]` | 4 |

三排是在答三道不同的下一字題。`argmax(dim=-1)` 沿候選軸取最高分，所以輸出形狀是 `[1,3]`，各位置各有一個猜測；本次初始化印出 `[[10,17,7]]`，和答案都不同，因為模型還沒訓練。續寫時，前兩排要猜的 2、3 已經在輸入裡，只有最後一排猜的是新字，所以只用最後那排選新 ID，接回輸入後再算下一步（[1.14](01.md#1.14)）。

若要用表中的三個答案算平均代價，每位置當一題：分數的形狀從 `[1,3,20]` 排成 `[3,20]`，答案 2、3、4 的形狀從 `[1,3]` 排成 `[3]`，再交給交叉熵（[1.8](01.md#1.8)）。下面接續上一段的 `logits`：

```python
import torch.nn.functional as F

target = torch.tensor([[2, 3, 4]])
scores_for_questions = logits.reshape(-1, logits.shape[-1])
answers_for_questions = target.reshape(-1)
print("三題平均代價", F.cross_entropy(scores_for_questions, answers_for_questions).item())
```

`reshape` 只整理形狀，不改題目順序；`-1` 推算題數 3，最後候選軸仍 20。三排依次跟答案 2、3、4 比，本次初始化的平均代價約 3.336。這是隨機模型的計算示範，不能說已知道這些答案。

這個 `TinyLM` 就是本章標題說的 **Transformer**：字的 embedding 表、位置表、一疊注意力加 FFN 的 block、最後 LN 與輸出層。之後看到 `TinyLM(ModelConfig(...))`，裡面就是這五樣零件。精簡版省略了函式庫依設定或參數改變的部分：

- `config.rotary` 為 True 時不建位置表，改在注意力裡旋轉 Q/K（RoPE，[14.1](14.md#14.1)）。
- `config.norm` 為 `"rms"` 時，最後 LN 也換成 RMSNorm（[14.2](14.md#14.2)），和各 block 一致。
- `config.tied` 為 True 時，輸出層與字的 embedding 表共用同一張表（權重共享，[14.6](14.md#14.6)）。
- `forward` 另收 `cache`，生成時從上次停下的位置接續（16.3）；回傳字典裡的 `"cache"`、`"auxiliary"` 兩鍵也是精簡版沒有的。
- `positions` 指定每個位置查位置表的哪一列（左邊補 PAD 時用），並和 `valid`、`segments` 一起交給各 block（[7.7](07.md#7.7)、[16.5](16.md#16.5)）；`embeddings` 讓圖片或聲音特徵以算好的向量直接送入，跳過查字的 embedding 表那一步（多模態輸入，[10.8](10.md#10.8)）。

函式庫版還會檢查設定是否合法、位置數是否超過 `max_length`，沒給設定時改用預設的 `ModelConfig()`；4.8 用到的 `description()` 也只在函式庫版。

練習把第二段程式的 `vocab_size=20` 改成 25，並把斷言的 `(1, 3, 20)` 改成 `(1, 3, 25)`。先預測輸出形狀變 `[1,3,25]`、兩版仍相同；最高分 ID 可能因為重新初始化而變。確定增加的是每題五個候選分數。
