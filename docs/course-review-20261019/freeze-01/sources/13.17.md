## 13.17 PPO與DPO，為什麼是兩條路？

有了同題兩篇回答的偏好資料，可以先教獎勵模型，再讓策略模型作答、拿獎勵、用PPO更新；也可以直接用偏好對調整策略模型，省去獨立的獎勵模型，這條路就是[13.4–13.6](#13.4)的DPO。它仍需要清楚的標準與可靠的偏好資料。

兩條路從同一個SFT底座分叉，都保留固定的參考模型。PPO還要學價值模型與收集新的選擇；DPO用13.5的相對差距做代價。圖中箭頭分叉，不是先跑PPO才有資格跑DPO。

![機制示意：同一個SFT底座分別走PPO或DPO，最後用同一任務檢查](../figures/rewrite-13-alternative-routes.svg)

先用兩張卡核對DPO：第一張標較佳，參考模型給兩張各0.5。當策略模型也各給0.5，相對差距0、代價0.6931；策略模型改成0.7與0.3時，beta 1的代價降為0.3567。

```python
import torch
from tiny_perceptron.alignment import dpo_loss

reference = torch.tensor([0.5, 0.5]).log()
for probabilities in [[0.5, 0.5], [0.7, 0.3]]:
    policy = torch.tensor(probabilities).log()
    loss = dpo_loss(policy[:1], policy[1:], reference[:1], reference[1:], beta=1.0)
    print("較佳／較差機率", probabilities, "偏好代價", round(loss.item(), 4))
```

`dpo_loss`的實作見[13.5](#13.5)。`policy[:1]`是切片：從第0格取到第1格之前，也就是只含第一張卡的一格tensor；`policy[1:]`從第1格取到最後，也就是第二張卡。兩張卡的log機率分別當作較佳與較差分數。這是手設機率，沒有獎勵模型或參數更新。DPO代價下降說明更偏向這份標籤；不保證實際回答滿足全部任務，也不保證和任意PPO實作得到相同模型。

13.16的有限卡比較，兩支都從逐項相同的SFT底座出發，在18道測試題通過12題，但相同步數不等於相同總成本：PPO另需教獎勵模型、更新價值模型與收集選卡，DPO直接重讀偏好對。這份小任務不足以宣稱哪種方法普遍較好，也沒有同資料、同預算的SFT對照。

若比較標籤來自真人，獎勵模型加PPO可以構成典型的**RLHF（人類回饋強化學習）**流程。本章回答卡的標籤來自作者規則，而且只做單步選擇，不能把它稱為已完成大型語言模型的RLHF；這些局部實驗也沒有用在[第19章](19.md#19.1)的公開成品上。

練習把第二組策略模型機率改成`[0.3, 0.7]`，先預測代價約1.2040。它更偏向較差卡；要知道最終用途，仍須實際選擇或生成，並檢查原能力。

[DPO原論文第4節公式7](https://arxiv.org/pdf/2305.18290v3)從帶參考約束的偏好目標推導這個方法，不等於「它保證與任何PPO實作得到同一個模型」。真實資料不完美、模型有限、更新配方也不同；兩者都要另外檢查用途。想追完整文字回答的log機率與梯度，可回看[13.3–13.6](#13.3)，那條路使用語言模型，與本章的有限選卡實驗分開。

正式CPU比較先保存148個參數的SFT底座，PPO與DPO兩支從逐項相同的參數開始；偏好都來自同一批訓練家族。這裡的家族是同一組兩個加數連同三種回答要求的題目，例如`1 加 2`的「只回數字」「一句話」與「缺購買數量」三題屬於同一家族；兩路都只使用分在訓練資料的44個家族。PPO做360次策略模型更新，DPO也做360次、每批64對，共抽用23,040對。兩者都在18道測試題通過12題，且[13.16](#13.16)列出的分項相同：數字與求補資訊成功，句子要求仍未學好。但同樣更新360次，不等於同樣的計算或資料預算：PPO另有300次獎勵模型更新、360次價值模型更新、7,680次真實抽樣；DPO直接重讀偏好對。

這次PPO段約0.66秒，DPO段約0.34秒；獎勵模型另花約0.27秒，都是本機CPU小網路的段落時間，不是大型LLM效能結論。偏好資料含示範階段沒教的條件，因此也不能說PPO或DPO勝過同資料、同預算的SFT。表格支持「這個固定配方新增了求補資訊的選擇，仍沒完成全部要求」，不支持哪種方法普遍比較好。

這些數都在[實驗紀錄`posttraining.json`](https://github.com/birdhackor/tiny-perceptron-vlm/blob/main/docs/course-experiments/results/posttraining.json)：148是`results.parameters.policy`；兩支起點相同，可核對`results.ppo.initial_state_sha256`與`results.dpo.initial_state_sha256`一致；44個家族是`results.splits.train.families`。PPO的360次是`results.ppo.policy_updates`；DPO的360次、每批64對與23,040對是`results.dpo.policy_updates`、`results.config.dpo_batch_size`與`results.dpo.processed_pair_draws`。300次獎勵模型更新是`results.config.reward_steps`，360次價值模型更新與7,680次抽樣是`results.ppo.value_updates`與`results.ppo.sampled_actions`。三段時間依序是`results.ppo.seconds`、`results.dpo.seconds`、`results.reward.seconds`；兩支的12／18是`results.evaluations.test.policies`下`ppo`與`dpo`的`greedy_full_request_success`。
