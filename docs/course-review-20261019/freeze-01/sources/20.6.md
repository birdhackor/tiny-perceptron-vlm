## 20.6 保留底座，怎麼只學一小份修正？

一層線性層讀四項特徵、輸出三項分數，它的權重矩陣 W 是 3×4。想讓輸出往新的方向調整，又不想改動 W，可以在旁邊加一條修正路：矩陣 A 先把四項壓成 r 項，矩陣 B 再把 r 項展開回三項，最後和原本的輸出相加。這就是 [8.8](08.md#8.8) 的 LoRA（Low-Rank Adaptation，低秩調適）。修正路中間只剩 r 項，這個 r 叫 rank（秩）；alpha（α）是另外選的縮放設定，修正路的結果要先乘上 alpha/r 再相加。下面的例子 rank 與 alpha 都是 2，倍率 alpha/r＝1。訓練時只更新 A、B，固定的 W 仍照常參與計算。

![固定W與可更新A、B接受同一輸入，輸出相加。](../figures/natural_base_adapter.svg)

8.8 是第 8 章的選讀延伸，那裡已節錄並逐行講解課程函式庫的 `LoRALinear`。這裡只用到其中幾點：`layer.base` 是被包起來、凍結不更新的原 Linear，`layer.a` 與 `layer.b` 是 A、B，而且 B 一開始全是 0，所以剛建好的層輸出和原層相同。下面把它建在 `nn.Linear(4, 3)` 上，做一次真正的更新：

```python
import torch
from torch import nn
from tiny_perceptron.alignment import LoRALinear

torch.manual_seed(42)
layer = LoRALinear(nn.Linear(4, 3), rank=2, alpha=2)
base_before = layer.base.weight.detach().clone()
a_before = layer.a.detach().clone()
b_before = layer.b.detach().clone()
optimizer = torch.optim.SGD([p for p in layer.parameters() if p.requires_grad], lr=0.1)
loss = layer(torch.ones(1, 4)).square().mean()
loss.backward()
optimizer.step()
print("可更新參數", sum(p.numel() for p in layer.parameters() if p.requires_grad))
print("原矩陣完全未變", torch.equal(base_before, layer.base.weight))
print("修正A這一步沒變", torch.equal(a_before, layer.a))
print("修正B真的改變", not torch.equal(b_before, layer.b))
```

`.detach().clone()` 複製一份獨立的舊值，之後才能和更新後的數字比較；若只是把 `layer.b` 另取一個名字，兩個名字指向同一份資料，更新後會一起變。`[p for p in layer.parameters() if p.requires_grad]` 只挑出可學的參數交給最佳化器（[1.13](01.md#1.13)），也就是 A 與 B。代價取輸出平方的平均，目標是讓輸出接近 0；這只是為了產生梯度的局部例子，不是讀照片。`loss.backward()` 做反向傳播、算出梯度，`optimizer.step()` 才真的更新參數。

輸出依序是 14 與三個 True。A 有 2×4＝8 個數、B 有 3×2＝6 個數，共 14 個可更新參數；W 一個數都沒變。A 這一步沒有變，是因為 B 還是 0：A 的改變要經過 B 才影響輸出，所以 A 的梯度全是 0（8.8 也看過這個現象）；B 則收到梯度而改變。等 B 不再是 0，A 才會在之後的更新中改變。注意這個小例子的 14 反而比 W 的 3×4＝12 多，不能拿它示範省參數：修正路要比較少，`r×(輸入數+輸出數)` 必須小於 `輸入數×輸出數`。

練習把 `rank=2, alpha=2` 改成 `rank=1, alpha=1`（倍率仍是 1），先預測可更新參數：A 是 1×4、B 是 3×1，共 7 個，才比 W 的 12 個少；其餘三項仍是 True。不論 rank 多小，固定的 W 仍要載入並參與計算（[20.3](20.md#20.3)）。

真正的候選把 LoRA 加在 Qwen 文字核心的注意力裡，產生 Query 與 Value 的那兩個 Linear 上（第 3 章的 Q、V），rank 8、alpha 16（倍率 2），共 1,605,632 個可更新參數；看圖的部分與 Whisper 都不因此重新訓練。小例子的學習率 0.1 只是為了看清一次更新，完整訓練用 0.00003，兩者不是同一個實驗。

每個候選的修正檔約 6.44 MB，只有修正參數，不含底座，也不含續訓需要的完整狀態。[訓練核對](../../docs/natural-assistant/evidence/v4-runtime/train-37217452291/training-audit-summary.json)是這次訓練機器可讀的完整紀錄（JSON），`independent_audit` 底下的 `changed_adapter_tensors` 是 112，表示 112 個修正張量的前後指紋都改變了；`frozen_scope` 說明底座只抽查了幾個位置，沒有逐一比較全部二十億個數值。更新確實發生，和用途因此改善，是兩件要分開證明的事。
