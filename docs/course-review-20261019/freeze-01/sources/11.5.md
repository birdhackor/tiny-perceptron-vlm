## 11.5 多開一些文字層，怎麼比較成本與效果？

圖片問答可以只調接頭，也可以連最後一個文字區塊一起調，或開放整個模型。先數每種方案允許改幾個數字，再用相同資料與預算比較答案；參數多，不代表新題一定更好。

```python
from tiny_perceptron.model import TinyLM, ModelConfig
from tiny_perceptron.multimodal import MultiModalLM

model = MultiModalLM(TinyLM(ModelConfig(width=8)))
for mode in ["projector", "partial", "all"]:
    model.requires_grad_(mode == "all")
    model.image_projector.requires_grad_(True)
    if mode == "partial":
        model.language.blocks[-1].requires_grad_(True)
    count = sum(p.numel() for p in model.parameters() if p.requires_grad)
    print(mode, count)
```

`for mode in [...]` 依序試三種方案。每輪先用 `model.requires_grad_(mode == "all")` 重設全部開關：只有 all 時括號裡是 True，其餘兩種先全部凍結，避免上一輪留下的開關；再打開接頭，partial 另外打開最後一個文字區塊。特徵寬度 8 的預設模型印 projector 136、partial 976、all 8296。

all 的 8,296 個裡，有 712 個屬於聲音入口與聲音接頭。第 12 章才講聲音（聲音入口的實作見 [12.8](12.md#12.8)），這裡只需要知道 `MultiModalLM` 也帶著這兩個零件；純圖片題的前向計算不經過它們，所以開放了也收不到梯度，不會被更新。

可訓練參數的數量是成本線索：訓練時，每個真的收到梯度、參與更新的參數還要存一份梯度，AdamW 再為它存兩份最佳化器狀態（m、v，見 [5.4](05.md#5.4)）。效果則要從相同起點、用同樣的題目與相同數量的有效目標比較，並另外測原文字任務。

[專案實際訓練過的小對照](../../docs/course-experiments/results/vqa.json)用的是文字核心特徵寬度 64、兩個區塊，圖片入口特徵寬度 16 的模型，與上面特徵寬度 8 的計數例不同。材料是紅、綠、藍各配圓形、方形的六種合成圖，每張圖各問顏色與形狀，答案分別是 `red`／`green`／`blue` 與 `circle`／`square`。訓練圖把圖形中心向左移 2 或 1 像素，或不移；驗證圖向右移 1，測試圖向右移 2；同一張原圖的兩題放在同一組。所以驗證題與測試題考的是沒練過的位置，顏色與形狀組合仍是已知的六種。

三版都從同一個起點開始：[11.3](#11.3) 那個只訓練過接頭、學過完整描述的模型。接著各練圖片問答 160 步，每版計入代價的有效目標都是 3,830 個。驗證題與測試題各 12 題，是分開的兩組：

| 更新範圍 | 可訓練參數 | 驗證題答對 | 測試題答對 |
| --- | ---: | ---: | ---: |
| 只訓練接頭 | 1,088 | 3/12 | 3/12 |
| 接頭＋最後文字區塊 | 50,816 | 10/12 | 12/12 |
| 全部 | 145,664 | 12/12 | 9/12 |

參數最多的「全部」沒有拿到最高的測試題成績，中間方案的驗證題也有錯。這批只有十二題，不能據此選出所有模型的最佳範圍；比較的是這份資料與配方，而不是單看參數排名。

練習把第一段程式的 `ModelConfig(width=8)` 改成 `ModelConfig(width=8, layers=2)`，先預測三行：接頭仍 136；partial 仍只開最後一個區塊，所以還是 976；all 多一個區塊的 840 個，變成 9136。寬度、深度與更新範圍是三種不同的選擇。

同一個名字在不同工具裡可能指不同範圍：本節程式與上表的 partial 都是「接頭＋最後一個文字區塊」；[T.6](../training.md#T.6) 的訓練指令 `--freeze partial` 則開放接頭加第一個與最後一個文字區塊。重做實驗時，要照所用指令的說明確認更新範圍。
