## 13.10 偏好比較能教另一個評分模型嗎？

對「只回數字：1+2=?」，我們標「3」比「1 加 2 是 3。」合適。DPO直接拿這種比較調整回答的模型；這裡換一種用法：接收這個比較的，不是未來作答的模型，而是另一個專門給分的模型。它叫**獎勵模型（reward model）**，讀問題與回答，輸出一個分數，估計這份回答有多合適；這個分數叫**獎勵（reward）**。從本節到13.16，會用它走一遍**近端策略最佳化**（Proximal Policy Optimization，PPO）的流程。

先用手設分數看學習目標。較佳分數減較差分數為差距d，將`sigmoid(d)=1/(1+exp(−d))`當成較佳勝出的估計機率，再取負log作代價。差距0表示0.5；差距2約0.8808。這是偏好選擇的估計，不是內容正確率。

```python
import torch
from torch import nn  # 本節節錄的FiniteRewardModel會用到nn
from torch.nn import functional as F  # 本節節錄的preference_loss會用到F
from tiny_perceptron.posttraining import preference_loss

for preferred_score in [0.0, 2.0]:
    chosen = torch.tensor([preferred_score])
    rejected = torch.tensor([0.0])
    gap = chosen - rejected
    win_probability = torch.sigmoid(gap)
    loss = preference_loss(chosen, rejected)
    print("差距", gap.item(), "勝出機率", round(win_probability.item(), 4), "代價", round(loss.item(), 4))
```

輸出兩行勝出機率與代價約為`0.5、0.6931`和`0.8808、0.1269`。把較佳的分數相對拉高，代價就降低；兩個分數一起加10，差距與代價都不變。所以分數2本身不是88%的正確率：0.8808只是「和分數0的回答相比，這篇勝出」的估計機率，有意義的是兩篇的分數差。

`preference_loss`的寫法如下：

```python
# 節錄自 tiny_perceptron/posttraining.py：preference_loss
def preference_loss(chosen_scores, rejected_scores):
    """Bradley–Terry 比較：只學同題勝者與敗者的分數差。"""
    if chosen_scores.shape != rejected_scores.shape or not chosen_scores.numel():
        raise ValueError("偏好兩邊必須同形狀且至少有一對")
    return -F.logsigmoid(chosen_scores - rejected_scores).mean()
```

三引號字串是給人看的說明（docstring），不影響計算；Bradley–Terry是這種「兩個分數相減，再經sigmoid變成勝出機率」的比較模型的名字。`if`那行檢查兩邊形狀相同、而且至少有一對（`numel()`數tensor裡有幾個數字），不符合就用`raise ValueError`停下。最後一行就是上面的代價：`chosen_scores - rejected_scores`是差距d，`F.logsigmoid`算`log(sigmoid(d))`，加負號成為代價，`.mean()`把一批比較對平均。它和[13.5](#13.5)的DPO代價同形；差別在輸入是獎勵模型給的分數，沒有參考模型，也沒有beta。

接下來用一個選回答卡的小任務，把評分和作答分開。每道題各有四張**回答卡**，由Python事先寫好；卡號的用途固定：0號只給數字，1號用一句話說明，2號是錯的數字，3號請對方補資訊。以1+2題為例：

| 卡號 | 回答卡文字 |
| ---: | --- |
| 0 | 3 |
| 1 | 1 加 2 是 3。 |
| 2 | 4 |
| 3 | 請再提供更多資訊。 |

只回數字時選0，要求一句話說明時選1。另有「單價1元、運費2元，總價多少？」的題，因缺購買數量，應選求補數量的3號卡（這題的3號卡寫「請補充購買數量。」），不能擅自把單價加運費當總價。

小網路讀的不是中文，而是整理好的四個數，叫**情境（context）**。例如「只回數字：1+2=?」寫成`[0.1,0.2,0,0]`：兩個加數各除以10、是否要求一句話、是否缺購買數量，後兩格1表示有、0表示沒有。候選裡的加法也先由Python算好。獎勵模型的程式如下：

```python
# 節錄自 tiny_perceptron/posttraining.py：FiniteRewardModel
class FiniteRewardModel(nn.Module):
    """對 context 與候選編號評分；不把候選中文當自然語言輸入。"""

    def __init__(self, features=4, width=24, actions=4):
        super().__init__()
        self.register_buffer("candidate_identity", torch.eye(actions))
        self.network = nn.Sequential(nn.Linear(features + actions, width), nn.Tanh(), nn.Linear(width, 1))

    def forward(self, features):
        contexts = features[:, None, :].expand(-1, len(self.candidate_identity), -1)
        identities = self.candidate_identity[None, :, :].expand(len(features), -1, -1)
        return self.network(torch.cat((contexts, identities), -1)).squeeze(-1)
```

`class`、`__init__`與`forward`的寫法見[3.7](03.md#3.7)：`__init__`建立零件，`forward`寫計算，呼叫`reward_model(x)`時會執行`forward`。這裡的`__init__`做兩件事：

- `register_buffer("candidate_identity", torch.eye(actions))`存一張4×4的單位矩陣：第k列只有第k格是1，代表第k張回答卡。它跟著模型保存，但不是可學的參數。
- `nn.Sequential`把三層依序接起來：`nn.Linear`把8個數混成24個，`nn.Tanh`把每個數壓到−1與1之間（另一種啟用函式，[2.4](02.md#2.4)用的是ReLU），最後的`nn.Linear`再混成1個分數。

`forward`收到形狀`(題數,4)`的情境：

- `features[:, None, :]`在中間多加一個長度1的軸，變成`(題數,1,4)`；`expand(-1, len(self.candidate_identity), -1)`沿這軸重複成`(題數,4,4)`，讓四張卡各配到同一份情境（`len(self.candidate_identity)`是卡數4，`-1`表示那一軸維持原長）。
- `candidate_identity[None, :, :]`替卡號表多加一軸，再重複到每一題，同樣是`(題數,4,4)`。
- `torch.cat((contexts, identities), -1)`沿最後一軸接起來：每題每張卡都有「4個情境數＋4個卡號數」共8個數。
- 網路替每題每張卡給1個分數，形狀`(題數,4,1)`；`squeeze(-1)`拿掉最後那個長度1的軸，輸出`(題數,4)`。

所以它一次替四張卡各打一個分數，讀的是情境和卡號，不是中文；[13.15](#13.15)會實際呼叫它並印出形狀。訓練時，把同一題較佳卡與較差卡的分數送進`preference_loss`。

偏好標籤由作者規則產生，沒有招募真人，所以它只教流程，不是人類回饋強化學習（RLHF）的實證。

練習把第一段程式的`rejected = torch.tensor([0.0])`改成`[1.0]`，先預測兩個差距變−1與1，勝出機率約0.2689與0.7311。再把兩邊都加10（`chosen`寫成`torch.tensor([preferred_score + 10])`、`rejected`寫成`torch.tensor([11.0])`），核對機率與代價都不變。
