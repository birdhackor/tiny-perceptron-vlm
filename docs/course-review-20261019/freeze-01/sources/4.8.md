## 4.8 多一層，是多了什麼計算與成本？

一層 block 讀前文並修正表示；第二層拿的是**第一層更新後的表示**，再讀取與加工。層數叫**深度**，不是把相同原卡平均三次。更多層有機會構成更複雜規則，但每層也要儲存自己的配方並增加運算。

先固定二十候選、每位置八格、位置表最多 128 個位置，只改深度 1、2、3。希望檢查輸出仍是相同形狀，並數清每多一層加多少參數。

```python
import torch
from tiny_perceptron.model import TinyLM, ModelConfig

for depth in [1, 2, 3]:
    model = TinyLM(ModelConfig(vocab_size=20, width=8, layers=depth))
    count = model.description()["parameters"]
    logits = model(torch.tensor([[1, 2]]))["logits"]
    print("層數", depth, "參數格數", count, "輸出", logits.shape)
    assert logits.shape == (1, 2, 20)
```

`layers=depth` 決定 [4.6](#4.6) 的 `blocks` 裝幾個 block。`model.description()` 是函式庫 `TinyLM` 附帶的函式，回傳設定與參數總數的字典，`["parameters"]` 取出全部參數的格數加總。三次輸出形狀都為 `[1,2,20]`：一筆兩位置，每位置二十候選。特徵寬度八格不會把候選數變成八。參數格數為：

| 深度 | 總參數格數 | 比前一個多 |
| --- | ---: | ---: |
| 1 | 2,200 | — |
| 2 | 3,040 | 840 |
| 3 | 3,880 | 840 |

為什麼三層不是一層的三倍？輸入端與輸出端的零件只存一套：字的 embedding 表 `20×8=160`、位置表 `128×8=1024`（128 個位置、每位置八格）、最後 LN 的倍率與偏移 `8+8=16`、輸出層 `8×20=160`，共 1,360 格。每個 block 則各存一份：

| 每個 block 的參數 | 計算式 | 格數 |
| --- | --- | ---: |
| Q、K、V 與輸出投影四個 Linear 的權重 | `4×8×8` | 256 |
| FFN 擴張、縮回的權重 | `8×32+32×8` | 512 |
| FFN 兩個 Linear 的偏移 | `32+8` | 40 |
| 兩個 LN 的倍率與偏移 | `2×(8+8)` | 32 |

合計 840，所以總數是 `1360+深度×840`。注意力的四個 Linear 和輸出層在程式裡寫了 `bias=False`（[3.7](03.md#3.7)、4.6），這是本課模型的設定；FFN 的兩個 Linear 照 `nn.Linear` 的預設帶偏移（[2.3](02.md#2.3)）。GELU 本身沒有可調數字。

把 8 換成特徵寬度 D（`width`）、20 換成字表大小（`vocab_size`）、128 換成位置上限（`max_length`），就是一般式：輸入端與輸出端共 `2×字表大小×D+位置上限×D+2D`；每個 block 是 `12D²+9D`，其中 `4D²` 來自注意力，`8D²` 來自 FFN 權重（中間寬度是 4D），`5D` 來自 FFN 偏移，`4D` 來自兩個 LN。D=8 時正好是 `12×64+9×8=840`。

更深也需要更多前向計算、反向傳播與中間結果。特徵寬度增加則影響許多矩陣的兩邊：8×8 變 16×16 是四倍；字的 embedding 表與位置表只有一邊是寬度，剛好兩倍。不能將層數、寬度、候選數都用同一倍率估算。

這幾份模型都未訓練，只檢查結構，不提供三層更準的證據。要比較品質，應固定資料，交代更新步數或計算預算，並在驗證資料上評估。更多參數也可能只記住少量訓練句。

練習只把 `width=8` 改成 16，候選仍二十，輸出形狀保持 `[1,2,20]`。先用一般式預測深度 1 的總數與每多一層的差額，再執行核對；答案在補充區。

練習答案：特徵寬度 16 時，輸入端與輸出端是 `2×20×16+128×16+2×16=2720`，剛好是 1,360 的兩倍；每個 block 是 `12×16²+9×16=3216`，約為 840 的 3.8 倍，因為注意力與 FFN 的權重隨 D² 增加。深度 1 共 5,936，之後每層多 3,216。

本課實際訓練過的一個模型也能用同一式核對。固定配方 `text_foundation`（4.7 補充的防偷看檢查也用它，重做指令在 [T.4](../training.md#T.4) 補充區）建立特徵寬度 64、兩層的 `TinyLM`，字表大小與位置上限用預設的 264 與 128。代入得輸入端與輸出端 `2×264×64+128×64+2×64=42112`、每個 block `12×64²+9×64=49728`，共 `42112+2×49728=141568`；`TinyLM(ModelConfig(width=64, layers=2)).description()["parameters"]` 也是這個數。寬度與層數寫在 [scripts/course_experiments/text.py](../../scripts/course_experiments/text.py) 的 `run_text_foundation`，參數數記在[實驗紀錄](https://github.com/birdhackor/tiny-perceptron-vlm/blob/main/docs/course-experiments/results/text_foundation.json)的 `results.training.parameters` 欄。264 是第 6 章 byte 字表的大小：256 種 byte 加 8 個特殊 token，不是 264 個中文字。那次訓練沒有另做同預算的一層對照，不能用來證明兩層更好。
