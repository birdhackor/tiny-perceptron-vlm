## 17.5 不同大小的權重，應共用一把刻度尺嗎？

兩列權重分別是`[0.01,0.03,0.05,0.08]`與`[10,30,50,80]`。用4-bit對稱碼−7至7時，全表共用一個刻度就要容納80，刻度是80÷7≈11.4286。小列除以它全都接近0，四個權重會一起變成碼0。

若每列自己選刻度，小列用`0.08/7`，大列仍用`80/7`，就能在不改位元數的情況下保留小列的差別。這次比較的是**哪些數共用刻度**。下面先用函式庫的`quantize_symmetric`看結果：迴圈變數`per_row`依序把False、True交給`per_channel`；False時全表共用一個刻度，True時每列各一個。

```python
import torch
from tiny_perceptron.quantization import quantize_symmetric

w = torch.tensor([[0.01, 0.03, 0.05, 0.08], [10.0, 30.0, 50.0, 80.0]])
for per_row in (False, True):
    q, scale = quantize_symmetric(w, bits=4, per_channel=per_row)
    restored = q.float() * scale
    error = (w - restored).abs().mean(-1)
    print("每列獨立", per_row, "碼", q.tolist())
    print("每列MAE", error.round(decimals=4).tolist(), "刻度個數", scale.numel())
```

`per_channel=True`在這張線性層權重表指每個輸出列各一個刻度，不是每個輸入欄。`(w - restored).abs()`取每格誤差的絕對值，`mean(-1)`沿最後一軸取平均；這張2列、4欄表的最後一軸是每列的四個權重，所以得到兩個「每列MAE」。全表共用時，小列的碼全是0，MAE是0.0425；逐列時小列的碼是`[1,3,4,7]`，MAE約0.0025。大列兩種都約2.5。逐列看誤差，才不會讓大列的平均掩蓋小列。

刻度是怎麼選的？`quantize_symmetric`放在[tiny_perceptron/quantization.py](../../tiny_perceptron/quantization.py)，原樣如下：

```python
# 節錄自 tiny_perceptron/quantization.py：quantize_symmetric
def quantize_symmetric(weight, bits=8, per_channel=False):
    if bits not in (4, 8):
        raise ValueError("教材支援 4 或 8 bit")
    maximum = 2 ** (bits - 1) - 1
    if per_channel:
        scale = weight.abs().amax(-1, keepdim=True).clamp(min=1e-8) / maximum
    else:
        scale = weight.abs().max().clamp(min=1e-8) / maximum
    integers = (weight / scale).round().clamp(-maximum, maximum).to(torch.int8)
    return integers, scale
```

開頭兩行只接受4或8bit：`bits not in (4, 8)`檢查bits是不是這兩個值以外的數，是的話`raise ValueError(…)`立刻停下，並顯示括號裡的錯誤訊息。`maximum = 2 ** (bits - 1) - 1`是正碼上限，`**`是次方：4-bit是2³−1＝7，8-bit是2⁷−1＝127。碼只用−maximum到maximum，所以4-bit的−8、8-bit的−128都不會出現。

`per_channel`為真時，`weight.abs().amax(-1, keepdim=True)`沿最後一軸取每列最大的絕對值，本例是0.08與80；`keepdim=True`讓結果保持兩列一欄的形狀，之後`weight / scale`時，每列就除以自己那一列的刻度。否則`weight.abs().max()`取全表最大的絕對值，只得到一個刻度。兩條路都接`.clamp(min=1e-8)`：某列若全是0，最大絕對值是0，刻度會變成0而無法拿來除，所以先把它限制在至少10⁻⁸。最後除以maximum，也就是**刻度＝最大絕對值÷正碼上限**，例如小列是0.08÷7。

`integers = …`這一行和17.2的程式相同：除以刻度、取最近整數、限制在±maximum、存成int8。`return integers, scale`同時交回碼與刻度，所以呼叫時寫`q, scale = quantize_symmetric(…)`，一次接住兩個結果。

逐列的成本是多存刻度：一個FP32刻度占4byte，兩列各一個就是8byte。也可以讓一列內每固定幾個權重共用一個刻度，叫**分組量化（per-group quantization）**；組越小，每個刻度只需遷就組內最大的那個數，誤差通常較小，卻要存更多刻度與分組資訊。若每個權重都配一個FP32刻度，壓縮的好處就消失了。

練習把第一段程式的第一列`[0.01, 0.03, 0.05, 0.08]`改成`[10.0, 30.0, 50.0, 80.0]`，讓兩列範圍相同。先預測：共用與逐列得到相同的碼與MAE，逐列仍多存一個刻度。分組是精度與附帶儲存的取捨，不是免費的改善。
