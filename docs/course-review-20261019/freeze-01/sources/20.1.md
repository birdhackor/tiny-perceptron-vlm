## 20.1 照片、打字與說話，怎麼交給同一位助理？

先打字說「接下來請用繁體中文回答」，附一張招牌照片問上面寫什麼，下一輪改用說話追問。我們希望前面的語言要求和照片都還在，改變的只是這一輪問題的輸入方式。本章的做法是讓所有輸入方式共用同一份聊天歷史：打字的文字直接加入；錄音先由 Whisper 轉成文字，再加入同一個位置。

Whisper 做的是語音辨識（ASR，[12.11](12.md#12.11)）：輸出「聽到哪些字」，也就是轉寫文字（transcript），不是問題的答案。回答由圖文底座 Qwen 生成，它讀照片、聊天歷史與這一輪的文字。這和 [12.14](12.md#12.14) 先轉寫、再根據文字與歷史回答的分工相同，只是兩站都換成上游已經訓練好的成熟模型。章首提到的 LoRA 是加在 Qwen 旁邊的小修正，不是另一個聊天模型；目前交付的配置沒有開啟它。

下圖上面三列依序是打字、錄音與照片三種輸入，最下面一列是它們會合的地方。照片先交給 Qwen 附的前處理器（processor，[20.7](20.md#20.7)），換成模型能讀的輸入。

![打字的文字或 Whisper 的轉寫文字都接到同一份歷史，與照片一起由 Qwen 回答。](../figures/rewrite-20-input-routes.svg)

下面用 [7.1](07.md#7.1) 的消息格式（每則消息是一個有 `role` 與 `content` 的字典）手寫這兩條路線。`typed_question` 是打字送出的問題，`recognized_question` 假裝是 Whisper 對同一句話的轉寫文字；兩者這次手寫成一樣。

```python
history = [{"role": "user", "content": "接下來請用繁體中文回答。"}]
typed_question = "請讀出照片裡的招牌。"
recognized_question = "請讀出照片裡的招牌。"
typed_chat = history + [{"role": "user", "content": typed_question}]
spoken_chat = history + [{"role": "user", "content": recognized_question}]
print("Qwen收到相同對話", typed_chat == spoken_chat)
print("這輪問題", spoken_chat[-1]["content"])
```

`history + [...]` 把兩份清單接成一份新清單，所以兩條路線都保留第一輪的語言要求，只在尾端多一則這輪的使用者消息。`==` 逐項比較兩份清單裡的字典，因此「Qwen收到相同對話」印 True；`spoken_chat[-1]` 取最後一則消息，也就是這輪的問題。程式沒有辨識錄音，也沒有讀圖，只示範兩條路線在哪裡會合：會合之後，Qwen 分不出這段文字是打的還是說的。

所以轉寫文字一旦出錯，錯字就成了 Qwen 收到的問題。成品介面因此先顯示「辨識原稿」，讓使用者更正後再送出。評測語音路線時要保留更正前的轉寫文字：更正後答對是人工介入的結果，不能算成 ASR 原本就聽對。這套配置也只以文字回答，沒有語音朗讀。真正比較兩條路線時，還要固定照片、歷史與生成設定，再查 ASR 有沒有改掉問題的條件，[20.12](20.md#20.12) 會用一個例子做這件事。

練習把程式的 `recognized_question` 改成 `"請讀出照片裡的找牌。"`，假裝 ASR 把「招」聽成「找」。先預測：「Qwen收到相同對話」變成 False，「這輪問題」印出有錯字的版本——這就是 Qwen 這一輪會收到的內容。
