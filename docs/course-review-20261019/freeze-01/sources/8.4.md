## 8.4 同一模型如何依要求切換寫法？

對「1+1=?」，短答要求的目標是「2」，積木比喻要求的目標則是「2，像把兩組積木合在一起再數。」。對「2+2=?」也同樣準備兩版。這次希望同一模型先讀本次要求，再選相應寫法，事實答案在兩版都保持不變。

因此輸入必須含寫法條件，目標回答也要配對。這叫**條件式風格**：決定寫法的條件是模型看得到的文字。如果資料只有1+1短答、2+2長答，它可能靠題目記寫法，沒有必要讀要求。下面照已保存實驗的寫法，把條件寫成問題前的英文前綴：`style=concise`表示短答，`style=vivid`表示積木比喻。

```python
records = []
for question, fact in [("1+1=?", "2"), ("2+2=?", "4")]:
    for style in ["concise", "vivid"]:
        reply = fact if style == "concise" else fact + "，像把兩組積木合在一起再數。"
        records.append({"提問": f"style={style}; {question}", "回答": reply})
print("筆數", len(records))
for row in records:
    print(row["提問"], "→", row["回答"])
```

兩層迴圈先換題目、再換風格，產生`2題×2種要求=4筆`。`reply`按風格選目標句：`fact if style == "concise" else ...`在條件成立時取左邊，否則取右邊，與[7.3](07.md#7.3)用過的條件表達式相同。`f"style={style}; {question}"`是f字串：引號前的`f`讓大括號裡的變數換成它的值，例如style是`vivid`、question是`1+1=?`時，得到`style=vivid; 1+1=?`。`append`把這筆配對存入清單。這是人寫規則整理示範，尚未訓練模型。四筆的用處在於讓每題都有「只改要求」的對照。

已保存的訓練例子另加入第三種寫法`style=json`：只回JSON（[7.13](07.md#7.13)），例如`{"answer": 4}`把數字4放在answer欄位。固定參數、每一步都選最高分的token後，同一題得到：

| 已教過的條件 | `2+2=?`的實際回答 |
| --- | --- |
| `style=concise` | `3` |
| `style=vivid` | `3，像把兩組積木合在一起再數。` |
| `style=json` | `{"answer": 3}` |

這三份回答有明顯的寫法切換，數字都不正確。積木比喻版的檢查只確認那句積木比喻有沒有出現，不代表會為新題創作恰當比喻。測切換時要用同一新題輪流給不同要求；另換一個從未教過的風格名字，則是在測不同能力。

練習把內層迴圈的風格清單改成只有`["concise"]`，預測只剩2筆，也失去同題改要求的訓練對照，再執行確認。

這次實驗從[8.3](#8.3)的加法底座出發，把短答、積木比喻與JSON三種寫法都配在相同的49道加法訓練題上，再加上日期題（[8.6](#8.6)會介紹：輸入給了日期就確認，沒給就追問），讓同一份模型更新1,000次。生成回答時，模型替下一個token的各種候選給分，每一步取最高分的那個，接回前文，再選下一個，逐步形成回答。下表固定看`2+2=?`這一題，計數則用全部七道加法測試題，三種條件各測一次：

| 提示中的條件 | 這一題的實際新回答 | 寫法符合 | 加法數值正確 |
| --- | --- | ---: | ---: |
| `style=concise` | `3` | 7／7 | 0／7 |
| `style=vivid` | `3，像把兩組積木合在一起再數。` | 7／7 | 0／7 |
| `style=json` | `{"answer": 3}` | 7／7 | 0／7 |

短答只核對是否只含數字，積木比喻只核對那句積木比喻，JSON則先把回答文字讀成資料（[8.5](#8.5)會說明這一步），資料只能有`answer`這個欄位，而且它的值必須是整數。這些窄小規則讓結果可重查；三種寫法都符合，不代表它能自由創造貼切比喻。每種條件下的七題都生成了EOS，輸出在此停止；表格只顯示EOS之前可見的回答文字。能結束回答，內容仍可以全部錯，所以這次展示的是條件式寫法，不是成功的加法器。
