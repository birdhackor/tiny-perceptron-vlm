## 18.12 MoE 教師能教 Dense 學生嗎？

教師內部有三位expert，學生只有一套Dense FFN，是否要先把教師所有的expert搬進學生？如果比較的是下一個token的分布，就不需要。教師的內部路由怎樣得到結果，是它自己的運算；學生只需在相同的前文後，產生相同候選意義下的分布。我們沿用[相同候選身份](18.md#18.6)和[KL目標](18.md#18.8)，先確認不同的內部結構仍輸出同一種答案分數。

例如教師特徵寬度16、一層，FFN換成三位expert、每個token選兩位；學生特徵寬度8、一層，用一套Dense FFN。`ModelConfig`的`experts=3`把區塊裡的FFN換成三位expert的MoE，`top_k=2`是每個token選幾位，回看[15.4](15.md#15.4)。兩邊的內部特徵分別是16與8個數，不能直接逐項相減；但字表都是264項，讀相同兩個token時，輸出都是 `[1,2,264]`。這個共同的輸出介面讓分布蒸餾可行，不要求同樣的層數、同樣的特徵寬度或同樣的expert數量。

```python
import torch
from tiny_perceptron.model import TinyLM, ModelConfig
from tiny_perceptron.alignment import distillation_kl

torch.manual_seed(0)
teacher = TinyLM(ModelConfig(width=16, layers=1, experts=3, top_k=2)).eval().requires_grad_(False)
student = TinyLM(ModelConfig(width=8, layers=1))
ids = torch.tensor([[1, 2]])
with torch.no_grad():
    t = teacher(ids)["logits"]
s = student(ids)["logits"]
labels = torch.tensor([[1, 2]])
loss = distillation_kl(s, t, labels, temperature=1.0)
loss.backward()
print("教師/學生分數形狀", tuple(t.shape), tuple(s.shape))
print("總參數", teacher.description()["parameters"], student.description()["parameters"])
print("學生輸出層權重有梯度", student.output.weight.grad.abs().sum().item() > 0)
```

輸入是同一段ID，兩個模型的字表沿用相同的預設設定。teacher內部用MoE，student用Dense；`distillation_kl`只接收分數與有效目標的標記，不讀內部的expert索引。這個人工標籤把兩個位置都設為有效，只檢驗資料介面與梯度，不模擬完整的對話遮罩。`description()`回傳模型的設定與參數總數，[4.8](04.md#4.8)用過。`student.output`是學生的[輸出層](04.md#4.6)，把每個位置的8個特徵轉成264個候選分數；最後一行檢查KL的梯度確實流到它的權重。應輸出相同的 `(1,2,264)`，總參數18048與6104，學生輸出層權重有梯度True。

兩個模型都隨機初始化，此例證明能構成學習路徑，沒有證明教師有數學或語言能力，更沒有完成真正的蒸餾。實際使用時需載入已驗證的教師，保留同學生架構的未蒸餾對照，再比較任務品質與成本。教師的MoE總參數、每個token啟用的expert數與實際計算時間也要分別記錄，不能因為每次只選兩位，就把第三位的權重儲存算成零。跨架構蒸餾是一條可選的路線，不要求Dense成品一定經過MoE教師。

本章的MoE教師確實教過特徵寬度32的Dense學生，條件見選讀。故事沒有題目與回答之分，所以這裡的分數是**整篇故事的平均 NLL**：算法和[18.10](18.md#18.10)相同，但每篇故事的每個token連同最後的EOS都是有效目標，不像18.10只算題目之後的回答；52篇測試故事共有41,914個有效目標。只學原文的學生是2.4601；加入教師分布的學生降到2.3890，教師自己是2.3017。加入教師分布的學生，平均 NLL 較低，也更接近教師的水準；但兩個學生續寫時都還在重複`the`這類常見詞，平均 NLL 的改善不等於已經會寫故事。

學生更小會限制它能學到的細節。即使候選分布對齊，Dense學生仍可能無法在所有輸入上接近教師，尤其教師不同的expert形成多種複雜規則時；這需要獨立評估，不能由形狀相同推論能力相同。反過來，學生沒有router，也不代表它一定更快，實際耗時仍受硬體與輸入條件影響。

練習只把程式學生那行改成 `TinyLM(ModelConfig(width=8, layers=1, vocab_size=265))`。先預測學生分數的最後一軸變成265、教師仍是264，`distillation_kl`開頭的形狀檢查會報錯，錯誤訊息裡的「詞表」就是字表；再執行觀察。改回264之後路徑恢復：候選欄位先對上，內部結構才有自由。
