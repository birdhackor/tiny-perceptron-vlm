## 14.7 為什麼位置公式算得出，長文章卻未必讀得好？

把「校慶週六上午開始請在操場入口集合」依序寫成十六張卡片，每張卡放一個字。這裡為了只看位置，約定一張卡就是一個token；真實文字如何切成token，仍由所用的tokenizer決定（[第6章](06.md)）。卡片從0編到15。假設一個模型訓練時，每段文字最多八張卡，它收到的位置便只有0到7。現在我們希望它連後面的八張也一起讀，位置公式算得出8到15，是否就表示它能讀好整段？

位置公式做的是替卡片提供位置資訊。回想[14.1](14.md#14.1)用旋轉表示位置的RoPE：Query是某位置用來查找關聯的向量，Key是其他位置供它比對的向量；把其中成對的數字依位置旋轉，兩者的點積便會包含相對位置的影響。旋轉可以繼續算下去，轉到位置15也不需要多查一張位置表。但這只是算出一組數字，模型還要學會在這組數字下，怎樣利用文字內容找出關聯。

在我們每段最多八張卡的假設裡，兩張卡最遠相隔7個位置，例如位置0和7；位置0和15卻相隔15個位置，這種距離沒有出現在原來的訓練段落中。即使在訓練過的位置範圍內，詞句之間的關係也有很多種，不是每一種都學會了；把文章拉長，又增加了原先根本遇不到的距離與位置組合。

下圖藍色卡片是原來可能出現的位置，橘色是延長後才會出現的位置。兩列只是把同一段文字折成兩行，第二列沒有重新從0編號。圖底把0到7、0到15的距離並排，請比較新增的是哪些位置關係。

![十六張文字卡片中，位置8到15與相隔15個位置的距離超出八張卡的訓練範圍](../figures/rewrite-14-7-position-range.svg)

下面用程式核對兩件事：位置公式真的算得出位置8到15，以及延長後多出哪些距離。`table` 是[4.1](04.md#4.1)那種位置表，只有八列；`rope` 是14.1介紹的函式庫版本。

```python
import torch
from torch import nn

from tiny_perceptron.modern import rope

table = nn.Embedding(8, 4)
positions = torch.arange(16)
print("位置表查得到嗎", (positions < table.num_embeddings).tolist())
print("RoPE 輸出形狀", list(rope(torch.ones(1, 1, 16, 4), positions).shape))
for length in (8, 16):
    print(length, "張卡：相隔0到", length - 1, "個位置的卡片各有幾對", [length - d for d in range(length)])
```

`table.num_embeddings` 是位置表的列數8；`positions < table.num_embeddings` 逐項比較，前八個是True、後八個是False：位置8到15在表裡沒有那一列，拿去查表會出錯。`rope` 卻照公式替16個位置都算出旋轉後的特徵，輸出形狀 `[1, 1, 16, 4]`。最後的迴圈數卡片對：在[因果注意力](03.md#3.6)裡，每張卡讀自己和前面的卡，所以一段 `length` 張卡中，相隔d個位置的卡片有 `length - d` 對（d=0是卡片和自己）。八張卡時，相隔7個位置只有位置0和7這一對，相隔8到15的一對也沒有；十六張卡則每種距離都有。遠距離在原本的訓練段落裡本來就少見，延長後還多出八種沒見過的距離。

這類把計算用到訓練範圍以外的做法，叫長度外推。它可能有用，但相對位置的公式本身沒有承諾外推後的品質。模型在熟悉範圍學到的比對方式，遇到新的旋轉組合時可能不再合適；後續還有把比對分數轉成注意力權重、混合內容和產生答案等步驟。因此，能算出長序列的向量，與能從長序列取出答案，中間仍有學習與驗收的工作。

這裡要分開三件事。訓練長度描述模型當時看過多長的片段；執行上限描述軟體這次允許送入多長的序列；任務能力則要看它能否完成問題。例如軟體接受十六張卡，表示輸入沒有因上限被丟掉；若要說它能取回遠處線索，還要提供答案明確的題目，核對完整回答。僅將上限從八改為十六，不會同時完成這三件事。

所以延長上下文視窗（context window，[2.5](02.md#2.5)）時，先問位置規則怎麼處理新增範圍，再問模型如何適應，最後才問它在指定任務上有沒有讀好。下一節的做法是保留十六張卡，將位置刻度縮回原來八個位置所配置的座標範圍。

練習把假設改成「訓練每段最多十二張卡」，仍讓輸入有十六張：把程式的 `nn.Embedding(8, 4)` 改成 `nn.Embedding(12, 4)`、迴圈的 `(8, 16)` 改成 `(12, 16)`。先預測哪些位置查不到、哪些距離在十二張卡裡一對也沒有，再執行核對：位置12到15查不到；原來最遠相隔11個位置，現在仍可相隔15個，相隔12到15的卡片對只出現在十六張卡裡。
