## 9.10 信心和正確率對得上嗎？

假設四題報告信心0.55、0.65、0.85、0.95，逐題對照正確答案，結果是對、錯、對、錯。平均信心(0.55+0.65+0.85+0.95)/4=0.75，實際正確率2/4=0.5，報得比實際答對的比例高。

按信心區間分組、比每組平均信心和正確率，叫**可靠度分箱（reliability binning）**，每個區間叫一箱。下面用兩箱：[0,0.5)與[0.5,1]。方括號表示包含該端點，圓括號表示不包含，所以0.5歸高箱，最後一箱連1也包含。四題都在高箱。

```python
import torch
from tiny_perceptron.alignment import reliability_bins

confidence = torch.tensor([0.55, 0.65, 0.85, 0.95])
correct = torch.tensor([1, 0, 1, 0])
bins = reliability_bins(confidence, correct, bins=2)
for row in bins:
    print(
        "區間",
        row["left"],
        row["right"],
        "筆數",
        row["count"],
        "信心",
        round(row["confidence"], 2),
        "正確率",
        row["accuracy"],
    )
ece = sum(row["count"] / len(confidence) * abs(row["accuracy"] - row["confidence"]) for row in bins)
print("平均校準差", round(ece, 2))
```

輸入四筆信心與對應的正確標記，1是對、0是錯。專案工具`reliability_bins`把每箱的筆數、平均信心、正確率整理成一個字典，全部放進清單`bins`。沒有樣本的箱不會印出，所以只有0.5到1.0這一行：筆數4、信心0.75、正確率0.5。

最後的式子對每一箱算「正確率與信心差多少」，`abs`取絕對值，再乘該箱筆數佔總數的比例；`sum(... for row in bins)`把各箱算出的值加總，得到0.25。這個量叫**ECE（Expected Calibration Error）**，在這裡可讀成按樣本量加權的校準差。只有一箱，所以權重4/4=1，差即|0.5−0.75|=0.25。

`reliability_bins`定義在[tiny_perceptron/alignment.py](../../tiny_perceptron/alignment.py)，整個函式如下：

```python
# 節錄自 tiny_perceptron/alignment.py：reliability_bins
def reliability_bins(confidence, correct, bins=5):
    result = []
    for i in range(bins):
        left, right = i / bins, (i + 1) / bins
        selected = (confidence >= left) & (confidence <= right if i == bins - 1 else confidence < right)
        if selected.any():
            result.append(
                {
                    "left": left,
                    "right": right,
                    "count": int(selected.sum()),
                    "confidence": float(confidence[selected].mean()),
                    "accuracy": float(correct[selected].float().mean()),
                }
            )
    return result
```

`bins=5`是預設值：呼叫時不寫就分五箱，上面的程式寫了`bins=2`。`for i in range(bins)`逐箱處理；`left, right = i / bins, (i + 1) / bins`一次算出兩個邊界，`i=0`時是0.0與0.5，`i=1`時是0.5與1.0。

`selected`那行替每一筆信心回答「在不在這一箱」。`confidence >= left`逐格比較，得到四個`True`或`False`；括號裡的`A if 條件 else B`（[9.2](09.md#9.2)）讓最後一箱用`<=`，把1.0也算進來，其他箱用`<`，所以0.5只屬於高箱。兩個布林tensor之間的`&`逐格做「且」：兩邊都是`True`才是`True`。本例`i=0`時四格全是`False`；`selected.any()`檢查有沒有任何一格是`True`，沒有就跳過，這就是低箱沒有印出的原因。

有樣本時，`int(selected.sum())`數出`True`的個數；`confidence[selected]`用[9.6](09.md#9.6)看過的布林選擇取出這一箱的信心，`.mean()`取平均，`float(...)`轉成普通Python數字。`correct[selected].float().mean()`把1、0的正確標記轉成小數再平均，就是正確率。每箱的五個值放進一個字典，`result.append(...)`把它接到清單尾端，最後`return result`交回所有有樣本的箱。

下圖的橫軸是平均信心、縱軸是正確率；灰色斜線標著「理想：正確率＝平均信心」，點落在線上表示「報幾成就對幾成」。本組的點(0.75,0.5)落在這條線下方，表示報出的把握比實際答對高，也就是過度自信。這個分析只計算每箱的平均，不改動任何一筆預測。四題只夠解釋計算：題目這麼少時，箱切得越細，每箱只剩一兩題，結果容易被單一題左右；換一種分箱方式，ECE也可能跟著改變。

![四份信心同在高箱，平均把握高於實際正確率](../figures/rewrite-09-10-calibration-bins.svg)

**溫度縮放（temperature scaling）**是常用的校準方法：選一個正數τ，叫校準溫度，把各候選的原始分數除以τ，再用[1.7的softmax](01.md#1.7)轉成機率。τ=1維持原尺度；τ較小讓原先較高分的候選更突出，較大則讓機率較平均，不會交換候選分數的高低次序。τ要在另一份沒拿來訓練的**校準資料（calibration split）**上選：事先列出幾個τ，逐一算平均分類交叉熵，取最低者；交叉熵按正確答案那一項的機率計算（[1.8](01.md#1.8)），不必像ECE先分箱。固定τ後才在測試資料上評估。[Guo等人的方法](https://proceedings.mlr.press/v70/guo17a.html)只改報出的機率，不改選出的答案；選出的τ在校準資料上代價最低，也不保證在測試資料上更可靠。已訓練小分類器的實測見補充，那次沒有另切校準資料。

練習在第一段程式把`confidence`改成`torch.tensor([0.55, 0.65, 0.85, 0.95, 0.25])`、`correct`改成`torch.tensor([1, 0, 1, 0, 1])`，也就是新增一筆信心0.25且答對的題。先預測：這次`i=0`那一箱的`selected.any()`成立，多印出低箱一行（筆數1、信心0.25、正確率1.0），高箱仍是四筆；ECE變成(1/5)×|1−0.25|+(4/5)×|0.5−0.75|=0.15+0.2=0.35。執行核對，並解釋為什麼這個新樣本讓整體差變大：它答對卻只報0.25；`abs`取絕對值，報低報高一樣計入。

我們對兩個已訓練的小分類器做過一次實測：第10章的圖片分類器（六類合成圖片）與第12章的單音分類器（low、high兩類）。兩章才介紹它們；這裡只需要知道，它們各自從固定的幾個候選中選一個答案。結果記在[encoders 實驗的實驗紀錄（JSON）](../../docs/course-experiments/results/encoders.json)，這是機器可讀的完整結果：`results.vision.calibration`與`results.audio.calibration`底下，`selection`列出每個τ在驗證資料上的平均交叉熵，`test.original`與`test.calibrated`裡的`ece`、`brier`、`mean_confidence`、`nll`就是下表與下文的數字。選溫度用的是分類交叉熵，也就是把正確答案的機率轉成猜錯代價，再對題目平均；正確答案的機率越低，代價越大。專案用負自然對數來轉換，例如正確答案機率0.8的代價約0.2231，機率0.2的代價約1.6094，算例可回看[1.8](01.md#1.8)。這個量看的是報給正確答案的機率，不只計算最高候選是否答對。

這次沒有另切校準資料，而是讓驗證資料兼任：各分類器在驗證資料上比較τ=0.5、0.75、1、1.5、2、3、5，選平均分類交叉熵最低者，再固定設定，到測試資料上評估；測試答案沒有參與選溫。這是[Guo等人提出的溫度縮放](https://proceedings.mlr.press/v70/guo17a.html)的固定網格教學近似，不是連續尋找最佳溫度。兩個分類器都選τ=0.5，這次使機率更集中：最高候選的機率更高，其餘候選的機率總和更低。為什麼變尖反而讓驗證代價變小？答對的題變尖後，正確答案就是最高候選，它的機率升高、代價變小；答錯的題變尖後，機率更集中到錯的候選上，這次那道圖片錯題的正確答案機率就跟著下降、代價變大。這兩批驗證題多半答對（圖片5/6、單音8/8），前者占上風，所以選出較小的τ。若驗證題錯得多，選出的方向就可能相反；這也與常見的「提高溫度降低過度自信」方向不同，所以方向必須由驗證數字決定。

實驗紀錄用五個等寬信心箱，從[0,0.2)到[0.8,1]，和`reliability_bins`預設的`bins=5`切法相同，但空箱也保存。除ECE外，另算**Brier分數**：把每個候選機率與正確答案的0或1逐項相減、平方、加總，再對題目平均，越小越好。例如正確答案是high，卻報low為0.8、high為0.2，這一題是0.8²+(0.2−1)²=1.28。本次採候選平方差的總和，沒有再除候選數，讀其他資料時應核對定義。
