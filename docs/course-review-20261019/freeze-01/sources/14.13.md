## 14.13 只在第三輪算 loss，其他輪會怎樣？

現在固定跑三輪，把第三輪的答案和正確答案比較。問題是「先有2件，加3件，再拿走1件」，目標是4。三輪都屬於同一題的內部計算，不需要替第一輪捏一個較差答案、第二輪捏一個半成品答案。

以最後答案分類為例，訓練代價（loss）是 `CE(head(s_3), y)`：這時 `head` 是輸出各類別分數的分類頭（[10.5](10.md#10.5)），y 是正確答案的類別4，CE 是[1.8](01.md#1.8)的交叉熵。把三輪展開後，第三輪的代價透過第三、第二、第一輪的計算回傳梯度；共享參數收到各次使用的貢獻，再由最佳化器更新一次。這是沿展開後的計算做[反向傳播](01.md#1.10)（程式裡的 `backward()`），常稱 **BPTT（backpropagation through time）**；此處的「time」是循環步驟，不是文字的實際時鐘。

下面只做一次梯度檢查。人工設計一個共享加法 `state=state+w`，w 初值0.2，跑三輪後得到0.6，離目標1還差0.4；代價取兩者差的平方。它沒有 Transformer，也沒有更新參數。

```python
import torch

w = torch.tensor(0.2, requires_grad=True)
state = torch.tensor(0.0)
for _ in range(3):
    state = state + w
loss = (state - 1).square()
loss.backward()
print("狀態", round(state.item(), 4), "代價", round(loss.item(), 4), "梯度", round(w.grad.item(), 4))
```

狀態0.6、代價0.16、梯度−2.4。因為三次加的都是同一個 w，最後狀態是3w，所以導數是 `2*(3w-1)*3`，代入得 `2×(−0.4)×3=−2.4`：三次使用各貢獻 `2*(3w-1)`，都加在同一個 `w.grad` 上。同一參數用三次並不是有三份獨立參數。

這樣訓練只直接要求第三輪的讀出好。第一、二輪的狀態確實參與運算及梯度，卻沒有要求當時的分類頭就能答對；第四輪甚至沒有參與這次展開。讀出答案的那一輪叫**終止深度**（exit depth），本節的終止深度固定是3。事後換成二輪或四輪，效果沒有保證：程式能接受一個新的終止深度，和該深度受過合適訓練，是兩件事。

大模型可能為了記憶體只對最後幾輪做反向傳播，稱為**截斷反向傳播**；這改變哪些展開路徑保留梯度，不能寫成與完整 BPTT 完全一樣。本課短實驗先用完整的反向傳播，避免把截斷與輪數差異混在一起。

練習把程式的 `range(3)` 改成 `range(2)`，先算二輪的狀態與代價：0.4和0.36，再執行核對。這些是手工參數下的結果；不能據此推論所有三輪訓練模型都一定在二輪較差。要促進多輪都可用，下一節改的是訓練配方。
