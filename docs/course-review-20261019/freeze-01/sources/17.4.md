## 17.4 碼0一定代表浮點零嗎？

4-bit有16種碼。若想覆蓋−1到2，可以把碼0至15均勻放在這段範圍：15個間隔，刻度是3÷15＝0.2。碼0代表−1、碼1代表−0.8……碼15代表2；浮點數0落在碼5，而不是碼0。

代表浮點數0的那個碼叫**零點（zero-point）**。刻度決定相鄰兩碼差多少，零點決定0落在哪個碼。存下碼之後，還原公式是`還原值＝(碼−零點)×刻度`，例如碼10還原成`(10−5)×0.2＝1`。前兩節讓碼0代表0、正負兩邊的碼一樣多，叫**對稱量化（symmetric quantization）**，只需要刻度；本節多了可移動的零點，叫**仿射量化（affine quantization）**。

```python
import torch

x = torch.tensor([-1.0, 0.0, 1.0, 2.0])
low = min(x.min().item(), 0.0)
high = max(x.max().item(), 0.0)
scale = (high - low) / 15
zero = round(-low / scale)
q = (x / scale + zero).round().clamp(0, 15).to(torch.uint8)
restored = (q.float() - zero) * scale
print("刻度與零點", scale, zero)
print("碼", q.tolist())
print("還原值", restored.round(decimals=4).tolist())
print("碼0到15的還原值", [round((code - zero) * scale, 1) for code in range(16)])
```

`x.min().item()`取出最小值變成Python數字，`min(…, 0.0)`再和0比、取較小者；`max(…, 0.0)`同理。這讓選定的範圍一定包含0，零點才找得到對應的碼。本例low是−1、high是2，刻度0.2、零點5；碼是`[0,5,10,15]`，還原值`[−1,0,1,2]`。這四個數剛好都是某個碼的還原值，所以沒有捨入誤差；一般數字仍會有。

最後一行畫出整把刻度尺。`range(16)`依序給出0到15，方括號裡的`for code in range(16)`對每個碼各算一次`(碼−零點)×刻度`，再把結果收成一個清單：從−1每次加0.2，碼5是0，碼15是2。

`torch.uint8`是不帶正負號的8位元整數，可存0到255；這裡只用到0到15，還沒有把兩個碼併進一個byte（[17.8](17.md#17.8)才做）。若x全是0，範圍寬度是0、刻度也是0，除法會出問題，要另外處理；本例只示範寬度不為0的情況。

同樣叫4-bit，本章不同步驟用的整數範圍不同：本節的仿射碼是0到15；[17.5](17.md#17.5)起的`quantize_symmetric`用對稱碼，4-bit只用−7到7（−8不用），8-bit用−127到127；[17.8](17.md#17.8)的打包器接受−8到7，存進byte前各加8，變成0到15。看到「4-bit」時，先問是哪一步的數字。

練習把程式的`x = torch.tensor([-1.0, 0.0, 1.0, 2.0])`改成`x = torch.tensor([-2.0, 0.0, 1.0])`。先預測：範圍寬仍是3，刻度仍是0.2，零點改成10，碼變`[0,10,15]`，最後一行的刻度尺改從−2排到1。刻度管間隔，零點管0的位置，兩者分工不同。
