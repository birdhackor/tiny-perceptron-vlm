## 10.5 形狀答案如何把梯度送回圖片入口？

看下面兩張合成圖：左邊是紅色方塊，右邊是藍色圓形。這次任務是回答形狀，所以人的答案先是「方塊」「圓形」。程式需要數字標籤，才約定方塊為 0、圓形為 1；因此兩張圖的正確標籤依序是 `[0,1]`。

![scene 合成的紅方塊與藍圓形各對到類別編號 0、1；紅色梯度箭頭從交叉熵回到分數，再經分類頭、平均回到圖片入口](../figures/rewrite-10-shape-gradient.svg)

前三節的切塊、patch embedding 與位置向量，再加上一段逐位置的加工，就組成把圖片變成特徵的**圖片入口**（image encoder，也叫編碼器）。圖的下半是計算順序：圖片入口 → 平均 → 分類頭 → 分數。**分類頭**（classification head）是接在特徵後面、為每一類各算一個分數的輸出層；這裡是一個 `Linear(8,2)`，方塊、圓形各一個分數。交叉熵比較分數與正確標籤，得到代價（loss）；梯度描述每個參數小幅改變時，代價會怎樣變。本節要核對的是：這條影響能不能一路傳回圖片入口。

```python
import torch
from torch import nn
from torch.nn import functional as F
from tiny_perceptron.multimodal import VisionEncoder, patchify, scene

torch.manual_seed(0)
encoder = VisionEncoder(width=8)
classifier = nn.Linear(8, 2)
images = torch.stack([scene("red", "square"), scene("blue", "circle")])
features = encoder(images)
logits = classifier(features.mean(1))
loss = F.cross_entropy(logits, torch.tensor([0, 1]))
loss.backward()
print("切塊", tuple(patchify(images, 4).shape), "特徵", tuple(features.shape), "分數", tuple(logits.shape))
print("圖片入口收到梯度", encoder.projection.weight.grad.norm().item() > 0)
```

`torch.stack` 把兩張 `(3,16,16)` 的圖疊成一批 `(2,3,16,16)`。第一行印出三個形狀：切塊後是 `(2,16,48)`；經過圖片入口變成 `(2,16,8)`，也就是兩張圖、各 16 個位置、特徵寬度 8；`mean(1)` 把每張圖的 16 條特徵平均成一條，分類頭再算出 `(2,2)`，每張圖兩個候選分數。

`backward()` 做反向傳播（backpropagation，[1.10](01.md#1.10)），把代價對每個參數的梯度存進 `.grad`。最後一行看圖片入口裡 `projection` 的梯度：`.norm()` 把整張梯度表縮成一個總長度，大於 0 就表示其中有數字不是 0，預期印出 True。程式沒有 `optimizer.step()`，參數尚未更新；這裡展示的是梯度通路，不是訓練後辨認形狀的成績。

為什麼看 `projection`？打開圖片入口的實作就知道：

```python
# 節錄自 tiny_perceptron/multimodal.py：VisionEncoder
class VisionEncoder(nn.Module):
    def __init__(self, width=16, image_size=16, patch_size=4):
        super().__init__()
        self.patch_size, self.image_size = patch_size, image_size
        self.projection = nn.Linear(3 * patch_size**2, width)
        self.position = nn.Parameter(torch.randn(1, (image_size // patch_size) ** 2, width) * 0.02)
        self.feature = nn.Sequential(nn.LayerNorm(width), nn.Linear(width, width), nn.GELU())

    def forward(self, images):
        if images.shape[1:] != (3, self.image_size, self.image_size):
            raise ValueError("先把圖片轉成這個 encoder 配置的 RGB 高寬")
        return self.feature(self.projection(patchify(images, self.patch_size)) + self.position)
```

`nn.Module` 類別的讀法和 [3.7](03.md#3.7) 相同：`class VisionEncoder(nn.Module)` 定義一種新零件；`__init__` 建立可學的零件，它的第一行 `super().__init__()` 先讓 PyTorch 做好登記參數的準備；`forward` 寫計算順序，呼叫 `encoder(images)` 時執行的就是 `forward`。

`__init__` 先用 `self.patch_size, self.image_size = patch_size, image_size` 一行同時記下兩個設定，`forward` 會用到；接著建三樣零件。`projection` 是 [10.3](10.md#10.3) 的 patch embedding：輸入 `3 * patch_size**2`＝3×4²＝48 個數（`**` 是次方），輸出特徵寬度 `width`。`position` 是 [10.4](10.md#10.4) 說的可訓練位置向量，形狀 `(1,16,width)`：`(image_size // patch_size) ** 2`＝(16÷4)²＝16 個位置，每個位置一排數字；`nn.Parameter` 把這個 tensor 登記成可學的參數；乘 0.02 讓起始值很小，免得一開始隨機的位置向量蓋過 `projection` 從像素算出的特徵。`feature` 用 `nn.Sequential` 把三步依序接起來：層正規化（LayerNorm，[4.3](04.md#4.3)）、寬度不變的 Linear、GELU（[4.4](04.md#4.4)）。

`forward` 先檢查去掉筆數軸後的形狀 `images.shape[1:]` 是不是 3 通道、16×16，不是就報錯。最後一行要由內往外讀：`patchify` 切塊 → `projection` 算特徵 → 加上 `position` → `feature` 再加工。`projection` 是第一個用到參數的步驟，離代價最遠；梯度要先經過分類頭、平均、`feature` 和位置相加，才到得了它。所以 `projection` 收到梯度，就表示整條路都通。圖中的紅色箭頭畫的就是這條路：從交叉熵往上回到分數，再往左經過分類頭、平均，一路回到圖片入口。

這兩張圖還有一個資料陷阱：紅色總是方塊，藍色總是圓形。即使後續練到兩張全對，模型也可能只用顏色。若要教形狀，應讓紅圓、藍圓同標圓形，紅方、藍方同標方塊；若要教顏色，則讓同色不同形狀共享顏色標籤。目標變了，資料與判準也要一起改。

平均也是一種選擇：它留下顏色這類全圖共有的線索，卻可能丟掉「紅塊在左還是右」這種排列資訊。同一份平均表示不會自動適合所有看圖問題。

練習把第一段程式的 `torch.tensor([0, 1])` 改成 `torch.tensor([1, 0])`，也就是故意給相反的形狀答案。先預測最後一行還是不是 True。預期仍是 True：梯度照樣傳得回去。有梯度只表示通路接通，不能證明標籤正確。
