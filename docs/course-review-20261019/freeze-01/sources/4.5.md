## 4.5 注意力、FFN與殘差怎樣接成一層？

現在有四種動作：LN 整理每張位置卡，注意力讀前文，FFN 加工各卡，殘差把新修正加回舊卡。希望把它們接成能反覆使用的一層，而且輸入與輸出保持同樣的筆數、位置數與特徵寬度。

這種層塊叫 **block**。本章採「分支先整理再算」，叫 **pre-norm**，分兩段：

`u=x+Attention(LN(x))`

`y=u+FFN(LN(u))`

第一段留著 x，分支整理後讀前文，再加回修正。第二段留著 u，分支整理後加工特徵，再加回。主路沒有被 LN 永久替換；LN 在分支中。

![主路保留表示，兩個分支先LN再算，先後加回修正](../figures/rewrite-04-block-flow.svg)

圖裡每條主路都是同樣三位置、每位置八格。注意力分支允許讀前文，FFN 分支在每位置獨立算；最後的輸出可交下一個同寬 block。

這兩個式子就是函式庫 `Block` 的計算。下面的精簡版 `Block` 直接從函式庫 import `CausalAttention` 與 `DenseFFN`：[3.7](03.md#3.7)、[4.4](#4.4) 已經核對過，不用後章功能時，這兩個函式庫零件和那兩節自己寫的類別算出相同結果，所以不必重貼。

```python
# 精簡自 tiny_perceptron/model.py：Block（省略 norm、kv_heads、backend、rotary、activation、experts 設定，valid、positions、segments、cache 參數，以及回傳的 KV 快取與輔助代價）
import torch
from torch import nn

from tiny_perceptron.attention import CausalAttention
from tiny_perceptron.modern import DenseFFN


class Block(nn.Module):
    def __init__(self, config):
        super().__init__()
        self.norm1, self.norm2 = nn.LayerNorm(config.width), nn.LayerNorm(config.width)
        self.attention = CausalAttention(config.width, config.heads)
        self.ffn = DenseFFN(config.width)

    def forward(self, x):
        attended, _ = self.attention(self.norm1(x))
        u = x + attended
        return u + self.ffn(self.norm2(u))
```

零件類別的寫法同 3.7。`__init__` 建立四個零件：兩個 LN（`norm1`、`norm2` 各有自己的倍率與偏移）、一個注意力、一個 FFN；`config` 是一份模型設定，下面說明。`forward` 逐行對上兩個式子：

- `attended, _ = self.attention(self.norm1(x))`：先 LN、再讀前文。函式庫的 `CausalAttention` 回傳輸出與 KV 快取兩樣（3.7），`_` 表示不用第二樣。
- `u = x + attended`：第一次殘差，就是 `u=x+Attention(LN(x))`。
- `return u + self.ffn(self.norm2(u))`：第二次殘差，就是 `y=u+FFN(LN(u))`。

```python
from tiny_perceptron.model import Block as LibraryBlock
from tiny_perceptron.model import ModelConfig

config = ModelConfig(width=8)
print(config)
torch.manual_seed(42)
block = Block(config)
with torch.no_grad():
    block.norm2.weight.fill_(2.0)
x = torch.randn(2, 3, 8)
y = block(x)
library = LibraryBlock(config)
library.load_state_dict(block.state_dict())
library_y, _, auxiliary = library(x)
same = torch.allclose(y, library_y)
print("輸入", x.shape, "輸出", y.shape)
print("與函式庫版本相同：", same, "輔助代價", auxiliary.item())
assert same and y.shape == x.shape
```

`ModelConfig` 是只存設定的小記錄，`print(config)` 列出全部欄位與這次的值；完整定義見 [tiny_perceptron/model.py](../../tiny_perceptron/model.py)。本章用到的是下面五個：

| 欄位 | 預設 | 意思 | 用在 |
| --- | ---: | --- | --- |
| `width` | 32 | 特徵寬度 D，每位置幾格 | 所有零件 |
| `heads` | 1 | 注意力頭數 | 3.7、本節 |
| `vocab_size` | 264 | 字表大小，也就是輸出層的候選數 | 4.6 |
| `max_length` | 128 | 位置表的列數，也就是最多幾個位置 | 4.1、4.6 |
| `layers` | 1 | 疊幾個 block | 4.6、4.8 |

本章的程式常只改 `width`，其他用預設。後面章節寫 `ModelConfig(width=8)` 時也是這樣，字表大小就是預設的 264，它的由來在第 6 章（[6.4](06.md#6.4)）。其餘欄位用來換成後章的零件：`norm`（14.2 的 RMSNorm）、`activation`（14.4、14.5）、`rotary`（14.1 的 RoPE）、`tied`（14.6 的權重共享，weight tying）、`kv_heads`（16.4）、`backend`（16.8）、`experts` 與 `top_k`（第 15 章的 MoE）。用預設值時，它們都是本章的做法。

輸入兩筆、三位置、每位置八格，輸出形狀也為 `[2,3,8]`。數值已經過兩次修正，相同形狀不表示內容沒變。

和函式庫比對之前，程式先把 `norm2` 的倍率改成 2，否則比對抓不到兩個 LN 用反：剛建立時兩個 LN 的倍率都是 1、偏移都是 0，精簡版就算把兩個分支的 LN 用反，也算出同樣的數字。`norm2.weight` 就是 [4.3](#4.3) 的倍率 γ；`with torch.no_grad():` 裡的 `fill_(2.0)` 把它每格都填成 2（`no_grad` 與尾端底線都見 [1.6](01.md#1.6)）。`load_state_dict` 再把這組參數連同其他參數一起抄給函式庫版。兩版算出相同結果，印出 True。

函式庫的 `Block` 回傳三樣：新的表示、KV 快取，以及**輔助代價**（auxiliary loss）。輔助代價是某些設計額外加進訓練的代價，例如第 15 章的 MoE 準備多組 FFN，用它鼓勵各組分到相近的工作量（[15.9](15.md#15.9)）；本章的 Dense 沒有這一項，所以印出 0.0。這**不是 [1.8](01.md#1.8) 的代價為 0**：這段程式還沒和正確的下一字比較。

精簡版省略的是函式庫依設定換零件、傳參數的分支：

- `config.norm` 為 `"rms"` 時，兩個 LN 換成 RMSNorm（[14.2](14.md#14.2)）。
- 注意力另外收到三個設定：`kv_heads` 減少 K/V 的份數（[16.4](16.md#16.4)），`backend` 改用 PyTorch 內建的注意力函式（[16.8](16.md#16.8)），`rotary` 改用 RoPE 表示位置（[14.1](14.md#14.1)）。
- `config.activation` 交給 `DenseFFN`，可換成 relu2（[14.4](14.md#14.4)）或 swiglu（[14.5](14.md#14.5)）；`config.experts` 不為 0 時，FFN 換成第 15 章的 MoE，這時輔助代價才不為 0。
- `forward` 另收 `valid`、`positions`、`segments`、`cache`，原樣交給注意力（[7.7](07.md#7.7)、[16.5](16.md#16.5)、[16.3](16.md#16.3)），並把新的 KV 快取一起回傳。

用預設設定時，函式庫算的就是上面這段。

本節只檢查連線和形狀，隨機輸出不說明語言能力。練習把 `x = torch.randn(2, 3, 8)` 的 2 改成 1，先預測輸出形狀變 `[1,3,8]`；改回 2、把 3 改成 4，預測 `[2,4,8]`。若只把 8 改成 16 會報錯，因為各零件的輸入格數由 `ModelConfig(width=8)` 決定，要一起改。
