## 20.10 讀懂意思，和逐字抄寫，是同一項能力嗎？

告示上寫「今天去臺北」，回答「今天去台北」可能保留了意思，卻沒有逐字抄對。用 OCR 做原樣轉寫時，「臺」寫成「台」這種字形差異，正是要檢查的內容。

逐字核對要先數清楚差了多少。[11.13](11.md#11.13) 的字元錯誤率（Character Error Rate，CER）就是做這件事：把預測改成正確答案，最少需要幾次插入、刪除或替換，再除以正確答案的字數。本例按 Unicode 字元計數，不按 UTF-8 bytes，所以「今天去臺北」是 5 個字。「是否完全相同」與 CER 各回答一個問題：有沒有全部抄對，以及差了多少。下面用 `text_error_report` 計算，它的輸入與回傳欄位見 [11.16](11.md#11.16)；那一節用過同一組字，這裡把它接到成熟模型的讀字驗收：

```python
from tiny_perceptron.natural_concepts import text_error_report

report = text_error_report("今天去臺北", "今天去台北")
print("完整相同", report["exact"])
print("最少編輯次數", report["edits"])
print("正確答案字數", report["reference_characters"])
print("CER", report["cer"])
```

第一個參數是正確答案，第二個是預測。完整相同是 False；「台」換成「臺」需要一次替換，正確答案 5 個字，所以 CER＝1/5＝0.2。分母永遠是正確答案的字數，不是預測的字數。

練習把 `text_error_report` 的第二個參數改成 `"今天去臺"`：臺抄對了，只漏掉「北」。先預測需要一次插入，CER 仍是 1/5＝0.2，分母還是 5、不是預測的 4。再改成 `"今天去台"`：臺寫錯又漏掉北，先預測要兩次編輯，CER＝2/5＝0.4。

核對前要先約定允許哪些整理。NFKC 是一種 Unicode 文字正規化（Unicode Normalization Form KC），會把全形的「Ａ」換成「A」這類相容寫法，但不會把「臺」改成「台」。是否忽略空白、標點，或接受繁簡互換，都必須事先訂好，原樣的結果也要保留。使用者要求用繁中解釋，也不代表模型可以自行把圖片上的簡體字轉寫成繁體。

沒有字的圖要另外測：回答補上一句熟悉的文字，也是錯誤。正確答案是空字串時沒有字數可除，不能直接報一般的 CER；`text_error_report` 這時把 `cer` 記成 `None`。圖片模糊到讀不清，則屬於「有字但沒有可讀內容」，又是另一種情況。合成文件、真實招牌、短行與整頁各有不同難點，得分要和實際材料的範圍一起報告。
