## 7.8 補了 PAD 該取哪個輸出？

生成下一個 token 時，要用每筆最後一個真實位置的 logits，不能一律取矩陣的最後一欄。第一筆在右邊補 PAD，valid 是 `[真,真,假,假]`，最後的真實位置是索引 1；第二筆在左邊補，valid 是 `[假,真,真,真]`，最後的真實位置是索引 3。

只用「真實位置數減一」會出錯：第二筆有三個真實位置，算出 2，正確答案卻是 3。正確做法是找出每筆 True 所在的最大物理索引，再替每筆取那個位置的 logits。下面用人工編號的分數，讓取到哪個位置一眼看得出來。

```python
import torch

valid = torch.tensor([[True, True, False, False], [False, True, True, True]])
positions = torch.arange(4)[None].expand_as(valid)
last = positions.masked_fill(~valid, -1).amax(dim=-1)
logits = torch.arange(40, dtype=torch.float32).reshape(2, 4, 5)
selected = logits[torch.arange(2), last]
print("最後的真實位置", last)
print("逐筆手動取", logits[0, 1], logits[1, 3])
print("一次取出", selected)
assert last.tolist() == [1, 3]
assert torch.equal(selected[0], logits[0, 1]) and torch.equal(selected[1], logits[1, 3])
```

先看 `last` 怎麼算。`torch.arange(4)` 產生 `[0,1,2,3]`，是物理位置的編號；`[None]` 在最前面加一個長度 1 的筆數軸（[4.7](04.md#4.7) 用過），變成 `[[0,1,2,3]]`；`expand_as(valid)` 把這一列沿筆數軸重複成和 valid 一樣的形狀 `[2,4]`，讓兩筆各有一份編號。`~valid` 把真／假對調，`masked_fill(條件, -1)` 把條件為 True 的地方換成 −1，也就是把非真實位置的編號蓋掉，兩筆分別變成 `[0,1,-1,-1]` 與 `[-1,1,2,3]`。最後 `amax(dim=-1)` 沿最後一軸取最大值，得到每筆最後一個真實位置 `[1,3]`。

logits 用 0 到 39 排成形狀 `[2,4,5]`：兩筆、每筆四個位置、每個位置五個候選，數字只為了看清取到哪裡。逐筆手動取時，`logits[0, 1]` 是第 0 筆位置 1 的 `[5,6,7,8,9]`，`logits[1, 3]` 是第 1 筆位置 3 的 `[35,36,37,38,39]`。`logits[torch.arange(2), last]` 一次做完這兩件事：方括號裡放兩份等長的索引清單時，PyTorch 會逐項配對，筆數 `[0,1]` 配上位置 `[1,3]`，取出 `logits[0,1]` 與 `logits[1,3]`，疊成形狀 `[2,5]`。每筆一組下一項的候選分數，沒有多出位置軸。最後的 assert 確認一次取出的結果和逐筆手動取的相同。

選取只是找對起點，不會修改分數，也不會替你選出下一個 token。若某筆的 valid 全是 False，last 會是 −1，而 Python 的索引 −1 代表最後一個位置，結果會默默取到 PAD；正式的程式要先拒絕空題。前面的 valid 或模型位置若錯，取對最後位置也修不好預測。

練習只把第一筆的 valid 改成 `[False,False,True,True]`。先預測 last 從 `[1,3]` 變成 `[3,3]`，第一筆取到 `[15,16,17,18,19]`，第二筆不變；再執行，並把手動取與 assert 裡第一筆的位置一起改成 3。這次第一筆的真實位置數仍是兩個，最後位置卻不同，正好說明數量與最後位置是不同的資訊。
