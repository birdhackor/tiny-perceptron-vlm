## 17.7 只量化權重時，輸入與運算用什麼？

先固定兩列權重`[0.7,0.2]`、`[−0.7,1.2]`，輸入`[1,1]`，原輸出是`[0.9,0.5]`。把權重按每列一個刻度存成4-bit，輸入仍保留浮點數，叫**只量化權重（weight-only quantization）**；這樣暫時不必估計各種輸入的中間特徵範圍。

第一列最大絕對值0.7，刻度0.1，0.7與0.2的碼是7與2，還原沒有誤差。第二列最大絕對值1.2，刻度是1.2/7≈0.1714；−0.7÷0.1714≈−4.08，取最近整數−4，還原成−4×0.1714≈−0.6857，所以壓縮後的輸出約`[0.9,0.5143]`。函式庫的`QuantizedLinear`把一個`nn.Linear`換成這種存法，下面固定輸入核對。

```python
import torch
from torch import nn
from tiny_perceptron.quantization import QuantizedLinear

layer = nn.Linear(2, 2, bias=False)
with torch.no_grad():
    layer.weight.copy_(torch.tensor([[0.7, 0.2], [-0.7, 1.2]]))
bits = 4
compressed = QuantizedLinear(layer, bits=bits)
x = torch.tensor([[1.0, 1.0]])
print("碼的型別", compressed.values.dtype, "輸出型別", compressed(x).dtype)
print("原輸出", layer(x).detach().round(decimals=4).tolist(), "壓縮輸出", compressed(x).round(decimals=4).tolist())
print("壓縮buffer bytes", compressed.storage_bytes())
```

第一行顯示碼存成`torch.uint8`，輸出卻是`torch.float32`；第二行是`[0.9,0.5]`與`[0.9,0.5143]`；最後一行是10byte。這些結果怎麼來？看`QuantizedLinear`本身：

```python
# 節錄自 tiny_perceptron/quantization.py：QuantizedLinear
class QuantizedLinear(nn.Module):
    """真正壓縮儲存，forward 仍反量化成浮點作參考。"""

    def __init__(self, layer, bits=4):
        super().__init__()
        q, scale = quantize_symmetric(layer.weight.detach(), bits, per_channel=True)
        self.bits, self.shape = bits, list(q.shape)
        self.register_buffer("values", pack_int4(q) if bits == 4 else q)
        self.register_buffer("scale", scale)
        self.register_buffer("bias", None if layer.bias is None else layer.bias.detach().clone())

    def forward(self, x):
        q = unpack_int4(self.values, self.shape) if self.bits == 4 else self.values
        weight = (q * self.scale).to(x.dtype)
        return F.linear(x, weight, None if self.bias is None else self.bias.to(x.dtype))

    def storage_bytes(self):
        return sum(b.numel() * b.element_size() for b in self.buffers())
```

`QuantizedLinear`是一個PyTorch零件，讀法同[3.7](03.md#3.7)：`__init__`在建立時執行一次，開頭的`super().__init__()`先讓`nn.Module`完成準備；`forward`定義每次的計算，`compressed(x)`這種呼叫就會執行`forward`。

建立時，`quantize_symmetric(…, per_channel=True)`替每個輸出列算一個刻度，`layer.weight.detach()`只取權重數字、不帶求導記錄。`self.bits, self.shape = bits, list(q.shape)`一次存兩個值：位元數，以及拆回時要用的原形狀`[2,2]`。`register_buffer`把一個tensor登記成模組的**buffer**：它會和參數一起被保存、一起搬到其他裝置，但不是參數，最佳化器不會更新它。`pack_int4(q) if bits == 4 else q`的意思是「條件成立取前者，否則取後者」：4-bit時兩個碼打包進一個`torch.uint8`的byte，8-bit時直接存`quantize_symmetric`回傳的int8碼。打包的做法[17.8](17.md#17.8)才講，這裡只需要知道`pack_int4`把碼壓緊、`unpack_int4`拆回原形狀。刻度與偏移（bias）也存成buffer；層沒有偏移時存`None`。

`forward`先拆回碼，`q * self.scale`讓每列的碼乘上自己那列的刻度，得到還原權重，再用`F.linear`做和`nn.Linear`相同的計算`x @ weight.T`（有偏移時再加上）。所以**存成整數與用整數乘法是兩件事**：這裡的輸入、還原權重與輸出都是FP32。`storage_bytes`把每個buffer的元素數乘每格byte再加總：4個4-bit碼打包成2byte，兩個FP32刻度佔8byte，合計10；`None`不佔空間。

```python
from torch.nn import functional as F
from tiny_perceptron.quantization import pack_int4, quantize_symmetric, unpack_int4

codes, scale = quantize_symmetric(layer.weight.detach(), bits, per_channel=True)
print("碼", codes.tolist(), "每列刻度", scale.flatten().round(decimals=4).tolist())
print("還原權重", (codes * scale).round(decimals=4).tolist())
rebuilt = QuantizedLinear(layer, bits=bits)
print("與函式庫版本輸出相同：", torch.equal(rebuilt(x), compressed(x)))
```

第三段先匯入節錄裡用到的`F`、`quantize_symmetric`、`pack_int4`、`unpack_int4`，照`__init__`裡`quantize_symmetric(…)`那一行算出碼`[[7,2],[−4,7]]`與每列刻度約`[0.1,0.1714]`，還原權重約`[[0.7,0.2],[−0.6857,1.2]]`，正是上面手算的結果。最後兩行用第二段節錄的`QuantizedLinear`重建同一層，得到`rebuilt`，再和第一段用函式庫版本建立的`compressed`比較，輸出完全相同。這要在Notebook裡依序執行過第二段才成立：第三段沒有匯入`QuantizedLinear`，跳過第二段時，這個名稱仍指函式庫版本，印出的True就沒有核對到節錄。

這些buffer不交給最佳化器更新，所以轉換後的層是拿來推論與核對的，不能直接沿用原本的最佳化器續訓。雖然存得小，每次`forward`仍會建立一份暫時的浮點權重，所以執行時的記憶體與速度要另外量。

練習把第一段程式的`bits = 4`改成`bits = 8`，從頭執行。先預測：碼不再打包，4個碼各1byte，兩個刻度仍是8byte，合計12；碼的型別變成`torch.int8`，輸出仍是FP32；第三段的碼變成`[[127,36],[−74,127]]`。固定權重與輸入，才能只比較位元數。
