## 6.3 怎麼訓練實用的 tokenizer？

只用「貓看狗。」與「a cat sees a dog.」兩句建立字表，卻要表示新文字「小鳥🙂new」——小、鳥和 🙂 都沒在這兩句出現過。如果字表一開始只收見過的字元，新字就表示不出來。改從 [6.1](#6.1) 的 256 種 byte 開始，再用 [6.2](#6.2) 的方法合併常見片段：見過的片段變短，沒見過的字仍能逐 byte 表示。

這種從 byte 開始合併的 BPE 叫 **byte-level BPE**。6.2 的手寫版只合併一次；實用的 BPE 要反覆合併很多次，還要處理空白與 byte 的細節，這裡交給 `tokenizers`：它是 Hugging Face 開發、專門訓練與使用 tokenizer 的函式庫，安裝本專案時已一起裝好。訓練學到的是合併規則；之後 `encode` 把文字轉成 ID，`decode` 把 ID 拼回原文。本課後面的程式多半用 [6.6](#6.6) 自己寫的 `ByteTokenizer`：它不學合併，每個 byte 一個 ID，是最簡單、一定能還原的起點。

```python
from tokenizers import Tokenizer, decoders, models, pre_tokenizers, trainers

tok = Tokenizer(models.BPE())
tok.pre_tokenizer = pre_tokenizers.ByteLevel(add_prefix_space=False)
tok.decoder = decoders.ByteLevel()
trainer = trainers.BpeTrainer(
    vocab_size=280,
    initial_alphabet=pre_tokenizers.ByteLevel.alphabet(),
    show_progress=False,
)
tok.train_from_iterator(["貓看狗。", "a cat sees a dog."], trainer)
print("字表大小", tok.get_vocab_size())
for text in ["貓看狗。", "小鳥🙂new"]:
    encoded = tok.encode(text)
    print(text, "UTF-8 bytes", len(text.encode("utf-8")), "token數", len(encoded.ids))
    print("片段", encoded.tokens)
    print("還原", tok.decode(encoded.ids))
    assert tok.decode(encoded.ids) == text
```

逐項看設定：

- `models.BPE()` 指定用 BPE 的合併規則。
- `pre_tokenizers.ByteLevel(add_prefix_space=False)` 是 BPE 之前的前處理，做兩件事：先在空白與標點處把文字分成幾段，空白黏在後一個詞的開頭，合併只在每一段裡進行；再把每個 byte 換成一個看得見的符號，方便統計。例如「a cat」會分成 `a` 與 `Ġcat` 兩段，`Ġ` 就是空白的可見代號。`add_prefix_space=False` 表示不在開頭自動補一個空白。這裡也沒有設定文字正規化（normalizer，例如把全形字換成半形、大寫換成小寫），原文不會被改寫。
- `decoders.ByteLevel()` 是反方向的工具：把看得見的符號換回 byte，再照 UTF-8 拼回文字。
- `initial_alphabet=pre_tokenizers.ByteLevel.alphabet()` 讓字表一開始就收進全部 256 種 byte 的符號，而不只是兩句裡出現過的 byte。
- `vocab_size=280` 是字表大小的目標；`train_from_iterator` 從兩句話學合併規則，字表到了目標，或再也沒有可合併的相鄰對，就停下來。

第一行印出的字表大小是 277，不是 280：256 種 byte 加上 21 次合併之後，兩句話裡已經沒有可以再合併的相鄰對了。資料這麼少時，字表未必長得到目標。

「貓看狗。」共 12 個 byte，整串都在訓練句出現過，合併到只剩 2 個 token：一個是「貓看狗」，一個是「。」。「小鳥🙂new」共 13 個 byte，訓練學到的合併一個都用不上，13 個 byte 各自成為一個 token。兩句的「還原」都和原文完全相同，assert 也通過。印出的片段像一串奇怪的拉丁字母，因為那是 byte 的可見代號，不是原文壞了；要核對的是還原後的文字，不是每個片段肉眼能不能讀。

保存 tokenizer 時，要連同版本與每個 ID 代表什麼一起保存。即使字表大小相同，重新訓練一次也可能讓同一個 ID 換成別的片段，不能直接接上舊模型。

練習把迴圈清單的 `"小鳥🙂new"` 改成 `"未見字🦊"`，先預測：三個中文字與 🦊 都沒在訓練句出現，13 個 byte 會切成 13 個 token，但還原仍等於原文，再執行核對。改回後，把 `add_prefix_space=False` 改成 `True` 再執行一次，先預測會發生什麼：每句開頭多補了一個空白，還原出來的文字也多了這個空白（例如 ` 貓看狗。`），assert 失敗。能不能還原，取決於整組前處理與解碼規則，不只 BPE 這個名字；改了任何一條，都要重新檢查空白、換行與特殊字元。
