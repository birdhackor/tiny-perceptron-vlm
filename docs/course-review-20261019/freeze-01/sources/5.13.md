## 5.13 資料或模型變大，哪個值得花預算？

模型變大、資料也從 16 篇換成 64 篇，成績提升後很難知道是哪個改動有用。先做兩種特徵寬度 × 兩種資料量的四格設計，讓一條比較只改模型，另一條只改資料。

計畫用特徵寬度 8 或 16、不同的記錄 16 筆或 64 筆，每次更新四筆、每筆八個有效目標、共更新 100 次。每一格都是 3,200 個有效目標的曝光：16 筆會被重複練更多次，64 筆則有更多不同的內容。

```python
from tiny_perceptron.model import TinyLM, ModelConfig

for width in [8, 16]:
    parameters = TinyLM(ModelConfig(width=width)).description()["parameters"]
    for records in [16, 64]:
        batch_size, answers_per_record, steps = 4, 8, 100
        print(
            {
                "特徵寬度": width,
                "不同記錄": records,
                "參數格數": parameters,
                "更新步數": steps,
                "有效目標預算": batch_size * answers_per_record * steps,
                "品質": "尚待訓練與量測",
            }
        )
```

輸入是實驗計畫，不是現成的訓練資料。`records` 是不同例子的數量；`batch_size, answers_per_record, steps = 4, 8, 100` 一次替三個名字依序賦值：每次更新四筆、假定每筆八個有效目標、共 100 次，所以每格有 `4×8×100=3200` 個有效目標。程式只建立模型、數參數，再印出四份計畫；品質欄保留未測的狀態，不能從參數數字推定分數。特徵寬度 8 的模型有 6,104 個參數（[5.9](#5.9) 算過），16 則有 13,744 個。

「公平預算」有多種定義。固定更新次數，方便看每次更新的效果；固定有效目標數，讓見到的監督總量相近；固定時間或 FLOPs，則更直接限制計算成本。FLOPs 是浮點運算次數，一次乘法與一次加法各算一次。設 D 是輸入的特徵數、M 是輸出的特徵數：密集的 Linear 用一張 M 列、D 欄的權重表，把 D 個輸入數加權混合成 M 個輸出數，每個輸出都用到全部輸入。處理一個位置約需 2×D×M 次運算，也就是每個權重一次乘法、一次加法；這裡忽略每個輸出最後加上偏移（bias，[2.3](02.md#2.3)）的成本與其他較小的成本。8 進 8 出約 128 次，16 進 16 出約 512 次。模型變寬會同時放大兩邊，所以相同的有效目標預算也不等於相同的計算預算。耗時的量法可回看 [5.9](#5.9)。

看四格實驗的品質時，訓練代價與驗證代價都是「每個有效目標的平均代價」，也就是 [1.8](01.md#1.8) 的代價（loss）：用相應資料的有效目標重算再取平均，規則回看 [5.2](#5.2)。補充區有一組實際做過的四格實驗：特徵寬度 16 時，64 篇練習短文的驗證代價 0.31105 低於 16 篇的 0.49288，訓練代價卻是 0.33032，高於 16 篇的 0.27166。兩組的訓練平均涵蓋不同的材料，訓練代價不能當成同一批新題的成績。

固定更新次數、有效目標數、秒數或運算量，各自回答不同的預算問題。比較前先選定主要的限制，再用共同的新題和實際成本判讀；四個小設定不足以外推大型模型的規模規律。

練習保持每次更新四筆，假設每筆只有 4 個有效目標，想維持 3,200 的有效目標預算要更新幾次？先算 `3200/(4×4)=200`，再把那一行改成 `batch_size, answers_per_record, steps = 4, 4, 200`，執行核對四列的有效目標預算仍是 3200。若只改成 `4, 4, 100`，預算只剩 1,600，已經不是同樣的監督量。把計畫中的假設換成實測的長度統計，才會成為真實的資源記錄。

| 特徵寬度 | 不同練習短文 | 累計有效目標 | 訓練代價 | 驗證代價 | 測試代價 |

較大模型與更多資料如何共同影響品質，常被研究成 scaling law（規模與表現的經驗規律）。眼前只有一個種子、有限的規則短文、四個小設定，能回答的是這批資料在這個更新預算下如何變化，不能由此說 64 篇必然較好，更不能外推大型模型的規律。[實驗紀錄（JSON）](../../docs/course-experiments/results/text_foundation.json)的 `results.scaling` 以 `scaling-w16-n16` 這類名稱（w 後面是特徵寬度、n 後面是練習篇數）保存四組：`training.final_loss` 是訓練代價，`evaluation.validation.nll` 與 `evaluation.test.nll` 是驗證與測試代價，`training.effective_tokens` 是累計有效目標數。重做這組實驗的指令在 [T.4](../training.md#T.4) 的補充區（`--experiment text_foundation`）。
