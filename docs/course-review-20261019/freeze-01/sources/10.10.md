## 10.10 配對標籤怎麼決定分數的調整方向？

兩張圖的正確描述依序放在文字欄 0、1。把每張圖對每段文字的分數排成一張表，正確配對落在從左上到右下的**對角線**上（圖 0 對文 0、圖 1 對文 1），其他格是錯誤配對。希望每張圖的正確欄分數比另一欄高。把同批文字當候選、正確欄當標籤，就能算交叉熵代價；這種拿正確配對和其他候選比較的學習叫**對比學習**（contrastive learning）。

本例另用手設分數 `[[2,0],[0,2]]`，只計算代價與梯度，觀察配對標籤要求的調整方向。

```python
import torch
from torch.nn import functional as F

scores = torch.tensor([[2.0, 0.0], [0.0, 2.0]], requires_grad=True)
targets = torch.arange(2)
loss = F.cross_entropy(scores / 0.5, targets)
loss.backward()
print("代價", round(loss.item(), 4))
print("梯度", scores.grad)
```

`targets` 是 `[0,1]`：第 0 張圖的正確欄是 0、第 1 張是 1。分數先除以 0.5 再交給交叉熵，這個除數就是 [1.15](01.md#1.15) 的溫度 τ：除以 0.5 等於乘 2，兩欄的差距從 2−0＝2 放大到 4−0＝4，softmax 後正確欄的機率更集中（約 0.982）。代價約 0.0181，梯度約 `[[-0.0180,0.0180],[0.0180,-0.0180]]`。

梯度下降用舊值減去學習率乘梯度（[1.12](01.md#1.12)）。正確欄是負梯度，若學習率是 0.1，2 會變成約 2−0.1×(−0.0180)＝2.0018；錯誤欄是正梯度，0 會變成約 −0.0018。這是從符號追到調整方向的手算；程式只做 backward，沒有真正更新。

實際模型裡，分數由圖片入口和文字模型的特徵算出，梯度會沿計算傳回兩端。兩端的參數同時影響表中許多格，所以更新的是參數，更新後要重新算整張表；不能直接把表裡的兩個正確格改大，就說訓練完成。

還要先確認候選確實不配。兩張圖若都是紅圓、兩段描述也都是「紅圓」，對角線以外的格子同樣是正確配對；硬把它當成錯誤，就是假負例（false negative）。可以允許多個正確描述，或在入門階段的每一批裡只放屬性不同的配對。

練習把程式的 `targets = torch.arange(2)` 改成 `targets = torch.tensor([1, 0])`，也就是把配對告訴模型反了。預期對角線以外的格子收到負梯度（約 −0.9820），代價升到約 4.0181。這不是合理的資料增強，而是錯誤標籤。
