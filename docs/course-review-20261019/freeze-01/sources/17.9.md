## 17.9 不更新權重，也能做量化嗎？

手上已有一份訓練好的權重，可以先固定它，選刻度、轉成低位元，再用同樣的輸入檢查。這叫**訓練後量化（Post-Training Quantization，PTQ）**。最基本的、只量化權重的PTQ，依權重本身的範圍選刻度，不必先收集中間特徵。

要看清轉換造成的差別，原版與量化版必須來自同一份數字。下面的短程式用隨機初始化的模型，只核對轉換與比較的方式；真正的PTQ要先載入選定的檢查點，再用同樣流程與任務題檢查品質。程式先用`copy.deepcopy`複製一份完全獨立的模型，再轉換副本裡的Linear層。

```python
import copy
import torch
from tiny_perceptron.model import TinyLM, ModelConfig
from tiny_perceptron.quantization import replace_linear_layers

torch.manual_seed(0)
original = TinyLM(ModelConfig(width=8, tied=False)).eval()
ids = torch.tensor([[1, 2, 3]])
bits = 4
with torch.no_grad():
    before = original(ids)["logits"]
    quantized = replace_linear_layers(copy.deepcopy(original), bits=bits)
    after = quantized(ids)["logits"]
    original_again = original(ids)["logits"]
print("兩版形狀", tuple(before.shape), tuple(after.shape))
print("原版是否被改", (before - original_again).abs().max().item())
print("量化分數MAE", (before - after).abs().mean().item())
```

輸入是3個token，`ModelConfig`預設的字表有264個候選，所以兩版分數的形狀都是`(1,3,264)`。`eval()`切到評估行為，`no_grad()`不記錄反向傳播要用的計算關係。原版前後的最大差是0，量化分數的MAE約0.029，不是0。轉換怎麼找到每一個Linear？看`replace_linear_layers`：

```python
# 節錄自 tiny_perceptron/quantization.py：replace_linear_layers
def replace_linear_layers(module, bits=4):
    """就地替換；tied embedding 的語意要在比較中明示，不自動維持共享。"""
    for name, child in list(module.named_children()):
        if isinstance(child, nn.Linear):
            setattr(module, name, QuantizedLinear(child, bits))
        else:
            replace_linear_layers(child, bits)
    return module
```

`named_children()`逐一給出`module`底下直接相連的子模組，以及它們的屬性名稱；迴圈裡會替換子模組，所以先用`list(…)`抄成一份清單，再逐一處理。`isinstance(child, nn.Linear)`問「這個子模組是不是Linear」。是的話，`setattr(module, name, QuantizedLinear(child, bits))`等於寫`module.<名稱> = QuantizedLinear(child, bits)`，把原層換成[17.7](17.md#17.7)的量化層；不是的話，就對這個子模組再呼叫同一個函式，往裡面一層層找。TinyLM最上層的輸出層`output`本身就是Linear，直接被換掉；`blocks`則要往下經過每個block的`attention`與`ffn`，才找到q、k、v、out、up、down這幾個Linear。

這個函式直接修改傳入的模組，也就是文件字串說的「就地替換」，所以程式先`deepcopy`，原版才保持不變；不能把原版直接傳進去，之後還假設它沒變。它只換Linear，embedding表與正規化層不轉換，所以也不是所有數字都變成4-bit。

```python
from torch import nn
from tiny_perceptron.quantization import QuantizedLinear

again = replace_linear_layers(copy.deepcopy(original), bits=bits)
print("輸出層", type(again.output).__name__, "embedding表", type(again.embedding).__name__)
with torch.no_grad():
    print("與函式庫版本分數相同：", torch.equal(again(ids)["logits"], after))
```

第三段先匯入節錄裡用到的`nn`與`QuantizedLinear`，再用第二段節錄的`replace_linear_layers`轉換另一份副本。`type(…).__name__`取出物件所屬類別的名稱：輸出層已換成`QuantizedLinear`，embedding表仍是`Embedding`；分數和第一段用函式庫版本算好的`after`完全相同。這要在Notebook裡依序執行過第二段才成立：跳過它，`replace_linear_layers`仍是第一段匯入的函式庫版本，印出的True就沒有核對到節錄。

本例`tied=False`，即不做[14.6](14.md#14.6)的權重共享（weight tying）：輸入的embedding表與輸出層各有自己的權重。若原本共享，把輸出層換成量化buffer會切斷共享關係，文件字串說的「不自動維持共享」就是這件事；這必須另外設計，不能默默當成只改精度。

若連中間特徵也要量化，還得選它們的範圍：可以每次看到輸入時當場估計，或先用一批資料做範圍校準。[17.12](17.md#17.12)才講範圍校準，這裡只需要知道它是收集中間特徵的數值範圍，和第9章讓信心對上正確率的機率校準不同。無論哪一種，PTQ本身都沒有更新權重，這是它和[17.14](17.md#17.14)的QAT不同的地方。

練習把第一段程式的`bits = 4`改成`bits = 8`，保持原版、種子與輸入。先預測：形狀與「原版是否被改」的0都不變，量化分數MAE變小；第三段仍印出True。速度則是另一個測量。
