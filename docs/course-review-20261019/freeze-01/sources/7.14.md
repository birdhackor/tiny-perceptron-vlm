## 7.14 少量錯誤答案會被學走嗎？

1+1 的正確答案是 2，資料卻標成 3。[1.8](01.md#1.8) 的交叉熵會自己發現標錯嗎？它只看我們提供的目標得到多少機率；模型越相信錯的標籤，這筆資料的代價反而越低。

用四個候選「0、1、2、3」做一個獨立的小算例：這裡的 ID 0 到 3 只是四個候選的編號，剛好和數字相同，不是 byte 字表裡字元「0」到「3」的 ID（那些是 56 到 59）。先給正確候選 2 分數 3、錯誤候選 3 分數 1，再只把錯誤候選的分數提高到 5。

```python
import torch
from torch.nn import functional as F

logits = torch.tensor([[0.0, 0.0, 3.0, 1.0]])
for label in [2, 3]:
    loss = F.cross_entropy(logits, torch.tensor([label]))
    print("提供的答案ID", label, "代價", loss.item())
wrong_favored = torch.tensor([[0.0, 0.0, 3.0, 5.0]])
print("提高錯誤候選分數後，錯標代價", F.cross_entropy(wrong_favored, torch.tensor([3])).item())
```

四個分數經過 softmax，候選 2 約 0.810、候選 3 約 0.110，所以提供 label 2 時代價約 0.211，提供 label 3 時約 2.211。最後把錯誤候選的分數提高到 5，錯誤標籤的代價降到約 0.139，儘管正確答案 2 得到的支持變少了。交叉熵完全照著輸入的 label 計算，不會自動檢查 1+1 的數學事實。

真實訓練中，錯誤答案也會產生清楚的梯度，推動模型在這類前文之後更常接出錯字。如果錯例反覆出現或答案很長，它佔的有效目標可能超過它的筆數比例，見 [5.16](05.md#5.16)。少量錯誤會不會造成可觀的影響，要實測才知道，不能只靠這一個位置的代價，推出所有模型都會如何的量化結論。

所以要先獨立核對標籤，再用乾淨的驗證題與測試題檢查內容。專案做過一個小對照：從同一個底座出發的兩條支線，一條保留正確答案、一條把四筆答案改錯，在同樣的十題測試題上分別答對 7 題與 6 題，錯標的那條平均代價卻略低。題目少、只有一個種子，不能據此估計錯標一般會造成多少退步；但它再次說明，代價較低不能代替答對（數字與條件見補充）。

練習只把最後錯誤候選的分數 5 改成 8。先預測：錯標的代價繼續下降，但正確答案 2 的代價會變大；再執行，並另外算 label 2 的代價核對。這次只改了模型的偏好，沒有改算術事實，能直接看到「最佳化我們提供的目標」與「外部任務是否正確」的差別。

這次錯標的支線少答對一題，測試題的平均代價卻略低。這並不矛盾：代價看的是給定正確前文時每個位置的機率，完整答對看的是模型沿著自己的輸出，最後能否生成整份答案，[5.8](05.md#5.8) 已拆過兩者。兩條支線在全部驗證題與測試題都會以 EOS 結束，這也不能替內容過關。只有一個種子、兩個被改動的家族和很少的新題，這些數字不能推成「固定比例的錯標必然造成多少退步」；它們提醒我們保存兩種結果，而不是挑代價較低的就說資料無害。[實驗紀錄（JSON）](https://github.com/birdhackor/tiny-perceptron-vlm/blob/main/docs/course-experiments/results/sft_ablation.json)的 `results.corruptions` 列出四筆改動，`results.runs.clean` 與 `results.runs.noisy` 是兩條支線的成績。
