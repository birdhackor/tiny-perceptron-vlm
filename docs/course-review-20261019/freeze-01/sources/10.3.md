## 10.3 每塊 48 個像素值，如何變成 8 個特徵？

上一節每塊有 48 個像素值，接下來希望每個位置改用 8 個數字表示。做法是對每塊的 48 個值各乘權重、加總，再加偏移（bias，見 [2.3](02.md#2.3)），一套配方產生一個輸出；準備 8 套配方，就得到 8 個輸出。這一排數字叫向量；8 套配方合起來，就是可以訓練的線性層。

```python
import torch
from torch import nn
from tiny_perceptron.multimodal import scene, patchify

torch.manual_seed(0)
patches = patchify(scene()[None], 4)
embedding = nn.Linear(48, 8)
features = embedding(patches)
print("輸入", tuple(patches.shape))
print("輸出", tuple(features.shape))
print("矩陣", tuple(embedding.weight.shape))
```

`scene()` 不給參數，用預設的紅方塊（[10.1](10.md#10.1)）。`nn.Linear(48, 8)` 建立 48 進、8 出的線性層；權重矩陣 `(8,48)` 的每一列是一套配方，負責一個輸出。固定種子 0，讓亂數初始化可以重做。程式印出 `(1,16,48)`、`(1,16,8)`、`(8,48)`：16 個位置都保留，只把每位置的特徵寬度從 48 改成 8。這個把每塊像素算成特徵的線性層叫 **patch embedding**；[10.5](10.md#10.5) 的圖片入口切完塊之後，第一步就是它（程式裡叫 `projection`）。

16 個位置共用同一張配方表，表示每個位置遇到相似像素時做相同計算，不表示 8 個數字已經懂顏色；它們的用途要由訓練目標建立。名字裡雖然也有 embedding，它和文字的 embedding 表（[2.1](02.md#2.1)）做法不同：文字是用 token ID 查出表中的一列；patch embedding 沒有表可查，是直接拿像素亮度做加權和算出來。

例如兩個亮度 `[1,0]` 和 `[0,1]`，都經權重 `[0.5,0.5]`、偏移 0，得到同樣的 0.5。這個特定配方抹掉了兩者的差異。48 轉 8 同樣可能壓掉資訊，訓練要尋找保留任務線索的配方；特徵寬度變小本身不是理解的證據。

練習把程式的 `nn.Linear(48, 8)` 改成 `nn.Linear(48, 16)`，預期特徵 `(1,16,16)`、矩陣 `(16,48)`。特徵形狀裡的兩個 16 分別是位置數與特徵寬度，不能因數值相同就當成同一件事。
