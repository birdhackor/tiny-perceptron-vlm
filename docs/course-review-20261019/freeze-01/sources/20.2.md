## 20.2 不重新訓練，怎麼先開啟成品？

想試用本章的助理，最穩的順序是先打字問候，再附一張照片提問，最後加一段錄音：每次只多開一條輸入通路，卡住時就知道是哪一站的問題。這一版使用 Qwen3-VL-2B-Instruct 圖文底座與 Whisper-large-v3-turbo，沒有加本課的 LoRA。試用不必重新訓練，但要把兩個成熟模型下載到自己的電腦，並在自己的電腦上執行。

本課實際走完並記錄的，只有 Linux 上的 CPU 路線：Bash 終端機、Git、Python 3.12，圖文模型用 float32（每個數字用 32 bits 存）。其中一次完整操作的紀錄在[學生操作指引](../../docs/natural-assistant/v4/STUDENT.md)第 2 節：兩個官方模型的檔案共 5,889,111,977 bytes，約 5.48 GiB；服務程式執行時的記憶體峰值為 13,496,104 KiB，約 12.87 GiB；模型已經下載好時，啟動到介面可用花 24.24 秒，四次聊天各等了 3.42 到 42.87 秒。這些是一臺機器、一組輸入的實測，不是最低需求；記憶體為什麼比下載的檔案大，[20.3](20.md#20.3) 用乘法說明。

macOS 與 Windows（包括 Windows 上的 WSL）都沒有經過本課驗證，下面的命令也是照 Linux 的 Bash 寫的；想走本課核對過的路線，就在 Linux 電腦上操作。可以先知道的差異有三項：Windows 的 PowerShell 不接受 `GIT_LFS_SKIP_SMUDGE=1 git ...` 這種寫在命令前面的設定；Windows 上專用環境裡的 Python 在 `.venv-natural\Scripts\python.exe`，不是 `.venv-natural/bin/python`（[W.1](../first-steps.md#W.1) 有同樣的對照）；啟動程式的 `--device` 只接受 `cpu` 與 `cuda`，沒有 Apple 晶片 GPU 的選項，所以 Mac 只能試 `--device cpu`。在這兩種系統上嘗試時，照下面的順序一步一步走，每一步先看到它自己的核對結果再往下：第一步顯示 `Python 3.12.x`，第二步的安裝命令都沒有錯誤訊息，第三步的 `--verify` 通過、終端機顯示助理已啟動，最後介面先回出一句文字。哪一步失敗，就從那一步查起：是缺少工具、命令寫法和 Bash 不同，還是那個系統裝不起某個固定版本的套件。不要為了讓檢查通過而修改清單裡的指紋。

第一步，取得固定版本的程式，並確認有 Python 3.12：

```bash
GIT_LFS_SKIP_SMUDGE=1 git clone --no-checkout https://github.com/birdhackor/tiny-perceptron-vlm.git tiny-perceptron-natural
cd tiny-perceptron-natural
GIT_LFS_SKIP_SMUDGE=1 git checkout --detach ee17b8871cfe2ba9807b796dd11f339b5dae3b5c
python3.12 --version
```

這會建立新的 `tiny-perceptron-natural` 資料夾，不動你原有的專案與練習；`python3.12 --version` 應顯示 `Python 3.12.x`。找不到 `git` 時，依 [Git 官方安裝指引](https://git-scm.com/downloads)安裝；找不到 `python3.12` 時，先安裝 Python 3.12 與它的 `venv` 支援，[Python 官方下載頁](https://www.python.org/downloads/)列出各系統的取得方式。之後的命令都在這個新資料夾裡執行。

第二步，建立成品專用的環境 `.venv-natural`，安裝固定版本的套件：

```bash
python3.12 -m venv .venv-natural
.venv-natural/bin/python -m pip install --upgrade pip
.venv-natural/bin/python -m pip install torch==2.8.0 torchvision==0.23.0 --index-url https://download.pytorch.org/whl/cpu
.venv-natural/bin/python -m pip install -r requirements-natural.txt
```

這條路線不用 W.1 的 uv：成品自己固定了 PyTorch 與其他套件的版本（`requirements-natural.txt`），另建一個環境，就不會動到前面小實驗用的 `.venv`。`venv` 與 `pip` 是 Python 內建的建立環境與安裝套件工具；每個命令都寫出 `.venv-natural/bin/python`，就不用猜終端機正在用哪一套 Python。帶 `--index-url https://download.pytorch.org/whl/cpu` 的命令安裝 CPU 版的 PyTorch 與 torchvision，`-r requirements-natural.txt` 補齊其餘套件。

第三步，查看並下載公開清單指定的配置，核對後啟動助理：

```bash
.venv-natural/bin/python scripts/fetch_natural_release.py --manifest docs/natural-assistant/v4/public-release.json --list
.venv-natural/bin/python scripts/fetch_natural_release.py --manifest docs/natural-assistant/v4/public-release.json --output checkpoints/natural-assistant/release-v4
.venv-natural/bin/python scripts/fetch_natural_release.py --manifest docs/natural-assistant/v4/public-release.json --output checkpoints/natural-assistant/release-v4 --verify
.venv-natural/bin/python scripts/fetch_natural_release.py --manifest docs/natural-assistant/v4/public-release.json --output checkpoints/natural-assistant/release-v4 --serve --device cpu --dtype float32
```

`--list` 只印出清單固定的版本資訊：這次發布的代號、配置文件放在哪個模型倉庫的哪一版、圖文底座與 Whisper 各自的版本，以及選定的配置（`selected_variant`，本版是 `base`，也就是原底座）；不列檔案，也不下載。只帶 `--output` 的命令取得兩份小型配置文件，加上 `--verify` 再核對它們，兩者都不含模型權重。加上 `--serve` 啟動服務時，才從指定的官方版本下載並載入圖文底座；Whisper 等第一次按「辨識語音」才下載。已經下載過的模型會重複使用。終端機顯示助理已啟動後，用同一臺電腦的瀏覽器開啟 `http://127.0.0.1:8766/`：這個位址指向你自己的電腦，運算也在你的電腦上，不是教材網站在代算；終端機要保持開啟，網頁才拿得到回答。這頁的 Bash 區塊在 Notebook 裡只是說明文字，不會自動執行下載。

接著在介面依序操作，每一步等結果出現再繼續：

1. 在「要送出的文字」寫「你好，請用一句話回答」，按「送出問題」。
2. 加入一張 PNG、JPEG 或 WebP 照片（8 MiB 以內），問畫面有哪些東西；再追問同一張圖裡某個物件的位置，照片與前文會留在這段對話中。
3. 準備一段最長 30 秒、8 MiB 以內的中文錄音（WAV、FLAC、MP3 或 OGG），在「中文語音」選取，按「辨識語音」，查看「辨識原稿」。這時只有轉寫文字，助理還沒有回答。
4. 確認或更正「要送出的文字」再送出，核對回答依據的是最後送出的那份文字。

「開始新對話」清除這段歷史與上傳的檔案。要停止時，在終端機按 Ctrl+C；已下載的模型留在快取裡，下次可以重用。這些步驟確認的是每條通路接通，不是回答可靠；回答品質看 [20.13](20.md#20.13) 的能力卡。

`git clone --no-checkout` 先只取得版本歷史，不把檔案展開；`git checkout --detach` 再把資料夾固定在本課核對過的那次提交，讓程式與公開清單都是當時的版本。這兩個 git 命令都設定 `GIT_LFS_SKIP_SMUDGE=1`，讓 Git 跳過以 Git LFS 保存的大型訓練資料：現在只用成品，不需要下載全部練習題。

[公開清單](../../docs/natural-assistant/v4/public-release.json)的 `base_model` 與 `asr_model` 兩欄固定兩個官方模型的版本，`files` 欄列出要下載的兩份配置文件與各自的大小、SHA-256；下載程式逐檔核對這兩項，不需要 Hugging Face 登入。本版沒有另加修正權重，所以 `adapter_parameters` 是 0。下載中途失敗時，可以重跑同一個下載命令；`--verify` 回報內容不同時，改用新的 `--output` 目錄重新下載，之後的 `--verify` 與 `--serve` 也要改成同一個新目錄。`--serve` 啟動前會先核對 `--output` 指定的目錄，還指著舊目錄就會再次失敗。

有 NVIDIA GPU 的安裝與啟動方式、離線使用（`--local-files-only`），以及聲音檔讀不進去時的處理，見[學生操作指引](../../docs/natural-assistant/v4/STUDENT.md)第 2、4、7 節。
