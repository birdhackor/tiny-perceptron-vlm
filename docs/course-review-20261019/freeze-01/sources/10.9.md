## 10.9 怎麼從向量方向比較圖文配對？

有兩張圖和兩段說明文字，先只問「哪段說明最配這張圖」，不要求生成句子。下面用手設向量代表它們：第一張圖 `[1,0]` 和第一段說明 `[2,0]` 同方向，第二張圖 `[0,1]` 和第二段說明 `[0,3]` 同方向。

`[1,0]` 和 `[2,0]` 方向一樣、長度不同，應該算一樣相配。所以先把每個向量除以自己的長度，讓長度都變成 1，比較時就只看方向、不受倍率影響。例如 `[3,4]` 的長度是 √(9+16)＝5，除完得到 `[0.6,0.8]`。這叫 **L2 正規化**（L2 normalization）；它只改一個向量的長度，和 [4.3](04.md#4.3) 會減平均、還帶可學倍率的層正規化不是同一件事。長度為 1 的兩個向量做點積（[3.2](03.md#3.2)：對應項相乘再相加），結果叫**餘弦相似度**（cosine similarity）：同方向是 1、垂直是 0、反方向是 −1。這是數字空間裡的方向，不是圖上的左右。

```python
import torch
from torch.nn import functional as F

image = torch.tensor([[1.0, 0.0], [0.0, 1.0]])
text = torch.tensor([[2.0, 0.0], [0.0, 3.0]])
similarity = F.normalize(image, dim=-1) @ F.normalize(text, dim=-1).T
print(similarity)
print("每張圖選文字欄", similarity.argmax(-1).tolist())
```

`F.normalize(..., dim=-1)` 對每一列向量各做一次 L2 正規化。文字矩陣轉置後，矩陣乘法一次算出每張圖對每段文字的點積，得到 `[[1,0],[0,1]]`。每一橫列是一張圖，每一直欄是一段文字；`argmax(-1)` 在每列選出最大的那一欄，得到 `[0,1]`，與本例預先安排的配對一致。

相似度不是機率，一列不必加總為 1。`[1,1]` L2 正規化成約 `[0.707,0.707]` 後，和 `[1,0]` 的相似度約 0.707；兩個候選可以同時得到這個值。之後用分類代價學配對時，才把候選分數轉成機率（[10.10](10.md#10.10)）。

這個手算只核對了比較方式，沒有用到真的圖片入口或文字模型。真圖與真文字需要各自學出有用的向量；同寬的隨機特徵不會自動有配對意義。這種從候選中找出相配內容的工作叫**檢索**（retrieval），和寫出新的描述不同。

練習把程式的 `text` 兩列對調，改成 `torch.tensor([[0.0, 3.0], [2.0, 0.0]])`，預期矩陣變成 `[[0,1],[1,0]]`、選中欄 `[1,0]`。配對關係不變，只是文字的欄順序換了。數值寫成 `2.0` 這種浮點數，是因為 `F.normalize` 要算長度，只接受浮點數；整個 tensor 都寫成整數（例如 `[[0, 3], [2, 0]]`）會報錯。
