## 14.16 能保證多一輪，loss 就下降嗎？

假設同一份驗證資料上的代價在1到5輪依序是1.2、0.8、0.6、0.7、0.9。若部署目標就是這批任務，第三輪目前最好，繼續算可能浪費工作。這不是違反循環架構：共享區塊沒有被定義成「每次都朝正確答案下降」的最佳化器。

有幾種辦法能**促進**改善。逐輪監督讓每輪都對答案負責；也可以在總目標加上 `λ*max(0,L_(r+1)-L_r)`，懲罰後一輪比前一輪差的情況。λ 是這一項的權重係數，這是軟限制：最佳化器在多個目標、題目及參數之間取捨，仍可能保留違反項，對新題更沒有逐題保證。

下面用人工代價檢查一個陷阱。只看「後輪比前輪差多少」的懲罰，模型甚至可以把早一輪變差，使差額縮小；因此還要監督各輪本身的品質。

```python
def penalty(before, after):
    return max(0.0, after - before)


for before, after in [(0.2, 0.4), (0.5, 0.4)]:
    print("早輪", before, "後輪", after, "懲罰", penalty(before, after))
```

兩組的後輪都是0.4；早輪從0.2惡化成0.5，懲罰卻從0.2變0。把懲罰變小不等於每輪能力提高。若加上各輪 CE，這條退路會付出其他代價，但仍是要實際平衡的訓練目標。

上一節的實測正好顯示這個界線：固定3輪模型的CE從第3輪0.0238升到第6輪0.1072，正確率也從99.49%降到97.67%。抽奇數模型的第3、4輪正確率同為98.65%，CE卻略升。多一輪可以有成本而沒有品質收益；CE與答案對錯也不必同時改變。

要談「保證」，須先說保證什麼：訓練資料的平均代價、每個訓練樣本、任意新題，還是正確率？這些要求不同。交叉熵下降也不一定讓 argmax（取最高分的候選，[1.15](01.md#1.15)）改成正確答案；正確率可以不變。即使限制狀態更新、讓它收斂到某個固定狀態，也只說明狀態不再變化，還不能證明那個狀態答對。

研究中有多深度監督、替各輪代價加限制的正則化（在訓練目標裡另加懲罰項，像上面λ那一項），以及自適應停止等方向；例如 LoopUS 把訓練正則化與停止設計放在一起研究。這些方向提供工程工具，不能改寫成所有新題的單調定理。一般部署可先在驗證資料上選定固定輪數；想逐題早停（看到某個訊號就提前結束，不跑滿固定輪數），還要有使用時拿得到的訊號，下一節討論。

練習：若第三輪代價最低但第四輪正確率最高，哪輪最好？先看產品目標；若任務按最後答案對錯驗收，不能只照代價排序。報告兩條曲線並保留差異，比要求它們一致更有用。

研究例：[LoopUS](https://arxiv.org/abs/2605.11011)。
