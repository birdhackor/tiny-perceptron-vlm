## 7.5 不算 loss 的內容就看不見嗎？

問題 Q 的位置不計代價，模型卻需要讀 Q 才能回答 A。這裡要分清兩件事。某個位置的預測和它自己的目標比對得到的代價，叫這個位置的**直接代價**；Q 所在位置的目標是 −100，沒有直接代價。可是 Q 這個 token 仍在輸入裡，後面預測 A 的位置會透過注意力讀到它，A 的代價也就沿著這條路，回頭影響 Q 的表示。

在最短的 Q／A 對話裡，Q 位於 X 的索引 2，ID 是 89。模型開頭用 ID 查 embedding 表 `model.embedding.weight`（每個 ID 一列，見 [2.1](02.md#2.1)），查出來的第 89 列就是 Q 的 embedding 向量。這張表被所有位置共用：任何位置讀到 ID 89，都查同一列。下面分別看兩個梯度：問題位置的 logits 的梯度，以及 Q 那一列 embedding 向量的梯度。

`logits` 是中間結果，PyTorch 預設不保留中間結果的 `.grad`，所以用 `retain_grad()` 要求留下它。`TinyLM` 的組成見 [4.6](04.md#4.6)，`masked_loss` 見 [5.1–5.2](05.md#5.1)。

```python
import torch
from tiny_perceptron.data import render_chat
from tiny_perceptron.model import TinyLM, ModelConfig, masked_loss

torch.manual_seed(42)
x, y = render_chat([{"role": "user", "content": "Q"}, {"role": "assistant", "content": "A"}])
model = TinyLM(ModelConfig(width=8))
logits = model(x[None])["logits"]
logits.retain_grad()
masked_loss(logits, y[None]).backward()
print("問題位置logits的梯度", logits.grad[0, 2].norm().item())
print("Q的embedding向量梯度", model.embedding.weight.grad[x[2]].norm().item())
```

`x[None]` 在最前面加一個長度 1 的筆數軸（[4.7](04.md#4.7)），所以 `logits.grad[0, 2]` 是這唯一一筆在位置 2、也就是問題 Q 所在位置的梯度。問題位置的目標是 −100，第一行應印 0：這個位置的候選分數完全不影響代價。第二行大於 0，因為後面答案的預測讀到了 Q。`norm` 把各數平方加總再開根號，這裡只用來看「是不是 0」；兩行屬於不同的量，大小不拿來互相比較。

第一行回答「這個位置的候選分數有沒有直接代價」，第二行回答「這份輸入表示有沒有影響後面的答案」。兩者都叫梯度，卻是對不同的變量問不同的問題。只檢查整個 embedding 層的 `.grad` 是不是 None，看不出 Q 那一列有沒有參與；只看到問題位置 logits 的梯度為 0，也不能推斷 user 內容都被凍結了。

所以不計 user 位置的代價，並沒有凍結 user 內容的 embedding 向量：它們會因為被後面讀取而收到梯度，在更新時跟著改變。若真的想切斷這條路，得另做別的操作，例如把查表後的向量 detach（讓梯度不再往回傳），或禁止回答讀 Q；那是新的設計決定，不是 −100 的效果。這段程式只求梯度，沒有呼叫 `step()` 更新參數；它檢查的是資料之間的依賴，還沒有教出回答能力。

練習只把 user 的 Q 改成 Z，答案 A 與種子都不動。先預測：問題位置 logits 的梯度仍是 0，Z 那一列 embedding 向量的梯度通常大於 0；再執行核對。X 索引 2 仍是問題字，程式會自動查新的那一列；這次測的是角色與位置的關係，不是 Q 這個字有什麼特別。
