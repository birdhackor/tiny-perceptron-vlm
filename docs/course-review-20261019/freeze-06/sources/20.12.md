## 20.12 助理答錯時，怎麼分清聽錯與回錯？

使用者說「請推薦不辣的晚餐」，ASR 的轉寫文字卻漏掉「不」，條件就反過來了。助理照著收到的字推薦辣菜，可能是正確使用了錯誤的中間輸入。診斷時要先查轉寫，再查回答，不把兩站混成一個錯誤。

下圖讓同一個問句走兩條路。左路的正確轉寫文字是錄音來源附的，不經過 ASR。

![同一問句走正確轉寫文字與真錄音兩路，交給同一個 Qwen，分開核對轉寫與回答。](../figures/natural-v4-asr-two-routes.svg)

先用 [20.10](20.md#20.10) 的 `text_error_report` 量出這個漏字：

```python
from tiny_perceptron.natural_concepts import text_error_report

reference = "請推薦不辣的晚餐。"
recognized = "請推薦辣的晚餐。"
report = text_error_report(reference, recognized)
print("最少編輯次數", report["edits"])
print("正確答案字數", report["reference_characters"])
print("CER百分比", round(report["cer"] * 100, 1))
print("兩份問題相同", reference == recognized)
```

補回一個「不」就和原話相同，所以最少編輯次數是 1；正確答案連句號共 9 個字，CER＝1/9，約 11.1%；兩份問題不相同。只差一個否定詞，要求就整個反轉，所以平均的字元差距不能代替「條件有沒有保留」。程式沒有播放錄音，也沒有生成回答。

練習把 `recognized` 改成 `"請推薦不辣的晚飯。"`（「餐」聽成「飯」）。先預測：最少編輯次數仍是 1，CER 仍約 11.1%，但這次條件沒有改變。CER 一樣，對回答的影響卻可能完全不同。

真正的評測讓同一個問句走兩條路：一條把來源的正確轉寫文字直接交給 Qwen，另一條把 Whisper 實際的轉寫文字交給同一個 Qwen；照片、歷史與要求都固定。正確文字也答錯，就繼續查回答這一站；正確文字答得好、錄音路線卻答錯，就先查 ASR 有沒有弄錯關鍵字。

AISHELL 提供朗讀錄音與正確轉寫文字，助理回答的判準由本課另訂；判準由 AI 助理撰寫，沒有逐題經人審核。這不是即興的長聊天，也沒有驗收各種噪聲、口音或多人同時說話。介面上的人工更正有助於使用，但評測原本的語音路線時，要保留更正前的結果。
