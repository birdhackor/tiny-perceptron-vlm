# 易懂教材的寫作與審閱

## 使用範圍

本 skill 隨 repo 保存，可用 `$clear-tutorial` 明確指定。它提供寫作與驗收規則，不代表模型已被永久訓練成另一種寫法。

先遵守使用者本輪指定的工作階段。若使用者只要分析、討論或審閱，不修改教材、不啟動訓練。新增或修改 skill 不等於授權重寫全書，也不代表既有教材已依新規則重新驗收。

預設讀者是數學不錯的高中生，或有基本數學能力但不熟的大學生。只假定他已學過明確列入入門內容的 Python，並依序讀過本節以前的課文；不假定他熟悉機器學習術語或本專案的開發歷史。「學過」不等於能立即熟用；公式要交代當下需要的符號與意義，較長推導可放補充區。依使用者指定調整背景，不因使用 skill 提高教材已公布的門檻。

## 本專案的工作順序

使用者指定分階段完成，不混做不同性質的任務：

1. 確定大綱、新增內容、權威來源與成品的有限任務。
2. 完成新增教材內容。
3. 依新架構改寫既有教材與必要圖解。
4. 依序完成易讀性、正確性、前後銜接的審閱與修正。
5. 獨立處理模型工程、訓練與能力驗收。
6. 回填成品事實、更新操作與權重並發布。

同一階段可以分工；上一階段尚未完成時，不預先進行下一種工作。實驗成績不決定成熟知識的教學安排；只有發現實質錯誤或實作與說明不符，才回修受影響的內容。

教材以原論文、官方文件及可靠教學支撐機制、用途與適用條件。小實驗用來建立直覺、展示實作與驗收成品，不要求每次重新證明業界知識。只保留有教學用途的數字與失敗案例；排版、文字或圖解更新不因此重跑訓練，只有能力宣稱或實作受到影響時才做相應驗證。

主線整合成品使用本課自行訓練的文字、視覺、語音與接頭權重。成熟模型的應用是清楚標示的延伸，不能用上游能力代替主線驗收。

## 核心標準

每一小節有一個主要學習問題。重要新概念或命名方法第一次用於解釋機制、推理或實作前，讀者應知道它是什麼、扮演什麼角色、為什麼在這裡學，以及與前文的關係。介紹上位類別或教會一個子步驟，不能自動代替整個方法的介紹。

重要縮寫給出完整名稱、中文意義與當下夠用的解釋；完整名稱不能代替概念介紹。已在前文完整教過的方法可以引用，不必每頁重講。允許先提出問題，再立即解釋；不以遠處後文、未讀程式或課外知識替前面的說明補洞。

## 寫作流程

1. 先用一句話寫下本節的學習目標。需要同時解釋多個不同實驗時，檢查是否應拆節或安排過渡。
2. 從具體任務與可見材料開始，交代希望得到的答案，再引入編號、向量與公式。每個編號與圖中元素都應有對應的意義。
3. 沿用例子與名稱，每一步增加一個主要變化。換資料、任務、模型或評分方式時，說明為什麼換，以及現在要回答的新問題。
4. 用自然段落串起「問題 → 材料與答案 → 做法 → 可觀察結果 → 原因」，不把每節寫成固定欄位表。講方法演進時，交代原有做法遇到的問題、改動、理由、可能收益與代價。
5. 用譬喻建立直覺，再對應到實際機制並說明適用範圍。概念、推導與資料操作也可有明確學習目的；只有涉及訓練時，才要求區分訓練材料、訓練後成果與使用時的輸入輸出。
6. 導覽、前置連結、安裝、完整參數與重做紀錄放在補充區；正文保留理解任務所必需的背景、方法介紹與實驗設計。
7. 顯示結果並解讀它。JSON、指令、得分表與證據連結可供查證，不能代替輸入、輸出及設計的說明。避免「我們已完成正式實驗」等開發進度敘事。
8. 只保留能教會概念的失敗案例；與學習無關的試錯歷史移出正文，限制結論所必需的證據仍須保留。

可直接貼用的短 prompt 見 [writing-prompt.md](references/writing-prompt.md)。

## 圖解與實驗

- 即使沒有圖，也檢查讀者是否需要自行想像素材、位置、對應、資料流或前後變化才能理解；必要時展示實際素材、忠實示意、SVG、表格或動畫，並交代這次要看哪裡。
- 圖、圖說、正文、公式與程式的數字和意義要一致。桌面正文與手機都應讀得清必要細節；放大檢視是補充，動畫停用時也保留關鍵資訊。
- 有瀏覽器工具時檢查實際頁面的圖、數學排版與閱讀流程。圖檔存在或建置成功不能代替視覺檢查；未做的項目標為未驗證。
- 展示實驗時，交代任務、輸入、答案規則、更新哪些參數、訓練與測試的區別、判準及結論範圍。分清手算、資料整理、梯度流通、真正更新參數與訓練後評測；沒有更新參數的 `backward()` 不能證明模型學會。
- 「一次增加一個主要變化」是寫作原則，不自動構成控制比較。比較效果時交代資料、模型、訓練及評分等重要差異；沒有優劣主張，就不要求證明優於其他方法。
- 分開原論文或官方文件的主張、本專案的實測與對機制的推論。得分交代分母、判準與失敗類型；不把 loss 下降、資料較多或小型 GPU 測試直接當成泛化能力。
- 效能數字交代計時範圍與設備條件；同步、啟動、前後處理、記錄、存檔或傳輸是否計入，會影響比較的意義。

## 審閱與修正

依 [review-protocol.md](references/review-protocol.md) 執行三輪：首次閱讀、技術與證據、前後銜接。完整閱讀包、記錄格式與通過規則以該文件為準。

首次閱讀者逐段取得目前內容與實際已讀前文；開放下一段前保存理解、原文依據、疑惑與缺圖。不提供作者摘要、答案、先前通過結論，或「補齊版」「故意留缺漏」等預期提示。

在主要新概念首次用於解釋機制、推理或實作時，以及小節末，回答四題：

1. 這個主要概念或整個方法是什麼，與前文有什麼關係？
2. 為什麼在這裡學它，回應什麼問題？
3. 如何使用，需要什麼、得到什麼，結果有何用途？
4. 例子、圖表或推導支持什麼理解或結論，哪些還不能推出？

每個核心主張附當下已讀的原文或圖中依據，區分「正文明說／導覽或前文已教／由已讀內容推得／目前不知道」。重要新方法另核對身分與整體角色、目的、本節步驟與方法關係的原句；這是四題的證據欄，不新增題目。合理推得不等於介紹已完整，必要連結仍缺時須列為具體問題。

按實際影響分開記錄名稱補充、概念介紹、教學時序、圖解、技術與證據問題。承認原文已教部分，指出仍缺的連結；後文釐清只能追加位置，不能刪除或改寫早期卡點。局部操作答對、全文復述正確，也不能消除閱讀斷點。

使用者要求獨立 subagent 時，使用不同審查者，首次閱讀者優先從無作者歷史的上下文開始。共用檔案系統不構成技術隔離；提前看過全文者記為非盲讀。沒有獨立審查者時標為作者自查，AI 審閱不等同實際目標讀者的理解測試。

已知問題示範見 [review-example-10-5.md](references/review-example-10-5.md)。

## 完成條件

- 主要問題、例子與方法介紹相互對應；當下必要的含義、角色與學習理由在使用前可理解。
- 四題在首次使用與小節末有實際記錄與逐項依據；必要介紹的缺漏已進入問題清單並複查，未靠作者或審查者腦補判通過。
- 必需素材與圖解實際可見，正文、圖說、程式與證據一致。
- 受影響的段落、圖與銜接已複查；未做的視覺檢查、執行或獨立閱讀標為未驗證。
- 回覆只陳述實際完成的工作與查證範圍，分清已測、推測與尚未測試。
