# 依閱讀順序審閱教材

## 目的與準備

熟悉技術的審查者可能讀完整節後重建作者意圖，卻漏掉學生中途需要的介紹。本方法保存「第一次讀到這裡的理解」，逐項核對它來自哪裡；完整復述正確不能消除先前的卡點。

1. 依 [SKILL.md](../SKILL.md) 指定讀者背景與範圍。順序讀者只使用入門內容和實際讀過的前文；跳讀者另開一輪，使用教材提供的導覽。
2. 凍結正文、必要圖與證據版本，保存路徑、code commit 和內容指紋。按有意義的單位拆成開場與例子、答案規則、方法、程式與結果、解釋與練習；圖與必需圖說一起提供。
3. 協調者保留全文；首次閱讀者每次只取得目前單位和已讀前文。不提供作者目標摘要、答案、未讀實作、先前通過結論或後續段落，也不透露「補齊版」「故意留缺漏」等預期結果。
4. 使用獨立 subagent 時，優先以 `fork_turns="none"` 開始，要求不搜尋後文、實作或外部解釋。共用檔案系統不是技術隔離；提前看過全文者記為非盲讀，另找未讀過者檢查。作者自查不得稱為獨立驗收。
5. 在主要新概念首次用於解釋機制、推理或實作的單位，以及小節末，安排 [SKILL.md 的四題](../SKILL.md#審閱與修正)。只審局部時，明列已提供前文與限制；沒有首次使用處的記錄，就不宣稱驗證了介紹時序。沒有新概念的單位可記「首次使用檢查不適用」，仍檢查當前任務與材料是否清楚。

## 第一輪：首次閱讀

### 開放下一段前留下當場理解

用讀者自己的話保存：

- 正在解決什麼，以及為什麼要做。
- 已出現的材料、答案、編號、圖中元素與箭頭各代表什麼。
- 下一個動作預期改變什麼，原文或圖中哪裡提供了依據。
- 哪裡需要猜測、回讀或課外知識；引用當時的原文。
- 需要看見但尚未看見的素材、對應或圖解。

程式出現前，確認讀者知道它要完成的任務及其示範範圍；程式後，確認輸出意義與結論範圍。說出 tensor shape 或照抄輸出，不足以代替這些理解。

開場提問、下一段立即解釋是合理安排，不要求讀者在教學前就懂新概念。真正的斷點是已拿未交代的概念或編號來推理、操作。尚未使用的細節可合理待教，但不能因此延後整個方法的基本介紹。

### 四題的逐項依據

依主入口的四題回答主要概念或整個方法；子步驟只作補充。重要新名稱有多個時，辨認各自分工，不用上位類別的定義代替新的命名方法。

每個核心主張分別附當下已讀的原文或圖中依據，使用以下來源狀態：

| 來源狀態 | 要留下的依據 |
| --- | --- |
| 正文明說 | 直接支持此主張的當前原句或圖中內容 |
| 導覽／前文已教 | 實際已讀的位置與內容；導覽的簡介不自動代表正文完整教過 |
| 由已讀內容推得 | 支持的句子及推論關係；合理推得不等於作者已明說 |
| 目前不知道 | 缺哪個主張，以及此刻是否已需要它；不借課外常識作答 |

在同一時點，為首次進入教學的重要命名方法整理「方法介紹原句對照」：

| 對照項目 | 核對內容 |
| --- | --- |
| 方法身分與整體角色 | 是什麼，在目前任務中負責什麼 |
| 方法目的 | 回應什麼問題，希望得到什麼理解、能力或結果 |
| 本節步驟與方法的關係 | 當前例子、操作或推導在方法中有什麼用途，為什麼現在教它 |

這是四題的證據欄，不新增題目，也不用為每個熟悉名詞建清單。可引用四題已記錄的證據編號；每項仍須分開記來源狀態及「已足夠／需補說明／合理待教」的理由。相鄰幾句可共同交代意義，不強求固定句型或一句包辦。

填完即核對問題清單：若方法身分、目的或本節步驟的用途仍需拼接導覽、上位類別與小操作才能理解，指出缺少的連結，至少記為增加理解負擔。不能只標「推得／未知」而判介紹完整。前文已完整教過的方法可引用，正常使用已教知識推導不算缺漏；合理待教須說明當下尚不需要哪個細節。

每個檢查時點保存以下記錄，四題分別作答；每個重要新方法留一份原句對照，可引用各題的證據：

```text
小節／閱讀單位／檢查時點：首次使用／小節末
當時已讀範圍：
四題逐項記錄：
  題號／回答的主要概念或整個方法：
  用自己的話回答：
  核心主張：主張／來源狀態／位置與引文／推論關係（若有）
方法原句對照（每個重要新方法一份）：
  方法名稱：
  身分與整體角色：證據／來源狀態／當下判定與理由
  目的：證據／來源狀態／當下判定與理由
  本節步驟與方法關係：證據／來源狀態／當下判定與理由
未知部分，以及當下是否已需要：
具體問題編號（沒有則記無）：
後來何處釐清（後續追加，不改早期判斷）：
```

四題適用於概念、架構、演算法、推導、評估與訓練。只有涉及訓練才區分訓練材料、訓練後成果及使用輸入輸出；一般概念不強求 optimizer、梯度、模型產物或訓練數據。沒有比較主張，就不要求證明較好；未看過的圖仍標為未驗證。

### 小變化與完整復述

每個主要例子加入一個有意義的小變化，請讀者預測並說理由。例如只換要求抄寫的區域，或維持圖片但改問形狀。只用當前已教概念，不用原樣照抄輸出充當理解測試；有歧義時，不把答錯怪在讀者身上。

讀完才做完整復述。後文釐清時追加位置，保留首次使用時的疑惑及介紹／時序問題；不能因最後答對，就讓早期卡點從報告消失。

## 圖與頁面的必要檢查

即使本節沒有圖，也明確回答：

1. 是否必須自行想像素材、位置、資料流或答案對應才能理解？
2. 哪個具體問題需要圖解，文字是否已足夠？
3. 已有圖是否回答這個問題，圖、圖說與正文是否一致？

有瀏覽器工具時，以實際頁面檢查桌面與手機，例如 1280×800 與 390×844；逐段閱讀時不展示未解鎖內容。檢查素材、必要字線、箭頭、數學排版與閱讀流程；基本說明不能依賴點擊放大，動畫停用時仍保留關鍵資訊。沒有工具或沒有實際檢查時標為未驗證，建置成功及 SVG 原始碼正確不能代替視覺驗證。

## 第二輪：技術與證據

首次閱讀問題修正後，另由未參與撰寫者檢查：

- 任務、輸入、答案及實驗設計是否一致，是否有資料洩漏或重要混淆因素。
- 程式實際做了什麼，更新哪些參數；分清手算、梯度流通、真正訓練與評測。
- 數字能否回查指定版本，分母與判準是否清楚；選定模型與部署是否一致。
- 得分是否混合辨識、範圍、格式、截斷與語意，造成能力誤解。
- 因果或優劣主張是否有相應比較；一次主要變化的敘事，不自動是控制實驗。
- 演進說明是否交代問題、改動、理由、收益與代價，是否分清論文主張、實測及機制推論。
- 效能計時範圍與設備條件是否可比，loss 下降或小型 GPU 測試是否被誤當成泛化能力。

逐項核對首次閱讀問題的來源。保留原文已教部分，只指出仍缺的連結；名稱未展開不自動表示角色、目的與使用方式全部未教。對不確定知識查原論文或官方文件，記支持的具體位置；按疑點執行相稱檢查，不為一處文句修改重跑全套訓練。

## 第三輪：前後銜接

技術修正後，由另一位讀者從相關前文讀到本節與下一節。檢查新概念順序、例子轉換、先備知識是否真的教過、同一術語意義是否一致。

改變目標或順序時，回查受影響的前文與導覽；局部修正重查相關閱讀單位、圖與過渡，不重新宣稱全書已驗收。

## 問題記錄與通過規則

每個問題至少保存：

```text
code commit／來源與圖的內容指紋／小節／閱讀單位：
當時可見的原文與圖：
讀者當時的理解：
原文已交代的部分、仍缺的主張與依據：
卡住位置、猜測或回讀及原因：
缺少的說明或圖解：
後文何處釐清（追加）：
問題類型：名稱補充／概念介紹／教學時序／圖解／技術／證據
嚴重程度：阻礙主要概念／增加理解負擔／選讀改善
分級理由：影響哪個理解、推理或操作
建議修正：
修正後的實際複查：
```

分級依實際影響：

- **阻礙主要概念：**必要背景缺失，無法理解主要概念、學習理由或使用方式。
- **增加理解負擔：**需要拼湊、猜測或回讀才能銜接；指出仍缺哪個連結。
- **選讀改善：**不影響當下主要理解的名稱補充或細節。重要縮寫未展開仍記錄，若角色與含義已清楚，不自動升為主要阻礙；若名稱解釋承載必要含義，按該缺漏的影響判定。

必要方法介紹、說明或圖解缺漏，須修正並複查後才能判該項通過；中度問題也不能只標「推得」或「後來懂了」便算解決。選讀改善可列待辦，但不得把未解決的必要介紹歸入這類。

保存逐段原始記錄及每輪修正後複查，註明實際來源與範圍。不以新摘要覆寫卡點，不把缺少逐段記錄的完整頁面閱讀或技術審查改標為首次閱讀盲讀通過；未做的視覺檢查、執行或獨立閱讀標為未驗證。

AI 審閱是輔助證據，不等同實際高中生或大學生的理解測試。可能時請目標讀者指出卡住處，據此調整後續標準。
