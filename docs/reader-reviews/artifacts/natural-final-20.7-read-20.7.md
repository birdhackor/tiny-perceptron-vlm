## 20.7 打字能答，為什麼說話還可能答錯？

你說「十三加二」，語音辨識漏掉「十」，逐字稿成了「三加二」。聊天助理即使可靠地處理收到的三加二，也沒有回答原來的問題。這是一個先後相接的系統：上一站把題目改了，下一站仍可能很認真地完成另一題。需要保存中間逐字稿，才知道錯誤從哪裡開始。

前置是[12.11語音轉成文字](12.md#12.11)、[20.1兩路共用對話](20.md#20.1)與[19.7請求、執行和讀回分開](19.md#19.7)。ASR指自動語音辨識，輸出說話內容的文字；聊天模型再依對話、圖片或可用工具作答。本章的聊天模型沒有直接接收波形，因此本成品不能稱為原生音訊模型。直接用音訊編碼器特徵接入LM是另一條可行路線，仍需自己的對齊資料、訓練與驗收。

先用一張人工故障卡看數字如何錯在上游：

```python
reference = "請算十三加二。"
recognized = "請算三加二。"
original_numbers = (13, 2)
recognized_numbers = (3, 2)
print("逐字稿完整符合", reference == recognized)
print("原問題的兩數相加", sum(original_numbers))
print("錯誤逐字稿的兩數相加", sum(recognized_numbers))
print("這是人工漏字示例，沒有辨識錄音或呼叫聊天模型")
```

兩份文字是手寫的，兩組數字也是我們依內容人工填入，沒有自然語言解析器。第一行False，後兩行15與5，顯示漏一個字可以改變最後任務。本程式的sum是真的Python加法，但不是模型選工具或讀回結果的證據；完整語音聊天仍要實際送錄音、保存辨識輸出，再由同一聊天模型回答。

正式驗收至少保留三條路：把正確文字交給聊天模型；把同一語意的錄音交給ASR，再用辨識逐字稿聊天；另看ASR逐字稿與資料真值的字符錯誤。第一條是文字能力對照，第二條是完整語音輸入，第三條定位聽錯哪些字。若文字路線已經答錯，不能把全部問題歸因於語音；如果逐字稿正確、回答卻錯，也不能拿低CER掩蓋聊天失敗。

真人資料還需看說話者與環境。只用合成人聲成功，不等於一般人的錄音都可辨識；同一人、同一臺設備、安靜短句的結果，也不能保證各種口音、噪聲與長錄音。ASR的公開朗讀資料可以檢查真人轉寫，卻未必有聊天問題和理想回應。這兩類資料會分開記錄，不能把文章逐字稿直接當成已訓練語音聊天的答案。

多輪時，文字與逐字稿都接回同一份歷史；附圖問題也使用相同的照片，才讓兩路比較有意義。使用者可以看到逐字稿並修正，這是應用提供的可操作入口；評估原始語音路線時仍保留修正前輸出，不能偷偷用真值替代ASR後再宣稱語音全對。這個階段先提供文字回覆，朗讀回覆或實時雙向語音屬於另一個任務。

最後測試使用12段FLEURS `cmn_hans_cn`真人華語朗讀，共131.98秒。[固定的Whisper-small](https://huggingface.co/openai/whisper-small/tree/973afd24965f72e36ca33b3055d56a652f456b4d)以`chinese`、`transcribe`設定產生逐字稿，再交給已選定的微調版聊天；它的241,734,912個參數沒有用本課錄音更新。這些素材是朗讀陳述，沒有日常聊天問句或官方助手回覆標註，成績只涵蓋這份小型朗讀考卷。

逐段比較[原始逐字稿與實際ASR輸出](../../docs/natural-assistant/evidence/final/transcripts.json)，獨立重算得到原始CER為150／481＝31.19%；先做Unicode NFKC、移除所有Unicode空白後，為129／464＝27.80%。後一種計算仍不刪標點、不換簡繁字形；「没／沒」這類字形差異也會計分，因此CER要搭配內容詞錯誤一起讀。12段ASR都以EOS結束，沒有截斷或未知結尾；正常停下來仍會辨錯字。來源原逐字稿沒有為評分改寫；作者與評閱者未播放錄音，以下字詞定位依原逐字稿及實際ASR文字，不作聽感或口音判斷。

聊天對照把正確逐字稿直接交給同一聊天核心；完整語音路線使用ASR真正輸出的文字。兩路都保留「繁體中文、簡短回應、不要只重複原話」的相同歷史設定，這組沒有附圖或此前的使用者對話。完整任務還須保留原意、不添加無據內容；[獨立評分](../../docs/natural-assistant/evidence/semantic-final/final-semantic-review.json)依相同要求分別核對[兩路完整回答](../../docs/natural-assistant/evidence/final/generations-adapter.json)。

| 最後12段朗讀的輸入路線 | 已選定微調版的完整任務成功 |
| --- | ---: |
| 正確文字→聊天 | 4／12 |
| 真人錄音→原始ASR→聊天 | 1／12 |

兩路都生成了12個EOS結尾的回答，但完整成功仍只有4題與1題。忠實程度與回應要求分開記錄：只有原句重播或同意思摘要，沒有確認、提醒、追問等回應，依輸出前就固定的「不要只重複」要求判未完成；邊界案例的忠實摘要與原文仍保留供讀者核對。這是本課的小型回應約定，不是一般日常聊天成功率，也不與另外的文字聊天、多輪聊天考題混算。以下兩個原始例子能把辨識與聊天錯誤拆開。

原話是「桥下垂直净空 15 米。该项目于 2011 年 8 月完工，但直到 2017 年 3 月才开始通车。」ASR卻寫成「乔夏垂直进空15米盖像墨鱼2011年8月晚供但直到2017年3月才开始通车」。微調版的語音回答接著寫「喬夏垂直進空15米，蓋像墨魚，2011年8月晚供，但直到2017年3月才開始通車。」題目的「橋下淨空」與「該項目完工」已在上一站損壞，聊天只是把錯字加上標點，沒有釐清。正確文字路線得到「橋下垂直淨空為15公尺，於2011年8月完工，2017年3月才通車。」兩路的內容差別在這裡可追到ASR；文字路線雖保留內容，仍只是重述，依同一回應要求也判未完成。

另一段說「这里几乎都是沙滩，游泳很安全，大部分地方都有新西兰圣诞树的树荫。」ASR把植物與遮蔭辨成「新西兰生难受的树鹰」。語音回答卻說「你說的可能有誤，新西蘭的海灘大多數是沙灘，但並非所有地方都有樹鷹。」它沿用錯詞，還把樹名中的新西蘭當成海灘所在地，添加原話沒有的判斷。即使直接給正確文字，同版仍回答「這裡是熱帶風景，不是南半球的。」這個氣候與半球判斷錯在聊天站，不能歸因於ASR。

此前相同384-token上限的6段驗證，正確文字路線為底座0／6、初版微調檔0／6；原始語音路線為0／6、1／6。這一題的差異只限小考卷及事先約定的回應要求；原先96-token試跑另留作流程紀錄，不能把換上限當作訓練增益。兩份聊天模型共用同一次ASR原稿，也沒有微調前後的ASR改善可報。

應用讓使用者先看辨識原稿，再修正要送出的文字；評估仍保留更正前的ASR輸出。這一版以文字回覆，沒有直接把波形交給聊天模型，也沒有TTS語音輸出。吵雜背景、長錄音、即興多輪、多人重疊與臺灣口音仍需另外測試。

練習只把`recognized`補回「請算十三加二。」，再把`recognized_numbers`改成(13,2)。先預測文字一致變True，兩種計算結果都15，再執行。這只是修好人工卡；實際測試需要改善辨識或讓使用者明確更正，不能由評估程式私下補答案。
