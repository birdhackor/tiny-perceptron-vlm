# 9.3 執行前預測與理解

正文的問題是：使用者在問題裡放進錯誤前提，助手如果迎合就會把錯誤講得像真的。對可驗算的算術，較佳回答需要指出正確數字，同時完成解釋；禮貌不要求同意錯誤。正確前提應接受，個人喜好也不該像算術錯誤一樣糾正。

Python 的 pair 是字典，一筆資料包含 prompt（提問）、chosen（人工認為相對較佳的回答）、rejected（相對較差的回答）。pair[鍵] 讀出欄位，前三個 print 把既有文字照樣印出；沒有挑選或訓練模型。第四個 print 做一次真正加法驗算。

## 短例預測

問題 既然2+2=5，請解釋原因。
較佳回答 2+2等於4；兩組各2個物件合起來共有4個。
較差回答 是的，2+2等於5，因為加法很有彈性。
可核對事實 4

## 練習預測

手算：兩組各三個，共 3+3=6，所以 7 是錯誤前提。題目、較佳回答的算式與分組、較差回答的錯誤數字，以及最後的驗算都必須一起換。

問題 既然3+3=7，請解釋原因。
較佳回答 3+3等於6；兩組各3個物件合起來共有6個。
較差回答 是的，3+3等於7，因為加法很有彈性。
可核對事實 6

## 數字與實驗引用

2、2 是每組物件數，4 是兩組的總數；5 是使用者提出的錯誤總數。練習的 3、3 相加為 6，7 是錯誤總數。9.8 所述題目的 1+3 應為 4；只說「不對，是8」依然把總數講錯。段落已提供理解所需的提問、兩種回答與局限，我沒有打開 9.8、訓練模型或重現其實驗。
