## 我理解的問題與例子

本節問的是：手上的資訊是否足以回答球數？盒內真有 3 顆，只是出題者知道；回答者沒看到盒內、也沒收到數量，即使猜 3 猜中了，仍無依據。若使用者已給 3 或清楚的照片，就應使用它。誠實不能只靠常說不知道，也不能只靠偶然答對。

程式的兩筆字典都把 hidden_count 存成 3，但 visible_count 分別是 3 與 None。清單用 examples 命名，for 每次取一筆字典叫 row。row["visible_count"] 按欄位名稱取值並存為 visible。target 是人工寫好的理想回應：visible is not None 時取 str(visible)，將整數 3 變成文字 3；否則取要求數量或圖片的句子。A if 條件 else B 是同一個二選一的分支，並不表示兩者都執行。print 每輪顯示可見值與目標回應。None 表示這裡沒有值，不是球數零，也不是文字「None」。hidden_count 完全沒有參與條件或目標。

本節沒有數學公式。需要分清的數字是：兩筆輸入、兩筆 hidden_count 均為 3、第一筆可見值是 3；後段引用的回答 6 是缺資訊時改問法得到的模型猜測，不是可由盒子或顏色推導的真值。盒子1 是引用問句的盒子標記，沒有提供球數。

訓練目標在這裡是資料作者希望模型學會輸出的答案文字。這兩行 Python 只是按已知規則製作目標，不等於模型自己知道何時不確定。後續測試需要同時包含能回答的題與缺必要資訊的題，而且要換球數與問法。只算猜中率會獎勵運氣，只算澄清句次數會獎勵資訊已足仍追問。

知道盒子是紅色本身不能推出球數。若任務明確提供「每個紅盒固定裝 3 顆」的規則，紅色才有推論用途；該規則也必須讓回答者看到。這是對資訊依據的限制，不是宣稱任何顏色都永遠沒用。

## 短例與練習的預測和實跑

原程式第一行預測為「可見 3 → 3」，第二行為「可見 None → 看不到球數，請提供數量或圖片。」。實跑 stdout 與預測逐字一致。

練習只在第二筆增加 box_color: 紅，保留 visible_count 為 None 與原判斷。預測兩行都不變，因為程式沒有讀 box_color。實跑也逐字一致。可在 exercise-red-box.py 確認只增加這個欄位，在 execution-evidence.json 與兩份 stdout.txt 核對真實輸出。
