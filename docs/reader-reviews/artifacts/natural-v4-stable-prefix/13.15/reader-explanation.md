# 我如何理解 13.15

本節解決的是如何把先前拆開的策略選卡、評分、舊基準和 PPO 更新接成一次訓練。它選的是四張已預先寫好的整篇回答卡，不是自動算 1+2、理解原句中文或逐 token 生成。卡 0 是正確短答、1 是算式加結果的一句話、2 是錯數字、3 是請求補資訊。條件由程式直接提供；因此考察的是選卡而非語言能力。

## 原短程式的輸入、關鍵行與輸出

context 是一題四格。前兩格是兩個數各除 10，故 [0.1,0.2,0,0] 對應 1+2；第三格 0 表示不要求解釋，第四格 0 表示沒有缺購買數量。第三、四格用 1 表示條件有、0 表示條件無。seed 42 固定初始化與抽樣所用的隨機序列。

policy 每題輸出四個候選分數；Categorical 用它們建立分布並 sample 一張卡。critic 同題估計尚未選卡前的回饋基準。reward_model 被凍結；reference 是 policy 起點的深複製，也被凍結。optimizer 登記 policy 和 critic 參數。no_grad 區块收集 action、所選卡舊 log 機率、reward 和 advantage，讓這一份採樣紀錄成為固定資料。gather 沿四卡軸只拿所選卡的評分；action[:, None] 為每題卡號多留一個索引軸，squeeze(1) 移除取一張卡後的單格軸。優勢是 reward 減作答當時 critic 的基準。

更新區塊重新算帶梯度的 policy 分數與同張卡新 log 機率，交給裁切函式。terms['policy_loss'] 是用於下降更新的策略代價；前置 13.13 說明了待提高替代目標取負的方向。value_loss 用 (critic 預測−這次 reward)² 再平均來教估計員。exact_kl 比較所有四卡的新 policy 分布與固定 reference 分布；本例尚未更新時两者一樣，KL 為 0。总 loss 將策略代價、0.1 倍 KL 和 0.5 倍估計平方誤差相加。SGD 的 lr 0.1 則決定每個已登記參數沿負梯度走多遠，並不是 KL 權重。

zero_grad 清梯度；backward 求本次 loss 對參數的梯度；step 才更新參數。before 是 policy 第一個參數張量的 detached clone。最後比較只證明這個張量已變，不代表每一格參數都一定變。critic 已登記且由 value_loss 提供梯度，但正文沒有打印 critic 的前後差，因此這份觀察輸出本身沒有直接展示 critic 改多少。評分員和 reference 沒有梯度，與 optimizer 登記內容及凍結設定相符。

我實際執行原例，exit 0，輸出卡 0、更新前 ratio 1.0、策略參數改變 True、評分員有梯度 False、context/new_logits 形狀 [1,4]/[1,4]、固定參考有梯度 False。ratio 是新機率除舊機率；此時還沒 step，故等於 1，沒有用到裁切平台。這不能證明卡 0 以後一定更常見、任务分數提高，也不證明新策略的全部 ratio 永遠在 0.8 到 1.2。

## 正文數值的意義與單位

- 除 10：將 1 到 10 的兩個題目數值縮到 0.1 到 1.0；不是十張卡。0.1、0.2 是縮放後輸入數值；兩個 0/1 是無單位條件旗標。
- 0 到 3 是卡號；四張卡、四格情境都是項數。形狀 [1,4] 的 1 是一題，4 在 context 是情境欄、在 logits 是候選卡。
- 42 是隨機 seed 編號。ratio 1.0 是無單位新舊機率比。20% 指前置裁切範圍 1±0.2 的比值偏移，並非正確率或參數改變上限。
- lr=0.1 是每次 SGD 更新的學習率；loss 中 0.1、0.5 是 KL/平方誤差的相對權重。它們都是這套無物理單位數值模型的配方係數，不是題數或回饋百分比。
- 兩個數各 1 到 10。無序家族把 1+2 與 2+1 算同一組；含相同數時可數 10+9+…+1=55 組。44/5/6 是訓練、驗證、最後檢查家族數；各家族三種條件，44×3=132、5×3=15、6×3=18 題。這些是資料划分，不是本輪抽樣數。
- 44 是只回數字的示範筆數；148 是選卡網路可學習參數數量；60 次配合每批 32 題，讀來是示範訓練的 60 次更新，不是 60 個獨立家族。
- label smoothing 的 0.2 我只能理解為平滑強度，讓其他卡保留少量目標份額；本文沒有規則，無法確定四卡目標是 [0.85,0.05,0.05,0.05]，還是 [0.8,0.2/3,0.2/3,0.2/3] 等另一配方。這是未解決的數字解釋缺口。
- 241 是獎勵評分員參數數量，97 是 critic 參數數量。660 是訓練偏好對數；300 是評分員更新次數、64 是每批偏好對數，300×64=19,200 次偏好對被抽用，並非 19,200 個獨立偏好對。
- PPO 120 是採集批數，每批 64 次真選卡，共 120×64=7,680 次作答。每批重用 3 回合，policy/critic 各做 120×3=360 次更新；更新讀取動作紀錄共 7,680×3=23,040 次，並非新作答。
- effective_tokens=0 的單位是訓練 token 數；此實驗直接學整卡選擇，沒有逐 token 訓練，因此為 0，不能說沒有學習資料。
- CPU 两個執行緒是執行配方；2.12 秒是正文引用那次含 DPO 分支完整實驗的總耗時，0.66 秒是同次 PPO 段耗時。這不是我本次執行的測量，也不含另一台的安裝時間。
- 最後 18 題是檢查題數；起點通過 6 題、PPO 後通過 12 題，都是正文引用的既有結果。我未執行完整訓練、未讀公開 report，也未確認逐題结果，因此不把這些數字說成我獨立驗證的任務品質。

## 未解釋詞與閱讀阻礙

策略、優勢、ratio、裁切、critic、KL、分數转機率與梯度，在實際所讀必要前置能找到解釋；gather、squeeze、SGD、lr、zero_grad、backward、step 的核心用途也在本節明說。四卡角色與兩幅圖沒有阻礙。

label smoothing 只給概念與目的，沒有交代 0.2 的確切目標份額；SFT 在本節與我實讀的必要前置中沒有展開名稱，也沒直接說它就是前面以示範正卡為目標的監督訓練。DPO 在 13.10 可理解為可省去獨立評分網路的另一路方法，但縮寫仍未展開；因本節只提完整實驗另含一個分支，對本節主要 PPO 流程不是阻礙，仍記為未展開詞。上述缺口沒有以自行搜尋程式或整個章節補上。
