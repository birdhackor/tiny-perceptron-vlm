## 本節的問題與完整流程

本節問先前的選擇、評分和更新能不能接起來。答案由一個有限四卡的短程式展示：題目條件先被轉成四個數字，policy 給四卡分數并抽選整篇回答，已凍結的獎勵模型取所選卡評分，critic 給題目通常能拿的舊基準；採集這次卡號、旧 log 機率與回饋，再用固定優勢教 policy，並用評分結果教 critic。reference 留住起點，KL 讓更新同時考慮離起點多遠。

四卡順序是短答、帶算式的一句話、錯數字、請補資訊。模型不需要讀原句，候選字句也由程式先寫好。所以流程成功與選對卡，還有自行做加法、理解中文、逐字生成，是不同主張。本節限定清楚。

## 程式輸入、關鍵行與輸出

[0.1,0.2,0,0] 是一個批次內的一題：前兩項是 1、2 各除 10；後兩項是否要求解釋、是否缺購買數量均為無。Categorical 將 policy 的四分數整理為抽樣分布，sample 得卡号；log_prob 保存所選卡的 log 機率。gather 選卡軸的一个位置，squeeze 去掉「每題只取一格」的軸，得到本次 reward。bandit_advantage 用 reward 減舊 critic 基準。

no_grad 讓採集紀錄不追蹤梯度；后面 new_logits/new_log_probability 重新計算，才讓策略代價能反傳。reward/reference 的 requires_grad_(False) 凍結它們。optimizer 只包含 policy/critic。參考以 deepcopy 從 policy 複製，所以第一步前兩者分布相同、KL 為 0；對同卡新舊機率比也為 1。policy_loss 下降方向對應前置的取負替代目標；value_loss 是 critic 与這次 reward 的平方誤差均值。總 loss 將這兩種學習及相對 reference 的偏離一起考慮。

SGD 的 lr 0.1 是梯度更新步長；另一个 0.1 是 KL 在 loss 的權重，0.5 是 value_loss 權重。zero_grad 清舊梯度，backward 求梯度，step 改參數。before 只保存 policy 第一個參數張量，所以打印 True 證明至少這個張量變了，不應說每格參數都變；critic 被登記且有自己的 loss，但此段沒有打印它的前後差。

我本輪直接逐 bytes 核對當前 Python block 與初輪真執行的 example.py 一樣，練習修改後的 code 也一样；沿用初輪的實跑證據，本輪沒有新執行。真實輸出都是卡 0、更新前 ratio 1.0、策略改變 True、評分員梯度 False、context/logits 各 [1,4]、reference 梯度 False。ratio 1 是 step 尚未發生的結果；裁切沒有觸發，不構成新策略被硬鎖 20% 的證据。随机评份和随机选择也不能证明任务品质改善。

## 目前數值與配方如何理解

四卡和四格是項數，不是同一種欄位；形狀 [1,4] 的 1 是題數、4 分別是輸入欄數和候選卡數。0/1 是條件旗標；卡號 0..3 是索引；seed 42 是隨機序列設定。lr/代價權重/ratio 都是這个数值模型的無物理單位係數或比值。

題目數值各在 1..10，无序家族把加數交換看成同一家族，含重複加數可數成 10+9+…+1=55 家族；44 訓練、5 驗證、6 最后檢查。每家族 3 要求，得 132/15/18 題。先用只回数字的 44 筆示範教 148 參數 policy：60 次訓練更新、每批 32 題。正文現在說這是 supervised fine-tuning（SFT，監督式微調），即給題目情境與指定示範答案，讓模型學著選示範；我不再需要猜 SFT 指甚麼或怎樣與前句相連。

label smoothing 的 0.2 现在是清楚的 20% 目標份額平滑。若卡 0 正確，原目標 [1,0,0,0] 的 80% 是 [0.8,0,0,0]；另 20% 均分四卡，各加 0.2/4=0.05，于是 [0.85,0.05,0.05,0.05]，合為 1。0.85 是 0.8+0.05，不是簡單留正卡 0.8 而把 0.2 分給其他三卡。現在文字區分了訓練目標與模型訓練後實際機率，沒有保證模型输出就固定是該向量。為保留其他卡探索而使用这个示范配方，也不意味所有 SFT 必须如此。

評分員 241 與 critic 97 是參數數量。660 是獨立訓練偏好對數；評分員 300 次更新×每批 64 对=19,200 次偏好對被讀用，不是 19,200 个新對。PPO 120 批×64次选卡=7,680 次真作答；每批重用 3 回合，兩可學模型各 360 次更新；23,040 是 7,680×3 次更新流程讀取紀錄。effective_tokens=0 是逐 token 訓練資料計數为 0，因为它直接選整张卡，並非沒有有效資料。

兩個 CPU 執行緒是引用實驗的運行設定。2.12 秒（完整、另含 DPO）與 0.66 秒（PPO 段）及最後 18 題起點过 6、PPO 後过 12，都屬正文引用的既有訓練結果。我沒有重新訓練或讀公開實測報告，不把它们說成我本輪驗證。完整 CLI 的用途与先依 W.1 在根目錄啟用環境的步驟可懂。
