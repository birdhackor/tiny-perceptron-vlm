# 後續派工準備

這份文件是協調者的工作說明，尚未派工，也不是審閱或通過紀錄。只有前輪修正、原人回讀與 `seal-stage` 成功後，才用真正的新 `fork_turns=none` 代理開始下一輪。實際 owner、manifest、時間與前輪 readiness receipt 另記 dispatch。

## 技術與證據輪

六組範圍沿用當時的 current manifest，每頁只分配一次。使用未參與作者、研究、工具或第一輪閱讀的新代理，實際閱讀 skill、protocol 與 infrastructure 格式後才給 GO。

每個 owner 用 `start --stage technical` 逐段讀原稿，保存自己的五欄理解與證據判斷。必要前文自己真讀；不使用作者摘要、研究 REPORT、他人理解或舊 pass 當證據。可以讀本頁真正引用的論文全文、官方文件／原始碼、原始實驗結果與可核對的程式。研究 cache 裡的原論文是材料，研究者替它寫的解釋不是原始權威來源。

每頁核對實際主張，按 infrastructure 的 `artifacts,sources,claims,checks` schema 記下自己的來源、版本、定位與支持範圍。概念、數字、程式與實驗主張分別選適合的核對方法，不把一個一般來源掛在整頁當作全數已核實。含程式／命令的頁面不能整頁標無實質主張；導航頁也須自己判斷適用範圍。

核對數據使用固定結果和真正的原始記錄，列出分母、判準、選模型方式與限制。需要計算或程式執行時做相稱的 CPU 檢查，保存實際命令、版本、輸出與原始內容指紋。不為修訂文字重跑長訓練，也不把讀取歷史輸出說成本輪重新訓練。API 文件、help 或靜態程式核对只能支持各自實際查過的契約，不能自動支持未執行的整套外部操作。

有不確定的概念，自己查看原論文或官方說明；無法核實便交 revise 和具體 issue。必要圖要本人實際看640/360 render，必要的頁面位置亦看實際桌面／手機；共用 render 不代表共用觀看。不填 reader 的四題清單，仍保留自己的逐段五欄。

組報告保留全部自己的 trace、原始 issues 及實際 artifacts。最初 revise 有效，完成後交自己的全組不可覆写報告。協調者只收件與修改教材，不替 owner 填理解、核實或 pass。修正後依新 freeze 由原技術 owner 回查，也由受影響的原 reader 回讀。

## 前後銜接與估時輪

技術輪全部必要問題關閉並 seal 後，再派六位另一批代理。每位從自己真正讀過的前文讀到主頁與相鄰下一段，保存五欄及每頁 `continuity_checks`：前文關係、過渡、新先備、術語、例子改變。分组提供的前文若省略必要頁，自己真補讀並保留限域卡點，不把策劃省略錯說成原教材沒教。

檢查新增內容的安排，也檢查其餘全書：讀者此刻知道的資料、問題與答案是否足够，跨節切換任務是否交代，導覽是否指到真前置；本節是否只使用已教知識，重要名字是否從同一角色延續。閱讀時不看作者新內容目標或舊審閱結論來補出書上沒有的連結。必要圖仍本人看，並按實際頁面記錄 placement。

完成相應最終正文的實際閱讀後，由 owner 自己為每頁估時。使用既有 `reading_time` 格式，對象是數學好的高中生或基本數學的大學生；包含理解文字、圖與範例程式、短暫思考，不包含安裝、操作、下載和等待訓練。給正整數的 min/max、具體判斷理由、真實 task、當頁與圖 SHA。這是 AI 估計，不是實測平均，也不以字數公式冒充本人閱讀。

每組同時交原樣估時 rows；改版頁由原 owner 真回讀後給新 row，不由協調者替舊數字換 SHA。協調者只彙整和計算合計，最終檢查所有325個 canonical 頁都有對應的實際來源。

銜接修正後，原 reader／必要技術 owner／原 continuity owner 按影響範圍回讀，保留舊版本和未知。`gate --stage all` 關閉當前版本的全部範圍後，才建立 active pointer、更新網站與 Notebook、檢查、提交發布。
