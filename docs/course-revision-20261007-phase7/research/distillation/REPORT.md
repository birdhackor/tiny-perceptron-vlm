# 第 18 章蒸餾：研究與教學設計建議

本輪只研究與提出教材設計，沒有修改章節、程式或圖，沒有啟動訓練。閱讀版本為 `3c0f3254d4762f5ed87e77bd55e5eaf9be2ec248`，完整閱讀 `course/chapters/18.md`，依 `.agents/skills/clear-tutorial/SKILL.md` 與其 `review-protocol.md` 做非盲讀核對；這不是首次閱讀驗收，也不是目標學生的理解測試。

教材應讓學生看見：**同一份原始資料能供兩種不同訓練使用；蒸餾的關鍵在教師提供了什麼目標，而不是學生是否從隨機權重開始。** 原始資料拿不到是蒸餾可能遇到的情境，並非必要條件。部署較小模型是常見目的，也不能自動推出學生訓練更省時。

原論文已足以支持這些成熟知識，不需要重新實驗。四篇原件已讀相關段落；URL、版本、短引文、PDF 頁碼、SHA256 與實際快取路徑見 [source-index.json](source-index.json)。依本輪協調要求，原始 PDF 與抽取全文存於 ignored `outputs/phase7-source-cache/distillation/`，避免重複全文進入公開研究檔案。下文 `[H]`、`[B]`、`[M]`、`[R]` 分別指 Hinton、Born-Again Networks、MiniLLM、DeepSeek-R1。

## 1. 先確定學生最後應能推論什麼

把完整原訓練集記成「輸入與原答案」。直接訓練小模型時，小模型從原答案學；蒸餾時，它可以仍讀相同輸入，但多讀或改讀教師的答案、機率分佈或其他訊號。以下固定同一學生架構與起始權重，教師已訓練好且固定，才比較訊號：

| 路徑 | 看到的問題 | 用來計算誤差的目標 | 與原資料直接訓練的差別 |
| --- | --- | --- | --- |
| 原標籤訓練 | `2+2=?` | 原答案 `4` | 基準 |
| 教師硬答案訓練 | `2+2=?` | 教師生成的 `4` | 若完整有效目標也相同，沒有新增監督訊號 |
| 教師軟目標訓練 | `2+2=?` | 候選 `[4,3,100]` 的 `[0.7,0.2,0.1]` | 提供每個候選的比例，改變誤差與梯度 |
| 原標籤加教師軟目標 | `2+2=?` | 原答案 `4`，另加教師比例 | 保留原答案要求，再加入教師對候選的偏好 |

這個表把輸入和監督訊號分開。若「完全相同原始訓練資料」包含原答案，軟蒸餾仍可保留原資料不變，只是在訓練時計算或讀取教師分佈。教師分佈不是新增原始樣本，而是教師先前從資料與訓練方式學到的對映所產生的目標。[H, §1，PDF p.2]

### 1.1 相同資料為何還可能產生不同學習？

Hinton 等人的原文直接寫：

> “For this transfer stage, we could use the same training set or a separate ‘transfer’ set.” [H, §1，p.2]

又寫：

> “We have found that using the original training set works well” [H, §1，p.2]

後一句接著說可加一個鼓勵學生預測真實答案的項。這不是「資料拿不到」的前提；原資料、原標籤與教師軟目標可以同時存在。§4 的語音例子也明確比較蒸餾模型與直接使用相同訓練資料的同尺寸模型。[H, §4，p.4；§4.1，p.5]

教師可能以較大容量、多模型平均、正則化或資料增強學出不同的輸入到輸出對映。學生只從每筆原答案學時，該答案不會逐項告訴它教師對其他候選的相對偏好。軟目標把這些偏好交給學生，**可能**提供有用的訓練引導。若教師完全由相同資料訓練而來，這不等於憑空新增真值；它是傳遞已學出的結構與偏好。Hinton 的「較會泛化的教師可教學生怎樣泛化」須保留其教師泛化良好的條件，不延伸成本課的小教師必然有這種能力。[H, §1，p.2]

### 1.2 軟分佈實際增加了什麼？

原答案 `4` 轉成三候選的硬目標是 `[1,0,0]`。教師的 `[0.7,0.2,0.1]` 則說明它對各候選的偏好。這些數字是教師在該前文下的模型機率，不是答案數值距離、不是真實世界正確率，也不是宣稱「100 有 10% 機會是正確的 2+2 答案」。[H, §1，p.2；本章 L113]

Hinton 以不同手寫 `2` 被誤認為 `3` 或 `7` 的比例說明：即使正確類別相同，各輸入仍可能有不同混淆關係。他稱這是資料的相似結構；教材要把例子的機制說清，不把任何語言模型的數字候選都解讀成算術距離。[H, §1，p.2]

在本章已有的學生比例 `q=[0.5,0.4,0.1]` 下，T=1、單位置的軟目標交叉熵對 logits 的梯度是 `q−p`；硬目標則是 `q−[1,0,0]`：

| 目標 | 學生分數梯度 | 沿反梯度方向調整分數的含義 |
| --- | --- | --- |
| 原答案 `4` 或同樣的教師硬答案 `4` | `[-0.5,0.4,0.1]` | 提高 4，降低 3 與 100 |
| 教師 `[0.7,0.2,0.1]` | `[-0.2,0.2,0]` | 提高 4，降低 3；對 100 的直接分數梯度為零 |

Hinton §2.1 的式 (2) 給出一般溫度下 `∂C/∂z_i=(q_i−p_i)/T`；上表只是 T=1 的代入。本章 18.4 已算出這兩列，無須再訓練模型來證明。[H, §2.1，p.3；本章 L115–L131]

這說明額外訊號改變更新要求，沒有證明品質一定改善。多候選機率必須同欄同義、同條件、同待預測位置；學生容量不足、教師錯誤、資料分佈不同或蒸餾目標不合適，都可能限制收益。Hinton §2.1 也明說極低分數可能是雜訊或有用資訊，哪個佔優是經驗問題。提高溫度只重新呈現既有 logits 的差距，不產生新推理。[H, §2–2.1，p.3；M, §1–2.1，pp.2–3]

### 1.3 教師硬答案與原答案恰好完全相同時

若每筆輸入、學生 tokenizer 得到的整串有效目標（包括 EOS）、前文、遮罩與樣本權重完全相同，用同一 CE 訓練，則 `L_original(θ)=L_teacher-hard(θ)`，每個給定學生參數 θ 的梯度也相同。來源欄寫「教師」不會改變這個式子，沒有額外的教師分佈、解釋或答案資訊被交給學生。

只有在初始學生權重、優化器狀態、batch 次序、更新設定、隨機操作與確定性條件也一致時，才進一步期待相同訓練軌跡。若這些不一致，結果可以有差異，但不能歸因於新增教師訊號。若只知道最後一個數字答案相同，卻多了推理文字、不同長度、重複次數、EOS 或遮罩，就還不能說目標相同。

這是損失函式的代數推論，不是把論文實測搬成普遍保證。本章 18.3 的選讀已經給出本專案具體例子：45 筆屬性題教師硬目標 ID 與真值完全相同，同一初始化與 batch 計畫下，CE 和教師硬目標學生的權重及成績也相同。[本章 L103–L105，**章內既有實測敘述，本輪未重新驗證其結果檔**]

### 1.4 從隨機權重開始也能蒸餾

「從哪份權重開始」和「學哪份目標」是兩個選擇。新建隨機學生，從教師分佈或回答學，仍是蒸餾；學生也可先預訓練，再接受蒸餾。蒸餾不必先複製教師權重，也不要求教師與學生的內部架構相同。

Born-Again Networks 的 Figure 1 清楚寫：

> “a new identical model is initialized from a different random seed” [B, Figure 1，p.2]

該論文的學生與教師採相同參數化，足以支持「隨機重初始化與蒸餾可同時成立」，也說明蒸餾不必為縮小模型而做。它的特定任務改善不能推成所有學生都會勝過教師，更不能把同尺寸例子說成壓縮證據。[B, Abstract、§1，p.1；Figure 1，p.2]

現代 LLM 蒸餾常續訓預訓練學生。MiniLLM §2.3 明說先從預訓練學生開始，先做資料集微調，再做其蒸餾。R1 §2.4 以現有 Qwen、Llama 模型微調，並非把這些 LLM 全部從隨機權重重訓。這兩個具體設定不改變蒸餾的一般身分。[M, §2.3，pp.4–5；R, §2.4，p.11]

### 1.5 教師生成文字與完整分佈要分開

MiniLLM §1 區分僅可取得教師文字的 black-box KD，與可取得輸出分佈或中間表示的 white-box KD。本章以回答文字與輸出分佈兩條路教學是合理的；白盒概念在相關文獻還可能涵蓋中間表示，正文可明說本章只處理輸出分佈。[M, §1，p.2]

完整文字答案可提供示範的內容、風格、格式與多步解答。每個保留 token 在學生 SFT 中是選定目標，不自帶教師當時整列候選機率。一條生成序列無法唯一還原教師分佈；大量抽樣序列可用於近似某些分佈目標，也不等於每個回答位置都有完整 logits。MiniLLM 對 sequence-level KD 的 forward KL 近似分析不應改寫成「一條文字就是完整分佈」。[M, §2，p.3；本章 18.1、18.3]

R1 §2.4 以約 800k 筆整理樣本對開源學生做 SFT，該段沒有描述逐位置完整分佈匹配；對學生明說僅 SFT、不含 RL 階段。§2.3.3 的材料含約 600k 推理樣本與約 200k 非推理樣本，後者有重用 DeepSeek-V3 SFT 資料等來源，不宜籠統說 800k 每筆都由最終 R1 全新生成。[R, §2.3.3–2.4，pp.10–11]

MiniLLM 則是 reverse KL 加 on-policy/policy-gradient 訓練。本課固定標準回答前文的 forward KL，不是 MiniLLM 完整方法；兩者同用教師分佈，仍有目標方向與取樣／最佳化方式的差別。[M, §2.1–2.3，pp.3–5；本章 L32、18.8]

## 3. 沿用一個例子的正文安排

建議保留原節號與主要學習問題，不把使用者提問原樣另做一節標題。以 `2+2=?`、原答案 `4`、候選 `[4,3,100]` 貫穿早段；每節只增加一個主要變化。

**18.1：先展示原資料，再增加教師提供的訊號。** 開場可先讓學生看到已有的 `(問題, 原答案)`，知道小模型本來就能從這筆資料學。接著展示教師硬答案 `4`，最後加上教師比例 `[0.7,0.2,0.1]`。讓學生先回答「哪一欄真的多了一份指導？」再引入黑盒／白盒名稱。保留兩教師相同第一名、不同分佈的小變化，以反證文字不能還原分佈。

可採用的說明方向：我們仍把同一道題交給學生，沒有換原始題庫。普通訓練告訴它答案是 4；教師完整比例另外告訴它教師怎麼分配候選。原題庫在手上，這兩份教法仍不同。比例是否有幫助要看教師與學生，先在本節辨識收到的是什麼。

**18.2：只改學生架構，說明兩條路可用同一隨機起點。** 保留尺寸計算。在真正訓練的設計說明中，讓普通小模型與蒸餾小模型各拿同一份隨機初始權重的副本，之後才選不同目標；不讓讀者把「隨機建立」理解成蒸餾的反義詞。也說明壓縮目的要先選較小學生，向教師學本身不刪參數。BAN 的同尺寸例子放短選讀，支持定義邊界即可。

**18.3：保持輸入，先只換硬答案來源。** 本節仍教收集、檢查文字資料。把 L103 的一般機制放到主文：原答案與教師答案若都是完整的 `4` 加同樣結束目標，兩者以同樣方式教學生時沒有新增訊號。然後只改一個條件：教師生成「2 個加 2 個共有 4 個，所以答案是 4」。這時訓練文字、前文、長度已不同，可能多了過程與風格的示範，同時花更多生成／訓練 token；這不等於拿到了完整分佈，也不保證示範正確或有益。

現有「4、5 先驗證」例子可保留，用於說明教師不是真值；不要讓學生把檢驗器算出的答案重新命名成教師能力。選讀保留本課的實際 45 筆 hard-ID 相等與其他風格錯誤結果，主文先教一般推論。

**18.4：再只換成軟目標，沿用原題與原答案。** 學生比例 `q=[0.5,0.4,0.1]` 與教師 `p=[0.7,0.2,0.1]` 用既有數值。把梯度表寫成三路：「原答案」「相同教師硬答案」「教師分佈」，前兩行完全相同、第三行不同。不新增訓練或追求哪一項 loss 更小；讓讀者看見不同教法已發生在每次更新要求裡。

保留教師改成 `[0.2,0.7,0.1]` 的現有小變化，要求預測會推高哪個候選。必須將「100 的直接 logits 梯度為零」與完整網路行為區分：其他分數改變會影響 softmax 歸一化，共享參數也會影響多個候選；不能說該 token 的機率或相關網路權重從此不變。

**18.5–18.9：接上已知問題，不另換教學目的。** 溫度回應「次要比例太小怎麼辦」；它不彌補教師錯誤。18.6 與 18.8 解釋同列候選與同前文的必要條件；18.9 保留原 `4` 作為獨立 CE，說明即使原資料在手上，仍可加入教師 KL。若改變貫穿候選或分數，應在後續寫作階段同步現有溫度圖、程式和正文；本報告沒有修改這些成品。

**18.10、18.11、18.14：把質量、訓練成本與部署成本分開驗收。** 18.10 用共同獨立真值比較同學生的普通訓練與蒸餾；18.11 回看教師錯誤、風格與拒答；18.14 說明模型尺寸來自架構、數值儲存來自量化。結果只是同一質量與成本問題的後續，不用某次小實驗的改善或失敗重新決定成熟知識是否值得教。

## 4. 效率要明確指哪一階段

Hinton 原文區分提取資料結構的訓練與受到延遲／資源約束的部署，並允許先訓練很龐大的教師。[H, §1，p.1] 這支持「先花教師成本，期待獲得適合部署的學生」，不支持無條件的「蒸餾比較省訓練成本」。

| 成本 | 應計入什麼 | 不能從什麼直接推出 |
| --- | --- | --- |
| 教師準備 | 原訓練、多模型整合或載入現有教師；是否屬於本專案增量成本須說明 | 已有教師不等於教師歷史成本為零 |
| 生成／取得目標 | 硬答案解碼、質量檢查；白盒 forward、快取、儲存／傳輸 | 凍結教師不等於 forward 免費 |
| 學生訓練 | 學生 forward/backward、token 總數、更新次數、蒸餾目標計算；線上教師計算另列 | 相同步數不等於相同 token 或相同總時間 |
| 部署使用 | 學生權重、實際執行記憶體、延遲、吞吐；硬體和請求條件 | 同架構普通與蒸餾學生的部署差異不由訓練目標自動產生 |

Hinton §1 提出，高熵軟目標每例可能有更多訓練資訊、較低梯度變異，學生「can often」以較少資料和較高學習率訓練。[H, p.2] 教材若引用，應保持這是特定條件下的原文解釋與可能收益，且尚未包含教師準備、生成或快取成本；不能變成所有蒸餾都更快收斂或更少樣本的斷言。

沿用 18.10 的人工例子：學生各花 10 秒，蒸餾另有 40 秒教師時間，合計 50 秒。這一設定比較相同學生更新預算下教師訊號的作用。若兩學生部署架構相同，不能靠「每次省推論」來自動回收額外 40 秒；這項推論要先有實際部署成本差異或更好質量帶來的價值。若比較龐大教師與較小學生，才另外問部署收益能否抵銷準備成本，同時確認學生質量可接受。

原始資料在手、學生同架構、學生完全從零初始化，都不妨礙作上述蒸餾對照。方法區別始終回到輸入條件、目標、訓練起點與成本記錄各自改變了什麼。

## 5. 有意義的轉移理解題與判讀標準

這些題應安排在讀者已見過相應機制之後。題目不要求啟動訓練；答案重在條件與理由，不能只寫「軟標籤資訊更多」。

**題 1（18.3 後）：** 現在有 100 筆已有正確答案的題，教師對每題給的完整文字、EOS 都與原答案一樣。兩小模型從同一起點用相同目標位置與 CE 學。哪份材料新增了什麼監督？若成績不同，要先檢查什麼？

預期：沒有新增監督目標；先看初始化、batch／重複加權、遮罩、優化器和隨機條件，不能把來源欄位當額外知識。若只說教師比較聰明所以學生應更好，仍未理解。不給「一定同權重」滿分，除非同時說明訓練軌跡條件。

**題 2（18.4 後）：** 換成動物分類，原標籤是貓，候選 `[貓,狗,鳥]`。學生 `[0.6,0.2,0.2]`，教師 `[0.8,0.15,0.05]`，兩者第一名都貓。原標籤與教師分佈分別會如何要求調整 logits？能由此斷言測試準確率上升嗎？

預期：硬目標梯度 `[-0.4,0.2,0.2]`，軟目標 `[-0.2,0.05,0.15]`；都推高貓，但其餘候選與強度不同。不能推出泛化改善，需要獨立評估。這題換了任務，檢驗能否遷移 `q−target` 而非記憶 `4` 的數值。

**題 3（18.3–18.4 後）：** API 只回一段逐步解答，最後是 `4`。另一服務可回每個答案位置的候選分佈。前者的理由文字算不算完整軟分佈？若原答案只有 `4`，它算不算改變監督？

預期：理由改變了文字目標與長度，可新增示範過程／風格；這些 token 仍是選定答案目標，無法還原整列機率，不能直接把它當教師完整 logits 做 KL。質量與成本須另看。

**題 4（18.2 後）：** 甲從隨機學生開始，讀原問題加教師分佈；乙從預訓練學生開始，只讀原答案。哪個設定含蒸餾？把甲改成和教師同尺寸後，這個判斷會改變嗎？

預期：甲含蒸餾、乙僅憑已給條件不含；同尺寸不改變甲的教師監督關係，但不再能把它當成壓縮例子。理由應同時區分初始化、監督來源、尺寸。

**題 5（18.9 後）：** 原題庫與正確答案完全可用，教師卻在某題偏向錯誤候選。能否同時保留原答案和教師分佈？只降低 KL 是不是改善任務？

預期：可用 CE 與 KL 混合，保留正確標籤；教師權重取捨用驗證資料，測試另留。KL 下降僅說明更像教師，可能更加錯誤；原資料可用不是阻止蒸餾的條件。

**題 6（18.10 後）：** 普通與蒸餾小模型同架構，學生訓練都 10 秒，蒸餾另需 40 秒生成教師材料，部署實測都是每請求 1 毫秒。可以說蒸餾效率更高，或請求夠多就從推論時間收回 40 秒嗎？

預期：需指定效率指標。總準備時間分別為 10 與 50 秒；當前兩者推論差為零，更多請求不能由這項節時抵銷成本。蒸餾若質量更好可另有價值；若它在較少學生更新下達到所需質量，也要把教師成本重新計入，而不能僅由題中條件宣稱。

**題 7（18.8 與方法選讀後）：** 一份說明以教師生成文字做 SFT；另一份在固定標準回答前文上用 `KL(teacher||student)`；第三份用學生取樣軌跡與 reverse KL。三者是否都能稱蒸餾？能否把前兩者直接稱 MiniLLM？

預期：都可能用教師指導學生，但文字／逐位置分佈／目標方向與取樣流程不同。前兩者不憑名稱變成 MiniLLM；R1 本文學生支線是經整理資料的 SFT，MiniLLM 是特定 reverse KL 與 on-policy 最佳化。不是隻會背「黑盒、白盒」就通過。

跨題判讀：學生應能說出實際輸入、目標變化、初始化與所得限制；能舉硬答案恰同原答案的邊界案例；能解釋額外機率如何改梯度；能把原論文主張、人工算例與本課實測分開。若仍將蒸餾理解成「原資料缺失才需使用」或「任何教師文字都含完整軟分佈」，這些核心理解尚未成立。
