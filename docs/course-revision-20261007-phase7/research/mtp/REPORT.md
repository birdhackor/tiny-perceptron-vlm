## MTP 是什麼，哪些做法不能混稱

Multi-token Prediction（MTP，多 token 預測）在訓練中，讓同一個前文位置除了練習下一個 token，也承擔後面其他位置的預測目標。增加的是訓練任務；真正生成時能否一次保留數個 token，還取決於採用的推論程序。

設一段序列為 `x₀, x₁, …`，`t` 表示讀到的位置。一般下一 token 目標是 `x[t+1]`。即使訓練一次並行計算整列位置，各位置仍只負責自己的下一項；這種時間軸上的並行不自動成為 MTP。

**Teacher forcing（提供正確前綴）**是在訓練時計算「讀到正確的 A，下一項該是什麼」，而非先用模型自己生成的錯誤字繼續。它描述前綴從哪裡來。MTP 描述同一位置要學哪些未來目標。一般單 token 訓練也用 teacher forcing；DeepSeek 順序式 MTP 也會提供正確的中間 token。兩件事可以共存，不能把「一次輸入整份正確答案」當成新增了 MTP。[G §2/Eq.1–2；第 7 章 7.4、7.11；第 19 章 19.5]

### 2024 論文：平行 future-token 分支

Gloeckle 等人讓共用 Transformer trunk 讀相同的因果前綴，將它的表示交給 `n` 個獨立分支，第 `h` 個分支練習 `x[t+h]`。`n` **包含**正常的下一 token 分支。原論文的分支含 Transformer layer，各分支共用最終 unembedding 矩陣；不能把它介紹成「每個分支都有一張獨立完整詞表」，或不加說明就畫成只有幾個線性層。[G1、G2]

例如在讀到 `〈assistant〉` 時，分支 1 練 A、分支 2 練 B、分支 3 練 EOS。平行分支 2 **沒有把 A 當作這個位置的新輸入**，分支 3 也沒有先讀 A、B；它們都是根據同一份可見前文預測較遠位置。模型仍受因果限制，不能為了預測 B，先讓這個分支看見 B。

原文的目標將各有效位置與各未來距離的交叉熵相加。多個分支的梯度會回到共用 trunk；這能示範「共用表示被多種目標訓練」，不能直接推出更好的任務答案。

### DeepSeek-V3：順序式額外模組

DeepSeek 用 `D` 個**額外**模組；`D` 不包含主模型的下一 token 預測。第 `k` 個模組把上一深度的表示與 `Emb(x[t+k])` 分別經 RMSNorm，接起來、投影，再送入該深度的 Transformer block，共用主模型 embedding 與 output head。訓練時的 `x[t+k]` 是正確序列中的 token。該模組的答案是 **`x[t+k+1]`**，不是剛送入的 `x[t+k]`。[D1、D2；Eq.21–23]

因此，`k=1` 使用主模型的表示與下一個正確 A，預測 B；`k=2` 再接正確 B，預測 EOS。各模組沿著深度順序串接，也在各自的序列軸上維持因果注意力。並行處理許多訓練位置，不會把深度依賴變成 Gloeckle 式獨立分支。

Figure 3 畫了兩個額外模組以說明可擴充機制；實際 V3 設定 **`D=1`，即下一 token 加一個額外 token**，不能由插圖宣稱 V3 實際用了三 token 或任意多個模組。[D5；§4.2]

DeepSeek Eq.25 將各深度的 MTP loss 平均，再乘權重 `λ`，作為主模型的額外訓練目標。Eq.24 的每深度分母寫的是輸入長度 `T`；後面的教學算例若使用每個 head 的有效目標數作分母，必須明說這是**局部示範的計分約定**，不能稱為逐式重現 DeepSeek。實際 V3 的 `λ` 為前 10T tokens 的 0.3、後 4.8T 的 0.1，屬於該模型配方，不是本課小模型的默認值。[D3；§4.2]

| 要分辨的事 | Gloeckle 2024 | DeepSeek-V3 |
| --- | --- | --- |
| 名稱中的數量 | `n` 個預測分支，含正常下一 token | `D` 個額外模組，加主模型共 `D+1` 個目標 |
| 較遠預測是否接收中間正確 token | 同一 anchor 的分支不接收新中間 token | 每增加一深度，接收下一個正確 token 嵌入 |
| 額外路徑 | 共用 trunk 上的獨立 Transformer 分支 | 上一深度表示＋移位嵌入＋投影＋Transformer |
| 一般推論 | 只用下一 token 分支即可 | 丟掉 MTP 模組，主模型即可運作 |
| 使用額外路徑加速 | 需要自我推測解碼及驗證 | 需要推測解碼及驗證 |

## 尾端、loss mask 與已經移位的標籤

第 7 章已教了兩種不同許可：哪些輸入可讀，以及哪些答案計 loss。MTP 新增第三個對齊問題：第 `h` 個目標是否真的存在，以及是不是本次允許學的答案。[7.3–7.7、7.9–7.10；16.5]

以原始序列 `〈assistant〉, A, B, EOS` 為例：

| 目前讀到的位置 | 往後 1 項 | 往後 2 項 | 往後 3 項 |
| --- | --- | --- | --- |
| 〈assistant〉 | A | B | EOS |
| A | B | EOS | 無目標 |
| B | EOS | 無目標 | 無目標 |
| EOS | 無目標 | 無目標 | 無目標 |

尾端不存在的目標必須忽略，不能繞回序列開頭、填 PAD 當答案，或重複填 EOS 製造額外標籤。新增的 PAD 也不能改變 loss 分子、分母。EOS 在原本存在的目標位置應保留監督，超過 EOS 的位置不能被誤當成這輪回答的一部分。

本專案 `RecordEncoder.encode` 已做 `labels = labels[1:] + [-100]`；`LimitedAssistant.forward` 要求標籤已對齊 logits，再直接算交叉熵。MTP 的第 `h` 個標籤若從現成 head-1 labels 推導，應讀 `labels[t+h-1]`，不是再對所有 logits／labels 做一次「下一 token 移位」。[dataset.py:218–219；model.py:373–381；第 7 章 7.4]

原論文没有為本课 assistant-only、多轮历史、soft-token slots 規定完整 mask 政策。教學示範應額外定義以下有限約定，不能把它們冒稱論文原配方：

1. 保留原本 assistant-only 的預測起點，即 head-1 label 有效的位置。問題仍可讀；忽略問題的直接 loss 並沒有刪掉問題。
2. 較遠目標必須存在、非 PAD、位於同一筆獨立文件及同一個連續 assistant 回答目標區間。跨越忽略區、user/tool/角色/模態槽或下一輪的預測，先不納入這個示範。
3. 每個距離重新建立有效目標 mask；不要直接拿 head-1 mask 給全部 head，也不要只有終點有效就允許跳過中間被忽略的區間。
4. 若將來採 packing，同時維持 attention 的文件隔離與每個 future target 的文件邊界，EOS token 本身不會自動隔離注意力或 future label。[16.5]
5. DeepSeek 模組還要限制所讀中間 token 的有效性與文件邊界；提供 `x[t+k]` 不代表可以讀到目標 `x[t+k+1]`。
6. 分開記錄每個 head 的有效目標數及正規化；某個 head 全無目標時，不能除以零。應在示範中明確跳過並記錄，或由配置驗證拒絕。

這份保守政策是為了沿用第 7、19 章的監督意義。只按「未來終點是 assistant token」移 mask，也可能使原本 head-1 不計分的 prompt 起點得到輔助 loss；那是另一種可定義的配方，必須明說，不能無意間改掉「哪些位置在學什麼」。

## 訓練與加速要分開教

兩篇 MTP 來源都明說：可以只保留正常下一 token 生成，不部署額外路徑。[G3、D4] 如果額外分支訓練曾改變共用主模型權重，即使部署時刪掉分支，交付的回答器也是新權重，不能沿用舊成品能力成績。

要利用多 token 草稿加速，還需要**主模型驗證**。以 greedy 解碼示範，候選 `[A, X, C]` 若主模型在 A 後選 B，應保留驗證通過的 A，拒絕 X 及依賴該錯誤前綴的 C，改用 B 接續；不能只刪 X 卻保留 C。這是有限的 greedy 機制示範，沒有重現完整服務。隨機抽樣的精確推測解碼則還需要接受機率 `min(1,p/q)` 及拒絕後的校正分布；不能只把 greedy 字相同檢查套到 sampling 並宣稱分布一致。[L §2.1–2.3、Algorithm 1]

推論工程必須處理候選區塊的因果驗證、首個拒絕後的 cache 回退、EOS、renderer-only token mask、`max_new_tokens`、完整歷史與 context 總容量。第 19 章現有快取支持正常逐 token 生成，**沒有**多 token 提議／驗證／回退路徑；架構可擴充不構成已加速或值得採用的證據。[model.py:384–418；7.19；16.2–16.3；19.9]

原論文的速度只能按原條件引用：Gloeckle §3.2 在 7B 模型上實作 greedy self-speculative decoding，報告 code 3.0×、text 2.7×；DeepSeek §5.4.3 報告第二 token 接受率 85–90% 與 1.8× TPS。這些數字不能貼成這份 5.45M 模型的預期。[G8、D7、D8] Leviathan 的分析除了接受率，還有 draft 成本與驗證並行的硬體假設；head 數或接受數不等於實測 wall-clock 速度。[L3；§3.3]

若將來要宣稱本課加速，至少在相同權重、硬體、精度、提示／輸出分布、EOS／採樣規則下，比較現有 KV-cache baseline 與實際 MTP 推測路徑；分開 prefill、decode、端到端時間，將提議、驗證及拒絕成本算入。保存接受率、實際 tokens/s、暖機與同步方式、峰值記憶體及生成一致性／任務品質。這是未來效能主張所需證據，**不是本輪教學新增的先決條件**。

## 來源的收益，能推到本課成品嗎？

不能直接推出。

- Gloeckle 的 code 尺度實驗為約 300M–13B、至少 91B 訓練 tokens；Figure 3 明說較小設定比 baseline 差、較大設定較好。[G4] 但 §4.1 的受控 induction 任務又在 ≤30M 非 embedding 參數模型有正面結果。[G6] 因此不能把「小模型必定無效」或「小模型也有正面結果，所以本模型會提升」當成結論；任務、資料、tokenizer 與配方都不同。
- 原論文等參數比較把多出的分支層從 trunk 扣回來。[G7] Appendix C/Table S5 還報告其具體訓練實作有非零時間開銷。摘要的低額外成本不表示在目前四層小模型上加分支免費，也不保證訓練資源相同。
- 原論文 Appendix D/Table S6 顯示，在既有 Llama 2 上追加 MTP 微調没有顯著整体改善。[G5] 這不能證明本課追加訓練必敗，但提醒我們：「從 MTP 預訓練得到的收益」不等於「拿已完成的 NTP 成品末端加 MTP」有相同收益。
- DeepSeek Table 4 的「Small MoE」是 **15.7B 總參數／2.4B 啟用參數、1.33T 訓練 tokens**；大組為 228.7B／20.9B、540B tokens。MTP 對多數 benchmark 改善，但並非每個分項都提升，例如大組 MMLU 67.5→66.6、小組 NaturalQuestions 22.7→22.3。[§4.5.1/Table 4] 這里的「small」仍不是本課 5.45M。

成熟來源足以支持「值得教它是什麼、怎麼訓練、可能用途及取捨」。目前沒有本專案的 MTP 對照可支持「會提升工具參數、語音理解或整體品質」，也沒有驗證接受率或硬體計時可支持「會更快」。

**不在本轮主線重訓的理由：**

1. 教學問題是理解一種成熟訓練目標；標籤、loss、依賴圖與驗證算例可以教會，不需要重新訓練一個 5.45M 多模態成品才准许介绍。
2. 已有證據没有建立 MTP 對当前工具参數或語音问题的改善。先寫「會改善」再重訓來兑現，是超出來源支持的承诺。
3. 新分支／顺序模塊會改訓練目標、参數／成本、checkpoint／objective 版本、輸出包與主權重身分；即使推論丢掉额外模塊也需要新的能力驗收。追加一次訓練不是修改文字的附带成本。
4. 原論文的从零 MTP 預訓練與既有 NTP 模型追加 MTP 是不同配方。為重現原訓練收益重做全鏈，會增加預算；只追加末端訓練又不能声称已重現原論文。
5. 当前完成的有限成品與失败已經可用于解释「接口通、入口辨识、生成答案、整條工具鏈」的不同層次。保留可查證的成品，不要求每次新增成熟方法就更新所有權重，符合明確的分階段工作。

**採用价值仍存在：**MTP 展示共享表示如何承擔更遠目標、訓練訊號與自我推測候選的關係，且已有可靠原論文支持相關條件下的效果。若未來独立工程任务把改善訓練效率或經量測的 decode 瓶颈列為目標，可以评估它。先明確选擇平行分支還是顺序模塊、从零還是追加訓練，再安排小規模目標正確性检查及有預算的對照；沒有理由在這輪未經检驗地选某個版本或 λ。

若届時比較能力，可把目前 3,734 題当历史回归資料，但它们已公開且本次決策讀過，不應再標成新的盲測最後考卷。應保留新家族／新素材作為未参與配方选擇的最終评測。比較時分開「同數據／更新條件的目標差別」與「同實測訓練預算的成本收益」，不能同時假定新增模塊仍有相同参數、FLOP、時間與监督量。本轮没有啟動這些實驗。
