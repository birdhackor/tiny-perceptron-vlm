## 19.6 圖片與聲音怎麼交給同一位助理？

下圖用的是公開 CPU 命令真正讀取的商品圖。第一題問「圖片中的服飾是什麼？」，模型生成「這是短靴。」；第二題改問「左邊是什麼？」，模型生成「左邊是褲子。」先看物件，再看位置：第二張的包在右格，不能因為圖裡有包就答包。

![公開推論的真商品素材：單物件短靴，以及左褲子右包的兩格場景；下方標示實際 CPU 生成回答。](../figures/p6-19-modal-fashion.svg)

服飾入口只學 Fashion-MNIST 的**褲子、包、短靴三類**。本輪把來源灰階商品像素放進自製場景，另外提供兩個格位的公開座標：例如左半張與右半張。程式按座標取出兩格，再把各格的像素與位置送進自行訓練的圖片入口。座標回答「看哪裡」，沒有提供「那裡是褲子」這個類別答案；這也不是模型自行偵測任意照片中的物件。

圖片入口算出物件特徵，接頭把它們轉成文字核心能讀取的向量，放進對話序列中預留的兩個圖片位置。格位座標與格位順序也進入表示，因此交換左右後，核心有機會分辨物件搬到了哪裡。這接續[10.6](10.md#10.6)的寬度轉換與[11.14](11.md#11.14)的位置保留：只留下「有褲子、有包」的平均摘要，還不夠回答「左邊是什麼」。

讀字再增加一個明確條件：使用者提供要讀的框。下面是公開命令的真字卡，綠框的原圖座標為 `[18,50,90,86]`；框內寫「大小」，上方的字不在這次回答範圍內。

![公開 OCR 推論的真字卡，綠框標出使用者提供的下方區域；該次 CPU 模型生成「大小」。](../figures/p6-19-modal-ocr.svg)

程式先依座標裁切，等比例縮放框內像素並補白邊，再交給自行訓練的讀字入口。它保留從左到右的特徵位置，接成32個輸入向量，由同一文字核心生成字串。因此「讀對字」「保留字序」「只讀框內」是三件要分開核對的事；裁切本身不會認字。

這份成品的字表是 **「大小上下左右開關入出人口」12字**，每次使用者提供一個連續、包含1–4字格的區域。字卡用 Noto Sans CJK TC 與 Noto Serif CJK TC，**兩種字體都出現在訓練中**。最後題可以檢查留出的字串、素材與版面變化，不能稱作未見字體測試；它也沒有自動找文字位置的模型。[11.18](11.md#11.18)的「先指定框，再讀框內字」在這裡成了實際推論介面。

聲音則保留隨時間變化的材料。公開例子使用一段 MInDS-14 中文 App 問題錄音，對話中目前的 user 文字只有「請回答這段語音問題。」；音訊附在這一輪，沒有把逐字稿或意圖標籤塞進問題。下圖的波形與色塊是**流程示意**，不是這段錄音的實測圖。

![語音流程示意：按時間排列的聲音特徵經自行訓練入口及保留分數比例的接頭，交給共享文字核心；實際生成的第一輪回答保存後，加入使用者改寫要求再續聊。](../figures/p6-19-modal-voice.svg)

固定的 log-mel 計算先把完整錄音變成按時間排列的40頻帶特徵。自行訓練的語音入口再處理時間變化，整理成16個有順序的區間向量，交給同一文字核心。這份材料只涵蓋地址更新、App 問題、卡片問題三類銀行需求，回答是專案撰寫的一般短提示，不涉及實際帳戶操作。

三種入口還有共同安排：除了內容特徵，也保留各候選類別或字形的**整組分數比例**，用可調投影接進核心。這種接頭可稱為 soft bridge，意思是還保留多個候選的程度，沒有先挑最大分數的類別，再查表貼一句固定答案。最終文字仍由文字核心逐字生成；感知分類頭的最大分數預測與最後回答，要各自評分。這個公開語音例的回答正確，獨立分類頭卻沒有選對類別，兩件事不能混稱通過。

公開 CPU 續聊也真的沿用了模型自己的回答：

| 這輪收到什麼 | 這輪實際生成什麼 |
| --- | --- |
| 先前要求「用一句回答」＋同一段 App 問題音訊 | 先檢查網路並重新啟動App，仍失敗再詢問官方客服。 |
| 保留上述真實回答，再加入「請將剛才的答覆改成兩點。」 | 1. 先檢查網路並重新啟動App。<br>2. 仍失敗再詢問官方客服。 |

第一輪生成後，程式保存原訊息、音訊路徑與這次真正的 assistant 回答；下一輪只加入新的 user 要求。音訊留在原來那輪，不重新當成目前問題，也沒有用示範答案替換第一輪。保存歷史讓核心收得到前文，使用歷史的行為則需要訓練，這正是[12.16](12.md#12.16)的兩項合作。

本輪先分別訓練圖片、讀字與語音入口，再在共同訓練中固定感知的骨幹與分類頭，更新文字核心和接頭。所有神經零件都由本專案從零訓練；聲音這條路沒有載入預訓練 ASR，也沒有先聽寫成文字。它是有限語音需求的文字回答，不能稱為通用聽寫或語音輸出。是否能依新素材改答、能否保留文字格式與續聊主題，統一用[19.12](19.md#19.12)的留出題及成對控制核對。
