# 先用譬喻認得零件

譬喻幫助建立第一個印象；右欄指出它不能替我們推論的部分。遇到新詞再回來查，不必一次背完。

| 名詞 | 可以先怎麼想 | 要保留的界線 |
| --- | --- | --- |
| token／tokenizer | 字卡／把文字切成卡片的方法 | 卡片可能是位元組，未必是一個完整字 |
| embedding | 用卡片 ID 查一本向量字典 | ID 不是大小；向量初始時尚未學出語意 |
| tensor／shape | 數字盒子／各軸有幾格 | 每個軸的意思由資料與程式決定 |
| Linear | 同一組加權配方 | 共用配方只沿指定的特徵軸運算 |
| activation | 在配方間加入彎曲 | 沒有它，多層 Linear 仍可合成一個 Linear |
| logits／softmax | 候選分數／把一塊餅分給候選 | 比例不代表已校準的真實正確率 |
| loss／gradient | 猜錯代價／每個旋鈕的敏感度 | 代價低不保證自由生成、誠實或安全都好 |
| attention | 查閱與這張卡相關的筆記 | 是加權混合數值，沒有人的注意力或理解 |
| Q／K／V | 查詢需求／筆記索引／筆記內容 | 三者是學出的向量，不是人工標記的關鍵字 |
| causal mask | 擋住明天答案的遮板 | 仍可看目前位置；資料本身也要避免洩漏 |
| padding／loss mask | 空椅子／哪些位置要出考題 | 不出題的提示內容仍可影響答案 |
| residual | 留著原稿，再加修訂 | 兩條路相加，仍要核對向量尺寸 |
| normalization | 每張卡片自己調尺度 | 不應跨時間讀到未來；LN 與 RMS 規則不同 |
| checkpoint | 暫停遊戲的存檔 | 接續訓練還需動量、步數、資料與隨機狀態 |
| SFT | 示範理想回應給學徒看 | 模仿示範不代表能推廣到所有新情境 |
| DPO | 給兩份作答，指出較偏好哪份 | 必須有合適的比較資料與參考模型 |
| safety alignment | 教清楚權限與處理邊界 | 小規則資料無法證明一般安全性 |
| LoRA | 在原畫旁疊一張薄修正圖層 | 基模仍佔空間；省的是更新參數量 |
| patch／projector | 圖片小方塊／尺寸轉接頭 | 尺寸合得上，不代表語意已對齊 |
| spectrogram／mel | 分時段看看有哪些音高成分 | 頻譜不是文字，音高分類不是語音辨識 |
| Dense／MoE | 大家一起做／分單給少數師傅 | 專家可能偏科或閒置；路由也有成本 |
| KV cache | 已寫好的舊筆記留著用 | 仍保存每層 K/V，長上下文可能很佔記憶體 |
| Flash Attention | 分塊算、避免搬整張中間表 | Python 的等價算式不等於高效 GPU kernel |
| quantization | 換成較粗的刻度尺 | 誤差、儲存、執行記憶體與速度分開量 |
| distillation | 小學生模仿較大的老師 | 老師可能答錯；學生需要獨立真值評估 |
| RAG／tool call | 先找小抄／開工單請工具做 | 找到資料不等於用對；文字工單不等於已執行 |

章節標題仍保留常用英文名詞，方便對照其他教材；正文先說現象，程式與公式再把譬喻說精確。
