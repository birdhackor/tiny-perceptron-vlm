# 第 1 章：從猜下一個字開始

在輸入法裡打出「貓」，下一字候選可能有「看」或「吃」。文字模型也在做這種接字工作：根據已經給出的字，替下一字的候選打分。本章先用短句建立字與編號、問題與答案的對應，再讓一張可調的數字表改變猜法。最後把猜出的字接回去，看看一個接字規則怎樣變成一段新文字。讀到忘了的名詞，可以查[名詞頁](../glossary.md)。

## 1.1 文字怎麼變成可還原的編號？

我們要讓程式看到「貓」時猜下一字。先準備一句材料：**貓看狗，狗看貓。** 希望程式既能記錄這些字，又能在猜完後把結果寫回人能讀的文字，所以需要一張雙向對照表。

替每種字安排一個整數，這個數叫 ID（identifier），也就是識別編號。本例的約定如下；標點也是句子的一部分，照樣編號。

| 字 | 。 | 狗 | 看 | 貓 | ， |
| --- | --- | --- | --- | --- | --- |
| ID | 0 | 1 | 2 | 3 | 4 |

因此原句可記成 `[3,2,1,4,1,2,3,0]`。兩次「貓」都用 3，兩次「狗」都用 1。ID 像書的索書號，只用來找同一項：3 不表示貓比狗大三倍，也不表示意思更接近哪個字。

![原句每字與固定編號的對應，並可查回文字](../figures/rewrite-01-character-ids.svg)

圖中的上下兩格是一個字與它的 ID。電腦往下查得到編號，往上查能還原文字；現在還沒有任何猜字能力。

下面讓 Python 建立這張表。包含所有可用字的清單叫**字表**（vocabulary），程式裡存在變數 `chars`。`set(text)` 去除重複字，`sorted` 再依每個字在 Unicode 裡的編號由小到大排列。Unicode 是電腦通用的字元編號標準，例如句號「。」是 12290、全形逗號「，」是 65292，所以句號排最前、逗號排最後。這個順序是約定，不是按字義或筆畫排列。清單、字典與方括號的寫法見 [W.2](../first-steps.md#W.2)。

```python
text = "貓看狗，狗看貓。"
chars = sorted(set(text))
to_id = {}
for i, char in enumerate(chars):
    to_id[char] = i
ids = [to_id[char] for char in text]
restored = "".join(chars[i] for i in ids)
print(chars)
print(ids)
print(restored)
assert restored == text
```

`enumerate(chars)` 逐項提供「位置、字」，迴圈將它存入字典 `to_id`。`[to_id[char] for char in text]` 則按原句順序逐字查編號。三行輸出依序是 `['。','狗','看','貓','，']`、`[3,2,1,4,1,2,3,0]` 和原句。

最後的 `chars[i]` 由編號查回字，`"".join(...)` 把字接起來。文字變編號叫**編碼**（encode），編號變文字叫**解碼**（decode）；`assert restored == text` 檢查來回後仍是同一句，通過時沒有額外輸出。這個檢查證明記錄可還原，不表示程式懂了貓或狗。

練習把程式的 `chars = sorted(set(text))` 改成 `chars = sorted(set(text), reverse=True)`，`reverse=True` 要求由大到小排。先預測 ID 和還原文字各會怎樣，再執行：字表變成 `['，','貓','看','狗','。']`，原句的 ID 變成 `[1,2,3,0,3,2,1,4]`，但編碼、解碼使用同一張新表，仍能得到原句。可見 ID 只在同一張字表裡有效；本章與下一章為了方便手算，常重新約定字表，每次都會先列出對照。

## 1.2 怎樣留下真正沒練過的題目？

如果學生練習「貓看狗。」後，考試又出完全相同的一句，高分可能只表示背熟了。要檢查新材料，先把文字分成不同用途，再讓模型接觸其中的一部分。

本節的材料是五份文件，每份只有一句，其中「貓看狗。」重複一次：

`貓看狗。／狗看貓。／鳥看魚。／魚看鳥。／貓看狗。`

希望得到三份互不重複的材料。**訓練資料**用來調整模型內的可調數字，這些數字叫**參數**（parameter）；**驗證資料**用來選設定；**測試資料**留到設定選完後，作最後檢查。設定指訓練前由人決定、訓練不會自己改的選擇，例如模型一次讀幾個前文字：[2.5](02.md#2.5) 會比較讀前 1、3、5 字的模型，看哪個在驗證資料上猜得較準，這就是選設定。挑設定時已經看著驗證成績做決定，驗證資料就不再是完全沒看過的題目，所以最後的檢查要另用一直沒碰過的測試資料。

專案的 `split_documents` 先移除完全一樣的文字，再打亂與分組。這五份只有四份不同文字，結果會是訓練兩份、驗證一份、測試一份。

下面先從專案的 `tiny_perceptron` 載入寫好的版本看結果，分組結果取名為 `parts`：這份字典以 `train`、`validation`、`test` 為鍵，分別對應訓練、驗證、測試的文件清單。`.items()` 每次提供一對「鍵與值」，所以迴圈的 `name` 接住組名，`documents` 接住該組清單。

最後用 `set(...)` 將清單變成只保留不同文件的集合；兩個集合的 `&` 是交集，找出兩組共有的文件。`not` 要求交集為空，確認沒有同一份文件同時出現在訓練與驗證。

```python
from tiny_perceptron.data import split_documents

docs = ["貓看狗。", "狗看貓。", "鳥看魚。", "魚看鳥。", "貓看狗。"]
parts = split_documents(docs, seed=42)
for name, documents in parts.items():
    print(name, len(documents), documents)
assert not (set(parts["train"]) & set(parts["validation"]))
```

每行輸出都列出組名、份數與實際文字，先逐份核對沒有同一份跨組。`seed=42` 固定打亂順序的起點，方便重現這次分組；42 本身沒有語言意義。

這個函式定義在 [tiny_perceptron/data.py](../../tiny_perceptron/data.py)，全文只有十一行：

```python
# 節錄自 tiny_perceptron/data.py：split_documents
def split_documents(documents, seed=42):
    """先去完全重複，再依完整文件切分；真實語料還要處理近重複家族。"""
    docs = list(dict.fromkeys(documents))
    random.Random(seed).shuffle(docs)
    n = len(docs)
    if n < 3:
        raise ValueError("至少三份不同文件，才能示範 train/validation/test")
    a, b = max(1, int(n * 0.8)), max(2, int(n * 0.9))
    b = min(b, n - 1)
    a = min(a, b - 1)
    return {"train": docs[:a], "validation": docs[a:b], "test": docs[b:]}
```

`def` 那行括號裡的 `seed=42` 是預設值：呼叫時不寫 seed，就用 42。下一行三個引號包住的文字是函式的說明（docstring），不會執行。`dict.fromkeys(documents)` 把每份文件當成字典的鍵；同一份字典的鍵不能重複，第二份「貓看狗。」不會變成另一個鍵，只留第一次出現的位置，`list(...)` 再把這些鍵排回清單。這裡不用 `set` 去重複，因為字典會照第一次出現的順序保存；`set` 裡文字的順序每次執行可能不同，打亂後的分組就無法重現（1.1 用了 `set` 之後立刻 `sorted`，才把順序固定下來）。

`random` 是 Python 內建的亂數工具，data.py 開頭已經 `import random`。`random.Random(seed)` 建立一個從 seed 起算的亂數產生器，`.shuffle(docs)` 用它把清單就地打亂；seed 相同，打亂結果就相同。`n = len(docs)` 數出不同文件有幾份；`if n < 3:` 表示條件成立時才執行下面縮排的那行，`raise ValueError(...)` 會主動停下程式、顯示括號裡的訊息：少於三份不同文件，就分不出三組。

接著算兩個分界：a 標出訓練資料在哪裡結束，b 標出驗證資料在哪裡結束。`a, b = …, …` 把逗號兩邊的結果分別存進 a 與 b；`int(...)` 去掉小數部分，`max(1, …)` 取兩數中較大者，保證 a 至少是 1，`max(2, …)` 同樣保證 b 至少是 2。目標是約八成給訓練、一成給驗證，其餘給測試。後兩行的 `min(…)` 取較小者：`b = min(b, n - 1)` 讓 b 之後至少剩一份測試，`a = min(a, b - 1)` 讓 a 與 b 之間至少有一份驗證。份數少時，去掉的小數和這些保證可能讓實際份數偏離目標。

最後用切片取出三段：方括號裡的冒號表示取一段，`docs[:a]` 是位置 0 到 a 之前，`docs[a:b]` 是 a 到 b 之前，`docs[b:]` 是 b 到最後。右端那個位置不包含在內，所以三段不重疊，也不漏掉任何一份。

本例 n=4：`int(4×0.8)=int(3.2)=3`、`int(4×0.9)=int(3.6)=3`，a、b 先都是 3；`b=min(3,3)=3`，`a=min(3,2)=2`。下面沿用第一段的 `docs` 與 `parts`，重做函式的前兩步，看看切之前的順序：

```python
import random

unique = list(dict.fromkeys(docs))
random.Random(42).shuffle(unique)
print(unique)
print(split_documents(docs) == parts)
```

`unique` 就是函式裡打亂後的 `docs`，順序是「鳥看魚。、狗看貓。、魚看鳥。、貓看狗。」。按 a=2、b=3 切開，前兩份當訓練、第三份當驗證、最後一份當測試，正是第一段輸出的 2、1、1 份。照順序執行過上面節錄的那一段後，同名的 `def` 已蓋過第一段載入的 `split_documents`，所以最後一行用節錄裡的定義重算（沒寫 seed，用預設的 42），結果和第一段用載入版本算好的 `parts` 相同，印出 `True`；跳過那一段，這行只是拿載入版本和自己比，同樣印出 `True`。[1.12](#1.12)、[1.14](#1.14) 與 [2.5](02.md#2.5) 的小實驗也用這個函式切 12 篇短文：a=9、b=10，得到 9、1、2 篇。

只查字串完全相等仍不夠。若從「貓看狗。狗看貓。」這篇每次取連續四個字當一段，再往後挪一個字取下一段，前兩段就是「貓看狗。」與「看狗。狗」；把這兩段分到兩組，它們共享「看狗。」。模型已練過其中的連續內容，卻又被當作新材料考一次，這叫**資料洩漏**（data leakage）。所以通常先按完整來源分組，再在各組內切片段；`split_documents` 收的正是一篇篇完整文件。同一篇的改寫、同一段對話的版本也應一起分：docstring 說的「近重複家族」，就是這類幾乎相同、應該整組放在同一邊的文件。第 5 章（[5.12](05.md#5.12)）才正式講家族，這裡只需要知道 `split_documents` 只去掉完全相同的文字。

共用「貓、看、狗」這些字沒有問題：新文件本來就使用舊字。需要避免的是把同一來源的複本或高度重疊片段當成新題。

練習在第一段程式的 `docs` 清單最後再加一份 `"貓看狗。"`。先預測：不同文字仍是四份，分組應和原來完全相同。再把新加的那份改成 `"鳥看貓。"`：不同文字變成五份，照上面的算法 a=3、b=4，應得訓練 3、驗證 1、測試 1。這次沒有訓練模型，只在確認函式先去重複、再按份數切分。

## 1.3 「猜下一字」該配哪個答案？

材料是「貓看狗。」。我們希望看到「貓」就猜「看」，看到「看」就猜「狗」，看到「狗」就猜句號，而不是看到什麼就照抄什麼。

| 目前提供的字 | 貓 | 看 | 狗 |
| --- | --- | --- | --- |
| 希望猜出的下一字 | 看 | 狗 | 。 |

句號後沒有提供下一字，因此本例不把句號當問題。先只看目前一字，後續再擴大能讀的前文；答案始終是下一個位置上的字。

`list("貓看狗。")` 把字串拆成一字一項的清單 `s`。接著用 [1.2](#1.2) 看過的切片：`s[:-1]` 的 `-1` 表示最後一項，取到它之前，也就是去掉最後一項作問題；`s[1:]` 從位置 1 取到最後，去掉第一項作答案。位置從 0 數起，見 [W.2](../first-steps.md#W.2)。

```python
s = list("貓看狗。")
x = s[:-1]
y = s[1:]
print(x)
print(y)
for current, answer in zip(x, y, strict=True):
    print("看到", current, "下一字", answer)
assert len(x) == len(y) == 3
```

前兩行分別印 `['貓','看','狗']` 和 `['看','狗','。']`。`zip` 按相同位置配對，再印出表中的三道題；`strict=True` 要求兩份長度相同。圖裡每條向下箭頭就是一題。

![下一位置對齊：目前字與右邊一字逐題配對](../figures/foundations_shift.svg)

這種讓每個位置配上它的下一個位置的做法，叫**下一位置對齊**，程式裡常叫 **shift**。它沒有修改原文，而是建立兩份切片。若誤把 `y` 也寫成 `s[:-1]`，題目就變成「貓→貓、看→看、狗→狗」；長度仍正確，學的工作卻變了。

練習先手寫「鳥飛。」的問題與答案，再把程式的 `s = list("貓看狗。")` 改成 `s = list("鳥飛。")`，長度檢查的 3 改成 2。應得到「鳥→飛、飛→。」兩題。接著故意令 `y = s[:-1]`，看看為什麼長度檢查無法發現照抄問題。

## 1.4 完全不讀前文，能用什麼猜法？

先準備一袋下一字候選：三個「貓」、一個「狗」、一個「鳥」。如果完全不知道前文，至少能讓常見字取得較多機會：貓佔五份中的三份，機率是 3/5=0.6；狗與鳥各 0.2。

這種只數單字的方法叫 **unigram**。它提供一個容易理解的**基準**（baseline），也就是之後拿來比較的簡單起點。次數回答「出現幾次」，機率回答「佔全部的多少比例」；三個候選的機率加總應是 1（機率的基本規則見 [W.4](../first-steps.md#W.4)）。

```python
from collections import Counter

text = "貓貓貓狗鳥"
counts = Counter(text)
total = sum(counts.values())
probability = {}
for char, count in counts.items():
    probability[char] = count / total
print(counts)
print(probability)
assert abs(sum(probability.values()) - 1) < 1e-6
```

`Counter` 替每種字計數，第一行會印貓 3、狗 1、鳥 1。`counts.values()` 取出全部次數，`sum(...)` 加起來得到總數 5；迴圈用 [1.2](#1.2) 的 `.items()` 逐對取出字與次數，把次數除以 5，第二行得到 `{'貓':0.6,'狗':0.2,'鳥':0.2}`。

最後一行確認加總接近 1：`abs` 取絕對值，`1e-6` 是 0.000001。電腦儲存小數有微小誤差，加總可能差一點點、不剛好是 1，所以只要求它與 1 的差距小於這個容忍範圍，並非允許漏掉候選。

這張分配沒有收到前文。因此問「貓看」後面接什麼，或問「狗吃」後面接什麼，它都給貓 0.6。猜貓可能經常碰巧正確，卻不能說抓住了前後字的關係。

拿到分配後還要選字：永遠取最高者，本例每次都是貓；按機率抽選，狗與鳥仍有機會。計算分配與使用分配是兩步，這裡先完成第一步。

練習把 `text = "貓貓貓狗鳥"` 改成 `text = "貓貓貓狗狗狗鳥"`。貓的次數仍是 3，但總數變 7，機率降至 3/7≈0.429。先手算，再核對程式，分清次數沒有減少與佔比下降。

## 1.5 知道前一字，怎樣改變下一字的機率？

讀這段材料：「貓看狗。狗吃魚。貓看鳥。」其中貓後面兩次都是「看」。如果知道目前是貓，應比完全不讀前文更偏向看；問題是怎樣把這條關係記成可計算的表。

一對相鄰字叫 **bigram**。我們讓列代表目前字、欄代表下一字：「貓→看」每出現一次，貓列、看欄就加 1。這張表叫**接字表**（bigram 表）。再讓每列除以自己的總數，得到「目前是這個字時」的下一字機率。這叫**條件機率**；`p(看|貓)` 讀作「在目前是貓的條件下，下一字為看的機率」。

材料少時，沒看過的組合不一定不可能。我們先在每格放 1，再加上觀察次數，這叫**加一平滑**。本例字表有七種字，貓列先放 7 個 1，再加上觀察到的 2 次「貓→看」，總數是 9。

下面改用數值工具庫 PyTorch（程式裡寫 `torch`）保存與運算這張表。它裝數字的容器叫 tensor，這裡是一張七列七欄的表；列、欄與軸的讀法見 [W.3](../first-steps.md#W.3)。之所以換掉 1.4 的字典，是因為接下來要讓程式自動算出每格該往哪邊調（[1.10](#1.10)），再真的更新（[1.12](#1.12)），這些工作 PyTorch 都替 tensor 準備好了。

```python
import torch

text = "貓看狗。狗吃魚。貓看鳥。"
chars = sorted(set(text))
ids = [chars.index(char) for char in text]
counts = torch.ones(len(chars), len(chars))
for current, answer in zip(ids[:-1], ids[1:]):
    counts[current, answer] += 1
totals = counts.sum(dim=1, keepdim=True)
probability = counts / totals
row = chars.index("貓")
print(chars)
print(counts[row], totals.shape, totals[row])
print(probability[row])
assert torch.allclose(probability.sum(dim=1), torch.ones(len(chars)))
```

`chars.index(char)` 查字在字表的位置，當作 ID。`torch.ones(len(chars), len(chars))` 建立七列七欄、每格都是 1 的表，也就是加一平滑的起點。`zip(ids[:-1], ids[1:])` 就是 [1.3](#1.3) 的下一位置對齊：每個目前字和右邊那一字配成一對。`counts[current, answer] += 1` 按目前字與答案選中一格，`+= 1` 是加 1 後存回同一格；這與 1.4 數全部字不同。字表為 `['。','吃','狗','看','貓','魚','鳥']`，貓列的「看」格是 1+2=3，其餘六格都是 1。

`counts.sum(dim=1, keepdim=True)` 把每列的七格加起來：`dim=1` 是欄的軸，跨欄加總後每列剩一個總數。只寫 `sum(dim=1)` 會得到七個數排成一排，形狀 `[7]`；加上 `keepdim=True` 則保留成七列一欄，形狀 `[7,1]`，第二行輸出的 `torch.Size([7, 1])` 就是它，貓列的總數是 9。用 `[7,7]` 的表除以這一欄時，PyTorch 讓每列的每格都除以同一列的那個總數，這種自動配對叫**廣播**（broadcasting）：貓列每格都除以 9，其他列各除以自己的總數。最後的 `torch.allclose` 逐格比較兩份數字是否幾乎相等，容許 1.4 說的微小誤差；這裡確認每列機率加總都是 1。

![貓這一列的計數和平滑機率](../figures/foundations_bigram_row.svg)

圖中橘格的 3/9≈0.333 就是 `p(看|貓)`，其餘六格各 1/9。3/9 不是 1，因為另外六格合起來還有 6/9：我們仍給未見候選留一點機會。每列機率加總為 1，整張表卻不是總和為 1：它包含七道不同的「目前字」問題。

練習把 `counts = torch.ones(len(chars), len(chars))` 改成 `counts = torch.full((len(chars), len(chars)), 0.1)`；`torch.full` 括號裡先寫形狀，再寫每格要填的數，這裡是每格先放 0.1。貓列總數變 `2+7×0.1=2.7`，看的機率為 `2.1/2.7≈0.778`。先算再跑，看看為什麼起始值變小會讓已見組合更佔優勢。

## 1.6 怎樣把接字偏好存成可調的數字？

為了逐格看清可調表，我們將字表縮成三個候選：「貓、看、狗」，本節重新約定 ID 依序是 0、1、2。看到貓時，我們先給下一字分數 `[0,2,0]`：看得分最高，貓與狗相同。這樣存偏好的好處是，以後可依答案調整分數，不必每次重數整段文字。

這些可調數字就是 1.2 說的**參數**。表的列仍是目前字，欄是候選下一字；分數能正、能負，不要求總和為 1。ID 對照固定，訓練時要改的是表格裡的分數。

`from torch import nn` 載入 PyTorch 的神經網路工具箱 `nn`（[W.5](../first-steps.md#W.5) 介紹過）。其中的 `nn.Embedding` 是可調的查表工具：`nn.Embedding(3,3)` 建立三列、每列三數，這裡直接用三數當候選分數。先手動填表，再查貓與狗兩列。

```python
import torch
from torch import nn

scores = nn.Embedding(3, 3)
with torch.no_grad():
    scores.weight.zero_()
    scores.weight[0, 1] = 2.0
inputs = torch.tensor([0, 2])
output = scores(inputs)
print(scores.weight)
print(output)
```

整張 `scores.weight` 是 `[[0,2,0],[0,0,0],[0,0,0]]`。`inputs=[0,2]` 要求取第 0 與第 2 列，所以 `output` 是 `[[0,2,0],[0,0,0]]`，形狀 `[2,3]`：兩道目前字問題，每題三個候選。

`zero_()` 清零，接著只把貓列、看欄設成 2；尾端底線表示直接改原物件。`with torch.no_grad():` 底下縮排的兩行在「不記錄」模式下執行：PyTorch 平常會記下參數參與的運算，以便之後求導，也就是算出每個參數該往哪邊調（[1.9](#1.9) 起才講）；手動填初值不必記。查表之後並沒有做參數更新，這裡所有偏好都由我們指定。

輸出開頭的 `Parameter containing` 與 `requires_grad=True` 表示這張表是之後能被調整的參數，第二個輸出的 `grad_fn=<EmbeddingBackward0>` 表示查表留下了運算記錄；它們都不表示已經訓練。

分數表的格數是字表大小的平方：每種目前字都要替每個候選準備一個分數。本例三種字是 3×3=9 格，1.5 的七種字就是 49 格。它能給分也能被調整，但仍只看最近一字；看到「顏色=」與「形狀=」時，最後一字同為等號，仍會取同一列。

練習在填表區加入 `scores.weight[2, 0] = 3.0`，和 `scores.weight[0, 1] = 2.0` 一樣縮排在 `with` 底下。預測貓那題保持 `[0,2,0]`，狗那題變成 `[3,0,0]`，再核對。你改了哪一列，就先影響使用那列的輸入。

## 1.7 候選分數怎麼變成機率？

沿用「貓、看、狗」三個候選，假設分數為 `[1,2,-1]`。我們想保留「看最高、狗最低」的偏好，又希望得到能拿來抽字的比例。原分數有負數、總和不為 1，不能直接當機率。

先用指數函式 `exp` 把每個分數換成正數，再除以正數的總和，這一整套叫 **softmax**。`exp(z)` 是 e 的 z 次方，e 約 2.718（e 與次方見 [W.4](../first-steps.md#W.4)）；三個正數約為 `[2.718,7.389,0.368]`，總和 10.475。逐個相除，得到約 `[0.2595,0.7054,0.0351]`，看仍最受偏好。

把全部分數加同一常數 c，每個指數都會多乘同一個數，因為 `exp(z+c)=exp(z)×exp(c)`；分子與分母都乘了 `exp(c)`，相除時便約掉。因此可以先減最高分 2，使分數成 `[-1,0,-3]`，避免指數過大，再得到相同機率。

```python
import torch

z = torch.tensor([1.0, 2.0, -1.0])
weights = (z - z.max()).exp()
p = weights / weights.sum()
print(weights)
print(p, p.sum().item())
print((z + 100).softmax(dim=0))
assert torch.allclose(p, z.softmax(dim=0))
```

第一行印約 `[0.368,1,0.050]`。第二行是三個機率與總和：`.item()` 把只有一個數的 tensor 取成普通數字（[W.3](../first-steps.md#W.3)），印出的 1.0000001 與 1 只差電腦小數的誤差。第三行將全部分數加 100 後，仍得到同一分配。最後將手算與內建 `softmax` 核對。

`dim=0` 指本例唯一的候選軸。若有多筆分數 `[筆數,候選數]`，應沿最後的候選軸換算，讓每題各自加總為 1。不同題目不能共用一份機率總額。

softmax 只整理偏好，沒有讀正確答案。若狗的錯誤分數最高，它仍會給狗最多機會。下一節才用答案判定這份機率好不好。

練習把 `z = torch.tensor([1.0, 2.0, -1.0])` 的第一個數，也就是貓的分數 1.0 改成 3.0，其他不動。三機率變成約 `[0.7214,0.2654,0.0132]`：看的分數沒改，機率卻降低，因為大家共用同一個分母。

<details>
<summary>補充與重做</summary>

`allclose` 容許很小的浮點誤差；`assert` 通過時不印額外訊息。此段沒有改任何參數，只把同一組分數換成比例。

</details>

## 1.8 怎樣用正確答案評分這次猜法？

答案是「看」。兩份預測都將看排第一，但一份給它 0.5，另一份給 0.9。只算「第一名有沒有對」會把它們當一樣；訓練時我們希望第二份付出的代價較低，才能看出微調分數是否有幫助。

取正確答案（ground truth）那一格的機率 p，算 `-log(p)`，得到**代價**，也叫 **loss**；這把尺在 [W.4](../first-steps.md#W.4) 介紹過。`log` 是自然對數：p=0.5 時代價約 0.693，p=0.9 時約 0.105，p=0.1 時約 2.303。正確答案得到的機率越少，代價越大；代價不是猜錯題數。

把多題的這種代價取平均，這裡稱**交叉熵**（cross entropy）。先用「貓、看、狗」分數 `[0,2,0]` 算一題：答案 ID 為 1，即第二個候選「看」。

```python
import torch
from torch.nn import functional as F

p = torch.tensor([0.1, 0.5, 0.9])
print("正確機率", p, "代價", -p.log())
logits = torch.tensor([[0.0, 2.0, 0.0]])
target = torch.tensor([1])
probabilities = logits.softmax(dim=-1)
manual = -probabilities[0, 1].log()
loss = F.cross_entropy(logits, target)
print(probabilities, manual.item(), loss.item())
assert torch.allclose(loss, manual)
```

`from torch.nn import functional as F` 的 `as F` 替 `torch.nn.functional` 取了短名字 `F`。第一段列出三種正確機率的代價。第二段的 `logits` 是原始候選分數，形狀 `[1,3]`；`target=[1]` 是一題的答案位置。`softmax(dim=-1)` 的 `-1` 表示最後一個軸（[W.3](../first-steps.md#W.3)），這裡就是三個候選那一軸。softmax 後約為 `[0.1065,0.7870,0.1065]`，`probabilities[0,1]` 取看的機率，手算與 `F.cross_entropy` 都約 0.2395。

`F.cross_entropy` 接收原始分數和答案 ID，內部已完成穩定的比例化與對數計算。因此交給它的是 `logits`；若交入機率，機率又被當成分數轉換一次，會算成另一個代價。

練習把 `target = torch.tensor([1])` 改成 `torch.tensor([0])`，手算那行的 `probabilities[0, 1]` 也改成 `probabilities[0, 0]`。分數完全相同，但答案換成貓，代價便升到約 2.2395。這讓你看見：判定好壞要同時有預測與答案，不能只看最高分。

<summary>補充與重做</summary>

本例代價單位是 nat，除以 `log(2)` 可換成 bit。比較平均代價需固定資料及文字拆分方式；[6.5](06.md#6.5) 會說明不同拆分如何影響比較。

## 1.9 參數微動時，代價會改多少？

代價高並未告訴我們哪個參數應該增大。為了能手算，先只留一個可調數字 w，把它想成 [W.6](../first-steps.md#W.6) 的水溫旋鈕：希望它靠近 3，代價 `L=(w-3)²`。現在 w=1，L=4。

| w | 代價 L | 相對於 w=1 的改變 |
| --- | ---: | --- |
| 1 | 4 | 原位置 |
| 1.1 | 3.61 | w 增 0.1，L 減 0.39 |
| 1.01 | 3.9601 | w 增 0.01，L 減 0.0399 |

「代價改變÷參數改變」分別為 -3.9、-3.99。步子越小，比例越接近 -4；這個在目前位置的極限比例叫**導數**（derivative），表示附近的敏感度。對每個參數都算一個導數，再排回原位置，就叫**梯度**（gradient）。

下面在左右各試很小一步：用 w+h 與 w-h 的代價差，除以兩點距離 2h。這種估算叫**有限差分**（finite difference）。程式用 `def` 把代價寫成函式（[W.2](../first-steps.md#W.2)），`**` 是次方。

```python
def loss(w):
    return (w - 3) ** 2


w = 1.0
h = 0.001
left = loss(w - h)
right = loss(w + h)
gradient = (right - left) / (2 * h)
print(left, right)
print(gradient, "公式計算", 2 * (w - 3))
```

h=0.001 時，左點 0.999 的代價為 4.004001，右點 1.001 的代價為 3.996001，印出的 `3.9960010000000006` 尾端多出的位數是電腦小數的誤差。從左往右，代價減 0.008、w 增 0.002，相除得到 -4；程式印出 `-3.9999999999995595`，同樣只差小數誤差。平方代價的導數公式 `2*(w-3)` 也給 -4。

負號表示「現在稍微增加 w，代價會下降」，不是要把 w 改成 -4。大小 4 表示附近 w 增加 0.001 時，代價約減少 0.004。它描述微小改變，不能保證跳很遠也變好。

練習把 `w = 1.0` 改成 `w = 5.0`：左側更靠近目標，梯度為 +4，所以希望往減少 w 的方向走。再試 `w = 3.0`，兩側代價都約 0.000001，梯度為 0。程式只測敏感度，w 還沒有被更新。

<details>
<summary>補充與重做</summary>

h 太大可能不能代表附近，太小則兩個近似小數相減的誤差會被除法放大。大型模型不逐格試左右兩次，下一節會用運算關係算導數。

</details>

## 1.10 參數的影響怎樣穿過兩段計算？

接字表的分數要先變成機率，再變成代價；參數與代價中間可能隔很多運算。先用兩段透明的材料看影響怎麼傳：`u=2*w`，接著 `L=u²`。當 w=3，前向得到 u=6、L=36。

如果 w 微增 0.001，第一段讓 u 增 0.002。第二段在 u=6 附近，每增加一單位 u，L 約增加 `2*u=12` 單位；所以 L 約增 `12×0.002=0.024`。相對原來的 w 小步，總敏感度為 `0.024/0.001≈24`。

每段的敏感度相乘，就是**鏈式法則**（chain rule）：`dL/dw=(dL/du)×(du/dw)=12×2=24`。符號 `dL/du` 是「對 u 的每單位變化，L 如何變」，不是把 L 除以 u。

![前向計算求數值，反向傳播按每段敏感度相乘](../figures/rewrite-01-chain.svg)

圖上方的 3→6→36 是數值；下方的 12×2=24 才是敏感度。兩者不能混讀。下面用 PyTorch 自動核對這條運算關係。

```python
import torch

w = torch.tensor(3.0, requires_grad=True)
u = 2 * w
loss = u.square()
loss.backward()
print("中間值", u.item(), "代價", loss.item())
print("第一段 du/dw", 2, "第二段 dL/du", 2 * u.detach().item())
print("合成梯度", w.grad.item())
assert w.grad.item() == 24
```

`requires_grad=True` 要求儲存 w 參與的運算關係；`u.square()` 是平方（W.6 用過）。從 w 依序算出 u 與 L，叫**前向計算**（forward）。`loss.backward()` 則從代價往回走，把每段的敏感度相乘，得到 w 的梯度並存進 `w.grad`，這叫**反向傳播**（backpropagation）。輸出依序是中間值 6、代價 36，第一段敏感度 2 與第二段敏感度 12，總梯度 24。

PyTorch 這套工具叫 **autograd**，儲存的運算連線叫**計算圖**（computational graph）。它用每個運算已知的求導規則往回算，不是靠左右試參數。`.item()` 的用法見 [1.7](#1.7)；`.detach()` 只在顯示時停止追蹤這份值的求導關係，不會改 w。

現在 w 仍是 3：`backward()` 算出影響量，沒有把參數搬到新位置。

練習將 `u = 2 * w` 改成 `u = 3 * w`，第二個 `print` 裡顯示第一段敏感度的 `2` 也改成 `3`。w=3 時，u=9、L=81，第二段敏感度是 `2×9=18`，梯度應為 `18×3=54`；把斷言同步改成 54 再核對。不能只把舊梯度乘 1.5，因為第二段所在的 u 也變了。

<details>
<summary>補充與重做</summary>

本例只有一條路。若同一參數沿兩條路影響同一結果，各路用鏈式法則求出影響後還要相加；[4.2](04.md#4.2) 會看一個例子。這裡的平方代價是手算材料，文字模型則仍使用 [1.8](#1.8) 的答案代價。

## 1.11 很多參數各自該往哪邊動？

兩個旋鈕目前是 `[1,2]`。第一個 w0 希望靠近 3，第二個 w1 希望靠近 0，但第二項代價只計一半。代價是 `(w0-3)²+0.5*w1²`，目前兩項為 4 與 2，總代價 6。

我們希望拿到每格自己的調整方向。只微動一格、其餘不動，得到的敏感度叫**偏導數**（partial derivative）。沿用[1.9](#1.9)的平方距離算例：距離若是 d，微增 h 時，代價改變為 `(d+h)²-d²=2*d*h+h²`；除以步子 h，得到 `2*d+h`。h 越接近零，這個比例越接近 `2*d`，所以平方距離的敏感度是目前距離的兩倍。代價前若乘上一個常數，敏感度也要乘上同一個常數。

第一格距離是 `1-3=-2`，敏感度為 `2*(1-3)=-4`。第二格距離是 `2-0=2`，但代價只計一半，敏感度為 `0.5*2*2=2`；按參數位置排成梯度 `[-4,2]`。

| 參數 | 目前值 | 梯度 | 希望降低代價時的小步方向 |
| --- | ---: | ---: | --- |
| w0 | 1 | -4 | 增加 |
| w1 | 2 | +2 | 減少 |

```python
import torch

w = torch.tensor([1.0, 2.0], requires_grad=True)
first_cost = (w[0] - 3).square()
second_cost = 0.5 * w[1].square()
loss = first_cost + second_cost
loss.backward()
print("參數", w.detach())
print("各項與總代價", first_cost.item(), second_cost.item(), loss.item())
print("梯度", w.grad)
assert torch.allclose(w.grad, torch.tensor([-4.0, 2.0]))
```

程式先分別算兩項再加總，列印可核對 4、2、6。對總代價做 `backward()` 後，參數仍 `[1,2]`，`.grad` 是 `[-4,2]`。它與參數形狀相同，每格敏感度都有自己的參數可對應。

為什麼一個總數可得出不同方向？計算圖記住 w0 影響第一項，w1 影響第二項；求導沿各自的路往回算。總代價 6 本身沒有這些方向資訊，不能拿 6 當成每格共同的更新量。

梯度也不是新參數。不能直接令 `w=[-4,2]`；我們會沿梯度的反方向走一小步，下一節再決定步子的比例。

練習只把 `second_cost = 0.5 * w[1].square()` 的係數 0.5 改成 2，預期總代價變 12、梯度變 `[-4,8]`。將斷言的第二格同步改成 8 再核對：第一格沒變，第二項的重要程度變成四倍，其梯度也變成四倍。

<details>
<summary>補充與重做</summary>

這裡的 w 是直接建立的可調來源，常叫葉節點。通常在這些參數的 `.grad` 讀更新所需梯度，中間結果的 `.grad` 不一定自動儲存。`allclose` 作逐格近似比較，`assert` 只檢查，不調參數。

</details>

## 1.12 真的更新一次，代價會怎樣？

回到一個旋鈕：w=1，目標是 3，代價 `(w-3)²=4`。剛才我們會算梯度 -4，現在才真正改參數。

更新規則是 `新參數=舊參數−學習率×梯度`。**學習率**（learning rate）是每次步子的比例；用 0.1，新 w 為 `1−0.1×(-4)=1.4`。再用新位置重算，代價是 `(1.4-3)²=2.56`。這叫**梯度下降**（gradient descent）：希望下降的是代價，參數本身可能增加。

![求導只填梯度，更新才改參數，然後重算代價](../figures/rewrite-01-update.svg)

圖把三個動作分開。梯度 -4 和參數 1 是兩份數字；先有梯度，再按指定學習率把參數改成 1.4，最後才得到新代價。

```python
import torch

w = torch.tensor(1.0, requires_grad=True)
before = (w - 3).square()
before.backward()
print("更新前", w.item(), before.item(), w.grad.item())
with torch.no_grad():
    w -= 0.1 * w.grad
after = (w - 3).square()
print("更新後", w.item(), after.item())
assert after.item() < before.item()
```

第一行印更新前的 `1、4、-4`。`w -= 0.1 * w.grad` 是「減去後存回 w」，真正改了 w；它放在 `torch.no_grad()` 裡，明確把這次調參數排除在求導記錄之外。離開區塊後，`after` 用新 w 重新算代價，所以第二行約為 `1.4、2.56`。

舊的 `before` 儲存的是原來算出的 4，不會因為 w 改了就自動變 2.56。要觀察更新效果，一定得重新前向計算。

正確方向配太大步子仍可能變差：學習率 2 會讓 w 跳到 9，代價 36。練習先把 `w -= 0.1 * w.grad` 的 0.1 改成 0.6，手算 w=3.4、代價 0.16，再執行；接著改成 2，原本「代價下降」的斷言應失敗。這個反例是在檢查步子，而不是宣稱求導算錯。

同樣規則可更新 [1.6](#1.6) 的接字分數。[T.3](../training.md#T.3) 的接字表實驗讓一張接字表在 9 篇短文上更新 200 次，平均訓練代價由 3.7733 降到 1.0568。它更新時用的是第 5 章的 AdamW（[5.4](05.md#5.4)、[5.5](05.md#5.5)），同樣靠梯度決定往哪邊調，但每步怎麼走另有規則，不是直接減「學習率×梯度」。這個結果顯示多次更新改變了猜法；能否接出合適新句，還要檢查生成結果（[1.14](#1.14)），以及模型在沒拿來更新參數的資料上表現如何。這類資料叫**留出**（held-out）資料，例如這次實驗按 [1.2](#1.2) 的切法留下的 1 篇驗證短文與 2 篇測試短文。

<details>
<summary>補充與重做</summary>

重做命令見 [T.3](../training.md#T.3)。兩個代價取自[實驗紀錄（JSON）](../../docs/course-experiments/results/simple_models.json)，這是機器可讀的完整結果：看 `results.runs.bigram` 的 `before_nll.train`（更新前）與 `after_nll_same_post_update_time.train`（200 次更新後）；欄名的 nll 是負對數機率，也就是 [1.8](#1.8) 的 `-log(p)`，這裡存的是每題的平均。本節只做一次求導，沒有清梯度的問題；下一節會看重複求導。PyTorch 不允許在一般求導模式下直接改需追蹤的葉參數，拿掉 `no_grad()` 會在原地更新處報錯。

## 1.13 沒更新參數，第二次梯度為什麼變大？

w=2，代價 w²，每次求導應得 `2*w=4`。如果 w 沒改，第二次不應突然更敏感；但 PyTorch 的 `.grad` 可能由 4 變 8，原因是它儲存的是**累積值**。

回顧三個動作：前向算出代價；`backward()` 算敏感度並放入 `.grad`；更新則另用敏感度改參數。這裡故意只做前兩個。把 `.grad` 想成收集桶，每次倒入新梯度，不會自動清空。

```python
import torch
from torch import nn

w = nn.Parameter(torch.tensor(2.0))
(w.square()).backward()
first = w.grad.clone()
(w.square()).backward()
second = w.grad.clone()
w.grad = None
(w.square()).backward()
print(first.item(), second.item(), w.grad.item(), w.item())
assert second.item() == 2 * first.item()
```

`nn.Parameter` 把 w 包成模型的可調參數，和 1.10–1.12 的 `requires_grad=True` 一樣會追蹤梯度；`nn.Embedding` 裡的表也是這種 Parameter，1.6 輸出的 `Parameter containing` 指的就是它。每次 `w.square()` 都重新做一份前向計算；`clone()` 儲存當次讀到的梯度副本。最後印 `4、8、4、2`：

| 動作 | 這次新梯度 | 桶中的 `.grad` | w |
| --- | ---: | ---: | ---: |
| 第一次求導 | 4 | 4 | 2 |
| 未清除，第二次求導 | 4 | 8 | 2 |
| 設 `.grad=None` 後再求導 | 4 | 4 | 2 |

w 一直是 2，所以變的是記錄方式。若每輪只想用當前資料更新，應先清舊梯度，再算新代價、求導與更新。管理更新的工具叫**最佳化器**（optimizer）；之後會用它的 `zero_grad()` 清梯度、`step()` 更新參數。

練習在 `w.grad = None` 那行最前面加上 `#`，讓它變成不執行的註解。第三次桶裡變 12，w 仍 2；斷言只檢查前兩次，所以仍通過。讀取全部輸出，才能知道清除是否如預期。

<details>
<summary>補充與重做</summary>

這不是對同一個 loss 物件連續求導：PyTorch 預設第一次後釋放部分計算圖材料。本例每次重新計算 w²，不需保留舊圖。刻意累積數份小批資料的梯度也是合理做法，見 [16.6](16.md#16.6)；它需要明確安排清除與更新時機。

</details>

## 1.14 下一字怎樣接成一段新文字？

給一個開頭「貓」，希望接出後續文字。這時沒有真實答案可對照：先算下一字分配、選一字、接回句尾，再把新字當下一次前文。重複接字就是**生成**。

為了只觀察這個流程，我們手動指定四字機率表，沒有訓練。字表直接寫成 `['貓','看','狗','。']`，ID 為 0、1、2、3；這次沒有排序，所以編號和 1.1 不同，只在本節有效。看到貓時取第 0 列，看的機率為 0.85；若選到看，下次就取第 1 列，而不是繼續用貓那列。

本例選字採用**抽樣**（sampling）：目前列中比例越大的字，越常被選中，但小比例的字仍有機會。`torch.multinomial(p[current], 1)` 按該列比例抽一個ID；程式用 `current` 保存目前字的ID，每次選完再接回前文。`g` 是本段專用的抽樣工具，`manual_seed(42)` 固定它的起點，方便在相同環境重做核對。`for _ in range(12):` 讓底下縮排的兩行重複十二次，`_` 表示用不到迴圈的編號。

```python
import torch

chars = ["貓", "看", "狗", "。"]
p = torch.tensor(
    [
        [0.05, 0.85, 0.05, 0.05],
        [0.40, 0.05, 0.50, 0.05],
        [0.05, 0.70, 0.05, 0.20],
        [0.50, 0.05, 0.40, 0.05],
    ]
)
g = torch.Generator().manual_seed(42)
current = 0
output = [chars[current]]
for _ in range(12):
    current = torch.multinomial(p[current], 1, generator=g).item()
    output.append(chars[current])
print("".join(output))
assert len(output) == 13
```

每次抽出的結果先用 `.item()` 取成整數，`append` 把對應字加到清單尾端；新 ID 也成為下一輪的 `current`。開頭已有一字，再抽十二次，結果共十三字。

表裡機率只有 0.05 的組合仍可能被抽中，例如看後面又接看（「看看」），或貓後面接貓（「貓貓」）。這段指定抽十二次才結束，句號只是普通候選，沒有自動停止功能；後面會另教結束標記（第 6 章起寫作 EOS），模型選到它就停止。

生成也能暴露只看一字的限制。[T.3](../training.md#T.3) 的接字表實驗（就是 1.12 那張表）用 12 篇「顏色=紅；形狀=圓。」這類短文，按 1.2 的切法拿 9 篇訓練。給開頭 `顏色=`，每步選最高分，它接出 `三角。`，合起來是「顏色=三角。」：三角是形狀，填錯欄位。

原因不在計算出錯，而在輸入只有最近一字：顏色欄與形狀欄都以等號結尾，表收到同一個輸入，自然給相同分配。訓練代價下降仍可能伴隨這種生成錯誤。下一章將更多前文送入模型，讓它有機會分清兩個欄位。

練習把 `manual_seed(42)` 的 42 改成 7，字表、機率、開頭和總長度都不變，抽到的文字可能改變。再把 `range(12)` 改成 `range(3)`，斷言長度也改成 4，核對每輪只新增一字。

<details>
<summary>補充與重做</summary>

`torch.Generator().manual_seed(42)` 固定本段抽樣工具的起點，通常能在相同軟體與裝置重現序列；不保證跨版本完全一樣。接字表的完整配方見 [T.3](../training.md#T.3)；`三角。` 取自[實驗紀錄（JSON）](../../docs/course-experiments/results/simple_models.json)的 `results.runs.bigram.samples`。

</details>

## 1.15 參數不動，選字規則怎樣改變輸出？

同一題得到「貓、看、狗」分數 `[3,1,0]`。如果永遠取最高分，就選貓；如果按機率抽，另外兩字仍可能出現。這是使用同一模型的兩種選字規則，並沒有學到新參數。

總選最高者叫 **greedy**，即貪婪選取；`argmax` 給最高分的 ID。按分配隨機抽就是 1.14 的抽樣（sampling）。還可以先用正數 τ 除原分數，再做 softmax；τ 是希臘字母，讀作 tau，叫**溫度**（temperature），只是控制分配尖銳程度的名稱。

τ=0.5 使分數變 `[6,2,0]`，差距變大，最高者更佔優勢；τ=2 使分數變 `[1.5,0.5,0]`，機率更平均。

```python
import torch

z = torch.tensor([3.0, 1.0, 0.0])
for temperature in [0.5, 1.0, 2.0]:
    probability = (z / temperature).softmax(dim=0)
    print(temperature, probability)
print("greedy的候選ID", z.argmax().item())
```

程式裡的變數 `temperature` 就是 τ。三行分配中，最高候選機率依序約 0.980、0.844、0.629。最後的 `argmax` 印 ID 0；用任何正溫度都不改分數排序，所以本例 greedy 仍選貓。溫度主要改抽樣時各字的機會。

用現在的參數算候選分數叫**推論**（inference）；生成反覆推論，再選字接回。改溫度改的是推論時使用的機率，更新參數才是訓練。高溫度可能增加多樣性，也可能增加不通順結果；低溫度也不保證正確。

練習只把 `z` 的第三個分數 0.0 改成 2.0。它的機率增加，三個溫度下最高者約為 0.867、0.665、0.506，greedy 仍選 ID 0。比較溫度時固定分數；比較模型訓練效果時，則固定溫度與選字方式，才能知道差別從哪裡來。

<details>
<summary>補充與重做</summary>

τ 必須大於 0；「趨近 0」不等於直接設 0，除以 0 無法使用。若最高分並列，還要由實際取最大值規則處理。更換抽樣種子也可改文字，見 [1.14](#1.14)。

</details>
