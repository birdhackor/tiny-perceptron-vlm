# B：從結構化回答到工具使用

前置：第7章對話與8.5結構化輸出。模型提出要求，外層程式驗證後調用白名單純函數，再把結果給模型。這裏不執行模型產生的任意Python或外部請求。

## B.1 模型怎麼要求程式幫忙？

**先想一想：**模型寫「已算出」就代表調用過計算器嗎？

![本節圖解](../figures/tools.svg)

讓模型學輸出工具名稱與參數，像寫一張服務單。工具請求只是文字/資料，直到外層程式真的執行纔會得到結果。

**把直覺寫成數學：**SFT示例同時含「該直接答」與「該請求工具」情境，避免每題都調用。

**最小實驗：**以下程式只處理這節的問題。

```python
request = {"name": "multiply", "arguments": {"a": 123, "b": 45}}
training_example = {"user": "123乘45", "assistant_tool_request": request}
print(training_example)
print("請求與實際執行結果分開記錄")
```

**如何讀結果：**這個請求人工編寫；模型生成版本需先通過B.2檢查，不能從流暢文字推斷執行成功。

**只改一件事：**只換問題數值，同步覈對參數。

## B.2 文字怎麼變成有效呼叫？

**先想一想：**JSON能解析但工具叫delete_all，應該執行嗎？

parse只把JSON變成結構，驗證還要檢查名稱、欄位與類型。像服務單必須符合菜單，不能允許未知工具或把代碼字串當數字。

**把直覺寫成數學：**allowlist＋schema validation；bool在Python是int子類，因此需type嚴格檢查。

**最小實驗：**以下程式只處理這節的問題。

```python
from tiny_perceptron.retrieval import call_tool

requests = ['{"name":"add","arguments":{"a":2,"b":3}}', '{"name":"delete_all","arguments":{"a":2,"b":3}}']
for request in requests:
    try:
        print(call_tool(request))
    except ValueError as error:
        print("預期拒絕", error)
```

**如何讀結果：**驗證失敗是合法診斷，不是隱藏跳過；原請求與錯誤要保留供讀者定位。

**只改一件事：**只把a改成true，確認不會把bool當數值。

## B.3 工具結果怎麼回到對話？

**先想一想：**參數錯了、工具算得對，最終答案可能仍錯嗎？

執行器按驗證後的參數調用純函數，並回填真實結果。模型最後文字只能引用這個結果；不能把預期答案當成工具返回。

**把直覺寫成數學：**tool_request→validated_call→tool_result→final generation。

**最小實驗：**以下程式只處理這節的問題。

```python
from tiny_perceptron.retrieval import call_tool

request = {"name": "multiply", "arguments": {"a": 123, "b": 45}}
result = call_tool(request)
trace = [{"role": "assistant", "tool_request": request}, {"role": "tool", "result": result}]
print(trace)
assert result == 5535
```

**如何讀結果：**真的工具部分已經執行，後續LLM生成需讀者的trained模型；不能用固定final字符串替代驗證。

**只改一件事：**只改變b，覈對trace與結果一起變化。

## B.4 任務完成後怎麼停止？

**先想一想：**只有次數上限，沒有完成信號，會知道任務成功了嗎？

工具循環要有完成信號與最大步數，像每張工單都有關閉方式。無限循環可能重複做同一件事；錯誤與未完成是不同狀態。

**把直覺寫成數學：**done、step_limit、invalid_request、needs_more_model_output各自記錄。

**最小實驗：**以下程式只處理這節的問題。

```python
from tiny_perceptron.retrieval import tool_loop

requests = [{"name": "add", "arguments": {"a": 2, "b": 3}}, {"done": True, "answer": 5}]
print(tool_loop(requests, max_steps=3))
print(tool_loop(requests, max_steps=1))
assert tool_loop(requests)["status"] == "done"
```

**如何讀結果：**人工requests只驗證外層協議；真實模型每一步產生新請求，評成功率與實際調用次數。

**只改一件事：**只刪除done，觀察狀態不應被寫成成功。
