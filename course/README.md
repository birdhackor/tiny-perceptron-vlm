# 小小感知機：從接話開始理解模型

你在手機上輸入「今天天氣」，輸入法會提供幾種接法。它怎麼知道哪些字比較可能出現？這套教材先把這個問題縮到幾個字，讓你親手看見程式如何記錄例子、做出猜測、衡量猜錯的代價，再修改猜法。理解這些小步驟後，我們才把它們組成能處理較長文字、圖片與聲音的模型。

## R.1 先讀一節，不必先安裝

你可以把網站當成一本書：先讀說明，再看範例程式，程式下方已有這個版本實際執行的結果。不必先準備 GPU，也不必先下載整個專案。[第一節：文字怎麼變成數字？](chapters/01.md#1.1)只整理一小段文字，沒有完整 Transformer，也沒有要求你先懂微積分。

程式是讓我們檢查想法的工具。第一節會拿「貓看狗，狗看貓。」當材料，替每種字編號，再把編號換回原句。讀到那裡時，你可以先在紙上寫字表，再對照程式的結果：如果兩次「貓」變成不同編號，就表示整理方法有問題。讀者要能說出發生什麼，才算完成這個例子；按下執行按鈕只是其中一種核對方法。

不熟 Python，也可以從這裡開始。遇到清單、字典或方括號，點進[暖身 W.2](first-steps.md#W.2)，再回原節繼續。往後遇到數字表的軸、機率或梯度，正文會連到對應暖身，而不是要你在開頭一次補完所有數學。[暖身目錄](first-steps.md)就在網站上，任何一頁的導覽列都能找到。

想親手改例子時，每節末尾的「在 Colab 動手做」會打開同一節的說明與程式。Colab 是瀏覽器裡的程式工作桌；如何開啟、執行和重跑，見[暖身 W.1](first-steps.md#W.1)。也可以下載本節 Notebook，在自己的電腦練習。Notebook 是把文字、程式和執行結果放在一起的檔案，詳細安裝步驟同樣放在 W.1。

現在可以做一個選擇：只想先理解，就開第一節並試著口頭解釋字與編號的關係；想立刻改程式，就先走 W.1 的操作步驟，再回第一節。兩條路都會讀到同一份正文，不需要在網站與另一套教材之間來回找答案。

## R.2 可以跳章，但要知道這一跳需要什麼

這套教材不要求你從頭到尾把同一個模型訓練到底。有時候一張數字表比大型模型更容易看清問題；有時候討論圖片，反而應該先拿一張只有四個方格的小圖，而不是等文字模型訓練完成。每節的小程式可以單獨執行，所需的概念則會用具體前置連結交代。

第一次接觸語言模型，建議從第 1 章開始：先看字怎麼編號、怎麼安排「題目與下一個字」、怎麼用出現次數猜字。接著才把猜法改成可調的數字，學習猜錯的代價和更新方向。第 2 章擴大可看的前文，第 3 章解釋如何從前文選線索，第 4 章才組成初始 Transformer。Transformer 是這些零件的一種組合方式；它不是第一節必須先背下來的名字。

如果你已有基礎，可以依眼前的問題選路線。表中的「先補」是看得懂後續例子所需的最短橋樑，不是要求先跑完那些章的訓練。

練習挑表裡一個真正想回答的問題，打開對應起點，先讀它的前置段落。能用自己的話說出「我已知道什麼，現在想查什麼」，就可以開始；不能時，沿那個具體連結補一節再回來。

## R.4 小實驗、訓練與譬喻怎麼配合

教材中的小實驗通常只有幾個數字。這樣做是為了讓你能逐步追蹤：這個輸入進來，這行程式改了什麼，輸出為什麼多了一列。像把一顆螺絲拆下來量尺寸，小實驗能看清零件，但不能用它證明整台機器已能工作。

「訓練」則是把許多例子交給模型，反覆調整內部數字。我們會用接字表、短句與合成圖片做有限的小任務。要真的連續更新、保存權重並檢查新題表現，請讀[訓練操作](training.md)。權重就是模型學習時調整並保存的數字；不是每跑一次範例就會產生一個實用模型。網站短程式下的結果是在 CPU 上驗證這段例子；正文另標為「正式實驗」的數字，則來自實際訓練與固定留出題，附有可查閱的[實驗報告](../docs/course-experiments/README.md)。人工構造的成績也會明說，讓你知道眼前是在示範計算方法，還是在報告量到的結果。

想先觀察訓練後的模型，不必自己從零等待訓練。教材提供按需下載的學生權重；從[訓練操作 T.3](training.md#T.3)選擇所需版本，再在 CPU 上試一個輸入。下載檔裡保留推論所需的數字與設定，但沒有接續原訓練所需的完整狀態。模型能開啟、能回答與答得正確，也要分開看：一個能執行的模型仍可能在新題上答錯，後面的正式實驗會把這些失敗一起保留。

想把這些零件放到同一個助理裡，另看[第19章整合專題](chapters/19.md#19.1)。它沿用同一個小模型，接續練習文字、圖片、聲音與使用工具；另外保存[用回答比較繼續訓練的對照](chapters/19.md#19.8)，以及[用較少位數存檔的版本](chapters/19.md#19.10)。各項能力都用新題檢查，實際成績與失敗見[19.12](chapters/19.md#19.12)。第13章另有獨立的[選卡回饋小實驗](chapters/13.md#13.11)，每次只從幾張預寫回答中選一張，和第19章生成文字的模型分開。

第19章還比較了[兩種教較小模型的方法](chapters/19.md#19.10)。一種只照理想回答練習，在同一份90題通過62題；另一種同時看較大模型怎樣猜下一個文字片段，模仿它分給不同候選的機率，通過61題。後一種教法叫蒸餾，這次沒有帶來較高總分，較大模型也有尚未學會的項目。把後一份模型改用較少位數存檔，再載入後仍通過61題。這些模型只處理本課合成小世界；一般聊天、自然照片與真人語音能力，不能從這份成績推得。

親手試用整合模型時，先按[19.11](chapters/19.md#19.11)取得指定的推論檔，再回19.1開啟介面。成品與學生共11份推論檔已公開，版本與指紋見[第19章下載清單](../docs/course-experiments/capstone-public.json)。原有30組各章實驗與120份存檔仍按[T.3](training.md#T.3)及[各章清單](../docs/course-experiments/public-models.json)下載；兩批共用同一Hugging Face倉庫。推論檔可用來回答，精確中斷續訓還需另外的更新器與進度狀態，兩者用途在19.11分開說明。

圖解會放在相關例子附近，正文也會說清楚箭頭、位置與數字代表什麼。例如，注意力先比較前文不同位置的數字，再按比例混合它們，具體流程見[3.1](chapters/03.md#3.1)。「查筆記」可以幫你記住這個流程，卻不能推成模型像人一樣理解。MoE 叫專家混合，是每次只選少數計算零件處理的設計，見[15.4](chapters/15.md#15.4)；「分單給師傅」可以幫你理解分工，卻不能推成某個零件天然就是醫師。譬喻提供起點，數字與程式負責說明它的邊界。

模型和前處理由本專案以 PyTorch 寫出。PyTorch 是處理數字表與計算更新方向的工具箱，正文會在需要時介紹它的用法。程式、文字與自製圖解採 MIT 授權；[固定訓練資料包](../assets/training/README.md)來自不同公開來源，各有自己的授權。這些資料包是小型起步樣本，不是已訓練權重，也不是完整能力測驗。

你可以在讀完一個例子後問自己：「這段結果實際證明了哪一件事？」例如，一個圖片處理零件輸出三個數，而文字模型剛好接收三個數，只能證明數量接得上。這樣的一排數字叫向量，它有幾個數就是尺寸，詳見[2.1](chapters/02.md#2.1)。要證明模型真的使用圖片，還得比較正常圖片和錯配圖片的回答。先寫下一句能由眼前結果支持的結論，再檢查有沒有多說。這個習慣會貫穿後面的所有章節。
